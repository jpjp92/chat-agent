# 국가법령정보 API 테스트 가이드

> 목적: `law_search` 기능 구현 전에 국가법령정보센터 Open API의 검색/조문 조회 응답 구조를 고정하고, `law-tool.ts` 구현 기준을 마련한다.

---

## 1. 테스트 대상

국가법령정보센터 Open API는 제공 범위가 매우 넓다. 공유된 활용가이드 기준으로 법령, 행정규칙, 자치법규, 판례, 헌재결정례, 법령해석례, 행정심판례, 위원회 결정문, 조약, 별표/서식, 법령용어, 지식베이스, 중앙부처 1차 해석, 특별행정심판, 사전컨설팅 의견서까지 약 191개 API가 제공된다.

`law_search` 1차 구현에서는 아래 두 endpoint만 사용한다.

| 단계 | Endpoint | 목적 |
|------|----------|------|
| 1 | `lawSearch.do?target=law` | 법령명 기반 목록 검색 |
| 2 | `lawService.do?target=law` | 법령 본문 또는 특정 조문 조회 |

`aiSearch`는 현재 MVP에서 제외한다. 실측 기준으로 빈 응답/검증 실패가 발생할 수 있고, 법령명 + 조번호 기반 질의는 `lawSearch`와 `lawService`만으로 처리 가능하다.

---

## 2. API 범위 분류

1차 구현과 후속 확장을 아래처럼 나눈다.

| 단계 | 범위 | 제공 API 예 | 판단 |
|------|------|-------------|------|
| Phase 1 | 현행 법령 | 현행법령 목록/본문, 조항호목 조회 | `law_search` MVP |
| Phase 2 | 법령 부가정보 | 영문법령, 법령 연혁, 변경이력, 신구법, 3단 비교, 법률명 약칭, 한눈보기 | 법령 카드 확장 후보 |
| Phase 3 | 실무 자료 | 행정규칙, 자치법규, 법령해석례, 행정심판례, 중앙부처 1차 해석 | 별도 intent 또는 필터 필요 |
| Phase 4 | 판례/결정문 | 판례, 헌재결정례, 위원회 결정문, 특별행정심판례 | `case_search` 계열로 분리 권장 |
| Phase 5 | 지식베이스 | 법령용어, 일상용어, 관련법령, 지능형 법령검색 | 검색 보강용. MVP 필수 아님 |
| Phase 6 | 기타 | 조약, 별표/서식, 학칙/공단/공공기관, 사전컨설팅 의견서 | 요구가 생길 때 개별 추가 |

MVP에서 범위를 좁히는 이유:

- 사용자가 가장 자주 묻는 “OO법 제N조”, “OO법 내용”, “음주운전 기준”은 현행 법령 목록/본문 조회로 처리 가능하다.
- 판례, 법령해석례, 행정규칙은 응답 구조와 검색 ranking이 다르므로 같은 renderer에 억지로 섞으면 정확도가 떨어진다.
- 법률 답변은 최신성/출처가 중요하므로, 먼저 안정적인 법령 원문 조회를 고정한 뒤 확장한다.

## 3. 실행 방법

```bash
node scripts/test-law-openapi.mjs
```

선택 옵션:

```bash
LAW_OC=your_law_openapi_oc node scripts/test-law-openapi.mjs
node scripts/test-law-openapi.mjs --oc your_law_openapi_oc
```

`LAW_OC`는 국가법령정보센터 Open API 사용자 식별값이다. 서버 환경변수로 관리하며, 코드 fallback을 두지 않는다.

```env
LAW_OC=your_law_openapi_oc
```

## 4. 검증 케이스

스크립트는 다음 케이스를 검증한다.

| 케이스 | 요청 | 기대 결과 |
|--------|------|-----------|
| 목록 검색 | `도로교통법`, `display=3` | `LawSearch.law`를 배열로 정규화 가능 |
| 단건 검색 | `민법`, `display=1` | `LawSearch.law`가 객체로 와도 배열로 정규화 가능 |
| 조문 조회 | `LM=도로교통법`, `JO=004400` | 제44조 제목과 항 내용 파싱 가능 |
| 조문 조회 | `MST=281875`, `JO=001000` | MST 기반 제10조 조회 가능 |

---

## 5. 구현 시 주의점

- `LawSearch.law`는 결과 수와 `display` 값에 따라 객체 또는 배열로 반환된다. 항상 `[value].flat().filter(Boolean)` 형태로 정규화한다.
- `법령.조문.조문단위`도 객체 또는 배열로 반환될 수 있다.
- 특정 조문 조회의 `JO`는 6자리 숫자 형식이다.
  - 예: 제44조 → `004400`
  - 예: 제10조 → `001000`
- `LM`으로 법령명 직접 조회가 가능하지만, 검색 결과 선택이 필요한 질의는 `lawSearch`에서 `법령일련번호` 또는 `법령ID`를 먼저 확보한다.
- 법률 답변에는 시행일자, 공포일자, 소관부처, 조문 제목/항 내용을 함께 전달해야 한다.
- 모바일 API와 맞춤형 API는 별도 endpoint/parameter가 섞일 수 있으므로 1차 구현에 포함하지 않는다.
- “판례 찾아줘”, “헌재 결정”, “행정규칙”, “고시”, “법령해석례” 같은 질의는 Phase 1에서는 일반 검색 안내 또는 미지원 fallback으로 처리한다.

## 6. MVP 구현 기준

`law-tool.ts`의 1차 범위:

1. 법령명 또는 키워드로 법령 목록 검색
2. 결과 1개 또는 상위 결과 선택
3. 조번호가 있으면 해당 조문만 조회
4. 조번호가 없으면 검색 결과 메타데이터와 상위 조문 일부만 반환
5. `json:law` 카드 출력에 필요한 정규화 payload 생성
6. 본문/조문 카드의 각 조항에 공식 원문 링크 생성
7. 법령 목록과 조문이 5개를 초과하면 `LawRenderer`에서 5개 단위 페이지네이션 제공

통칭 검색어 보정:

| 사용자 표현 | 검색 후보 |
|-------------|-----------|
| `소방법` | `소방기본법`, `소방` |
| `교통법` | `도로교통법` |
| `개인정보법` | `개인정보 보호법` |
| `근로법` | `근로기준법` |

## 7. 앱 테스트 샘플

아래 질의는 채팅 UI에서 `law_search` 라우팅과 `LawRenderer` 렌더링을 점검하기 위한 샘플이다.

### 7-1. 목록 검색

| 샘플 질의 | 기대 모드 | 확인 포인트 |
|-----------|-----------|-------------|
| `도로교통법 관련 법령 목록 보여줘` | `list` | 도로교통법, 시행령, 시행규칙 후보가 카드 목록으로 표시 |
| `개인정보 보호법 법령 목록 찾아줘` | `list` | 개인정보 보호법 계열 검색 결과 표시 |
| `근로기준법 관련 법령 검색해줘` | `list` | 현행 법령 후보와 시행일자 표시 |
| `민법 관련 법령 목록` | `list` | `LawSearch.law` 단건/다건 정규화가 깨지지 않는지 확인 |
| `소방법 관련법안 찾아줘` | `list` | 통칭 `소방법`이 `소방기본법`/소방 관련 법령 후보로 보정되는지 확인 |

### 7-2. 특정 조문 조회

| 샘플 질의 | 기대 모드 | 핵심 확인 조항 |
|-----------|-----------|----------------|
| `도로교통법 제44조 알려줘` | `article` | 제44조 술에 취한 상태에서의 운전 금지 |
| `민법 제1조 내용 보여줘` | `article` | 제1조 법원 |
| `개인정보 보호법 제15조 정리해줘` | `article` | 개인정보의 수집ㆍ이용 |
| `근로기준법 제56조 알려줘` | `article` | 연장ㆍ야간 및 휴일 근로 가산임금 |
| `상법 제398조 내용` | `article` | 이사 등과 회사 간의 거래 |
| `형법 제250조 알려줘` | `article` | 살인 |

### 7-3. 주제형 법령 질의

| 샘플 질의 | 기대 모드 | 확인 포인트 |
|-----------|-----------|-------------|
| `도로교통법 신호위반 조항 정리해줘` | `body` | 제5조 신호 또는 지시 위반, 제156조 벌칙 관련 조항 우선 노출 |
| `도로교통법 음주운전 기준 알려줘` | `body` | 제44조 혈중알코올농도 0.03퍼센트 이상, 제148조의2 벌칙 관련 조항 우선 노출 |
| `개인정보 보호법에서 개인정보 수집 동의 관련 조항 찾아줘` | `body` | 수집ㆍ이용 및 동의 관련 조항 우선 노출 |
| `근로기준법에서 연장근로 수당 관련 조항 찾아줘` | `body` | 제56조 등 임금 가산 관련 조항 우선 노출 |
| `민법에서 손해배상 관련 조항 찾아줘` | `body` | 손해배상 관련 조항이 앞쪽 일반 조문으로만 잘리지 않는지 확인 |
| `정보통신기반 보호법 주요 조항 보여줘` | `body` | 조문 accordion, 조문별 원문 링크, 5개 단위 페이지네이션 확인 |

### 7-4. 현재 MVP 미지원 또는 후속 확장 대상

| 샘플 질의 | 기대 처리 |
|-----------|-----------|
| `신호위반 판례 찾아줘` | 현행 법령 MVP 범위 밖. 판례 검색은 후속 `case_search`로 분리 예정 |
| `헌재 결정례에서 개인정보 관련 사건 찾아줘` | 헌재결정례 후속 확장 대상 |
| `행정규칙에서 개인정보보호위원회 고시 찾아줘` | 행정규칙/고시 후속 확장 대상 |
| `도로교통법 신구법 비교해줘` | 신구법/3단 비교 후속 확장 대상 |
| `도로교통법 별표 찾아줘` | 별표ㆍ서식 후속 확장 대상 |

### 7-5. 회귀 체크리스트

- `json:law` 코드블록이 채팅에 raw JSON으로 노출되지 않고 `LawRenderer` 카드로 표시되는지 확인.
- 목록 검색 카드에서 원문 링크가 새 탭으로 열리는지 확인.
- 목록 검색 결과가 제목 중심 compact 카드로 표시되고, 5개 초과 시 하단 `이전/다음`으로 탐색되는지 확인.
- 본문/조문 카드에서 각 조항의 `원문` 링크가 공식 조문 페이지로 열리는지 확인.
- 조문 카드에서 첫 번째 조문은 기본 펼침 상태인지 확인.
- 조문 accordion을 펼치고 접어도 카드 가로 폭이 흔들리지 않는지 확인.
- 조문이 5개를 초과할 때 하단 `이전/다음`으로 5개씩 탐색되는지 확인.
- 항/호가 있는 조문에서 항 내용과 하위 호가 함께 보이는지 확인.
- 관련도 필터가 주제형 질의에서 앞쪽 20개 조문만 무조건 반환하지 않는지 확인.
- `LAW_OC`가 없을 때 서버 로그에 환경변수 누락 오류가 남고, 코드 fallback으로 조용히 호출하지 않는지 확인.
