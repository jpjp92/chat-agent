## 2. 버그픽스 — drug_info OCR 토큰 누출 + 각인 로고 오판 (pre-existing, 3-A E2E 중 발견)

커밋 `ceaa37f`. generator 리팩토링과 무관한 별도 2건.

### 2-1. OCR 토큰 누출 — 텍스트 질문 답변 앞에 "JPW" 등 노출
- **증상**: 이미지 없이 텍스트로 약품 설명만 요청("파모티딘 설명해줘")했는데 답변 맨 앞에 `JPW` 같은 무관한 토큰이 붙음.
- **근본 원인** (systematic, 진단 로그로 실증): [drug-info-tool.ts](../../server/agent/drug-info-tool.ts) `extractImprintViaVision`가 MFDS DB 각인이 placeholder `"마크"`인 약품의 알약 이미지를 **LangChain `ChatGoogleGenerativeAI.invoke()`** 로 OCR — 이 중첩 LLM이 `tools` 노드에서 실행됨. [chat/route.ts](../../app/api/chat/route.ts)의 `on_chat_model_stream` 포워딩이 **denylist(`langgraph_node === 'vision'`만 차단)** 라 `tools` 노드의 중첩 OCR 토큰("JP"/"W")이 부모 SSE로 누출. 진단 로그 실증: `node="tools"`→"JP"/"W", `node="generator"`→json:drug. 실각인 약품(타이레놀 TYLENOL·엔테론정 E50)은 `needsVision=false` → 누출 없음(증상 비발생이 원인 입증).
- **수정**: chat 라우트 스트림 게이트를 **allowlist**로 전환 — `if (langGraphNode !== 'generator') continue;`. 사용자 prose는 최종 generator 노드 토큰만 전달, vision·tools중첩·router LLM 전부 배제. 안전망: `on_chain_end==='generator'` 폴백 존재.
- **검증**: 파모티딘 재현 → 스트림이 곧바로 `\`\`\`json:drug`로 시작(누출 소멸), 타이레놀 회귀 정상, tsc 0.

### 2-2. 각인 OCR 로고 오판 — 애매하면 "마크" 유지
- **문제**: placeholder "마크"(로고형) 약품을 `extractImprintViaVision`가 OCR할 때 프롬프트가 *"로고도 가장 유사한 알파벳으로 표현하라"*고 강제 → 곡선 로고를 "M"/"W"/"JP"로 **자신 있게 오판**(M/W는 180° 뒤집힌 동형이라 특히 취약), temp 0.1이라 실행마다 흔들림. 약품 식별 맥락에서 "틀린 각인 단정"은 위험.
- **수정** (사용자 설계): ① 프롬프트를 "명확한 숫자·알파벳만 그대로, 로고·애매한 기호·방향따라 달라보이는 건 `마크` 출력"으로 전환(억지 추측 제거) ② Vision이 `마크`/`없음` 반환 시 override 안 함(DB placeholder 유지) ③ temp 0.1→0(결정성).
- **검증**: 위더스파모티딘정(곡선 로고) → Vision raw `"마크"` → 카드 `imprint_front: "마크"`, 뒷면 명확한 숫자 `"2"` 그대로. 다른 후보의 실제 "JP" 각인은 정상 override. tsc 0.
