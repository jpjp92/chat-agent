# DEV_260603 — 멀티턴 URL 후속턴 tool_code 환각 버그 수정

> 작성일: 2026-06-03

---

## 1. 증상

`gemini-3.5-flash`로 다음 시나리오를 진행하면 응답 본문에 도구 호출 코드가 그대로 노출됐다.

1. URL을 붙여 페이지 요약 (1턴)
2. 같은 세션에서 URL과 무관한 **새 검색질의**를 던짐 (멀티턴)
3. 응답에 다음과 같은 텍스트가 그대로 출력됨:

```text
알겠습니다. 미니맥스 코드의 테크니컬 리포트 존재 여부를 구글에서 검색해 보겠습니다.
[tool_code]
print(google_search(query='미니맥스 코드 테크니컬 리포트'))[/tool_code]
```

이 `[tool_code] print(google_search(...))` 블록은 **Gemini Flash가 "검색 의도는 강한데 grounding 툴이 실제로 안 붙어있을 때" 내부 호출 코드를 본문 텍스트로 토출하는 환각 패턴**이다. 검색을 실행하는 대신 검색 호출 코드를 그대로 답변으로 내보낸 것.

---

## 2. 원인

`server/agent/nodes/generator.ts`의 Google Search 게이트 분기 문제.

### 원인 사슬

1. **1턴**: URL 요약 → `hasUrlContent` → `useGoogleSearch = false` (정상).
2. **멀티턴**: URL과 무관한 새 검색질의("…테크니컬 리포트 검색해줘"). 명시적 "검색" 키워드라 원래라면 `needsSearch = on`.
3. 그런데 `historyHasUrl`이 **메시지 히스토리 전체**를 스캔해 1턴 human 메시지의 URL을 발견 → `historyHasUrl = true`.
4. `if (historyHasUrl || currentMsgHasNonYtUrl) useGoogleSearch = false;` 가 **무조건** 검색을 꺼버림.
5. 이 줄이 general 검색 게이트(`intent==='general' && useGoogleSearch`)보다 **먼저** 실행되므로, 사용자의 명시적 검색 요청이 무시됨.
6. 결과: 단일패스가 `tools:[{googleSearch:{}}]` **없이** 실행 → 모델은 검색 의도가 강한데 툴이 없으니 `[tool_code] print(google_search(...))`를 텍스트로 토출.
7. responseText에 대한 **tool_code 후처리/필터가 없어서** 그대로 사용자에게 노출.

### 문제는 두 겹

| # | 문제 |
|---|------|
| **A** | `historyHasUrl`가 너무 뭉툭함 — 한 번이라도 URL을 붙이면 그 대화 내내 모든 후속 질문의 검색이 영구히 꺼짐(새 질문이 URL과 무관해도). |
| **B** | `[tool_code]`/`print(google_search(` 환각이 responseText로 새도 잡아내는 방어 가드가 전혀 없음. (`prompt.ts`에 tool_code 출력 금지 지시는 있으나 이 조건에선 모델이 무시 — 프롬프트만으론 부족) |

---

## 3. 수정

수정 파일: `server/agent/nodes/generator.ts`

### Fix A — 검색 게이트 정밀화

`import`에 `isFollowupReference` 추가(`intentRules.ts`).

기존:

```ts
if (historyHasUrl || currentMsgHasNonYtUrl) useGoogleSearch = false;
```

변경:

```ts
if (currentMsgHasNonYtUrl) {
    useGoogleSearch = false;            // 현재 메시지 자체가 요약 대상 URL → 기존대로 off
} else if (historyHasUrl) {
    const isNewSearchQuery = classifySearchNeed(latestUserText) === 'on';
    const isUrlFollowup = isFollowupReference(latestUserText);
    if (isUrlFollowup && !isNewSearchQuery) {
        useGoogleSearch = false;        // 직전 답변 가공·참조형 follow-up일 때만 off
    } else {
        // 새 검색질의면 grounding 유지 → 아래 general 게이트가 판정하도록 위임
    }
}
```

- 현재 메시지에 URL이 있으면(요약 대상) → 기존대로 off.
- history에만 URL이 있으면 → 현재 질문이 **직전 답변 가공·참조형 follow-up**(`요약/정리/비교/위에서…`, `isFollowupReference`)이고 **새 검색요구가 아닐 때만** off. 새 검색요구(`classifySearchNeed==='on'`)면 grounding을 살려 general 게이트가 판정.
- 이로써 "URL 요약 → 다음 턴 무관한 새 검색질문" 시나리오에서 grounding이 살아남아 **환각 원인 자체가 제거**됨.

### Fix B — tool_code 환각 안전망

responseText 확정 직후(빈응답 체크 직전) tool_code 패턴을 감지하는 가드 추가.

- 감지 정규식: `/\[tool_code\]|print\s*\(\s*google_search/i` (오탐 최소화 위해 명확한 환각 신호만)
- 감지 시 → Google Search 켜고 1회 재시도(`needsSearchFallback`면 2.5-flash, `thinkingBudget:0`). 성공 시(`grText` 비어있지 않고 tool_code 미포함) responseText 교체, grounding 출처도 갱신.
- 재시도 실패/에러 시 → `stripToolCode()`로 `[tool_code]...[/tool_code]` 블록·`print(google_search(...))` 라인·잔여 마커 제거.
- A를 우회하는 다른 경로(image+search 충돌 등)에서 재발해도 사용자에게 날 코드가 노출되지 않도록 방어.

## 4. 검증

### 타입체크

`npx tsc --noEmit` 통과 (0 errors).

### 실런타임 (dev 서버, 4턴 시나리오)

| 턴 | 시나리오 | 로그 핵심 | 결과 |
|----|---------|----------|------|
| 1 | URL 요약 | `URL content provided — Google Search disabled` | ✓ |
| 2 | 새 일반질문(검색불요) | `historyHasUrl but new query (followup=false, newSearch=false) — keeping search gate open` → general 게이트 `needsSearch=false` → off | ✓ |
| 3 | 가공·참조 follow-up | `historyHasUrl follow-up reference — Google Search suppressed` (라우터 503 폴백 needsSearch=true였으나 가드가 먼저 off 확정) | ✓ |
| 4 | **새 명시적 검색질문** | `historyHasUrl but new query (followup=false, newSearch=true) — keeping search gate open` → `useGoogleSearch=true` → two-track grounding **25개 출처** | ✓ (이전엔 tool_code 환각) |

- 4턴 모두 tool_code 환각 없이 정상 응답.
- **Fix B(안전망)는 한 번도 발동하지 않음** — Fix A가 근본원인을 막아 환각 조건에 도달하지 않은 이상적 결과. B는 다른 경로 재발 대비로 잔존.

### 곁다리 관찰 (이번 수정과 무관)

- Turn 2가 38.5s 소요. 멀티턴 누적 컨텍스트(`contentsLen` 증가) + 3.5 Flash thinking 길어짐으로 추정. Vercel 함수 타임아웃(300s 기본) 내라 실패는 아니지만 체감 latency 관점에서 별도 이슈로 기록.
