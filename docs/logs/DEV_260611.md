## 1. 채팅창 카드 미리보기 (mock)

"현재 상영시간표 카드를 메인 챗에 그대로 넣으면 어떻게 보일지" 검증용 생성기 `scripts/test-chat-card-preview.mjs`.
- 카드/테마 CSS는 `test-showtimes-server.mjs`의 `<style>`를 **추출 재사용**(DRY), 실 데이터는 떠 있는 서버 `/showtimes`에서 가져와 채팅 mock에 끼움.
- 채팅 chrome(헤더 pill·오브·유저 말풍선·AI 응답·입력바) + 카드를 **모바일 390 / 데스크톱 760**, 라이트/다크로 렌더 → `movie-spike-output/chat-card-preview.html`. browserless 스크린샷으로 자가 평가.

**평가**
- 잘됨: 채팅 테마(글래스·바이올렛·오브)와 카드 조화 자연스러움. 좁은 폭(390)에서 카드 **자동 1열**, 칩 가독.
- 걸림(실 통합 시): ① **세로 길이**(3사×영화 다수 = 매우 긴 메시지) ② **이중 박스**(말풍선→체인 패널 테두리→카드 3중 중첩) ③ 포스터 빈칸은 browserless 미국 IP가 `cdn.cgv.co.kr` 차단한 스샷 artifact(실앱 한국 정상).
- 데스크톱(760)은 카드 2열이라 여유 있음 — 현행 OK.

## 4. 모바일 채팅 변형 (적용 완료)

§1 "걸림"(세로 길이·이중 박스·상영관명 잘림)을 채팅 맥락 전용 변형(`.chatv`)으로 해소. `test-chat-card-preview.mjs`가 모바일 현재 / 모바일 변형 / 데스크톱 변형 3프레임 비교 렌더.

- **① 칩 1열** — `.chatv .grid2,.chatv .rest{grid-template-columns:1fr}`. 2열에서 잘리던 상영관명을 풀 노출.
- **② 패널 경량화** — `.chatv .chain{background:none;border:none;border-top:2px solid var(--c);border-radius:0}`. 말풍선→패널 테두리→카드 3중 박스를 얇은 체인색 상단 액센트만 남겨 제거.
- **③ 영화 더보기** — 체인당 `MV=3`개만 노출 + `영화 N개 더보기` 토글(`.movMore`)로 세로 길이 완화.

→ 좁은 폭(390)에서 칩 가독·세로 단축·박스 중첩 해소 모두 확인.
- **데스크톱 보강**: 좌우가 놀아 카드 **전폭 1열 + 칩 2열**로 폭 활용 + 메시지 컨테이너 와이드(프리뷰 프레임 760→880, computed 검증: 카드 815px·칩 349px×2). 모바일은 현 사이즈/1열 유지. React 통합본은 `MovieRenderer` 칩 `grid-cols-1 sm:grid-cols-2` + `ChatMessage` movie 블록 데스크톱 폭 85%→92%(약국 카드와 동급, 모바일 95% 유지).

## 5. CGV 상영관명 정제

CGV `scnsNm`이 `4관[SCREENX] (리클라이너,Laser)`처럼 과하게 길어 칩이 지저분 → 정제 헬퍼 추가.

- `cleanCgvScreen(s)`: 괄호 `(...)` 제거(좌석/포맷 부가정보), 대괄호 `[X]`→` X`(특수관만 유지), 공백 정리 후 `slice(0,16)`.
  - `1관 (Laser)` → `1관`, `4관[SCREENX] (리클라이너,Laser)` → `4관 SCREENX`.
- 풀네임은 버리지 않고 `screenFull`로 보존 → 칩 `<u title="${screenFull}">`로 **데스크톱 호버 시 원본 노출**(모바일은 호버 불가라 정제본만, 정보 손실 없음).
- 호버 대신 정제를 택한 이유: 모바일에 호버가 없어 정제가 필수, 호버는 데스크톱 보너스로만.

## 6. ★ 메인 챗 React 통합 (영화 도구 정식 편입)

standalone 스파이크를 실제 앱 도구/렌더러로 이식. **초기 로딩 구조 = 클라이언트 페치**(스파이크 UX인 지점 드롭다운+스켈레톤+캐시가 어차피 클라 호출 엔드포인트를 요구하므로 자연스러운 선택): movieTool은 가벼운 기본지점만 반환, 상영시간표는 렌더러가 직접 조회.

### 데이터 흐름
```
영화 질의 → router(movie_search) → generator(movieTool) → json:movie{region,defaults}
   → fast-pass(LLM 우회) → ChatMessage 파싱 → MovieRenderer
   → 체인별 GET /api/showtimes (마운트·드롭다운 변경 시) → 스켈레톤 → 카드
```
- **챗 응답 즉시 종료**(CGV browserless ~2.5s가 챗 함수 밖). 드롭다운 재조회와 동일 엔드포인트 재사용. 단 과거 대화 재오픈 시 '오늘' 기준 재조회(상영표는 비영구).

### 신규 파일
| 파일 | 역할 |
|------|------|
| `data/theater-branches.json` | 스파이크 `branches.json` 번들(3사 532지점). 메가박스 지점명 HTML 엔티티(`&#40;`)는 `lib/theaters`에서 디코드 |
| `lib/theaters.ts` | 공유 순수 헬퍼: `flatBranches`·`findDefaultBranch`(지역 키워드→최적 지점, 부분일치+강남 폴백)·`CHAINS`. 서버·클라 공용 |
| `app/api/showtimes/route.ts` | 3사 fetch + SWR 캐시(fresh 120s/stale 30분) 이식. **HTML 대신 구조화 JSON**(`list[]`) 반환. `runtime=nodejs`·`preferredRegion=icn1`·`maxDuration=60` |
| `server/agent/movie-tool.ts` | LangChain 도구. region→3사 기본지점 → `json:movie` 블록(상영표는 안 가져옴) |
| `components/MovieRenderer.tsx` | 글래스 커스텀 드롭다운(검색)+스켈레톤+칩 카드를 React/Tailwind로 포팅. **채팅 변형 적용**(칩 1열·패널 경량화 border-top·영화 MOVIE_CAP=3 더보기·CGV 정제 title 호버) |

### 기존 파일 배선 (lawTool 패턴 그대로)
- `state.ts` IntentType + `intentRules.ts`(영화/상영/CGV/롯데/메가박스 정규식, 최상단) + `router.ts`(프롬프트 카테고리·validIntents) + `prompt.ts`(INTENT_FOCUS_HINT) + `generator.ts`(LANGCHAIN_INTENTS·allTools 게이트·fast-pass) + `graph.ts`(ToolNode) + `chat/route.ts`(`on_tool_end` movieTool→blockType 'movie') + `ChatMessage.tsx`(blockRegex·파싱·lazy import·렌더 분배).

### 검증
- `npm run build` ✓ (`/api/showtimes` 동적 함수 등록), `tsc --noEmit` 클린.
- 포팅 fetch 라이브 확인(standalone): 메가박스 강남 19편+좌석/롯데 가산 19편+좌석 = 오늘 데이터 정상. CGV는 스파이크 검증된 동일 browserless 경로.
- `findDefaultBranch` 매칭: 강남/홍대/노원/부산서면 모두 합리적 지점, region 미지정 시 강남 폴백.
- (샌드박스에서 next dev 유지 불가 → 엔드포인트 라이브 호출 대신 fetch 로직 standalone 검증 + 빌드로 배선 확인.)

### 후속 폴리시 (피드백 반영)
- **데스크톱 폭 확대**: §4 보강 참조 — 칩 `sm:grid-cols-2` + movie 메시지 컨테이너 85%→92%.
- **조회 중 애니메이션**: 정적 `…` → 점 3개 바운스(`LoadingDots`, stagger 0.15s). 스켈레톤과 함께 로딩 상태 일관화.
- **지점 페이지 링크**: 드롭다운 옆 ↗(호버 시 체인색). `lib/theaters.branchUrl()` — 롯데 `Cinema/Detail?divisionCode&detailDivisionCode&cinemaID`·메가박스 `theater?brchNo` 딥링크(둘 다 HTTP 200 확인), **CGV는 신규 SPA가 `siteNo` 쿼리 무시**(browserless로 확인: "선택 된 극장이 없습니다") → 극장별 예매 공통 페이지(`/cnm/movieBook/cinema`)로 연결.
- **지점 데이터 저장 위치 검토**: Supabase 테이블·Vercel 스토리지(Edge Config/Blob) 대비 — 변동성 낮고(개폐점 연 수회) 드롭다운이 클라 사이드라 **JSON 번들 유지**(0ms). 갱신 자동화가 필요해지면 Edge Config(서버 <15ms, 단 Hobby 64KB 한도라 addr 등 미사용 필드 정리 필요) 또는 Blob(클라 CDN 직접 fetch) 승격.
