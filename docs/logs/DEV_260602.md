## 2. Supabase MCP warning 검토

Codex 시작 시 발생한 Supabase MCP startup warning을 점검했다.

```txt
MCP client for `supabase` failed to start
OAuth token refresh failed: Failed to parse server response
```

확인 결과:

- `~/.codex/config.toml`의 MCP URL이 구 Supabase project ref를 가리킴.
- 현재 앱 env의 `SUPABASE_URL`은 신규 프로젝트 `gaomgqnpsjtabrvwnpad`를 사용.
- MCP warning은 앱 런타임 문제가 아니라 Codex MCP OAuth refresh 및 MCP 설정 불일치 문제로 판단.

권장 조치:

```bash
codex mcp logout supabase
# ~/.codex/config.toml project_ref를 신규 ref로 수정
codex mcp login supabase
```

이번 세션에서는 우선순위가 낮아 실제 MCP 설정 변경은 보류했다.

## 3. 사이드바 최근 기록 `New Chat` 순간 노출 수정

### 증상

웹에서 새 페이지로 진입할 때 사이드바의 가장 최근 기록이 잠깐 `New Chat`으로 보였다가, 이후 정상 제목으로 바뀌는 현상.

### 원인

사이드바는 초기 렌더링에서 DB fetch보다 먼저 `localStorage`의 `chat_sessions_cache_v1` 캐시를 사용한다.

문제 흐름:

1. 새 채팅 생성 시 DB 기본 제목은 `New Chat`.
2. AI 응답 완료 후 `summarizeConversation()` 결과로 세션 제목을 요약 제목으로 변경.
3. 화면 상태와 DB 제목은 갱신되지만, `localStorage` 세션 캐시는 갱신되지 않음.
4. 새 페이지 진입 시 오래된 캐시의 `New Chat`이 먼저 렌더링됨.
5. `/api/sessions` fetch 완료 후 DB 제목으로 덮여 정상화됨.

### 수정

수정 파일:

- `src/hooks/useChatSessions.ts`
- `src/hooks/useChatStream.ts`

변경 내용:

- `writeSessionsCache()`를 export해 스트리밍 훅에서도 캐시를 갱신할 수 있게 변경.
- 메시지 전송 중 새 세션 생성 시 `setSessions()`와 함께 `localStorage` 캐시도 즉시 갱신.
- 제목 요약 완료 후 세션 title 상태와 `localStorage` 캐시를 함께 갱신.
- 기존 캐시에 남아 있던 빈 `New Chat` placeholder는 초기 hydration에서 제외.

효과:

- 새 페이지 진입 시 오래된 `New Chat` 캐시가 먼저 노출되는 flicker 제거.
- DB fetch 전에도 로컬 캐시가 최신 제목을 유지.
- 이미 오염된 캐시의 빈 placeholder도 첫 로딩에서 숨김.

```bash
npx tsc --noEmit
```
