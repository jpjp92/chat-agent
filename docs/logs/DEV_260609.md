# DEV_260609

## 1. 작업 개요

증상: 모바일 웹(chat-gem.vercel.app)에서 **"야생동물 관련 법률 알려줘"** 등 법률 질의 시 정상 카드 대신 LLM 일반지식 폴백 답변("현재 국가법령정보센터 API 서비스의 일시적인 통신 오류…")이 나옴. **로컬에서는 정상, 프로덕션에서만 실패.**

결론: 빈 환경변수 문제가 **아니었음**. 실제 원인은 **함수가 미국 리전(iad1)에서 실행**되어 한국 정부 API(law.go.kr) 접근 지연/실패 + Gemini 503 누적으로 `maxDuration=60` 한도 초과.

---

## 2. 런타임 로그 단서

| 항목 | 값 | 해석 |
|------|------|------|
| Request Region | `icn1` (서울) | 요청은 서울로 인입 |
| **Function Region** | **`iad1` (미국 버지니아)** | 함수는 미국에서 실행 ← 핵심 차이 |
| Duration | **60044ms** | `maxDuration=60` 정확히 초과 |
| External APIs | Supabase 201 + Gemini ×5 (400/200/503/timeout) | Gemini 과부하 재시도 누적 |

law 도구는 [`law-tool.ts:7-9`](../../server/agent/law-tool.ts#L7-L9)에서 `FETCH_TIMEOUT_MS=15000` × `FETCH_MAX_ATTEMPTS=3`. law.go.kr이 미국 IP에서 느리거나 차단되면 최대 45초가 쌓이고, Gemini 지연까지 겹쳐 60초 한도를 넘김 → 응답이 끊기고 LLM이 폴백 답변 생성.

## 3. 오진 → 정정 (LAW_OC 빈 값 가설 폐기)

초기에 `vercel env pull` 결과가 `LAW_OC=""`로 나와 "프로덕션 env가 비었다"고 판단 → **오진**.

**반례:** 같은 pull에서 실제로 프로덕션에서 작동 중인 `SUPABASE_KEY`, `BROWSERLESS_KEY` 등도 전부 `len=0`(빈 값)으로 나옴. 작동하는 키가 빈 값으로 보인다는 건 **pull이 Sensitive 변수의 복호화 값을 못 가져오는 것**이지 실제로 빈 게 아님.

> 교훈: `vercel env pull`의 빈 값은 Sensitive 타입 변수에서 정상. 빈 env의 증거로 쓸 수 없음.

- 로컬 `.env`: `LAW_OC=jpjp9202` (정상)
- law.go.kr 직접 호출(OC=jpjp9202): HTTP 200, 0.43초 → **API·키 모두 정상**

## 4. 수정

### ① 서울 리전 고정 (실제 원인 대응)

[`app/api/chat/route.ts:13-14`](../../app/api/chat/route.ts#L13-L14):
```ts
// 서울 리전 고정: law.go.kr 등 한국 API 접근성·지연 개선 (기본 iad1 → icn1)
export const preferredRegion = 'icn1';
```

law·약국·병원·동물병원·약품 도구가 모두 `/api/chat` 함수 안에서 실행되므로, 이 라우트 하나만 `icn1`로 고정하면 한국 API 호출 전부가 서울에서 나감. **재배포해야 반영됨.**

### ② LAW_OC 환경변수 복원

오진 과정에서 프로덕션 `LAW_OC`을 지웠다 재등록함 → 원래대로 **Sensitive + 값 `jpjp9202`**로 복원 완료.

- ✅ Production: Sensitive, `jpjp9202`
- ⚠️ Preview: 미등록(이 CLI 버전이 "모든 프리뷰 브랜치" 비대화형 추가 거부 — `git_branch_required`). 라이브는 Production이라 영향 없음. 필요 시 대시보드에서 Preview+Sensitive로 추가.

## 5. 검증 (남은 일)

재배포 후:
1. 런타임 로그 `Function Region`이 `iad1` → **`icn1`** 으로 변경되는지
2. 법률 질의가 정상 `json:law` 카드로 렌더되는지
3. Duration이 60초 한도 아래로 떨어지는지

> Gemini 503/timeout은 별개의 2차 이슈(provider 과부하). 서울 리전 이전으로 지연은 줄지만, 근본적으로는 키 로테이션/폴백([`config.ts`](../../server/config.ts))에 의존.
