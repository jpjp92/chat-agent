## 2. 🔴 A — 계획서가 고쳐진 취약점을 P0 으로 들고 있었다

[PLAN_HARDENING §1](../../../plans/PLAN_HARDENING_260822.md) 표 #2 와 §P0-2 는 이렇게 적혀 있었다.

> Chat `model` 서버 검증 없음 — **검증됨**
> body 의 `model` 을 그대로 받아 `model || DEFAULT_CHAT_MODEL` 로 흘린다. **검증이 없다.**

실제 코드는 [app/api/chat/route.ts:70](../../../../app/api/chat/route.ts#L70):

```ts
const finalModel = isChatModelId(model) ? model : DEFAULT_CHAT_MODEL;
```

**이 절이 요구한 "`SERVER_MODELS` 를 단일 출처로 서버에서 enum 으로 끊는다"가 그대로 구현돼 있다.**

같은 문서 [§6](../../../plans/PLAN_HARDENING_260822.md#6-작업-순서)(2026-09-05)이 마지막 문단에 *"`model` allowlist는 현재 코드에 이미 있다"* 고 한 줄로 정정했다. **그런데 정정당한 §1 표와 §P0-2 에는 아무 표시가 없었다** — 제목·본문·⚠️ 경고까지 초판 그대로라, 문서를 위에서부터 읽으면 여전히 열린 P0 취약점이다.

⚖️ **이건 [09-04 감사 §5](DEV_260904.md) 의 C1·C2 와 정확히 같은 형태다** — *"정정은 했는데 정정당한 자리에 표시를 안 남겼다."* 다만 C1·C2 는 **역사적 로그**였고 이건 **다음 작업의 순서를 정하는 활성 계획서**라 대가가 다르다. 4월 로그의 낡은 체크박스는 읽는 사람을 잠깐 헷갈리게 하지만, 이건 **작업자를 이미 끝난 일에 투입한다.**

조치는 레포 관례대로 **초판을 지우지 않았다** — §P0-2 제목에 "⚖️ 해소됨"을 달고 정정 블록을 앞에 세운 뒤, 초판 서술은 *"초판 서술 (2026-08-22, 당시 코드 기준)"* 로 보존했다([09-04 의 §3.0 "초판 / 실제" 표](DEV_260904.md)와 같은 방식).

### 2.1 📌 남는 규칙

**요약 절에서 한 정정은 정정당한 자리에도 남긴다.** §6 처럼 "순서"를 다시 쓰는 절은 자기 관점에서 옳게 적어도, **그 판단의 근거가 되는 항목 절이 반대로 남아 있으면 문서는 여전히 틀린 것을 말한다.** 이 레포의 ⚖️ 관례는 이미 그 해답이고, 09-04 가 같은 진단을 내렸는데 **9일 만에 같은 자리에서 재발했다.**

## 3. 🔴 B — "깨진 링크 0건"이 아니었다

09-04 감사는 링크를 전수 검사하고 **0건**으로 닫았다. 다시 돌리니 **13건**이 나왔다.

🔴 **왜 0건으로 보였나:** 09-04 검사기는 1차에서 오탐 39건(인라인 코드의 `[url]`·`(A)` 같은 인용 마커 예시)을 만났고, **그걸 걸러내려 "경로형"만 남기는 필터를 좁게 잡으면서 이들까지 함께 떨어졌다.** ⚖️ **오탐을 줄이는 수정은 정탐도 같이 줄인다** — 필터를 좁힌 뒤 **총 검사 건수가 얼마나 줄었는지**를 보지 않으면 알 수 없다(이번 하니스는 `상대링크 1135건 검사` 를 항상 찍는다).

## 5. 신규 하니스 — `tests/test-doc-links.mts`

09-04 §7-3 이 남긴 항목이다. 판정을 셋으로 갈랐고 **가른 기준이 핵심이다**:

| 대상 | 판정 | 근거 |
|---|---|---|
| 파일 부재 | ❌ 실패 | 정책이 이미 있다(인라인 강등) |
| `.md` 앵커 부재 | ❌ 실패 | 제목을 고치면 남의 문서가 **조용히** 깨진다 |
| 코드 `#L` 행번호 | `docs/logs/` 는 ⚠️ 경고, 그 외는 ❌ 실패 | **날짜 로그는 그날의 기록**이라 코드가 움직였다고 고치면 기록을 바꾸는 것이다. 계획·가이드·TODO 는 **현재를 말하는 문서**다 |

이 구분이 실제로 일했다 — `PLAN_HARDENING §P1-1` 의 `chat/route.ts:310` 은 **대상이 251줄**이라 실패로 잡혔고(실제 `process.off` 는 `:236`), `DEV_260731` 의 같은 종류는 경고로 남았다. `TODO` 의 `fetch-url:18`(현재 `SSRF_BLOCK` 은 `:22`, 18 은 빈 줄)처럼 **범위 안이라 자동으로는 안 잡히는 드리프트**도 있어, 행번호는 하니스가 아니라 사람이 봐야 하는 축이 남는다.
