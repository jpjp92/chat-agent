# 프롬프트 계층 분리 — 이음매를 먼저 만들고, 나머지는 바이트로 증명했다

> 날짜: 2026-09-24 · 상태: 0~7단계 완료. **프롬프트 문구 변경 0건**, 응답 변화 없음(바이트 동일).
> [계획서](../../../plans/PLAN_PROMPT_LAYERING_260923.md) · [조립 순서](../../../guide/REF_Architecture.md#prompt-composition--language) · [하니스](../../../../tests/test-prompt-assembly.mts)

## 1. 판정

프롬프트 21,208자가 한 덩어리였고, **조립 결과를 볼 방법이 없었다.** `generator.ts` 클로저의
지역 변수라 노드를 돌려야 보이는데, 돌리면 네트워크를 탔다. 그래서 *"구조만 바꿨다"* 를
증명할 수단이 애초에 없었다.

순서를 뒤집었다 — **이음매를 먼저 만들고**(`assemblePrompt`), 골든을 박고, 그 다음에 옮겼다.
결과로 2~7단계는 전부 **바이트 동일**이 증명된다. 증명되지 않는 단계는 **이음매 추출 하나뿐**이다.
응답이 달라진다면 원인은 거기다.

| 단계 | 한 일 | 증명 |
|---|---|---|
| 0 | 조립을 순수 함수로 추출 | ❌ 불가 — 증명 수단을 **만드는** 단계라 |
| 1 | 골든 스냅샷 | — |
| 2·3 | 턴 규칙 6종 → 도메인 파일 + 계약 검사 | ✅ 바이트 동일 |
| 4 | 렌더러/의도 경계 판정 | ✅ **코드 변경 0건** |
| 5 | `INTENT_POLICIES` 개명 · 논문 정책 분리 | ✅ 바이트 동일 |
| 6 | `paper_search` 줄 단위 판별 | ✅ **이동 보류로 결론** |
| 7 | base → 무결성 / 응답 형태 | ✅ 4개 언어 전부 |

단계별 근거는 [계획서 §10-5~§10-8](../../../plans/PLAN_PROMPT_LAYERING_260923.md) 에 있다.

있어야 하고, 그게 안 되면 하니스가 문구를 **흉내 내기 시작한다**([tests/README](../../../../tests/README.md) ①②③).

## 3. 🔴 옮기다 나온 것들 — 이게 수확이었다

### 3-1. 소스 grep 49건이 세 번에 걸쳐 드러났다

문구를 파일로 옮길 때마다 **문구는 한 글자도 안 바뀌었는데** 하니스가 깨졌다:

| 시점 | 건수 | 파일 |
|---|---:|---|
| 턴 규칙 추출 | 11 | `test-card-followup` · `test-chat-models` · `test-paper-card` |
| 논문 정책 분리 | 35 | `test-paper-card` |
| base 분할 | 3 | `test-chat-models` |

전부 `prompt.ts` 를 **소스 텍스트로 읽고** 있었다. *"프롬프트를 검사한다"* 고 적혀 있었지만
실제로는 **파일의 철자를 검사**했다. 그중 3건은 정규식이 `` \` `` 같은 **TS 소스에서만 참인
이스케이프**를 써서, 런타임 문자열이었다면 애초에 안 맞았다.

> 소스 grep 의 두 얼굴: **텍스트가 움직이면 시끄럽게 거짓으로 깨지고, 내용이 사라지면
> 조용히 통과한다.** 앞의 것은 고치게 되지만 뒤의 것은 아무도 모른다.

전부 export 된 문자열·조립 결과를 보도록 바꿨다.

### 3-2. 블록을 통째로 지워도 통과하던 검사

```js
prompt.indexOf('[RETRACTED PAPERS]') < prompt.indexOf('[PROSE RULES — CRITICAL]')
```

**`[RETRACTED PAPERS]` 를 통째로 지워도 통과한다** — `-1` 이 제일 작다. 철회 논문 인용 금지
규칙이 사라져도 순서 검사는 초록이었다. `comesBefore()` 로 존재를 먼저 요구하게 고쳤고,
변조 시험으로 **1 red → 2 red** 를 확인했다.

### 3-3. 논문 정책 두 벌에 1,693자가 글자 그대로 중복

`paper_search` 와 `arxiv_search` 의 **9번째 줄부터 14줄이 완전히 동일**했다(산문 3문단 +
인용 번호 규칙). 공유 상수로 합쳤고 **바이트는 안 바뀌었다**(같은 자리에 같은 문자열을 보간).

위험은 자수가 아니라 **한쪽만 고치게 되는 것**이었다. 근거: 그 구간에 이미
*"PubMed **and arXiv** sort by their own relevance"* 처럼 두 DB 를 함께 말하는 문장이 있다 —
애초에 공유가 의도였는데 두 벌로 복사돼 있었다. 검증: 공유 상수 한 곳을 고치니
**3건이 함께 빨개졌다**(분리돼 있었다면 1건만 깨졌을 것이고, 그게 조용히 갈라지는 증상이다).

### 3-4. `\n\n` 이 글자로 박힐 뻔했다

턴 규칙 추출 스크립트가 `` `\n\n${...}` `` 를 **`\\n\\n`** 으로 써서 개행 2개가 리터럴 문자
4개가 됐다. 블록당 정확히 **+2자**. 눈으로는 못 찾는다 — 골든이 `25973 ≠ 25971` 로 즉시 잡았다.

## 4. 판정만 하고 옮기지 않은 것

### `sports` 의도 정책 0자 — 누락이 아니라 배치

그 의도에서만 참인 규칙(팀명 한국어 표기·`[NOT_DETERMINED]` 처리)은 **존재한다.** 다만
[worldcup-tool.ts](../../../../server/agent/worldcup-tool.ts) 가 **도구 결과에 실어 보낸다.**
프롬프트로 올리면 중복이 되고, 도구를 안 탄 턴에까지 걸린다 → **현행 유지.**
대신 0자를 하니스가 고정한다 — 누가 채우면 깨지고, 그때 중복 여부를 되묻게 된다.

### `paper_search` 39번 줄(장애≠없음) — 전역인데 옮길 수 없다

"장애를 없음으로 말하지 말라"는 19개 의도 중 **논문 2개에만** 있어 공백처럼 보였다.
**두 번 검증해 둘 다 뒤집혔다:**

1. **그대로 올리면 발동하지 않는다.** 문구가 *"carries an `error` field"* 를 전제하는데,
   약국·병원·동물병원·법령은 실패를 `count: 0` + 한국어 `notice` 로 낸다 — **0건과 구조가
   완전히 같다.** 맞는 필드가 없으니 **한 번도 켜지지 않는 규칙**이 된다. 커버리지처럼
   보이는데 아닌 것은 규칙이 없는 것보다 나쁘다.
2. **이미 있다 — 턴 계층에.** `buildEmptyCardRules()` 가 같은 말을 하고, `cardHasResults()` 가
   카드 종류를 안 가려 **모든 카드 의도에 이미 걸려 있다.** 의도 계층으로 올리면 결과가
   멀쩡한 턴에도 실린다.

⚠️ 곁다리로 **두 계층이 같은 턴에 반대 방향으로 말하는 것**을 발견했다(PubMed 장애 턴에서
792자 간격): 턴 규칙은 *"아는 내용을 반드시 함께 주세요"*, 의도 정책은
*"never turn an outage into a verdict"*. 턴 규칙은 약국·법령용으로 쓰였는데 **의학 근거
질문에도 발동한다.** 측정한 것은 **프롬프트 내용이지 응답이 아니다** — 결함이라 부르지 않는다.
확인은 논문 도구가 `error` 를 내도록 강제하고 7회 돌리면 된다.
