# DEV_261027 — 검색 OFF 규칙이 라우터 LLM 을 덮어써 최근 제품 존재를 부정

> 미배포. 유료 호출: 라우터 Gemini 4회 + gpt-6-luna 4회(비교용).

## 증상

chat-agent-dev 에서 `클로드 코드에서 코덱스 연결해서 사용하는 방법` → GPT·Gemini 모두 검색 없이 "공식 기능은 없습니다" 로 단정. 실제로는 Claude Code 용 Codex 플러그인이 있다(최근 제품이라 모델 지식에 없음).

## 원인

라우터 `general` 의 검색 판정 순서가 규칙 ON → **규칙 OFF** → LLM 이었다. `SEARCH_OFF_PATTERNS` 의 `코드` 가 제품명 "클로드 **코드**" 에 걸려 `needsSearch=false` — 라우터 정의의 "최근 제품·버전은 존재를 부정하기 전에 검색" 규칙이 판정에 닿지도 못했다. 라우터는 채팅 모델과 무관하게 Gemini 하나라 두 모델 답이 같이 틀렸다.

## 수정 — `server/agent/nodes/router.ts`

OFF 규칙은 LLM 판정이 없을 때(라우터 429/503)만 쓴다. ON 규칙(최근·출처·순위 등)은 검색 누락 방어라 그대로. 키워드 추가 없음.

`classifySearchNeed` 자체는 그대로라 `tests/test-search-policy.mts` 영향 없음.

## 실측 — 튜닝 세트 `ROUTER_SEARCH_OFF_RULE`(`tests/manual/router-cases.mts`, `probe-router-gpt.mts --set=searchoff`)

| 문장 | 수정 전(Gemini) | 수정 후 Gemini | 수정 후 gpt-6-luna |
|---|---|---|---|
| 클로드 코드에서 코덱스 연결해서 사용하는 방법 | off | on | on |
| 커서 에디터에서 MCP 서버 연결하는 법 | — | on | on |
| 파이썬 리스트 정렬 코드 짜줘 | — | off | off |
| 이 함수 디버그해줘 왜 None 나와 | — | off | off |

순수 코딩 요청은 LLM 도 검색을 꺼서 지연 증가 없음. 로컬 하니스 37 통과.

남는 것: chat-agent-dev 배포 후 원문 재확인. 번역·작문(`작성해`·`써줘`) 문장도 이제 LLM 판정을 따른다 — 배포 후 검색이 붙은 작문 답이 늘었는지 로그로 확인.
