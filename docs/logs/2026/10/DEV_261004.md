## 1. 요약

- **회원은 유료 키 먼저, 게스트는 무료 로테이션.** 유료 실패 시 무료 + 모델 2.5 로 함께 강등. 스위치 off 면 현행과 동일.
- **3.6 `groundingReliable=true`.** 검색 끄면 0/7 인 문항에서 3.6·3.7·3.8 21/21, 2.5 18/21(실패 3건 전부 *검색을 안 하고 틀림*). 08-17 의 3.6 결함(2/5)은 두 번째로 재현 안 됨.
- **스포츠 의도 제거.** 월드컵(7월 종료) 전용 도구가 프리미어리그 질문을 가로채 Gemini 는 거절, GPT 는 학습 지식으로 **출처 없는 순위표**를 냈다(로컬 실사용). 스포츠는 `general` 검색으로.

## 2-1. GPT 스포츠 순위 — 출처 없음·승패만

스포츠 의도를 뺀 뒤에도 GPT 는 출처 없이 "승-패" 표를 냈다. 앱 코드가 아니었다 — **OpenAI web_search 가 순위 질문을 내부 스포츠 API 로 푼다**(직접 호출):
`query: sports: {"tool":"sports","fn":"standings","league":"epl"}` · `sources: [{"type":"api","name":"oai-sports"}]` · annotations 0.
- 데이터에 **무승부가 없다** — 브렌트퍼드 2승 3무 0패(Gemini·웹 5곳)가 "2승 0패"로. 틀린 정보다
- 출처가 URL 이 아니라 `normalizeOpenAIWebCitations` 의 `http` 필터에서 버려져 칩이 0개
- 대응: OpenAI 검색 지시에만 "스포츠 매체 페이지에서 전체 표(경기·승·무·패·득실·승점) + 인용" 규칙([search-provider.ts](../../../../server/agent/search-provider.ts)). 직접 호출 3회 중 **2회 전체 표 + 웹 출처**(Gemini 와 수치 일치), 1회 표 미출력 — 완전하지 않다
- 공식 사이트로만 유도하면 더 나빴다 — premierleague.com 이 JS 렌더라 "시즌 시작 전, 전부 0경기" 로 답했다
- `api` 출처는 URL 이 없어 칩으로 만들지 않았다(가짜 URL 금지)
