# DEV_261024 — 보안 재검토 ①~③ 처리 (약품 이미지 · 게스트 쿼터 · PDF 상한)

> 계획: [PLAN_SECURITY_REVIEW_261023 §3](../../../plans/PLAN_SECURITY_REVIEW_261023.md). 미배포. 유료 호출 0.

## 1. ① `sync-drug-image` — 덮어쓰기 · 형식 · SSRF

`app/api/sync-drug-image/route.ts`

- **덮어쓰기 차단** — 업로드 `upsert: false`. 이미 있으면(409) 오류로 보지 않고 기존 파일 URL 을 준다. 공용 캐시라 처음 저장된 사진이 기준이다.
- **약 이름 정규화** — trim · 연속 공백 1칸 · 100자. 깔끔한 이름은 해시가 그대로라 기존 캐시 키가 맞는다.
- **바이트 판별** — content-type 대신 매직바이트(JPEG·PNG·GIF·WebP)로 판정하고 그 형식으로 저장. 10MB 상한. `octet-stream` 은 더 이상 이미지 근거가 아니다.
- **`drugFetch`** — 외부 요청 6곳을 `safeFetch`(hop 마다 내부 주소 차단) + 최종 도착지 약품 허용목록 검사로 교체. HTML 에서 뽑은 `og:image` 등도 허용목록 밖이면 받지 않는다. 생 `fetch` 는 우리 Supabase 공개 URL HEAD 1곳만 남았다.

실측(Storage 쓰기 없음, 같은 로직 임시 스크립트): ConnectDI "타이레놀" 검색 200 → 이미지 200 `image/jpeg` 94KB, 판별 jpeg · `169.254.169.254`·`localhost` 차단 · 허용목록 밖 도착 차단 · HTML 은 판별 null.
추가 확인(10-24 오후): nedrug `itemImageDownload` 원본도 리다이렉트 없이 200 · `image/jpeg` 100KB · 판별 jpeg(로컬, 같은 로직). Vercel Preview 에서 "마그네스정" 카드 → `sync-drug-image` 200 · `publicUrl`(drug-cache/…jpg) 반환. `pillVisual: null` 은 정상 — 낱알 정보는 ConnectDI 경로에서만 뽑는다.

남는 것: 예전에 `octet-stream` 으로 저장된 캐시 파일은 지우지 않았다(사용자 결정 — 캐시 유지). 정리는 Storage AWS 이전 때.

## 2. ② 보조 라우트 게스트 일일 한도

- SQL [`docs/guide/db/aux-quota.sql`](../../../guide/db/aux-quota.sql) — `aux_usage`(RLS on · 정책 없음) + `consume_aux_quota(p_kind)`. 게스트 한도 `fetch_url` 20 · `drug_image` 60 · `showtimes` 20(함수 안 상수). 회원은 `member` 로 통과, 세지 않는다. **운영 DB 적용 완료(10-24, 사용자).**
- [`server/aux-quota.ts`](../../../../server/aux-quota.ts) — 회원은 RPC 를 부르지 않는다. 게스트는 RPC 실패 시 503(fail-closed), 초과 시 429. 응답에 `list: []` — 상영표 화면이 오류 응답도 `list` 를 배열로 읽는다.
- 세는 시점은 **캐시 미스 뒤**: fetch-url 은 `url_cache` 미스 · sync-drug-image 는 Storage HEAD 미스 · showtimes 는 메모리 캐시 없음/30분 경과/`nocache`.

화면: 약 카드는 기존 폴백(프록시 이미지 또는 이미지 없음), 상영표는 "조회 실패", URL 읽기는 기존 실패 경로(내용 없이 답).
시험 안 한 것: 배포 환경에서 게스트 토큰으로 한도 소진.

## 3. ③ PDF·직접 받기 바이트 상한

`app/api/fetch-url/route.ts` `readCapped` — 직접 받기 본문을 **30MB** 까지만 읽는다. `Content-Length` 가 이미 넘으면 1KB 만 읽어 형식만 본다.

| 경우 | 동작 |
|---|---|
| 상한 이하 | 기존과 같음(PDF 면 텍스트층 추출) |
| 초과 PDF | `isPdf` 만 반환 — 첫 턴은 모델이 URL 을 직접 읽어 정상, 후속 턴 근거(`pdfText`)만 빠짐 |
| 초과 그 외 | 413, 유료 스크래퍼로 넘기지 않음 |

20MB 로 시작했다가 큰 보고서 PDF 를 덮으려고 30MB 로 올렸다. 텍스트 추출이 20만 자에서 멈춰(`lib/pdf-text.ts`) 크기만큼 파싱이 늘지 않고, 다운로드 10초 abort 는 그대로다.
가짜 스트림 시험: 5MB 통과 · 길이 없는 25MB 는 상한에서 끊김 · 길이 헤더 30MB 초과는 64KB 만 읽음(20MB 상한 기준으로 돌린 값).
남는 것: 파싱 취소 불가(워커 분리)는 범위 밖.

## 5. 상영표 — CGV browserless 대신 서명 직접 호출

게스트 쿼터 확인 중 영화 질문 1번에 `showtimes` 3(체인별 1회)이 세지는 것을 보고 상영표 비용을 다시 봤다.

- 06-10 [DEV_260610 §8](../06/DEV_260610.md): 같은 HMAC 서명으로 `api.cgv.co.kr` 직접 호출 → **403**(Cloudflare Bot Management, 가정 IP 도). 그래서 browserless 로 갔다.
- 10-18 CGV 가 API 를 `cgv.co.kr/api/v1/` 로 옮겼다([DEV_261018 §8](DEV_261018.md)).
- 10-24 새 주소로 Node `fetch` + 서명 헤더만 → 로컬 200 · 13행. **Vercel Preview(icn1) 게스트**에서도 CGV 강남 6편 11회 `"ms": 79` — browserless 콜드(~2.5s)로는 불가능한 값이라 직접 경로다.

`app/api/showtimes/route.ts` `fetchCgvDirect` 를 먼저 부르고, 403·JSON 아님·예외면 기존 browserless 로 폴백한다. 경로는 `[showtimes] cgv path` 로그. 6월처럼 다시 막힐 수 있어 폴백은 유지한다.

효과: CGV 지연 ~2.5s → 수십 ms, 상영표의 browserless 비용 거의 0(`fetch-url` 의 Cloudflare 우회 단계는 계속 browserless).
보류: Supabase 상영표 공유 캐시 — 비용 이유가 사라져 쿼터 집계·인스턴스 간 공유 목적만 남는다. 게스트 상영표 한도(20, 질문당 3)는 사용량을 보고 조정.

## 6. GPT 약 질문 두 번째 턴 빈 답 — `max_messages`

**증상:** chat-agent-dev 에서 GPT-5.6 luna 로 "마그네스정" 다음 턴 "펠루비서방정" → 게스트·회원 모두 18초 뒤 실패. 로그 `OpenAIChatError status 503 code max_messages 'OpenAI returned empty response text'`(3회 재현). 게스트 화면은 "무료 이용량이 많아… 로그인 후" — 원인과 무관한 안내.

**재현(직접 Responses API, luna 6회 · 1센트 미만):**

| 조건 | 결과 |
|---|---|
| 웹 검색만, 기록 없음 (`required`·`auto`) | 둘 다 completed |
| 함수 호출 → 정리 단계 검색 `required`, 기록 없음 | 검색 1 → completed 8.6s |
| 같은데 **이전 턴 1개** | 검색 0 · reasoning/message 수십 개 반복 → **incomplete `max_messages`** 18.4s |
| 이전 턴 1개, 정리 단계 `auto` | 검색 없이 completed 4.7s |

`drug_info` 는 `followupWebSearch: true` 라 정리 단계가 항상 `tool_choice: 'required'` 였다. 기록이 있으면 모델이 검색을 부르지 않은 채 메시지를 이어 붙여 한도에 걸린다.

**수정 (`server/openai/chat.ts`):**
- 정리 단계(`functionPhase === 'followup'`)의 웹 검색은 `auto`. 일반 검색 요청(함수 없음)은 `required` 유지.
- 빈 답은 미완료여도 502 — 503 이면 `forGuest` 가 "무료 이용량" 안내로 바꾼다.
- `tests/test-chat-models.mts` 기대값 `required` → `auto`. `npm test` 36 통과.

**남는 것:** `auto` 라 첫 턴에도 모델이 검색을 건너뛸 수 있다 — 약 답의 웹 출처가 줄었는지 배포 후 GPT 약 질문 몇 개로 본다(근거는 식약처 함수 결과). 사용자가 "검색해서"라고 한 함수 intent(`withExplicitSearchFollowup`)도 같은 경로라 검색 강제가 풀린다.

## 7. 약 카드 URL 이 모델 손에서 깨짐

**증상:** GPT 3번째 턴 타이레놀 카드의 `connectdi_url` 에 `…%EB%A6%AC% הוא%EA%B7%B8…`(히브리어). 출처 칩 링크가 깨진 검색어로 열린다.
**원인:** 다른 카드는 도구 출력을 고정(`cardType`)하지만 약 카드는 모델이 JSON 을 쓰고 URL 은 "그대로 옮기라"는 지시뿐이다. 긴 퍼센트 인코딩 한글을 베끼다 흔들린다.

**측정** — `tests/manual/probe-drug-card-urls.mts`(실제 그래프, 5약×2회, TIER1):

| 모델 | 수정 전 | 수정 후 |
|---|---|---|
| Gemini(약 질문은 LangChain 2.5-flash) | 0/10 | — |
| GPT-5.6 luna | **1/10**(타이레놀 `…밀리%그람`, 같은 "리그람" 자리) | **0/10** |

판콜에이내복액은 두 모델 모두 카드 없음 — URL 과 별개, 미조사.

**수정:** `server/agent/drug-card-urls.ts` `repairDrugCardUrls` — 카드의 `image_url`·`mfds_url`·`connectdi_url` 을 `[MFDS_DRUG_DATA]` 후보 값으로 덮어쓴다(후보 1개면 그것, 여럿이면 mfds_url → 이름 일치, 못 고르면 손대지 않음). OpenAI 정리 단계 끝(`server/openai/chat.ts`)에서 적용. 하니스 `tests/test-drug-card-urls.mts` 8개, `npm test` 37개 통과.

**남은 것:** Gemini 는 카드를 토큰으로 흘려 보내 최종 텍스트 보정이 화면에 늦다 — 측정상 깨짐 0 이라 보류. 깨지면 route 스트림에서 json:drug 블록을 버퍼링해야 한다.

## 8. 판콜에이내복액 카드 없음 — 설계대로

약 조회 API 는 낱알식별 DB(`MdcinGrnIdntfcInfoService03`)라 **고형제만** 있다. "판콜에이내복액" 0건 · "판콜에이" 는 판콜에이**캡슐** 1건. 액제·시럽·연고는 `[MFDS_NOT_FOUND]` → "카드 만들지 말고 웹 근거로 설명" 경로가 맞다.

§6 에서 정리 단계 검색을 `auto` 로 바꿔 이 경로(도구가 `DRUG_HOSTED_SEARCH_REQUIRED` 로 검색을 요구)가 검색을 건너뛸까 확인 — GPT 2회 모두 검색함(약학정보원 health.kr 출처 1~2개, 성분·효능 정상). 회귀 없음.

개선 여지(미착수): 액제도 카드를 원하면 허가정보·e약은요 API 로 모양 없는 카드를 만들 수 있다.
