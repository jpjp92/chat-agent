# DEV_261016 — 사이드바 정렬을 마지막 대화 순으로

> 날짜: 2026-10-16

---

## 1. 채팅 목록이 가끔 최신순이 아님

**증상:** 예전 채팅에 이어서 대화해도 사이드바 목록에서 위로 올라오지 않았다.

**원인:** 목록은 `chat_sessions.updated_at desc` 로 정렬하는데([sessions/route.ts](../../../../app/api/sessions/route.ts)), `updated_at` 은 세션 행이 수정될 때 — 사실상 **제목이 바뀔 때**만 갱신됐다. 메시지는 `chat_messages` 에 따로 쌓여 세션 시각을 건드리지 않았다. 클라이언트도 메시지를 보낼 때 목록 순서를 바꾸지 않았다. 새 채팅만 만들면 맞아 보여서 "가끔" 틀린 것처럼 보였다.

**수정**
- [session-activity.sql](../../../guide/db/session-activity.sql) — `chat_messages` insert 트리거가 그 세션의 `updated_at` 을 올린다. 기존 데이터는 마지막 메시지 시각으로 1회 보정.
- [useChatStream.ts](../../../../src/hooks/useChatStream.ts) — 기존 세션에 보내면 그 세션을 목록 맨 위로 옮긴다(새로고침 전에도 반영).
- 제목 변경으로 위로 올라가는 동작은 그대로 둔다(정렬 기준을 `last_message_at` 으로 분리하는 안은 보류).

**적용:** dev DB 에 `session-activity.sql` 실행 → 확인 후 운영 DB. SQL 을 실행하기 전에는 새로고침하면 예전 순서로 돌아간다.

## 2. 빈 "New Chat" 세션이 쌓임

**증상:** 게스트로 들어오면 빈 "New Chat" 이 생겨 있고, 메인 화면에서 바로 질문하면 새 세션이 하나 더 생겨 빈 세션이 남았다. "새 채팅" 을 누르고 입력하지 않아도 남았다.

**원인:** 첫 진입(세션 0개)·"새 채팅"·마지막 세션 삭제가 모두 DB 세션을 **미리** 만들었다. 메시지를 보낼 때도 세션이 없으면 따로 만들어서 둘이 겹쳤다.

**수정:** [useChatSessions.ts](../../../../src/hooks/useChatSessions.ts) `createNewSession` 이 DB 에 쓰지 않고 현재 세션만 비운다(웰컴 화면). 세션은 첫 메시지를 보낼 때 [useChatStream.ts](../../../../src/hooks/useChatStream.ts) 가 만든다. 이미 쌓인 빈 세션은 지우지 않았다.
