## 2-1. 법률 목록 카드 후속이 카드만 읽음 (10-10 로컬 실측, 수정)

`근로기준법 관련 법률 알려줘` → 목록 카드(법률·시행령·시행규칙) → `근로기준법 시행규칙 설명해줘` → 공포일·시행일만 → `구체적인 내용 설명해줘` → "카드에는 조문이 포함되어 있지 않습니다" (Gemini 3.7).

- 원인: [card-followup.ts](../../../../server/agent/card-followup.ts) `decideLawInteraction` — 카드가 떠 있으면 설명 요청은 **무조건 `refine`**(카드 문맥으로만 답함). 본문·조문 카드라면 맞지만 **목록 카드엔 메타데이터뿐**이다.
- 수정: `lawCardHasArticles(cardContexts.law)` — 카드 JSON 에 `articles` 가 있을 때만 `refine`, 목록 카드면 `synthesize`(→ `law_qa`, lawTool 본문 조회 후 설명). `구체적·자세히·상세` 를 카드 지칭어에 추가해 법률 판정이 없는 후속도 법률로 잡는다.
- 하니스 `test-card-followup` +6 (182/0). 프롬프트 바이트 변화 없음.
- 참고 — "카드가 축약됐다"는 오해: 카드 종류는 문장이 정한다(실측, 라이브 API). `관련 법률 알려줘` → **목록**(법령 3개, 메타데이터만) / `근로기준법 알려줘`·`설명해줘` → **본문**(조문 20개, 펼침·원문 링크). law-tool 질의 해석기 설계 그대로, 변경 이력 없음. 목록 카드에 조문 미리보기 추가는 API 1회·1~2s 비용이라 보류.
- 남은 위험: `구체적인 내용 설명해줘` 처럼 법령명이 없는 후속은 모델이 이전 턴에서 `law_name` 을 채워야 한다 — 실기기 확인 필요.

## 2-11. 응답 대기 문구 재구성 + shimmer (Thinking Orb 옆)

**왜 어떤 건 나오고 어떤 건 안 나왔나** — 첨부 문구를 URL 처리 **전에** 정하고, URL 분기가 덮어쓰거나 즉시 지웠다(arXiv: 설정 직후 null · YouTube: 3초 뒤 null · URL: 가져온 뒤 null). 알약 키워드의 `'정'` 한 글자가 "정리·정보·일정"에 걸려 표 사진 + "정리해줘" 에 "약품 식별 중"이 떴다.

**원칙(사용자 결정 10-10, ChatGPT·Claude 참고)**: 짧은 진행형 한 줄 "○○을 분석 중입니다" — 소요 시간·괄호 설명·"..."·모델명 없음. 진행감은 **shimmer**(글자 위로 빛이 지나감)로. 4개 언어 동일 구조.

## 2-12. 서버 진행 상태 — 검색·조회만 알린다

**원칙(사용자 결정 10-10)**: 기본은 **Orb 만**. 오래 걸리는 일을 **실제로 시작할 때만** 문구. 브라우저가 미리 아는 것(영상·문서·URL·이미지)은 §2-11, **서버만 아는 두 가지**를 여기서 추가. ChatGPT("Searching the web")·Claude("Searching…") 와 같은 방식 — 시간 경과로 가짜 단계를 보여 주지 않는다.

| 서버 상태 | 언제 | ko | en |
|---|---|---|---|
| `lookup` | 라우터가 외부 조회 의도로 확정(약국·병원·동물병원·법령·영화·날씨·논문·arXiv·약품 정보) — 카드 **후속**은 제외 | 정보를 조회 중입니다 | Looking up information |
| `searching` | generator 가 **실제로** 웹 검색을 켰을 때(Gemini `useGoogleSearch` · GPT `useWebSearch`) | 웹을 검색 중입니다 | Searching the web |

- 🔴 검색은 라우터의 `needsSearch` 가 아니라 **search-gate 결정 뒤**에 알린다 — 이미지·URL·렌더러 턴은 검색이 꺼지므로 라우터 값이면 "검색 중"인데 검색 안 하는 거짓 표시가 된다(하니스로 고정).
- 구조: [server/agent/status-event.ts](../../../../server/agent/status-event.ts) — `statusForRouter`(순수) · `emitStatus`(LangChain `dispatchCustomEvent`). [stream-dispatch.ts](../../../../server/agent/stream-dispatch.ts) 가 `on_custom_event`·라우터 종료를 SSE `{status}` 로 — 같은 상태 중복 금지, 본문이 이미 나갔으면 안 보냄. 클라 [geminiService.ts](../../../../services/geminiService.ts) `onStatus` → [useChatStream.ts](../../../../src/hooks/useChatStream.ts) 가 본문 전일 때만 shimmer 문구로. 구 클라이언트는 `status` 를 무시(호환).
