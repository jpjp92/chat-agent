## 2-1. 법률 목록 카드 후속이 카드만 읽음 (10-10 로컬 실측, 수정)

`근로기준법 관련 법률 알려줘` → 목록 카드(법률·시행령·시행규칙) → `근로기준법 시행규칙 설명해줘` → 공포일·시행일만 → `구체적인 내용 설명해줘` → "카드에는 조문이 포함되어 있지 않습니다" (Gemini 3.7).

- 원인: [card-followup.ts](../../../../server/agent/card-followup.ts) `decideLawInteraction` — 카드가 떠 있으면 설명 요청은 **무조건 `refine`**(카드 문맥으로만 답함). 본문·조문 카드라면 맞지만 **목록 카드엔 메타데이터뿐**이다.
- 수정: `lawCardHasArticles(cardContexts.law)` — 카드 JSON 에 `articles` 가 있을 때만 `refine`, 목록 카드면 `synthesize`(→ `law_qa`, lawTool 본문 조회 후 설명). `구체적·자세히·상세` 를 카드 지칭어에 추가해 법률 판정이 없는 후속도 법률로 잡는다.
- 하니스 `test-card-followup` +6 (182/0). 프롬프트 바이트 변화 없음.
- 참고 — "카드가 축약됐다"는 오해: 카드 종류는 문장이 정한다(실측, 라이브 API). `관련 법률 알려줘` → **목록**(법령 3개, 메타데이터만) / `근로기준법 알려줘`·`설명해줘` → **본문**(조문 20개, 펼침·원문 링크). law-tool 질의 해석기 설계 그대로, 변경 이력 없음. 목록 카드에 조문 미리보기 추가는 API 1회·1~2s 비용이라 보류.
- 남은 위험: `구체적인 내용 설명해줘` 처럼 법령명이 없는 후속은 모델이 이전 턴에서 `law_name` 을 채워야 한다 — 실기기 확인 필요.

## 2-2. 법률 카드 폭 들쭉날쭉

- 목록 카드는 좁고 본문 카드는 넓었다(GPT-6 luna 로컬 실측). 카드 자체는 `w-full` 인데 **말풍선이 내용 폭**이라 긴 조문이 있을 때만 넓어졌다.
- 약국·병원·동물병원은 이미 고정 폭(`w-[98%] sm:w-[92%]`) 목록에 있었고 법률만 빠져 있었다 → [ChatMessage.tsx](../../../../components/ChatMessage.tsx) 정규식에 `law` 추가.

## 2-3. 한 줄 요약이 도구·카드 답변에 붙음 (Gemini 3.7·GPT-6 둘 다)

- 법률 본문 조회 설명(3.7)과 본문 카드 후속(GPT-6 luna)에 `한 줄 요약` 헤딩이 붙었다. 10-09 SCOPE 는 "사용자가 제공한 자료만"인데, 두 모델 모두 **도구·카드 데이터를 제공 자료로 해석**했다.
- 수정: [prompt-integrity.ts](../../../../server/agent/prompt-integrity.ts) SCOPE 에 한 문장 — 도구 반환·카드 데이터(법령·약·장소·논문)와 그 카드 후속은 제공 자료가 아니다. 골든 42개 갱신(전 base +191자).
