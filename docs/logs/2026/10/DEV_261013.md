## 5. 개선 2차 — 세부 후속 검색 규칙 + "부재 ≠ 반박"

## 6. MT-05 원인 — GPT web_search 가 `site:` 한 번으로 끝낸다 (알려진 한계)

측정용 fetch 스파이(Responses 응답의 `web_search_call` 쿼리·열람 출처·인용 출력)로 확인.

- **T0**: 검색 1회에 열람 40+ (Le Monde·AP·Axios·위키백과 2026 페이지 등), **인용은 AP 1건** → `src=1` 은 인용 수다.
- **MT-05**: 쿼리 `site:nobelprize.org 2026 Nobel Prize laureates …` **1회**. 결과는 2025년까지인 전체 목록·발표 일정 페이지뿐 →
  "공식 사이트에 없다 = 틀렸다" 번복. OpenAI 검색 인덱스에 nobelprize.org 2026 수상자 페이지가 아직 없는 것으로 보인다.

| 시도 (GPT, MT-05 각 3회) | 결과 | 검색 |
|---|---|---|
| OpenAI 전용 규칙: "공식 목록에 없으면 항목 자체·보도도 검색, 목록 부재 ≠ 반증" | ❌ 3/3 | 1회 · `site:` |
| 위 + reasoning effort `none`→`low`(측정에서만 요청 덮어씀) | ❌ 3/3 | 1회 · `site:` |

- 규칙을 읽고도 추가 검색 0 — 지시로 바뀌지 않는 hosted 도구 동작으로 판단. **규칙은 되돌렸다**
  (모든 GPT 검색 턴에 붙는 비용, 효과 0, 다른 질의 부작용 미측정 — §4 ④ 와 같은 기준).
- 남은 수단(보류): 검증 턴에 직전 출처 URL 을 주고 열게 하기(출처 미재주입 원칙 변경) · 검증 요청만 Gemini 로(사용자 모델 선택 변경). 비용 대비 이득 작음.

## 7. 대용량 PDF 후 멀티턴 — "요청이 너무 큽니다 (10.4MB)" · 후속 턴 문서 근거

### 7-1. 증상·원인

Gemini 3.7 Flash, PDF 3.9MB "분석하자" 정상 → 후속 "지원분야가 상당히 많네?" 에서 클라 선차단(`MAX_BODY_BYTES` 4.4MB).

- 업로드 후 URL 치환이 지역 변수 `latestHistory` 에만 반영되고 **세션 상태엔 원본 base64 가 남았다**([useChatStream.ts](../../../../src/hooks/useChatStream.ts)).
- 다음 턴 그 메시지는 최근 6개 안이라 `sanitizeAttachment` 가 base64 를 유지 → `attachment` + `attachments[0]` 두 번 = 5.2MB × 2 = **10.4MB**(계산 재현 10.40MB).

### 7-2. 수정

- 업로드 직후 세션 상태의 사용자 메시지도 URL 첨부로 교체.
- 전송 시 `attachments` 가 있으면 `attachment` 사본을 뺀다(히스토리·이번 턴 모두) — 서버(history.ts:94, route.ts)는 `attachments` 우선.
- 계산: 후속 요청 10.40MB → ~3KB. (중복 제거만으로는 5.20MB — 한도 초과)

### 7-3. 따라 나온 문제 — 후속 2회째부터 PDF 를 못 본다(기존 동작)

`buildHistoryMessages` 의 `mediaWindow = 3` 이 **메시지** 단위라, 후속 1회째만 PDF 파일이 가고 2회째부터 `[Attached File: …]` 이름표만 간다(하니스 확인).
PDF 는 `extractedText` 가 없어 `lastActiveDoc` 복원 경로도 없었다. 413 이 풀리면 바로 드러날 회귀.

수정: 첨부 시 브라우저에서 pdfjs 로 텍스트층 추출 → `pdfText`([lib/pdf-text.ts](../../../../lib/pdf-text.ts), 200K자) →
후속 턴 `lastActiveDoc.pdfText` 를 기존 `[PREVIOUSLY_UPLOADED_DOCUMENT_CONTENT]`(30K자) 경로로. 첫 턴엔 안 씀(네이티브 그대로), 서버로 안 보냄.
`pdfjs-dist@4.10.38` 직접 의존성 추가(kordoc 선택 의존성으로 이미 설치돼 있던 버전). kordoc PDF 파싱은 이 WSL 에서 네이티브 모듈 크래시(exit 135)라 쓰지 않음.

### 7-4. 미검증(브라우저)

### 7-5. 곁가지 — 로컬 `Failed to fetch sessions: 500`

브라우저의 만료·무효 Supabase 토큰(같은 시점 `Invalid Refresh Token`)이 원인. 무효 토큰으로 PostgREST 를 치면 **401 PGRST301** 인데
[sessions route](../../../../app/api/sessions/route.ts) 가 모든 DB 오류를 500 으로 바꾼다. DB 자체는 정상(서비스 키 조회 200). 재로그인으로 해소.
개선 후보: PGRST301 → 401 로 내려 클라가 재로그인 유도.
