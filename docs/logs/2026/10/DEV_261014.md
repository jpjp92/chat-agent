# 다운로드형 PDF 링크(`.do`) 요약 실패 — 응답으로 PDF 판별

> 날짜: 2026-10-14 · 브랜치: dev · 미배포
> 이전: [DEV_261013](DEV_261013.md) · 관련: [REF_Architecture — URL Prefetch](../../../guide/REF_Architecture.md)

## 1. 발단

KDI 경제정보센터 다운로드 링크 `https://eiec.kdi.re.kr/policy/callDownload.do?num=276195&filenum=1&dtime=20260122173016`
요약이 GPT-6 luna · Gemini 3.7 Flash 모두 실패(웹 테스트 + GPT 검토, 10-13).

## 2. 원인

- 클라([useChatStream.ts](../../../../src/hooks/useChatStream.ts))는 `pathname.endsWith('.pdf')` 로만 PDF 를 알아본다 → `.do` 는 일반 URL.
- fetch-url 이 바이너리를 `response.text()` 로 읽어 HTML 스크래핑으로 흘렸다.
- **KDI 실제 응답(직접 조회)** — Content-Type 헤더 **없음**:
  ```
  HTTP/1.1 200 OK
  Content-Length: 449324
  Content-Disposition: attachment; filename="R2601744.pdf";
  본문: %PDF-1.4
  ```
  검토안 P0 "Content-Type 으로 판별"만으론 계속 실패한다 — `Content-Disposition`·`%PDF-` 가 필요.

## 3. 측정 — URL 을 그대로 모델에 넘기면 읽는가

[probe-url-pdf.ts](../../../../scripts/probe-url-pdf.ts) — 앱과 같은 방식(Gemini `fileData` + `mimeType: application/pdf`, GPT `input_file.file_url`), 각 2회.

| URL | Gemini 3.7 Flash | GPT-6 luna |
|---|---|---|
| KDI `callDownload.do`(Content-Type 없음) | ✅✅ 9.0 / 9.5s | ✅✅ 14.9 / 10.6s |
| 대조 arXiv `.pdf` | ✅✅ 7.9 / 9.4s | ✅✅ 6.9 / 5.6s |

두 모델 모두 실제 제목 「인공지능 투명성 확보 안내 지침(가이드라인)」과 내용(사전 고지·생성물 표시·1년 이상 계도기간)을 맞혔다.
→ 모델은 문제없다. 서버가 받아 Storage 에 다시 올리는 방식(B)은 불필요, **판별만 고치면 된다**.

## 4. 수정

- [server/pdf-sniff.ts](../../../../server/pdf-sniff.ts) 신설
  - `isPdfResponse(headers, bytes)`: Content-Type `application/pdf` · `Content-Disposition` 파일명(`filename`/`filename*`) `.pdf` · 첫 바이트 `%PDF-` 중 하나.
  - `isPdfText(text)`: 대체 스크래퍼가 PDF 바이너리를 글자로 돌려준 결과(맨 앞 `%PDF-n`).
- [fetch-url route](../../../../app/api/fetch-url/route.ts)
  - 직접 fetch 는 `arrayBuffer()` 로 받아 판별 → PDF 면 `{ isPdf: true, content: '' }`. 아니면 `TextDecoder` 로 기존 HTML 경로(`text()` 와 같은 UTF-8).
  - ScrapingBee(static·render)·browserless 결과가 PDF 글자면 캐시에 넣지 않고 같은 응답.
  - 직접 fetch 실패 시 원인 로그(`direct fetch failed`) 추가 — 이번 조사에서 침묵하던 지점.
- [useChatStream.ts](../../../../src/hooks/useChatStream.ts): `fetchUrlData` 의 `isPdf`(타입엔 있었지만 서버가 안 채우던 필드)면 URL 을 `.pdf` 링크와 같은 경로(`[URL_PDF_LINK_QUEUED]`)로 첨부.
- 하니스 [test-pdf-sniff](../../../../tests/test-pdf-sniff.mts) 9/0 · npm test 31/31 · tsc 통과.

## 5. 테스트 — fetch-url 라우트 직접 호출

| URL | 결과 |

| W3C `dummy.pdf?x=1` | 수정 전: 대체 스크래퍼가 **PDF 바이너리를 글자로**(6,701자 `%PDF-1.4 …`) 요약 본문으로 반환. 수정 후 실행에선 대체 스크래퍼가 전부 실패해 502 — 글자 반환 시 판별은 하니스로 확인 |
| example.com | ✅ HTML 그대로(945자) |
| 위키백과 노벨상 | ✅ HTML 그대로(15,028자) |

- W3C 는 우리 브라우저 UA 를 403 으로 막는다(curl 기본 UA 는 200 `application/pdf`). 단 경로가 `.pdf` 라 실사용에선 클라가 fetch-url 전에 PDF 로 보낸다.
- 브라우저 실측(KDI 링크 붙여 요약 → 두 모델) 은 미검증.

## 6. 브라우저 실측(Gemini 3.7 Flash) — 첫 턴 ✅, 후속은 웹 기사로 답했다

| # | 질문 | 결과 |
|---|---|---|
| B1 | KDI 링크 `요약해줘` | ✅ 제목·시행일·계도기간·대상·표시 방법 문서와 일치, 페이지 표기 |
| B2 | `계도기간은 얼마나 돼?` | ⚠️ "최소 1년 이상" 맞지만 출처 mt.co.kr·youtube·chosun — **PDF 를 못 봄** |
| B3 | `딥페이크는 어떻게 표시해야 한대?` | ⚠️ 출처 7곳(기사). "오른쪽 상단에 '이 영상은 합성된 영상입니다' 상시 표시"는 **문서에 없는 문구**(추출 텍스트 확인) |

원인: 링크 PDF 는 업로드 반영(`setSessions`)보다 늦게 `finalAttachments` 에 붙어 **세션 메시지에 안 남았다** → 다음 턴 history 에 PDF 없음.
텍스트 근거(`pdfText`)도 업로드 때만 만들어진다. `.pdf` 링크도 같았다(첫 턴 요약만 확인해 와서 몰랐다).

## 7. 수정 2차 — 링크 PDF 후속 근거

- [server/pdf-text-node.ts](../../../../server/pdf-text-node.ts): 노드에서 같은 `extractPdfText` 실행(DOMMatrix 등 빈 껍데기 — `@napi-rs/canvas` 크래시 회피, 8s 상한, 실패 시 빈 값).
- fetch-url: PDF 판별 시 이미 받은 바이트로 텍스트 추출 → `{ isPdf, pdfText }`. KDI 6쪽 3,155자(보도자료 전문), 1.0s.
- 클라: 링크 PDF(`.pdf` 경로·서버 판별 모두)를 세션 사용자 메시지 첨부와 `lastActiveDoc`(+`pdfText`)에 기록 → 후속 턴 `[PREVIOUSLY_UPLOADED_DOCUMENT_CONTENT]`. `.pdf` 링크도 fetch-url 로 텍스트만 받아 둔다(첫 턴 +~1s).
- `next.config` `serverExternalPackages` 에 `pdfjs-dist` 추가(kordoc 과 같은 이유 — 서버 번들 제외).
- tsc · npm test 31/31.

## 8. 남은 것

1. 브라우저 재확인: KDI 링크 B1→B2→B3, 출처 칩이 기사 대신 문서 기준인지. 운영(Vercel)에서 서버 pdfjs 동작.
2. 문서 근거가 있을 때 규칙 분류기 on(시의성)이 첨부 문서 게이트를 여는 기준 — "얼마나" 류 문서 질문까지 검색하는지 별도 검토.
3. 로컬 `.env.local` 의 url_cache 조회가 `Invalid API key` — 로컬은 매번 스크래퍼를 탄다(운영 영향 없음, 확인 필요).

**원인(GPT B2):** 라우터 LLM(ROUTER_MODEL)은 직전 답변 앞 300자만 보고, 첨부 문서가 활성인지 모른다. 직전 요약이 "기본법은 2026년 1월 22일 시행…"으로 시작해 `law_*` 로 분류 → 규칙에는 걸리지 않지만 `intentIsLaw` 로 법률 경로 진입. 모델 차이가 아니라 라우터 비결정성(같은 ROUTER_MODEL)이다.

**수정:** `server/agent/nodes/router.ts` Doc guard — webContent 에 `[EXTRACTED_CONTENT:`/`[PREVIOUSLY_UPLOADED_DOCUMENT_CONTENT:` 가 있고, 규칙이 law_search 가 아니며(사용자가 법령을 직접 말하지 않음) 법령 카드도 없으면 `law_*` → `general`.

**UI:** 링크 PDF 카드가 아래 긴 URL 말풍선 폭만큼 늘어나던 것 — 첨부 래퍼가 `w-full` 이라 카드가 stretch. PDF·문서 카드에 `w-fit max-w-full`(+사용자 `ml-auto`) (`components/ChatMessage.tsx`).
