## 1. 증상

GPT-6 luna 게스트로 "마그네스정 설명" → 답변이 **"없음"** 한 단어와 출처 칩만 나왔다. 약 카드·설명 없음. Gemini 는 정상. 재현: 서버 SSE 원문도 `{"text":"없음"}` 하나뿐이었다(화면 문제 아님). 10-17 인증 변경과 무관 — 카드는 서버 도구가 만들고 `sync-drug-image` 는 카드가 그려진 뒤 이미지만 가져온다.

## 2. 원인

1. [stream-dispatch](../../../../server/agent/stream-dispatch.ts) 는 `generator` 노드의 `on_chat_model_stream` 만 사용자에게 보낸다(도구 안 LLM 출력이 새던 사고의 방어).
2. 그런데 **GPT 경로는 도구를 generator 노드 안에서 실행한다.** 약 도구의 Gemini 각인 판독(OCR, [drug-info-tool.ts](../../../../server/agent/drug-info-tool.ts) — "각인이 없으면 '없음'을 출력")이 generator 이름을 달고 샜다.
3. `fullAiResponse` 가 "없음" 으로 채워져, generator 종료 때 GPT 최종 답(약 카드 + 설명)이 `msgText && !st.fullAiResponse` 조건에 걸려 **통째로 버려졌다.** 법령 카드 산문 폐기(같은 파일 주석)와 같은 계열.

Gemini 경로는 도구가 `tools` 노드에서 돌아 노드 필터로 걸러졌다.

## 3. 수정

- [server/agent/internal-llm.ts](../../../../server/agent/internal-llm.ts) — 내부 호출 태그 `INTERNAL_LLM_TAG`. 노드 이름은 경로마다 달라 믿을 수 없어, **호출 쪽이 표시**한다.
- drug-info-tool 각인 판독 `model.invoke(…, { tags: [INTERNAL_LLM_TAG] })`, stream-dispatch 는 태그가 붙은 이벤트를 버린다.
- 다른 LangChain 모델 호출 확인: `nodes/vision.ts` 는 vision 노드(노드 필터로 이미 걸러짐), `nodes/langchain-path.ts` 는 실제 generator 다.

## 4. 검증

- [test-stream-dispatch](../../../../tests/test-stream-dispatch.mts) §6 에 회귀 2건 — 수정 전 코드에서 2건 실패, 수정 후 48/48
- 로컬 재현(게스트, gpt-6-luna): `json:drug` 카드 + 설명 정상. gemini-3.6-flash 도 카드 정상
- 참고(별건): 같은 질문에 Gemini 의 성분이 "산화마그네슘 250mg", GPT 는 "젖산마그네슘수화물 470mg + 피리독신염산염 5mg" 로 달랐다. 카드 성분은 모델이 MFDS 결과를 옮겨 적는 값이라 공급자별 차이가 있을 수 있다 — 어느 쪽이 맞는지는 미확인

## 5. 약 카드 각인 — 앞/뒤가 애매하게 나옴

**증상:** 마그네스정 카드가 앞면 "없음", 뒷면 "마크(로고)". 사진에는 왼쪽 알약에 "dHP" 로고가 있다. Gemini·GPT 모두 같아 모델 문제가 아니다.

**원인(MFDS 원본 조회):** `PRINT_FRONT=null`, `PRINT_BACK="마크"`, `MARK_CODE_BACK_ANAL="dHP,dP,d-P,cHP"`.
1. MFDS 가 로고를 "뒷면" 으로 적었는데 사진 배치(왼쪽=앞)와 어긋난다 — 카드는 MFDS 값을 그대로 옮긴다.
2. "마크" 보정용 비전이 **사진 위치**로 면을 골라(뒷면 = 오른쪽) 민무늬를 읽고 "없음" → 보정 실패. §1 의 "없음" 유출도 이 호출.
3. MFDS 가 주는 로고 판독값 `MARK_CODE_*_ANAL` 을 쓰지 않고 있었다.

**수정:**
- [server/agent/drug-imprint.ts](../../../../server/agent/drug-imprint.ts) — "마크" 면은 ANAL 첫 값으로 "마크(dHP)". ANAL 이 있으면 **비전을 부르지 않는다**(지연·비용·유출 경로 감소).
- [drug-info-tool.ts](../../../../server/agent/drug-info-tool.ts) — ANAL 이 없을 때만 비전. 각인이 한 면에만 있으면 위치 대신 "각인이 새겨진 알약" 을 읽게 한다(`side: 'marked'`).
- 하니스 [test-drug-imprint](../../../../tests/test-drug-imprint.mts) 11건.
- 실측: 마그네스정 → Gemini 3.6 · GPT-6 luna 모두 `imprint_back: "마크(dHP)"`. (Gemini 3.7 은 이번엔 카드 없이 검색 답 — 매번 같지 않다, 별건)

**앞/뒤 표기(결정 대기):** [DrugRenderer](../../../../components/DrugRenderer.tsx) `imprintSides` — `'mfds'`(기본, MFDS 그대로) / `'neutral'`(한 면만 각인이면 "각인 / 반대면"). `/dev/drug-preview` 에서 마그네스정·아프로바스크(앞면만)·타이레놀(양면)로 나란히 비교.

## 8. CGV API 이전 · 지점 목록 갱신

**증상:** CGV 상영시간이 강남·용산·강변·왕십리 전부 0편(10-17 확인, 변경 전 코드도 동일). 롯데·메가 정상. 웹 검색으로 CGV 강남은 운영 중 확인 — 우리 수집 문제.

**원인:** CGV 가 API 를 `api.cgv.co.kr/cnm/atkt/*` → **`cgv.co.kr/api/v1/*`** 로 옮겼다. 예전 주소는 browserless 페이지 안 fetch 가 `Failed to fetch` 로 막혔고, 라우트는 이를 **오류 없이 빈 목록(200)** 으로 돌렸다. 지점 갱신 스크립트도 같은 이유로 CGV 0곳 → sanity 게이트가 갱신을 막았다.

CGV 페이지 네트워크 기록(browserless)으로 새 주소를 찾고 후보를 시험:

## 10. "부작용은?" 에 날씨 카드가 다시 뜸

**증상(사용자, GPT-6 luna 멀티턴):** 서울 날씨 → 마그네스정(카드) → 마그너스정(산문) → **"부작용은?"** → 서울 날씨 카드가 새로 떴다.

**원인:** [weather-followup.ts](../../../../server/agent/weather-followup.ts) `detectCityMention` 이 "X은?" 단독 재질의의 X 를 사전에 없어도 **모르는 지명(unknown)** 으로 쳤고, 지명이 언급되면 무조건 새 조회(`new`)다. "부작용은?" 이 "순천은?" 과 같은 꼴이라 날씨 재조회가 됐다. LLM 판정보다 규칙이 먼저라 LLM 이 "unrelated" 를 줘도 막지 못했다.

**수정:** "X은?" 은 **사전에 있는 도시만** 지명으로 본다. `X 날씨` 처럼 날씨를 명시한 경우는 모르는 지명도 새 조회로 둔다(사전은 allowlist 가 아니다). 모르는 단어의 "X은?" 은 LLM 판정 → 없으면 카드 해석(새 카드 아님).

**확인:** [test-weather-followup](../../../../tests/test-weather-followup.mts) +4건("부작용은?"·"가격은?" → 새 조회 아님, LLM unrelated 존중, "순천 날씨" 는 새 조회) 기준선 유지. 실사용 세션 그대로 재생(dev DB) → GPT 2회 모두 "마그네스정의 대표적인 부작용은 설사…" 로 답, 날씨 카드 없음.

## 11. GPT 법령 해설이 조문 없이 일반론으로 끝남

**증상(멀티턴 D, GPT-6 luna):** "영화관 소음 관련 법 있어?" → "관련 법령을 확인하지 못해". "소음진동관리법 설명해줘" → 시행일만 맞고 일반론. "벌금은?" → 금액 없이 "상황에 따라 다르다". 의도 분류(영화 → 법령 전환, 맥락 유지)는 모두 맞았다 — **도구 데이터 문제**.

**원인:** 법제처 API·도구는 정상(단독 호출로 확인). GPT 경로는 해석기를 끄고(`interpret_with_gemini: false`) GPT 인자를 그대로 쓴다.
- GPT 가 `mode` 를 비우면 기본값 `list` — 법령 이름·시행일만, **조문 없음**. 해설(`law_qa`)인데 근거가 없었다.
- 검색은 **법령 이름 검색**이라 주제 원문("영화관 소음 관련 법")은 0건. 본문 검색(`search=2`)은 건축법 시행령 등 엉뚱한 6건이라 대안 아님.
- 조문 점수가 질의 토큰 일치라 "벌금은?" 의 조사 붙은 토큰이 벌칙 조문과 안 맞아 목적·정의부터 나왔다.

**수정:** [law-tool.ts](../../../../server/agent/law-tool.ts) · [local-tool-registry.ts](../../../../server/agent/local-tool-registry.ts)
- `default_mode` — `law_qa` 는 mode 가 비면 `body`(카드 `law_search` 는 그대로 `list`).
- 법령명은 **모델이 문맥으로** 고른다: GPT 도구 설명·Gemini 해석기 프롬프트에 "주제형이면 관련 공식 법령명" + 예시. 키워드 매핑 추가 없음.
- 0건이면 해석기(Flash 1회, 요청의 key tier)로 한 번 더.
- 토큰화에서 끝 조사를 뗀 형태도 넣는다("벌금은" → "벌금").

**확인:** [test-law-plan](../../../../tests/test-law-plan.mts) 7건 · verify 36개 통과. 도구 실호출(GPT 경로 등록 그대로): "영화관 소음 관련 법 있어?" → 소음ㆍ진동관리법 body 8조(생활소음과 진동의 규제·층간소음기준 등), "소음진동관리법 벌금은?" → 벌칙 3 · 양벌규정.

## 12. 법령 카드가 질문에 답을 못함 (멀티턴 E~H)

**증상(GPT-6 luna, 15턴 멀티턴):** 맥락 유지는 전부 맞음. 다만 "근로기준법 연차휴가 알려줘" → 제1~5조(목적·정의) 카드, "김영란법 식사 한도 얼마야?" → 청탁금지법 제1~5조 카드만 · 금액 답 없음, "위반하면 처벌은?" → 맞는 제재 조문 없이 일반론.

**원인:**
- [router.ts](../../../../server/agent/nodes/router.ts) 법률 블록에서 `decideLawInteraction`(정규식)이 LLM 의 `law_qa`/`law_search` 판정을 **덮어썼다**. 규칙에 안 걸리면 기본값이 `lookup` → 카드 전용 → 글 답 없음. "얼마야?" 가 그렇게 갔다.
- 조문 선택이 질의 글자 일치라 "연차휴가" 가 "연차 유급휴가" 와 안 맞아 제1조부터 보여줬다. 모델은 제60조를 알지만(다음 턴에서 바로 찾음) 번호를 넘기지 않았다.

**수정 — 문맥 판단을 존중:**
- 라우터: LLM 이 law_search/law_qa 를 직접 골랐으면 그 값을 유지. 규칙은 LLM 이 법령으로 안 봤을 때와 카드 후속(refine·acknowledge)·이탈(unrelated)에만.
- 라우터 프롬프트: law_search = 법령·조문을 **보여 달라**, law_qa = 법이 답하는 **질문**(금액·한도·나이·허용 여부·처벌·대처, 법령명 없는 생활 법률 포함). 판단 기준은 "무엇을 돌려받고 싶은가".
- 도구 설명([local-tool-registry.ts](../../../../server/agent/local-tool-registry.ts) · lawTool 스키마): 질문에 답하는 조문을 **확실히 알면** `article_no` 에 넣는다(연차휴가 → 제60조). 불확실하면 비움.
- 조문 점수: 공백을 뺀 본문으로도 맞춘다(띄어쓰기 차이).

**확인:** verify 36개 통과. 회원 토큰 GPT 단일 턴 3회 — "근로기준법 연차휴가 알려줘" → 제60조 카드, "김영란법 식사 한도 얼마야?" → "1인당 5만 원" 답(시행령 위임 언급), "전세 보증금 안 돌려주면 어떻게 해?" → 주택임대차보호법 제3조 근거 해설. 남은 것: 시행령·별표까지 조회(김영란법 금액은 시행령에 있음 — 이번 답은 모델 지식).

## 13. 시행령에 위임된 숫자를 모델 기억으로 채움
