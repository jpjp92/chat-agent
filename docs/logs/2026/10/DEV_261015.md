## 1. 대기 문구 — 일반 질문은 2초 뒤에만

**발단:** 웹 검색·분석이 아닌 일반 질문은 대기 중 문구 없이 오브만 보였다. 10-10 원칙("실제로 오래 걸리는 일을 시작할 때만 알린다", [status-event.ts](../../../../server/agent/status-event.ts))에 따른 의도된 동작이다.

**판단:** 처음부터 "생각 중…" 을 띄우면 대부분 1~2초 안에 첫 글자가 와서 문구가 깜빡이고 사라진다. 대신 **늦어질 때만** 띄운다.

**수정**
- `SLOW_TURN_MS = 2000`([loading-status.ts](../../../../src/lib/loading-status.ts)) — 문구 없는 턴이 2초 안에 첫 조각도 서버 알림도 못 받으면 "답변을 준비 중입니다"(4개 언어, [useChatStream.ts](../../../../src/hooks/useChatStream.ts)).
- 타이머 취소: 첫 조각 · 서버 알림(searching·lookup) · 재시도 · 종료. 첨부·URL 처럼 처음부터 문구가 있는 턴은 타이머를 걸지 않는다.
- 기준은 3초로 시작해 미리보기에서 보고 2초로 정했다. 2~3초에 끝나는 답은 문구가 잠깐 비칠 수 있다(응답 시간 실측 자료는 아직 없다).
- 대기 표시를 [WaitingIndicator.tsx](../../../../components/WaitingIndicator.tsx) 로 분리 — 채팅 화면과 미리보기가 같은 컴포넌트를 쓴다.
- **미리보기** `/dev/loading-preview`(dev 전용, 프로덕션 404) — 시나리오 8종(일반 빠름·보통·느림·매우 느림, 웹 검색, 검색 알림 늦음, 카드 조회, 문서 첨부) + 기준 슬라이더.
- `next dev` 가 레포 루트에 `AGENTS.md`·`CLAUDE.md` 를 자동 생성해 `next.config.ts` 에 `agentRules: false`.

**테스트:** `test-loading-status` 에 지연 문구 검사 3개 추가(문구 있는 턴은 타이머 없음 · 취소 4곳 · 4개 언어). 대기 표시 분리로 위치가 바뀐 소스 계약 검사 2개(`test-loading-status`, `test-status-event`)를 새 위치에 맞췄다.

## 2. 날씨 카드 한 줄 설명

**발단:** "오늘 서울 날씨 어때? 우산 챙겨야 할까?" 에 카드만 나오고 산문이 0줄. 날씨는 카드를 모델 합성 없이 바로 보내는 fast-pass 경로다.

**판단**
- 모델에게 요약을 시키지 않는다 — 1~2초 지연·비용이 붙고 수치를 잘못 옮길 수 있다. 카드와 같은 데이터로 서버가 문장을 만든다.
- 조언(우산 등)은 넣지 않는다 — 묻지 않은 질문에 답하게 된다. 카드에 있는 사실만 한 문장으로.
- 이번에는 날씨만. 약국·병원·법령·영화 카드는 붙일 내용이 적다.

**수정**
- [weather-summary.ts](../../../../server/agent/weather-summary.ts) — 예: "서울은 현재 맑고 16°입니다. 오늘 기온은 10~21°, 강수확률은 30%입니다."
  - 한국어는 상태별 연결형(맑고·흐리고·비가 오고…), 조사는 받침에 맞춘다(서울은·도쿄는). 어미는 "~입니다"로 통일("~예요" 섞임 수정).
  - 영어는 상태별 서술형(rainy·snowy·foggy) — 카드 표기(Rain)를 넣으면 "Seoul is rain" 이 된다. es/fr 는 "상태, 기온" 나열이라 카드 표기를 소문자로.
  - 오류 카드·깨진 블록에는 붙이지 않는다.
- 상태 표기를 [lib/weather-labels.ts](../../../../lib/weather-labels.ts) 로 옮겨 카드와 문장이 같은 표를 쓴다.
- [stream-dispatch.ts](../../../../server/agent/stream-dispatch.ts) 가 카드를 보낼 때 **각 카드 바로 위**에 그 도시의 한 줄을 둔다(Gemini·GPT 공통). 사용자 언어는 route 가 넘긴다.
  - 처음엔 카드 아래 끝에 몰아 붙였는데 여러 도시에서 문장과 카드가 떨어져 보여 문장 → 카드 순서로 바꿨다.
- 날씨 카드만 가운데 정렬(`mx-auto`)이라 문장과 기준선이 어긋나 왼쪽 정렬로 바꿨다(다른 카드와 같음).

**테스트:** `test-weather-summary` 신규 13항목 — 문장 형식·연결형·조사·4개 언어·오류 카드·여러 도시 짝짓기, 실제 SSE 루프에서 문장이 카드보다 앞에 오는지. 브라우저에서 서울 단일·서울+부산·서울+전주(GPT-6 luna) 확인.

**멀티턴:** 날씨 카드 판정은 모두 메시지 안 어디든 `json:weather` 를 찾는 방식이라 문장이 앞에 와도 영향 없다(router `weatherCardShown`, 클라이언트 카드 추출). 실제 모델 멀티턴은 브라우저 확인 대기.
