# DEV_261017 — 공개 API 라우트 인증

> 날짜: 2026-10-17 · 계획: [PLAN_PUBLIC_ROUTE_AUTH_261017](../../../plans/PLAN_PUBLIC_ROUTE_AUTH_261017.md)

---

## 1. 발단

외부 보안 리뷰(origin/dev 기준)가 `fetch-url`·`sync-drug-image` 무인증 + service_role 쓰기를 HIGH 로 짚었다. 코드와 대조한 뒤 `app/api` 11개 라우트를 전수조사했다(계획서 §2).

- 리뷰에 없던 것: **`parse-document` 직행(≤4MB)은 위조 토큰이 통과했다.** `userIdFromToken` 은 JWT 를 디코드만 하고, 이 경로는 DB·Storage 를 거치지 않아 서명 검증이 한 번도 일어나지 않았다.
- 0단계: dev DB 에서 `profiles` 행이 없는 auth 사용자 0명 확인 → `profiles` 기준 인증이 기존 사용자를 막지 않는다.

## 3. 검증

- proxy-image: `example.com` → 403, `dthumb-phinf…?src=example.com` → 403
- **유효 토큰**(dev DB 익명 가입으로 받은 게스트 토큰) — 정상 경로가 막히지 않는지:
