## 1. 발단 — 실기기 (dev, GPT-6 luna, 2.07MB 사업계획서 PDF "분석")

- 응답이 오래 걸렸고 **표 머리글 `| 세부 업무 | 수행내용` 만 두 번 찍힌 채 끝났다**(구분선 없음). 같은 PDF 재시도는 정상.
- 🔴 **답한 건 GPT 가 아니라 Gemini 2.5 였다.** OpenAI 어댑터(`toInputContent`)가 텍스트·이미지만 넘기고 PDF 는 버려서,
  generator 가 PDF 가 보이면 조용히 2.5 로 핀했다(`pinOpenAIUnsupportedMedia` + `pinUrlFileData` — GPT 모델은 `MODEL_CAPS` 에 없어 `urlFileData=false`).
  화면엔 GPT 라벨 그대로.
- 끊김 원인은 **미확정** — Vercel 로그 조회 실패(MCP 403 · CLI 400). 재시도 정상 + 300s·16384 토큰에 못 미침 → 2.5(`thinkingBudget: 0`)의 일회성 표 퇴행으로 추정.
  잘림 감지(`finishReason`·`incomplete` 가 빈 응답일 때만 검사됨)는 별도 과제로 남긴다(§4).

## 5. Google 로그인 — 계정 선택 화면에 Supabase 주소가 뜨던 것

- 증상: 로그인 시 "**ghdpnuwbvlrxmxcazzci.supabase.co**(으)로 이동", 개발자 정보의 앱 이름도 같은 주소.
- 원인: 리다이렉트 OAuth(`signInWithOAuth`·`linkIdentity({ provider })`)의 콜백이 Supabase 인증 서버라서.
  앱 이름은 Google Auth Platform 브랜딩 + **브랜드 인증** 몫(콘솔 작업, 코드 아님). 이동 주소는 커스텀 도메인(유료) 또는 **앱 안 ID 토큰**으로만 바뀐다 → 후자 선택.
- 방식: Google Identity Services 공식 버튼(`renderButton`, 팝업/FedCM) → ID 토큰 → supabase-js 2.90.1
  `linkIdentity({ provider: 'google', token, nonce })`(게스트 승계, 같은 uuid) / `signInWithIdToken`(로그인).
  nonce 는 Google 에 SHA-256 hex, Supabase 에 원문. 성공 후 **새로고침** — 리다이렉트 복귀와 같은 끝맺음을 유지(캐시·프로필 전제).
- 🔴 계정 전환(헤더)도 모달로 옮기며 발견: `guestHasData` 는 정식 사용자에게도 참 → 그대로 두면 계정 전환이 **지금 계정에 다른 Google 신원을 붙인다.**
  `shouldLinkGuest = is_guest && guestHasData` 로 link/signIn 기준을 한 곳에.
- **"다른 계정으로 로그인" 제거**(사용자 결정, 같은 날): 로그아웃 → 새 게스트 → 모달에서 계정 선택(대화 없는 게스트 = signIn)으로 결과가 같다.
  버튼이 로그아웃과 나란히 있어 차이가 안 보였고, 전환 경로는 위 link 위험만 늘렸다. ChatGPT·Claude 웹도 로그아웃만 둔다. 모달 `switch` 모드·4개 언어 문구·헤더 버튼 삭제.
- 충돌(이미 다른 유저의 Google 계정): 받은 토큰을 다시 써서 바로 로그인 — 계정을 두 번 고르지 않는다. 리다이렉트로 돌아온 충돌은 기존 경로.
- 폴백: `NEXT_PUBLIC_GOOGLE_CLIENT_ID` 없음·GIS 스크립트 차단/6s 초과 → 기존 리다이렉트 버튼. 설정 전 배포해도 로그인이 깨지지 않는다.
- CSP `frame-src` 에 `https://accounts.google.com`(GIS 버튼 iframe).

## 6. 카카오 로그인

- 방식: Supabase 내장 Kakao 공급자 + **리다이렉트 OAuth**(`signInWithOAuth`·`linkIdentity({ provider: 'kakao' })`).
  Google 과 달리 ID 토큰으로 바꾸지 않는다 — 카카오 동의 화면에는 Supabase 주소가 아니라 **앱 이름·아이콘**("Chat Agent")이 뜬다. OIDC 는 OFF.
- link/signIn 기준은 Google 과 같다(`shouldLinkGuest`). 🔴 리다이렉트 충돌(`identity_already_exists`)은 URL 로 돌아오므로
  **시도한 공급자를 sessionStorage 에 남긴다** → 충돌 화면 "기존 계정으로 로그인" 이 같은 공급자로 간다(없으면 Google 로 가 엉뚱한 계정).
- 버튼: 카카오 디자인 가이드(#FEE500 · 검정 말풍선 심볼 · "카카오 로그인"/"Login with Kakao"), Google 버튼 아래. 높이 40px — GIS large pill 과 맞춤.
  Google 버튼 테마는 다크에서도 `outline`(흰 단색) — `filled_black` 은 반투명 회색이라 카카오 노랑 옆에서 흐려 보였다.
- 🔴 **사진 누락 → scopes 명시.** 동의 화면엔 프로필 사진이 있었는데 identity_data 에 `avatar_url`·`picture` 가 없었다(사진 있는 계정, dev DB 확인).
  `scopes: 'profile_nickname profile_image account_email'` 을 명시하자 재로그인에서 사진이 들어왔다(`auth.users` 갱신 트리거가 빈 avatar 를 채움).
- 🔴 **카카오 → 로그아웃 → Google 이 안 들어가던 것.** 카카오(implicit) 뒤 주소에 `#access_token=…` 이 남고, 로그아웃·GIS 성공의 `reload()` 가
  끝난 세션 토큰을 다시 싣고 열렸다. `reload()` → 해시 없는 주소로 `location.replace`, 세션 확보 직후 `stripAuthHash()` (토큰이 주소·히스토리에 남지 않게).
- 참고: VS Code 내장 브라우저에선 Google(FedCM)이 `FedCM get() rejects with NetworkError` 로 실패 — 일반 Chrome 에선 정상. 개발 도구 환경 한정.
  dev 서버 Turbopack HMR 패닉(`EcmascriptMergedChunkVersion ... no longer exists`)은 `rm -rf .next` 후 재시작.
- 헤더 프로필 창의 게스트 버튼 "Google로 계속하기"(G 마크) → **"로그인"**(공급자 중립). 이 버튼은 모달을 여는데 Google 전용처럼 보여 "로컬에선 구글만 된다"로 읽혔다.
- 프로필: 이름·사진은 identity 동기화 트리거가 `name`·`full_name`·`avatar_url`·`picture` 를 모두 본다([auth-mvp-identity-sync.sql](../../../guide/db/auth-mvp-identity-sync.sql)) — 카카오도 추가 SQL 없음(실기기로 확인 필요).
