# DEV_261110 — 에러 코드 한곳 정리 · 코드 값 snake_case

## 1. 에러·결과 코드 문서 `REF_ErrorCodes`

- 문제: 코드가 7종류로 흩어져 있었다. 사용자 에러 분류·`[turn]` errCode·outcome·재시도 사유·OpenAI 내부 코드·`[trace]` 상태·원문 모드 `why` 다. 정리 문서 `PLAN_ERROR_HANDLING` 은 5월 기준이라 없어진 경로(`api/_lib/config.ts`·`api/chat.ts`)를 가리켰다.
- `docs/guide/REF_ErrorCodes.md` 를 새로 만들었다.
  - 종류별로 값·정하는 곳·남는 곳을 정리했다.
  - 사용자 분류 조건표를 넣었다.
  - **원인별 대응표**를 넣었다. 같은 원인이 화면·로그·재시도에서 각각 무엇이 되는지 보여 준다.
  - 표기 규칙: 코드 값은 snake_case, JSON 필드 이름은 camelCase.
- 표를 만들며 찾은 **어긋남 4건**(§3 에서 고침):
  1. 504·OpenAI 타임아웃이 로그에 `server` 로 남는다(화면은 `unavailable`).
  2. `TimeoutError`·`AbortError` 가 화면에서는 `generic` 이다(로그는 `timeout`).
  3. OpenAI 할당량이 로그에서 `rate_limit` 으로 합쳐져 Gemini 429 와 구분되지 않는다.
  4. 안전 차단·키 전부 소진이 로그에 `other` 로 남는다.
- `PLAN_ERROR_HANDLING` 은 경로·분류 이름만 현행화하고, 코드 목록은 새 문서로 연결했다. `PLAN_TURN_LOG` errCode 행과 가이드 목록에도 연결했다.

## 2. 사용자 에러 분류 값 snake_case

- 바꾼 값: `rateLimit`→`rate_limit`·`dailyExhausted`→`daily_exhausted`·`openAIQuota`→`openai_quota`·`guestCapacity`→`guest_capacity`(나머지 4개는 원래 한 단어).
- 이 값은 서버 안에서만 쓴다. route 가 이 값으로 `CHAT_ERRORS` 문구를 골라 **문구만** 보낸다. 그래서 브라우저·로그·DB 영향이 없다.
- `CHAT_ERRORS` 타입을 `Record<string, …>` 에서 `Record<ChatErrorType, …>` 로 바꿨다. 분류와 문구 키가 어긋나면 컴파일에서 걸린다(전에는 오타가 나도 런타임에 `undefined` 문구가 됐다).
- 바꾸지 않은 것:
  - 변수 이름(`rateLimitedKeys` 등)은 식별자라 그대로다.
  - JSON 필드 이름은 기존 로그와 비교할 수 있게 그대로 뒀다.
  - 날씨 조건 코드(`highPop` 등)는 에러가 아니라 카드 내용 코드다.
  - 보조 라우트의 영어 오류 문장은 클라이언트가 문장으로 분기하는지 확인이 먼저다.
- 검증: `test-chat-models` 126 통과, strict·eslint·knip 깨끗.

## 3. 어긋남 4건 고침 — 같은 원인은 같은 이름

- `errCodeOf`(turn-log):
  - 504·`DEADLINE_EXCEEDED`·OpenAI `code: timeout` → `timeout`(전엔 `server`).
  - OpenAI 할당량 코드 → `openai_quota`(전엔 `rate_limit`). 할당량 코드 목록은 `chat-error-policy` 의 `OPENAI_QUOTA_ERROR_CODES` 를 같이 쓴다.
  - `safetyBlock` → `safety`, 키 전부 소진 → `keys_exhausted`(둘 다 전엔 `other`).
  - 메시지는 고정 표지만 보고, 문장은 값으로 나가지 않는다.
- `classifyChatError`: `TimeoutError`·`AbortError` → `unavailable`("잠시 후 다시"). 전엔 `generic`("응답 생성 중 문제")이었다. 게스트는 기존 규칙대로 `guest_capacity`.
- 하니스: `test-turn-log` 36(새 코드 5건·문장 비노출), `test-chat-models` 127(타임아웃 → unavailable). 전체 44개 통과, strict·eslint·knip 깨끗.
- 11-10 이전 `[turn]` 과 비교할 때는 이 네 경우의 값이 바뀐 점을 감안한다(REF_ErrorCodes §4).
