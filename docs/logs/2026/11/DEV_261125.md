# DEV_261125 — 약 정보 도구 지연 조정

계획: [PLAN_GEMINI_25_SHUTDOWN_261122 §10-6](../../../plans/PLAN_GEMINI_25_SHUTDOWN_261122.md) · 앞: [DEV_261124 §7](DEV_261124.md)

## 1. 문제

DEV_261124 §7 ⑥(도구 안 허가사항 검색)을 넣자 drug_info 평균이 14.3 / 17.5s → 17.4 / 18.7s 로 늘었다(2.5 / 3.5 FL).
- 전문의약품(아모잘탄)은 검색 1회만큼 +~8s — 근거를 얻는 대가.
- **타이레놀은 필요 없는 검색**(+~6s): "e약은요에 없는 첫 후보"를 검색 대상으로 잡아, 1번 후보(타이레놀정500mg, 수록) 대신 2번 후보(우먼스타이레놀)를 검색했다.

## 2. 바꾼 것 (`server/agent/drug-info-tool.ts`)

- **검색 대상 = 질문과 맞는 후보 1건**(없으면 첫 후보). 그 후보가 e약은요에 있으면 검색하지 않는다.
- **순차 유지** — e약은요 실측 486~572ms(6회). 병렬로 줄어드는 건 ~0.5s 뿐이고, 일반의약품(대부분 수록) 조회마다 버려지는 검색 호출이 생긴다. 병렬로 바꿨다가 실측 뒤 되돌렸다.
- **품목기준코드별 캐시** — 인스턴스 메모리, 6시간, 200건.
- **이름 정규화 Strategy 4(구 → 신 표기)** — 측정 중 3.5 FL 이 "아모잘탄정5/50밀리그**람**"으로 넘겨 신 표기 품목("…밀리그**램**")을 놓치고 참조 검색 경로(18s)로 빠졌다. 기존 Strategy 3 은 신 → 구 방향뿐이었다(주석의 "DB 는 구 표기 기준"도 실제는 혼재라 정정).

## 3. 측정 (`probe-tool-intents.mts` drug_info 4문항 × 2회, 모델별 별도 프로세스)

캐시가 프로세스 안에서 공유돼, 두 모델을 한 번에 돌리면 뒤 모델이 앞 모델이 채운 캐시를 써 지연이 짧게 나온다 → `ONLY=` 로 모델별 실행.

| 문항 | 2.5 (1회 · 2회) | 3.5 FL (1회 · 2회) |
|---|---|---|
| 타이레놀(e약은요 수록) | 10.0 · 13.0s | **5.0 · 4.7s**(연동 이전 수준) |
| 아모잘탄(전문, 허가사항 검색) | 17.4 · 8.1s(캐시) | 15.3 · **4.7s**(캐시) |
| 이부프로펜(성분 질문) | 16.5 · 25.3s | 18.8 · 21.8s |
| 판콜에이(액제) | 19.9 · 10.0s | 15.8 · 14.9s |
| 평균 | 15.0s | **12.6s** |

- 남은 것: 허가사항 검색 1회 ≈ +10s(캐시 없을 때). 이 검색은 아직 `DRUG_SEARCH_MODEL`(2.5, 기본 thinking) — §9 에서 3.5 FL `minimal` 유료 검색으로(§8-1 검색 1.9s vs 4.2s).
- 성분 질문·액제 15~25s 는 기존 참조 검색 경로(Google grounding + DDG) 몫, 이번 변경과 무관.
- 하니스 판정 함정 두 번: 도구 결과에서 "e약은요"·"[PRODUCT_LABEL_SEARCH]" 를 찾으면 **지시문 본문에 있는 같은 단어**까지 잡아 오탐 → 실제 블록 줄(`용법(e약은요·식약처):`, 검색 결과 블록)로 판정.
