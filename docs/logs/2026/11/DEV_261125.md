## 1. 문제

DEV_261124 §7 ⑥(도구 안 허가사항 검색)을 넣자 drug_info 평균이 14.3 / 17.5s → 17.4 / 18.7s 로 늘었다(2.5 / 3.5 FL).
- 전문의약품(아모잘탄)은 검색 1회만큼 +~8s — 근거를 얻는 대가.
- **타이레놀은 필요 없는 검색**(+~6s): "e약은요에 없는 첫 후보"를 검색 대상으로 잡아, 1번 후보(타이레놀정500mg, 수록) 대신 2번 후보(우먼스타이레놀)를 검색했다.

## 2. 바꾼 것 (`server/agent/drug-info-tool.ts`)

- **검색 대상 = 질문과 맞는 후보 1건**(없으면 첫 후보). 그 후보가 e약은요에 있으면 검색하지 않는다.
- **순차 유지** — e약은요 실측 486~572ms(6회). 병렬로 줄어드는 건 ~0.5s 뿐이고, 일반의약품(대부분 수록) 조회마다 버려지는 검색 호출이 생긴다. 병렬로 바꿨다가 실측 뒤 되돌렸다.
- **품목기준코드별 캐시** — 인스턴스 메모리, 6시간, 200건.
- **이름 정규화 Strategy 4(구 → 신 표기)** — 측정 중 3.5 FL 이 "아모잘탄정5/50밀리그**람**"으로 넘겨 신 표기 품목("…밀리그**램**")을 놓치고 참조 검색 경로(18s)로 빠졌다. 기존 Strategy 3 은 신 → 구 방향뿐이었다(주석의 "DB 는 구 표기 기준"도 실제는 혼재라 정정).

- KMA 는 요청 URL 에 발표 시각이 들어가 슬롯마다 캐시 키가 달라 같은 위험이 작다.

**고침**(`server/lib/weather/index.ts`)
- OWM 현재·예보는 `cache: 'no-store'`, 좌표 변환(geocode)만 하루 캐시.

### 11-2. 날씨 카드 뒤 짧은 답

**문제**: 첫 날씨 질문은 fast-pass(카드 + 템플릿 한 줄)라 "오늘 서울 날씨 어때? 우산 챙겨야 할까?" 에 우산 답이 없었다(11-25 로컬 실화면). 템플릿은 조언을 넣지 않는 게 맞다.

**바꾼 것**
- `server/agent/weather-answer.ts` — 그래프가 끝난 뒤 route 가, 본문이 카드 + 한 줄뿐이면 역할 모델(3.5 FL)에 질문 + 카드 요약을 주고 1~2문장을 받아 붙인다. Gemini(langchain fast-pass)·GPT(함수 호출 fast-pass) 두 경로 모두 본문이 같은 모양으로 끝나 한 곳에서 처리된다.
- 날씨만 물었는지는 키워드가 아니라 **모델이 `NONE`** 으로 판단. 결론 먼저·근거 수치 최대 2개·요일로 지칭·카드에 없는 정보(미세먼지·시간대)는 없다고. 요일은 서버가 미리 붙여 넘긴다.
- 자세한 분석은 다음 턴 — 카드가 떠 있으면 기존 후속 규칙이 카드 데이터로 답한다.
- 모델 산문이 이미 있는 턴·오류 카드에는 붙이지 않는다. 제한 시간 6s, 실패·시간 초과는 조용히 생략(카드는 이미 나갔다).
- 순수 부분(`weather-answer-prompt.ts`)을 나눴다 — 키·모델 설정이 `server-only` 라 하니스(`run-all` 은 react-server 조건 없음)가 임포트하지 못했다.

- 카드 뒤 지연 중앙값 1.74s · 최대 2.6s(카드는 먼저 보인다).
- 예: "우산 챙겨야 할까?" → "오늘은 비 소식이 없어 우산을 챙기지 않으셔도 되지만, 모레인 금요일에는 비가 오니 우산을 챙기시는 것이 좋습니다." · "세차하기 좋은 날은?" → "목요일이 가장 좋습니다. 비 소식이 없고 최고 기온이 16도까지 올라갑니다." · "저녁 몇 시에 비 와?" → "카드에는 시간대별 예보가 없어…" · "미세먼지 괜찮아?" → "카드에는 미세먼지 정보가 없습니다…"
- 아쉬운 점: "제공된 카드에는" 같은 딱딱한 표현, 1건 현재 상태를 "구름 많음"(오늘 대표값)으로 섞어 말함. 수치 오류는 없었다.

### 11-4. 표현 개선 1차 · 역질문 라우팅 실측

**프롬프트 변경**(`weather-answer-prompt.ts`): 출처(기상청/OpenWeather)를 수치 근거일 때 한 번 · "카드·데이터" 언급 금지 · 관측 `observedNow` / 예보 `dailyForecast` 로 이름 분리 · 카드로 결론 못 내는 것(시간대·미세먼지·자외선·다른 지역)은 결론 먼저 + "찾아볼까요?" 역질문(다른 사이트 안내 금지).

**③ 기존 32문항 재측정**(유료 32콜): 일치 **31/32**, 지연 중앙값 2.05s · 최대 2.9s.
- 좋아진 것: 말투("~좋겠어요", "~거든요"), 출처 "기상청 예보에 따르면", 역질문("몇 시쯤 오는지 찾아볼까요?", "미세먼지도 찾아볼까요?"), 다른 사이트 안내 사라짐.
- 남은 문제
  - `NONE` 위반 1건 — "내일 서울 날씨는?" 에 답을 붙였다(1/2회).
  - **지어낸 근거 1건** — "두 날 모두 낮 기온이 평년보다 높아요"(평년값은 데이터에 없다).
  - 관측·예보 섞임 여전 — 현재 맑음인데 "지금은 구름이 많지만" 2건. 이름 분리만으론 부족: 위 한 줄이 이미 "현재 맑고"라 모델이 오늘 예보 상태(구름 많음)를 지금으로 끌어온다.
  - 출처 문구가 거의 매번 붙어 반복적("기상청 예보에 따르면" 13/22).
  - "미세먼지 정보는 제공되지 않아" — 시스템 말투가 남았다.

**① 첫 질문 라우팅**(라우터 실호출, 유료 키 단독, 2회): "오늘 서울 미세먼지 괜찮아? 날씨도" · "서울 날씨랑 미세먼지 알려줘" → **general + 검색(카드 없음)** 2/2. 기존 규칙(미세먼지 → 검색)대로다. 날씨 카드도 같이 원한 질문이라 카드가 빠지는 건 따로 볼 문제.

**② 역질문 뒤 짧은 답** — 카드 + "몇 시쯤 오는지 찾아볼까요?" 다음 턴:

| 다음 말 | 결과(2회 같음) | 기대 |
|---|---|---|
| 응 · 응 찾아봐 · 네 | `general` · 검색 **없음** · 카드 후속(`wf`) | 검색 |
| 찾아줘 | `general` · 검색 없음 | 검색 |
| 아니 괜찮아 | `general` · 검색 없음 | 맞음 |

→ **역질문을 그대로 내보내면 "찾아볼까요?" → "응" → 안 찾는다.** 카드가 떠 있으면 짧은 후속을 카드 데이터 답(`wf`, 검색 억제)으로 보내는 후속 판정 때문이다. 역질문은 이 라우팅을 고친 뒤에만 켠다.

### 11-5. 역질문 다음 "응" → 검색 (라우터 `lookup`)

**원인 두 겹**
- 라우터 LLM 은 직전 답의 **앞 300자**만 봤다. 날씨 턴은 "한 줄 + 카드 JSON + 제안" 순서라 300자가 카드 JSON 에서 끝나 "찾아볼까요?" 가 안 보였다.
- `follow_up` 에 "제안 수락 / 카드에 없는 걸 찾기" 값이 없어 `refine`(카드 근거 답, 검색 꺼짐)으로 갔다.

**고침**(키워드 규칙 없이 맥락으로)
- `server/agent/previous-response.ts` `previousResponseExcerpt` — 직전 답의 코드 블록(카드 JSON)을 `[card shown]` 으로 줄이고 400자 넘으면 앞 220 + 뒤 160. 모든 의도에 쓰인다.
- 라우터 프롬프트 `follow_up` 에 `"lookup"` — 직전 답이 찾아보겠다고 제안했고 사용자가 받음(맨 "응"·"네"도), 또는 카드에 없는 정보(시간대·미세먼지·자외선)를 찾아 달라는 것. 거절은 아님.
- `decideWeatherFollowup` 에 `lookup` 결정 — 다른 도시(새 조회) 다음, refine 규칙보다 먼저. 라우터는 general + 검색 켬. 다른 카드 소비자(영화·장소·법령)엔 `unrelated` 로 넘긴다(그쪽 분기에 없는 값).
- 영화는 이미 키워드 방식(`SEARCH_OFFER_MARKER` + `AFFIRM`)이 있으나 날씨는 따르지 않았다 — 제안 문구가 모델 생성이라 표현이 매번 다르다.

**실측**(라우터 실호출, 유료 키 단독, 9경우 × 2회): **18/18**
- 응 · 응 찾아봐 · 찾아줘 · 네 → `general` + 검색
- 아니 괜찮아 · 고마워 → 검색 없음
- 그럼 토요일은? · 그럼 금요일 우산 챙겨야겠네 → 카드 근거(`wf`)
- 응 그리고 부산은? → `weather`(부산 카드)

**회귀**: `live-card-suction.mts`(1회, ~180콜) 변경 전 HEAD 와 비교 — 대조군과 갈린 판정 14건(22%) → 11건(17%). 새로 생긴 흡입 없음(남은 차이는 1회 측정 흔들림 수준: 같은 "표로 정리해줘" 가 약국 ↔ 동물병원으로 자리만 바뀜).

### 11-6. 표현 개선 2차 — 지어낸 근거·NONE·관측/예보 섞임 (같은 32문항, 회당 유료 32콜)

| 회차 | 바꾼 것 | 일치 | 남은 문제 |
|---|---|---|---|
| 1차(§11-4) | 출처·시스템 단어·이름 분리·역질문 | 31/32 | "평년보다"(지어냄) 1 · NONE 위반 1 · "지금은 구름이 많지만" 2 · 출처 13/22 |
| 2차 | 데이터 밖 비교 금지 · 다른 날 예보도 NONE · 오늘 칸 하늘 상태 제거 · 출처는 수치가 근거일 때만 | 29/32 | NONE 위반 3("이번 주 날씨 알려줘" 에 우산 팁) · "가지고 있지 않은데" |
| 3차 | NONE 을 기본값·팁 금지 · 단계 분리(판단 → 답) | 30/32 | **"날씨 어때? 우산 챙겨야 할까?" 를 NONE**(과잉 교정) · "토요일이 일요일보다 기온이 낮아"(틀린 비교) |
| **4차** | 날씨 요청 + 판단 질문이면 질문 부분에 답 · 비교는 수치로 확인 | **32/32** | "가지고 있지 않아 / 나와 있지 않아" 3건(시스템 말투 잔여) |

- 4차에서 지어낸 근거·관측/예보 섞임 0. 출처는 3/22 — 수치가 근거일 때만("기상청 예보로 금요일 강수확률 60%").
- 역질문은 "날은 맑아요. 미세먼지도 찾아볼까요?" · "오늘은 비 소식이 없고, 비는 금요일에 와요. … 몇 시쯤 오는지 찾아볼까요?" — 묻는 날에 비가 없으면 비 오는 날을 먼저 말한다.
- 지연 중앙값 3.2s(1차 2.05s) — 프롬프트가 길어졌고 회차 간 편차도 크다(같은 프롬프트 1.7 ↔ 2.0s). 카드는 먼저 나가므로 체감은 답 문장만 늦다. 배포 뒤 `[weather] 카드 뒤 답 … ms` 로그로 본다.

**GPT 선택 시**: 카드 뒤 답은 선택 모델과 무관하게 역할 모델(3.5 FL)이 쓰고, 라우터도 같다. GPT 경로는 함수 호출 fast-pass 가 도구 출력(카드 블록만)을 그대로 본문으로 내 판정이 카드를 돌려준다(하니스 "GPT fast-pass(카드만)"). GPT 에서 달라지는 건 ① 템플릿 한 줄이 없는 본문 ② "응" 다음 검색 답(선택 모델 + web_search) — 실화면 확인 필요.

### 11-7. 글 배치 — 한 줄도 카드 아래로

로컬 실화면(Gemini 3.8 Flash): 템플릿 한 줄은 카드 위, 카드 뒤 답은 카드 아래라 글이 카드를 사이에 두고 갈라졌다. 답을 위로 올리려면 답이 나올 때까지(2~3s) 카드를 붙잡아야 해 "카드가 바로 뜬다" 를 잃는다 → **한 줄을 카드 바로 아래로**(`interleaveWeatherSummaries`). 카드 → 한 줄 → 답 순서. 여러 도시는 각 카드 아래에 그 도시 한 줄, 답은 맨 끝. 같은 화면에서 답 자체는 의도대로("오늘 우산은 안 챙기셔도 돼요. 비는 금요일에만 오고 오늘은 강수 확률이 20퍼센트입니다.").

### 11-8. 글은 화면에서 카드 위로

§11-7 뒤 실화면 피드백: 글은 카드 **위**가 더 자연스럽다 — 특히 모바일은 카드가 화면을 채워 아래 글이 스크롤해야 보인다.
- 본문(서버 스트림) 순서를 바꾸면 답이 나올 때까지(2~3s) 카드를 붙잡아야 하고, 날씨만 물어 답이 없는 턴도 그만큼 늦는다.
- → **본문은 카드 → 한 줄 → 답 그대로, 화면에서만** 카드 바로 뒤 글 조각을 카드 앞으로 그린다(`ChatMessage.tsx`). 카드는 바로 뜨고, 답이 스트리밍되면 위 글이 늘며 카드가 아래로 밀린다.
- 여러 도시는 각 카드와 바로 뒤 글을 짝으로 바꾼다(마지막 카드의 글 조각에 답이 붙어 있어 마지막 카드 위로 간다).
- 저장된 옛 메시지(한 줄이 카드 앞, §11-7 이전)는 카드 뒤에 글이 없어 그대로 보인다.
