# DEV_261113 — 떠돌이 rejection 근원 수정 · 요청별 리스너 제거

계획: [PLAN_STABILITY_261112](../../../plans/PLAN_STABILITY_261112.md) §1

## 1. 근원 — SDK 가 만들고 LangChain 이 버린 Promise

- `@google/generative-ai`(0.24.1) `generateContentStream` 은 응답 스트림을 tee 해 `{ stream, response }` 를 준다. `response` 는 스트림을 끝까지 읽는 별도 Promise 다.
- `@langchain/google-genai`(2.2.0) 스트리밍 경로는 `const { stream } = …` 로 `response` 를 버린다. LangGraph `streamEvents` 아래에선 이 경로를 탄다.
- 스트림이 깨지거나(`Failed to parse stream`) 25s 타임아웃으로 끊기면 같은 오류가 두 곳으로 간다.
  - `stream` 쪽 → langchain-path catch → 다음 키로 재시도(정상).
  - `response` 쪽 → 받는 쪽 없음 → `unhandledRejection`.
- 가짜 fetch(잘린 마지막 청크)로 재현: 호출 1번에 caught 1 + 떠돌이 1.

## 2. 그동안의 증상

- [route.ts](../../../../app/api/chat/route.ts) 가 요청마다 `process.once('unhandledRejection')` 를 걸어 자기 스트림에 generic 오류를 보냈다(4월 K3, [DEV_260423](../04/DEV_260423.md)).
- `process` 는 동시 요청이 공유한다 → 떠돌이 1건에 **그 순간 열린 요청 전부**가 오류 문구를 받았다.
- 재시도가 성공한 턴에도 오류 문구가 먼저 나갈 수 있었다. TODO 의 "빈 답 + 출처만"(10-18, [DEV_261018 §6](../10/DEV_261018.md#6-실측-키--제목-생성-키-tier))도 같은 길이다 — 무료 키 소진 중 스트림 오류가 떠돌았다.

## 3. 수정

- [server/process-guard.ts](../../../../server/process-guard.ts) `installProcessGuard()` — route 모듈 로드 때 한 번.
  - `GenerativeModel.prototype.generateContentStream` 결과의 `response` 에 빈 catch 를 붙인다. 오류는 `stream` 으로도 오므로 잃는 것 없음.
  - 프로세스 리스너 1개(`globalThis` 표식으로 중복 방지) — `[process] unhandled rejection {name, code, status}` 로그만, 오류 문구·SSE 없음.
  - 리스너를 없애지 않은 이유: Node 15+ 는 처리 안 된 rejection 에 프로세스를 끝낸다.
- route 의 요청별 `process.once`/`process.off` 제거. 요청 오류는 기존 try/catch/finally 만.
- `@google/generative-ai` 를 직접 의존성으로 올림(이미 설치된 0.24.1 그대로, 직접 import 하므로).

## 4. 검증

- 하니스 [test-process-guard](../../../../tests/test-process-guard.mts) 7건 — 실제 `ChatGoogleGenerativeAI` 에 깨진 스트림, 동시 3개: 각 호출 catch 로 오류 전달 · 떠돌이 0건 · 리스너 1개 · 요약에 문구 없음. **패치를 빼면 2건 실패**(떠돌이 3건)로 하니스가 회귀를 잡는 것도 확인.
- 전체 45개 통과, tsc·knip 이상 없음, eslint 오류 0(경고는 하니스 `any` 수준), build 통과. 번들에서 패치와 SDK 가 같은 서버 청크(같은 모듈 인스턴스).
- 남은 확인(배포 후): `[process] unhandled rejection` 줄이 찍히는지 — 찍히면 다른 출처가 있다는 뜻이라 그 Promise 를 찾아 막는다.
- 패키지 갱신 주의: LangChain 이 `response` 를 처리하게 바뀌거나 SDK 구조가 바뀌면 패치는 무해한 덧칠이 된다. 하니스가 계속 지킨다.
