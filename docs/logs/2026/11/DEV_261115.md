# DEV_261115 — 재시도 사유 전 경로 · 라우터 제한 시간 · OpenAI 재시도 · 실패 주입 하니스

계획: [PLAN_STABILITY_261112](../../../plans/PLAN_STABILITY_261112.md) §4

## 1. `routerMs` 표본 — 모으는 방식이 성립하지 않았다

- LangSmith 루트 메타데이터 집계(v2 `POST /api/v2/runs/query`, `project_ids`·`is_root`·`selects`): 11-14~15 **4건**, `routerMs` 1,136~1,309ms, 전부 `intentFrom=router`, 재시도·규칙 폴백 0. 11-13 Vercel 로그의 1건(1,298ms)까지 5건.
- 라우터 비중은 전체 턴의 11%(중앙값). `saveMs` 중앙값 100ms·최대 182ms.
- dev 는 사용자 한 명이라 하루 2건꼴 — "며칠 모아 p95" 는 불가능. 공개 뒤 표본이 늘면 다시 본다.
- 부수: 4건 중 1건이 `needsSearch=false`·`search=true`·출처 있음 — 라우터 판정을 상위 규칙이 덮은 턴으로 보이나 `searchBy` 를 같이 안 뽑아 미확인.

## 2. 재시도 사유를 나머지 경로로

전: `retryReasons` 는 Gemini SDK 경로만 셌다 — 라우터·LangChain·OpenAI 의 재시도는 `[turn]` 에 `retries: 0`.

| 경로 | 재시도 방식 | 남기는 것 |
|---|---|---|
| 라우터 | 키를 바꿔 최대 2회 → 규칙 분류 | 노드 출력 `routerRetries`(실패 사유, 시도 순) → stream-dispatch 가 `[turn].routerRetries`(횟수)와 `retryReasons`(사유) 로 |
| LangChain | 429·타임아웃·503·스트림 오류 시 다음 키 | generator 의 `noteRetry` 를 `onRetry` 로 넘김 |
| OpenAI | (당시) 재시도 루프 **없음** — §6 에서 추가. PDF 를 못 받으면 Gemini 2.5 로 한 번 | `noteRetry('pdf_fallback')` · 재시도는 `onRetry` |

- 사유 2개 추가(9 → 11종): `stream_error`(LangChain 의 Failed to parse stream·INTERNAL), `pdf_fallback`.
- `routerRetries` 를 따로 둔 이유: `routerMs` 가 "느린 1회"인지 "실패 뒤 재시도"인지 갈라야 제한 시간을 정할 수 있다.
- 라우터 사유: 429 → `rate_limit`, 무효 키·401·403 → `auth`, 타임아웃·끊김 → `timeout`, 그 밖 → `unavailable`. 실패 로그에서 오류 문구(140자)를 빼고 사유만 남겼다. LangChain·OpenAI PDF 전환 로그의 문구도 같이 뺐다.
- 라우터 호출 span 에 `attempt`·`retry_reason` 을 넘긴다(LangSmith 에서 재시도 호출이 보인다).

## 3. 라우터 제한 시간

- 전: 라우터 Gemini 호출에 상한이 없었다 — 멈추면 그만큼 첫 토큰이 늦고, 최악엔 끝없이 매달린다.
- `ROUTER_CALL_TIMEOUT_MS` = **5,000ms**(시도당, `AbortSignal.timeout`). 넘으면 다음 키로 1회, 또 넘으면 규칙 분류 — 최악 약 10초 뒤 생성으로 넘어간다.
- 5초의 근거: 관측 1.1~1.3s(n=5)의 약 4배. 표본이 작아 **잠정값**이다 — 공개 뒤 `routerRetries`·`retryReasons=timeout`·`intentFrom=rule` 비율로 조정. env `ROUTER_CALL_TIMEOUT_MS` 로 덮을 수 있다(하니스가 200ms 로 쓴다).

## 4. 실패 주입 하니스

실제 장애를 기다리지 않는다 — fetch 를 가짜로 바꿔 실패를 순서대로 준다(API 호출·비용 없음). [test-retry-reasons](../../../../tests/test-retry-reasons.mts) 20건.

| 주입 | 확인 |
|---|---|
| 라우터 429 → 성공 | 재시도 성공(`intentFrom=router`), 사유 `rate_limit` |
| 라우터 503 ×2 | 규칙 분류(`intentFrom=rule`), 사유 `unavailable` 2건, 호출 2회 |
| 라우터 멈춤 → 성공 | 제한 시간에 끊고 재시도 성공, 사유 `timeout` |
| 라우터 멈춤 ×2 | 규칙 분류, 상한 2회분 안에 끝남 |
| 라우터 무효 키 | 사유 `auth` |
| LangChain 503·429·타임아웃·`fetch failed`·INTERNAL | 사유 `unavailable`·`rate_limit`·`timeout`·`timeout`·`stream_error`, 재시도 성공 |
| LangChain 400 | 재시도 없이 오류(사유 0건) |
| 공통 | 사유는 열거값만 — 오류 문구(이메일·전화)가 출력에 없음 · 떠돌이 rejection 0건 |

- 만들며 안 것: `AbortSignal.timeout` 의 타이머는 이벤트 루프를 붙잡지 않는다 — 가짜 fetch 가 영영 안 끝나면 Node 가 그냥 종료한다(실제로는 소켓이 붙잡는다). 가짜 쪽에서 붙잡아 준다.
- 옛 SDK(`@google/generative-ai`)는 fetch 오류의 `name` 을 버리고 문구만 감싸 올린다 — LangChain 경로의 타임아웃 판정은 문구(`aborted`·`fetch failed`)에 기대고 있다. 하니스가 실제 문구로 고정.
- `test-turn-log` 50건(+3: `routerRetries` 병합·새 사유), `test-openai-pdf` 32건(+1: PDF 전환이 사유를 남김), `test-tracing` 그대로.
- 전체 48개·tsc·knip·build 통과, eslint 오류 0.

## 6. OpenAI 재시도

- 전: OpenAI 호출은 한 번 실패하면 바로 사용자 오류였다(429·5xx·네트워크 끊김 포함).
- [server/openai/chat.ts](../../../../server/openai/chat.ts) `request` 에 재시도 — 키가 하나라 Gemini 처럼 키를 바꾸지 못하고 **잠깐 기다렸다 같은 요청을 다시** 보낸다. 대기 0.6s → 1.8s, 최대 2회(호출 3회).

| 오류 | 다시 보내나 | 끝내 실패 시 로그 `errCode` | 화면 문구 |
|---|---|---|---|
| 429(할당량 아님) | ✅ `rate_limit` | `rate_limit` | 요청이 많아 지연 — 잠시 후 다시 시도 |
| 500·502·503 | ✅ `unavailable` | `server`(500·502) · `unavailable`(503) | 응답 생성 중 문제 — 다시 시도 / 서버 일시 불안정 — 잠시 후 다시 시도 |
| 네트워크 끊김(fetch 실패) | ✅ `unavailable` | `unavailable`(전엔 `other`) | 서버 일시 불안정 — 잠시 후 다시 시도(전엔 "응답 생성 중 문제") |
| 타임아웃(120s) | ❌ — 두 번이면 함수 상한 300s 에 닿는다 | `timeout` | 서버 일시 불안정 — 잠시 후 다시 시도 |
| 할당량 소진(`insufficient_quota` 등) | ❌ — 다시 보내도 같다 | `openai_quota` | GPT 토큰 할당량 소진 |
| 400·401·403 | ❌ | `bad_request`·`auth` | 응답 생성 중 문제 / 인증 오류 |

- 사유는 generator 의 `noteRetry` 로 `[turn].retryReasons` 에, 재시도 호출 span 에는 `attempt`·`retry_reason`.
- 네트워크 끊김(`code: network_error`)을 화면·로그 모두 "일시적"으로 맞췄다([chat-error-policy.ts](../../../../server/chat-error-policy.ts)·`errCodeOf`).
- 끝내 실패하면: 로그는 코드만(`[turn].errCode`·`Model request failed` 의 표지), 화면은 위 표의 지역화 문구 — 모두 "다시 시도" 안내가 들어 있다.
- 하니스(`test-retry-reasons` OpenAI 9건, 가짜 fetch): 429 뒤 성공 · 503+끊김 뒤 성공 · 5xx/429/끊김이 계속되면 호출 3회 뒤 오류와 그때의 로그 코드·화면 분류 · 할당량·400·401·타임아웃은 호출 1회.
- 주의: 재시도 2회가 다 차면 응답이 최대 2.4s + 호출 시간만큼 늦는다. 도구 호출 턴(initial·followup)은 호출마다 따로 재시도한다.
- 전체 48개·tsc·knip·build 통과, eslint 오류 0.
