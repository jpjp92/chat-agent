## 1. 계기

외부 검토(11-28, 실기기 전주 카드 캡처) 지적을 코드와 대조 — 모두 사실이었다.
- 강수 안내가 `truncate` 로 잘림: `5.5mm · 오늘 예상 곧 …` — 우산 안내가 사라졌다.
- 습도·풍속·구름 3열이 `whitespace-nowrap` 한 줄 + 가운데·오른쪽 정렬이라 좁은 화면에서 가운데 값(`3.6m/s`)이 오른쪽 아이콘과 붙었다.
- 5일 예보 `12° 3°` 최고·최저 사이 간격이 공백 한 칸.

검토에 없던 것: `precip.mm` 의 기간이 상태마다 다르다(`precipOf`).
- `now` = 최근 1시간 관측(KMA `RN1` / OWM `rain.1h`)
- `expected` = 오늘 예보 합계(`daily[0]`) — OWM 은 지금 이후 칸만이라 실제로는 "오늘 남은 시간"

## 3. OWM 카드 최고·최저 = 현재 기온

기상청 API 시간 초과로 OWM 폴백된 서울 카드가 `최고 10° / 최저 10°`, 답 문장은 "4~10°".
- 원인: OWM `current.main.temp_min/max` 는 하루 범위가 아니라 그 시각 관측소 간 편차.
- 수정: `daily[0]`(오늘일 때만) 범위에 현재 기온을 합친다 — KMA 경로와 같은 방식.

## 4. 카드 '오늘' 값은 날짜가 맞을 때만 (`server/lib/weather/index.ts`)

밤엔 `daily[0]` 이 내일이 된다.
- OWM: 예보는 지금 이후 3시간 칸(KST 09·12·…·21·00시) — 21시가 지나면 첫 칸이 내일 0시.
- KMA: 23시 발표 단기예보는 내일 0시부터.

그대로면 비 그친 밤에 내일 비 예보가 "오늘 예상 8mm · 우산 챙기세요"로 나온다. 답 문장은 02e3a2b 에서 같은 이유로 고쳤는데 카드만 남아 있었다.
- 두 경로 모두 `daily[0].date === 오늘` 일 때만 강수량·강수확률·최고·최저에 쓴다. 아니면 `expected` 블록은 숨고(지금 비면 최근 1시간만), 최고·최저는 현재 기온.
- KMA 는 현재 기온을 내일 칸 최고·최저에 합치던 것도 함께 막혔다.

## 10. 이미지 약 식별 — 계획과 첫 수정 (G8·G9)

외부(GPT) 개선안 두 차례를 코드와 대조해 [PLAN_PILL_IDENTIFY_261128](../../../plans/PLAN_PILL_IDENTIFY_261128.md)로 정리했다. 제안한 검색 단계(DB → 약학정보원 → 웹)는 이미 있었고, 남은 빈 곳 중 측정 없이 고칠 수 있는 버그 둘을 먼저 고쳤다. 원칙: 정확도를 올리되 지연을 늘리지 않는다.

- **G9 `exact` 과신**: MFDS 1단계는 앞·뒤 각인 코드를 합쳐 `overlaps`(OR) + 색상 + 모양, 1건이면 exact → 카드였다. 앞 `ABC`/뒤 `123` 사진에 `ABC` 만 가진 약이 카드로 나갈 수 있었다. 받은 행에서 읽은 면의 코드가 **각각** 있는지 서버에서 확인하고(`server/pill-face-match.ts`), 1건일 때만 exact. 아니면 imprint_only(후보 표, 면 일치 행을 앞에). 추가 쿼리 없음. 약학정보원 쪽 `filterResults` 는 원래 면별 대조였다.
  - 부작용: DB 에 한쪽 각인만 등록된 약은 양면을 찍으면 카드 대신 후보 표가 된다 — 의도(일치도 불명은 카드 X). P0 에서 빈도 확인.
- **G8 웹 폴백 조기 종료**: MFDS·약학정보원 모두 0건이면 도구의 문구를 보고 웹 게이트 **전에** 실패 답으로 끝났다. 각인을 읽었으면 `match_type: none` 으로 웹 폴백까지 가고, 웹도 비면 기존 실패 답. 각인이 없으면 전처럼 즉시 종료(불필요한 검색 없음).
- 검증: `test-pill-face-match` 7/0, `test-pill-messages` 26/0, `npm run verify` 56/0. 실사진 미확인.

## 11. 실사진 사례 1 — 웹 폴백 끝까지 (위더스세픽스캡슐)

주황 경질캡슐(캡 위더스 로고 · 몸통 `CFX`). 로컬 `mfds_pills` 에 품목 자체가 없어 웹 폴백만이 찾을 수 있는 약이었다. 테스트마다 막힌 자리가 하나씩 드러났다.

| 순서 | 증상 | 원인 | 조치 |
|---|---|---|---|
| 1 | 웹 결과 0건 | 검색어가 양면을 `"WU / CFX"` 한 구절로 묶음 | 긴 각인 하나만 묶기 |
| 2 | 여전히 0건 | DDG 가 Node fetch 를 봇 확인(202 anomaly)으로 전부 차단(curl 은 통과) | 사용자 모델 검색(GPT web_search·5개 낱알식별 도메인 / Gemini grounding)으로 교체, DDG 는 2차. 차단은 0건과 구분해 로그 |
| 3 | 웹이 찾았는데 답은 "웹에서도 확정 못 함" | 웹 규칙 **뒤에** 붙는 공통 규칙 "DB 결과만 유일한 출처" 가 덮어씀 | 웹 폴백 시 그 줄 교체 → 그래도 누락 → **서버가 표로 직접 답**(생성 모델 생략) |

| - | `((주)한독)` 괄호 겹침 | 제조사 법인 표기 | 후보 제조사에서 `(주)` 등 제거 |

## 12. 근본 원인 — 약학정보원 각인 검색 복구(P0)와 로고 비교(P1 일부)

사례 1 이 테스트마다 다른 이유로 막힌 근본 원인: 각인으로 찾는 결정론 경로가 끊겨 LLM 웹 검색(8~10s, 회차마다 결과 다름)에 정확도가 걸려 있었다.

- **약학정보원 "시작" 검색**: `s_anal_flag=2`(시작)라 `HLB CFX`·`마크 CFX` 류가 전부 빠졌다(CFX 5건). "포함"(0)이면 26건/3페이지, 위더스 포함. 마지막 페이지를 읽어 병렬로. "포함"이 느린 질의(TYLENOL 12~13s)는 4s 에서 끊고 "시작"(~0.7s)을 같이 돌려 합친다.
- **호출 조건**: MFDS 가 색상·모양(similar)만 내도 각인을 읽었으면 약학정보원 먼저(전엔 MFDS 0건일 때만 → 사실상 안 돌았다).
- **각인 토큰**: 비전이 한 면에 `UU CFX` 를 붙여 내 검색 키가 `UUCFX` → 공백 토큰 중 가장 긴 것으로. 앱 로그(`.next/dev/logs/next-development.log`)로 확인.
- 정렬: 제형 > 면 각인 정확 일치 > 색상. 약학정보원 exact 는 1건일 때만.
- 결과: 앱 재테스트에서 후보 5개 중 **정답 위더스세픽심캡슐 2위**(`pharm.or.kr idx=11456`, 사용자 확인), 웹 미도달.
- 표시: 약학정보원 결과를 "식약처 DB 에서 검색" 으로 적던 문구 → 링크로 출처 판단. 각인 칸 `CFX /` 제거.
- **로고·사진(G13)**: 약학정보원 목록 행에 제조사 로고 gif·알약 썸네일이 이미 있는데 버리고 있었다 → 각인 `마크 CFX` + 후보 표에 로고·사진(채팅 이미지 작게 고정). **로고 판독(G12)**: 비전이 엠블럼을 글자로 추측하지 말고 `마크`.
- Gemini 웹 폴백: 유료 키에서도 3.8 Flash grounding 9s+(3.5 FL 2s), "여러 사이트에서" 문구 제거, grounding 리디렉트 주소는 Location 으로 풀어 도메인 확인.
- verify 가 메모리를 많이 먹어 세션이 끊겼다(exit 137) — 평소엔 tsc + 관련 하니스만.
