## 1. Anatomy 통합 기획 검토 → physics diagram 고도화로 방향 전환

외부 기획 `reference/chat_agent_anatomy_integration_plan.md`(인터랙티브 구조도·도면 해설) 검토.

- 맞는 점: `json:<type>` + `lazy()` 렌더러 패턴, "신뢰된 템플릿 + 제한된 JSON" 보안 원칙, `observed | inferred | unknown` 구분.
- 문제: 1·2차 템플릿이 모터·NFC 카드 2개뿐이라 걸리는 질문이 적다(공수 11~20 MD 대비). Drawing Inspector 는 비전 bounding box 정확도가 미측정. 새 의도·경계 세트가 필요하고 `physics`·`DiagramRenderer` 와 역할이 겹친다.
- 결론: 현행 `json:diagram` 이 이미 같은 구조(LLM 은 파라미터, 그림은 코드)라 **새 의도 없이 diagram 을 SVG·인터랙티브로 고도화**하는 쪽이 낫다. 교과서 물리 장치는 파라미터형이라 템플릿 하나가 많은 질문을 받는다.

## 2. 현행 canvas vs SVG 비교 — `tests/manual/compare-diagram-svg.mts`

같은 JSON(프롬프트 예시 4 + 경계값 2)을 두 렌더러에 넣어 SSR 요소 수를 세고 비교 페이지를 만든다.

| | canvas | SVG 시제품 |
|---|---|---|
| HTML 안 라벨·화살표·조작 요소 | 전 샘플 0·0·0 | 경사면 5·5·5 등 |

비교하다 찾은 **운영 canvas 버그**(`components/DiagramRenderer.tsx`, 미수정):

1. 경사면 힘을 라벨 키워드(`중력`·`mg`·`normal`…)로만 그린다 — 스페인어 `Peso`·`Rozamiento` 는 사라진다.
2. 포물선 높이를 280px 로 잘라 75° 에서 H/R 이 0.93 → 0.44 로 그려진다.
3. 다크 모드에서 쐐기 색이 `#e2e8f0` 고정.
4. 🔴 **평행 분력 `(cos, sin)`·마찰 `(−cos, −sin)` 방향이 경사면을 따르지 않는다**(내적 ±0.5, ±1 이어야 함). 지금 사용자에게 틀린 그림이 나간다.

## 3. 외부 시안 검토 — AI 시안 5개 중 4개가 경사면 벡터 방향을 틀렸다

| 시안 | 틀린 벡터 | 경사면 방향과 내적(30°) |
|---|---|---|
| 우리 SVG 시제품(1차) | 평행 분력·마찰 — canvas 에서 옮겨옴 | 0.5 / −0.5 |
| Codex `physics_svg_reference.html` | 법선 `(sin, −cos)`·`mg cosθ` | 0.866 |
| `physics_lab_v2.html` | 같은 법선 오류, 상자 오프셋, 충돌 애니메이션 B 순간이동, `u2=0` 고정, reduced-motion 없음 | 0.866 |
| GPT 웹 샘플 | 법선이 오른쪽 위 | — |
| Claude 웹 샘플(θ=37°, 5.5kg) | 없음 — 좌표를 삼각함수로 계산 | 수치 4개 일치 |

Codex 피드백 중 "법선은 오른쪽 위여야" 는 틀렸다(오른쪽이 높은 경사면의 바깥 법선은 왼쪽 위). 채택: 물리 파라미터 중심 스키마, 실제 힘과 분해 성분 구분, 같은 축척 포물선·시간 슬라이더, 수치 패널·판정 문장.

결론: **방향을 LLM 이 정하게 두면 안 된다.** LLM 은 `angleDeg`·`massKg`·`mu` 만 넘기고 방향·길이는 렌더러가 계산, 하니스로 고정.

## 운영 canvas 방향 수정 (`components/DiagramRenderer.tsx`)

빗면은 오른쪽이 높다(화면 좌표 빗면 위 방향 = (cos, −sin)). 두 화살표가 빗면을 가로질렀다.

| 힘 | 이전 | 수정 |
|---|---|---|
| 빗면 평행 분력 mg sinθ | (+cos, +sin) 오른쪽 아래 | (−cos, +sin) 빗면 아래 |
| 마찰 | (−cos, −sin) 왼쪽 위 | (+cos, −sin) 빗면 위 |

라벨도 화살표 끝 바깥쪽으로 옮김. 수직항력·수직 분력은 원래 맞음. 마찰은 미끄러져 내려가려는 경우 기준이고, 위로 미는 문제는 SVG 이식 때 `physics-model` 판정으로 처리. `npm run verify` 38/0 — canvas 픽셀은 하니스가 보지 않으므로 배포 후 눈으로 확인.
