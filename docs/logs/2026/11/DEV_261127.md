# DEV_261127 — 날씨 카드 뒤 답 말투·지연 다듬기

앞: [DEV_261125 §11~13](DEV_261125.md) · 계획: [PLAN_WEATHER_COMPOSITE_261125](../../../plans/PLAN_WEATHER_COMPOSITE_261125.md)

## 1. 문제

카드 뒤 판단 답(역할 모델 3.5 FL, `weather-answer.ts`)에 남은 두 가지(DEV_261125 §11-10):
- "나와 있지 않아 / 가지고 있지 않아" 같은 시스템 말투 3/32
- 지연 중앙값 3.2s(처음 1.7s) — 규칙을 덧붙이며 프롬프트가 길어진 탓으로 봤다

## 2. 지연 — 프롬프트 탓이 아니었다

커밋된 프롬프트(3,000자)와 줄인 프롬프트(1,994자)를 같은 시간대에 번갈아 32회씩(유료 키):

| | 일치 | 지연 중앙값 / p90 |
|---|---|---|
| 기존 3,000자 | 32/32 | 822 / 1,024ms |
| 줄임 1,994자 | 32/32 | 817 / 1,021ms |

- 둘 다 ~0.8s. DEV_261125 의 3.2s 는 그때 네트워크·시간대 편차였다. 길이를 줄여도 지연은 그대로, 정확도도 그대로 → 짧은 쪽을 쓴다(규칙은 같다).

## 3. 말투 — 프롬프트로는 막히지 않았다

| 시도 | 결과 |
|---|---|
| 금지 문구를 따옴표로 나열("나와 있지 않", "알 수 없"…) | 3/32 — **나열한 표현이 그대로 나왔다**(떠올리게 한다) |
| 금지 목록 대신 바른 예시 2개 | 서울 32문항 0건, 그러나 예시를 베꼈다 — 비 오는 14°C 부산 카드에 "쌀쌀해요", 예시와 다른 질문엔 "제공된 일별 예보에는 … 나와 있지 않아요" 다시 |
| **JSON `{none, answer, lookup}` + 역질문은 서버가** | answer 칸을 "알 수 없어요"·"제공되지 않아요"로 채움 6/38 |
| + "없다" 문장 서버 필터 | 0/38. 대신 묻지 않은 역질문(빨래 → "비 그치는 시간도"), 오늘 범위 반복, 출처 문구 증가 |
| + `lookup` 은 사용자가 직접 물은 것만 · 현재 기온·오늘 범위 반복 금지 · 출처는 보통 생략 | 금지 0 · 출처 0 · 묻지 않은 역질문 0. 예시 이름 베낌("저녁 몇 시에 비 와?" → "비 **그치는** 시간도") |
| + 예시 이름 중립화 | **우산 질문이 2/2 none** — JSON 으로 옮기며 "날씨 요청 + 판단 질문이면 답한다" 문장이 빠졌다. 부산 "내일 **오전부터** 맑아져요"(일 단위 데이터에 없는 시각) |
| **+ 그 문장 복원 · 하루 안의 시각 금지(최종)** | **32/32 · 금지 말투 0 · 시각 지어내기 0 · 출처 0 · 묻지 않은 역질문 0 · 지연 중앙값 0.91s** |

최종 구조(`weather-answer-prompt.ts`):
- 모델은 JSON 스키마 `{none, answer, lookup}` 로만 답한다. `lookup` 은 사용자가 물은 카드 밖 정보의 이름("미세먼지", "시간대별 강수", "자외선 지수").
- `composeWeatherAnswer`: "…도 찾아볼까요?"(4개 언어)는 서버가 붙인다. answer 에서 "없다" 를 말하는 문장은 뺀다(4개 언어 정규식) — 남는 게 없으면 역질문만.
- 이건 의도 판정이 아니라 출력 다듬기다(카드 뒤 답 문장 한정).

예(최종): "오늘은 비 소식이 없어 우산은 안 챙기셔도 됩니다." · "목요일이 비 소식이 없고 맑아 세차하기 가장 좋습니다." · (비 오는 부산, "몇 시에 비 그쳐?") "부산은 오늘 하루 종일 비가 이어질 예정이에요. 시간대별 강수도 찾아볼까요?" · ("자외선도 강해?") "자외선 지수도 찾아볼까요?"

## 4. 검증

- 하니스 `test-weather-answer.mts` 45항목 — JSON 계약·compose(none·서버 역질문·"없다" 문장 필터·깨진 JSON)·묻지 않은 lookup 금지·하루 안 시각 금지·날씨 요청 + 판단 질문은 답함.
- verify(하니스 55) · knip · typecheck · build 각각 통과.
- 실측 비용: 3.5 FL 약 300콜(A/B 64 + 반복 측정 38 × 6) — 약 $0.05.

## 5. 해요체 통일

- 프롬프트에 한국어만 "해요체(~요), ~습니다 금지" 를 넣었다 → 32/32 · p50 0.91s, 그래도 22건 중 2건이 "좋겠습니다"·"60퍼센트입니다".
- 서버가 흔한 어미만 바꾼다(`toHaeyo`): 겠습니다·있습니다·없습니다·됩니다, "입니다" 는 앞 글자 받침으로 이에요/예요, `%입니다` → `%예요`. 숫자 바로 뒤 "입니다" 는 단위마다 소리가 달라 그대로 둔다 — 불규칙 동사까지 규칙으로 덮으면 틀린 말이 생긴다.
- 같은 측정에서 "제공하지 않아서 확인이 어려워요" 가 "없다" 필터를 빠져나가 패턴 2개 추가.
- 하니스 50항목(+4) · verify 55 · knip · build 통과. 측정 3.5 FL 32콜 ≈ $0.005.

## 6. 한 말풍선 안 말투·수치 일관

실화면(GPT, 모바일): 템플릿 한 줄 "15°입니다 … 30%입니다" 아래에 답 "…30퍼센트라 … 돼요" — 말투가 섞이고, 한 줄에 있는 강수확률을 답이 다시 말하며 표기도 달랐다.

- 템플릿(`weather-summary.ts`) 한국어를 해요체로: "15°예요", "30%예요".
- 프롬프트: 오늘 강수확률도 반복 금지(숫자 대신 "낮다/높다"), 그 밖 숫자는 기호로(60%, 16°).
- 재측정 32/32 · p50 0.84s · ~습니다 0 · "퍼센트" 0. 오늘 강수확률 숫자 반복은 22건 중 3건 남음(근거로 붙임).

## 7. 모바일 카드 높이

- 375px 다크(실화면)·라이트(미리보기) 확인 — 다섯 칸 잘림 없음.

## 8. 카드 날짜·시각·강수확률 표기

- '오늘' 기준: `localYmd` 가 브라우저 현재 시각을 써서, 지난 대화의 카드를 다음 날 열면 첫날이 요일로 보였다 → 카드를 만든 시각(`updatedAt`) 기준.
- 머리 시각: `updatedAt`(카드 생성)이 관측처럼 보였다 → "기상청 · 관측 15:00"(`current.observedAt`, 없으면 `updatedAt`).
- 예보 % 가 습도·구름으로 읽힐 수 있어 제목 줄 오른쪽에 "강수확률 %"(en Rain chance % · es Prob. lluvia % · fr Prob. pluie %).
- 확인: 11-26 15:28 카드를 11-27 에 서버 렌더 → 첫날 '오늘' 1칸 · "관측 15:00" · "강수확률 %". 개발 서버가 내려가 있어 화면 캡처는 못 함.

## 9. 카드 뒤 "미세먼지는?" 이 검색으로 안 나감

실화면(GPT): 카드 뒤 "미세먼지는?" → "미세먼지 수치가 포함되어 있지 않아 확인할 수 없어요. 실시간 검색 없이 답변드렸어요."

- 재현(라우터, 3.5 FL): LLM 은 `needs_search=true` 인데 `follow_up` 을 "refine" 으로 내 6/6 카드 답(검색 꺼짐). 자외선은 lookup 2/2. 미세먼지·황사가 날씨처럼 들려 "카드 해석" 으로 읽혔다.
- 키워드 규칙 대신 정의를 고쳤다(`nodes/router.ts`): refine = 카드 값으로 답할 수 있는 것(카드에 있는 값을 나열), lookup = 대기질(미세먼지·황사·오존)·자외선·꽃가루·시간대 — "날씨처럼 들려도 refine 아님".
- 처음엔 refine 에 카드 값 목록이 없어 "습도는 어때?" 까지 검색으로 갔다(2/2) → 목록 추가.
- 결과 12문항×2: 미세먼지·초미세·황사·자외선·시간대 비 → 검색 10/10, 습도·바람·체감·내일·우산·가장 더운 날 → 카드 12/12. 측정 약 70콜 ≈ $0.015.

## 10. 밤 OpenWeather 폴백 — 내일 값을 "오늘" 로

실화면(GPT, 22:41 전주): 카드 출처 OpenWeather, 예보 첫 칸 '토'(오늘 칸 없음), 한 줄 "오늘 기온은 4~9°" 는 내일 값, 카드 머리 최고·최저 10°/10° 와 안 맞음.

- 로그: KMA 네 호출 모두 4~5초 — 중기 2개 4초 시간 초과, 실황 4.3초 성공, 단기 5.0초 시간 초과 → OpenWeather 폴백.
- 직접 측정(22:46~22:50, 상한 30초): 차례 호출도 0.2초·12~13초·30초 넘김이 섞이고, 동시 4개는 단기·실황이 2/2 30초 넘김. 동시 호출 탓이 아니라 기상청 API Hub 지연 → 5초 차단·폴백은 의도대로(늘리면 12~30초 대기).
- 고친 것: 첫 칸이 카드 생성일(도시 현지) 오늘이 아니면 한 줄에서 "오늘 기온·강수확률" 을 뺀다(`weather-summary.ts`). 카드 뒤 답 데이터도 첫 칸을 오늘로 가정하지 않고 날짜로 고른다(`compactCard`).
- 보류: 최근 성공한 KMA 결과 짧은 보관(인스턴스가 바뀌면 사라져 효과 제한).

## 11. 미세먼지·자외선 답의 근거와 출처

실화면: "에어코리아의 오늘 전주 미세먼지 예보는 보통입니다." — 근거 없음. 프롬프트가 "수치·발표 시각은 묻지 않으면 빼라" 였다. 출처 칩 "에어코리아 :".

- 1차(근거 넣기): 등급 + 괄호 근거(수치·기준 시각), 측정/예보 구분, 해요체. GPT·Gemini 4문항 → 근거는 붙었지만 Gemini 가 서울 "초미세먼지 매우 나쁨 95㎍/㎥, 주의보" 를 **뉴스 기사**(한경·이데일리)에서 옮김 — 같은 시각 GPT 는 서울시 대기정보로 "보통".
- 2차(오늘 값만, 뉴스 금지): 뉴스는 빠졌지만 서울이 07시 측정 "좋음"·17시 예보 "나쁨"·18시 측정 "나쁨" 으로 갈리고, 제3자(오늘달력·AccuWeather) 출처가 남음.
- 3차(출처 고정): GPT 검색을 `allowed_domains: ['airkorea.or.kr', 'go.kr']` 로 제한(`generateOpenAIChat` 에 `webSearchDomains` 추가), 프롬프트에 에어코리아 예보 페이지(https://www.airkorea.or.kr/web/dustForecast)·기상청을 기본 출처로, 측정값은 3시간 이내만(카드 도시 현지 시각을 프롬프트에). 2회 × 8 → 출처 전부 에어코리아·기상청, 서울 나쁨 3/4. 수치 대신 "오늘 예보 기준" 이 많다 — 예보에는 수치가 없다.
- 출처 칩: 제목 끝 ":" 를 떼고 비면 도메인(`chipTitle`).
- 측정 약 40콜(GPT·Gemini 유료 키) ≈ $0.5.

## 12. Google 로그인 버튼 문구가 늦게 뜸

## 13. 데스크톱이 확대된 느낌 (그램 노트북, 브라우저 100%)

- 캡처 2551px 폭에서 제목(48px)이 약 90px, 사이드바(272px)가 약 480px → Windows 배율 약 175%, 브라우저 폭 약 1,450px. 배율은 정상이고 우리 기본 크기가 비슷한 서비스보다 큰 편이었다(제목 48px, 대화·입력 폭 896px).
- 데스크톱만 줄였다(모바일 그대로): 첫 화면 제목 `sm:text-5xl` → `sm:text-4xl`(36px), 대화·입력·하단 폭 `max-w-4xl` → `max-w-3xl`(768px, App.tsx 3곳 + ChatInput). 사이드바 기본 272px·추천 칩 14px·본문 16px 는 이미 보통 크기라 유지.
- 1450×850 캡처로 배치 확인(headless 라 한글 글꼴 없음).
