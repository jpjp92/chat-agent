## 1. Supabase 신규 프로젝트 이전

### 배경

기존 Supabase 프로젝트(구 계정)를 신규 계정의 프로젝트로 전면 이전. DB 테이블 3개 + Storage 버킷 3개 마이그레이션.

### DB 마이그레이션

**신규 프로젝트 테이블 DDL 생성 순서** (FK 의존 순서 준수):
1. `users` — `GENERATED BY DEFAULT AS IDENTITY` (원본 id 유지 목적으로 최종 변경)
2. `chat_sessions` — uuid PK, `user_id` FK
3. `chat_messages` — bigint PK, `session_id` FK

**초기 이전 시 발견된 문제**:
- `GENERATED ALWAYS AS IDENTITY` 컬럼에 명시적 id 삽입 불가
- users 재삽입 시 새 id가 부여되어 기존 로그인 기기의 localStorage `chat_user` 캐시와 불일치 → FK 오류
- 해결: `ALTER TABLE public.users ALTER COLUMN id SET GENERATED BY DEFAULT;` → `TRUNCATE public.users CASCADE;` → id 포함 재마이그레이션
- 마이그레이션 완료 후 시퀀스 리셋: `SELECT setval(pg_get_serial_sequence('public.users', 'id'), 1054);`

## 3. ** 볼드 렌더링 수정 (`components/ChatMessage.tsx`)

### 문제

모델 응답에서 `**"text"**의` 패턴처럼 closing `**` 바로 앞에 따옴표(`"`, `'`, `"`, `"`, `'`, `'`)가 오고 뒤에 한국어가 이어지는 경우 `**`가 렌더링되지 않고 raw 텍스트로 출력.

### 원인

CommonMark flanking 규칙상 closing `**`가 punctuation(따옴표) 뒤에 위치할 때 right-flanking 판정이 rule (b)를 따르는데, remark-gfm이 이 케이스를 정확히 처리하지 못하는 경우 발생.

기존 fix(closing `**` + 한국어 → 뒤에 공백 삽입)는 한국어 직접 인접 케이스는 처리했으나 `따옴표 + ** + 한국어` 조합은 불완전.

### 수정

`ChatMessage.tsx` 3곳(textPart, processedVisible, processedRemaining)에 ZWNJ(U+200C) 전처리 추가:

```ts
// 신규: 따옴표 뒤 ** + 한국어 → ZWNJ 삽입 (rule (a)로 right-flanking 강제)
textPart = textPart.replace(/(["""'''])\*\*(?=[가-힣A-Za-zÀ-ÿ])/g, '$1‌** ');
// 기존: ** + 한국어 → 뒤에 공백 (유지)
textPart = textPart.replace(/\*\*([^*\n]+?)\*\*(?=[가-힣A-Za-zÀ-ÿ])/g, '**$1** ');
```

**ZWNJ(U+200C)**: Unicode Cf 카테고리 — CommonMark 기준 whitespace도 punctuation도 아님 → closing `**`가 rule (a)로 right-flanking 처리되어 더 안정적으로 닫힘. 렌더 결과에서는 보이지 않음.

## 4. 사이드바 세션 로딩 성능 분석

### 현황

`api/sessions.ts`의 세션 목록 조회 쿼리에 `limit` 없음:

```ts
supabase.from('chat_sessions').select('*').eq('user_id', user_id).order('updated_at', { ascending: false })
// ← limit 없음 → 현재 1,267건 전체 반환
```

`user_id` 필터는 정상 적용되어 있음 (다른 유저 세션이 섞이는 문제는 아님).

### 원인별 분류

| 원인 | 발생 시점 | 심각도 |
|---|---|---|
| 세션 1,267건 전체 조회 | 앱 로드마다 | 🔴 High |
| localStorage 캐시 30개 → API 응답 1,267개 re-render | API 응답 후 리스트 확장 | 🟡 Medium |
| `isLoadingSessions` 초기값 `true` | 첫 로드 (캐시 없을 때) shimmer | 🟡 Medium |
| 세션 클릭 시 메시지 fetch + blur overlay | 첫 선택 시 | 🟢 Low |

### 개선 구현 — Infinite Scroll + 30개 단위 페이지네이션

#### 에러 1: `.vc-config.json already exists`

```

```

**원인**: 구 Vercel Function(`api/chat.ts`)과 신규 Route Handler(`app/api/chat/route.ts`)가 같은 `/api/chat` 경로를 동시에 타겟팅 → Vercel 빌드 출력 디렉터리 충돌.

**수정**: 구 Vercel Function 파일 12개 전체 삭제 (`api/_lib/` 제외):

```
api/auth.ts           api/chat.ts            api/create-signed-url.ts
api/fetch-transcript.ts  api/fetch-url.ts    api/pill-search.ts
api/proxy-image.ts    api/sessions.ts        api/speech.ts
api/summarize-title.ts   api/sync-drug-image.ts  api/upload.ts
```

`npm run build` 재확인 후 커밋 → 푸시.

---

#### 에러 2: `api/*.ts` functions 패턴 불일치

```
Error: The pattern "api/*.ts" defined in `functions` doesn't match any Serverless Functions.
```

**원인**: `vercel.json`에 `functions: { "api/*.ts": { maxDuration: 60 } }` 설정이 남아 있는데 해당 파일들을 모두 삭제한 상태 → Vercel이 매칭 대상을 찾지 못함.

**수정**: `vercel.json`에서 `functions` 블록 전체 제거.

```diff
-  "functions": {
-    "api/*.ts": {
-      "maxDuration": 60
-    }
-  },
```

`maxDuration: 60`은 각 Route Handler 파일에서 `export const maxDuration = 60`으로 이미 설정되어 있으므로 해당 블록 불필요.

커밋: `fix: vercel.json에서 삭제된 api/*.ts functions 참조 제거` → 푸시 완료.

### 9-2. URL 버그 수정 — 코드 내 URL 처리

#### 현상

CI YAML 등 URL이 포함된 코드를 텍스트로 붙여넣어 분석 요청 시 두 가지 에러 발생:

1. `/api/fetch-url 400` — 코드 내 `https://x-access-token:${{` 형태의 invalid URL을 fetch 시도
2. `TypeError: Failed to construct 'URL': Invalid URL` — `ChatMessage.tsx`에서 `new URL(source.uri)` 호출 시 React 크래시

#### 원인

- `useChatStream.ts`의 URL 추출 정규식 `/(https?:\/\/[^\s\)]+)/g`이 코드 블럭 여부를 구분하지 않고 전체 입력에서 URL 추출
- 추출된 invalid URL이 `manualGroundingSources`에 저장됨
- `ChatMessage.tsx`에서 `new URL(source.uri).hostname` 호출 시 예외 처리 없이 크래시

#### 수정 — `src/hooks/useChatStream.ts`

**① 코드 블럭 사전 제거**:

```ts
const contentWithoutCode = content
  .replace(/```[\s\S]*?```/g, '')
  .replace(/~~~[\s\S]*?~~~/g, '')
  .replace(/^( {4}|\t).*/gm, '');
const urls = contentWithoutCode.match(urlRegex);
```

**② `manualGroundingSources` invalid URL 필터링**:

```ts
const manualGroundingSources = (urls || [])
  .map(url => url.replace(/[.\)\]\!,?]+$/, ''))
  .filter(cleanUrl => { try { new URL(cleanUrl); return true; } catch { return false; } })
  .map(cleanUrl => { ... });
```

**③ `isValidUrl` 플래그로 fetch 스킵**:

```ts
let isValidUrl = false;
try {
  new URL(rawUrl);
  isValidUrl = true;
} catch { }

// ...
} else if (!isValidUrl) {
  // URL 파싱 실패 — fetch 시도하지 않음
} else {
  // /api/fetch-url 호출
}
```

#### 수정 — `components/ChatMessage.tsx`

그라운딩 소스 chip 렌더 전 invalid URI 필터:

```tsx
{hasGrounding && message.groundingSources!
  .filter(source => { try { new URL(source.uri); return true; } catch { return false; } })
  .map((source, idx) => (
    <a ...>
      <img src={`https://www.google.com/s2/favicons?domain=${new URL(source.uri).hostname}&sz=32`} />
    </a>
  ))}
```

> `dev` 브랜치에서 수정 후 `main`에 cherry-pick(`f770c0d` → `81bb3bd`).
