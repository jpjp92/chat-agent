# DEV_260731 — 날씨 멀티턴 카드 반복 회귀 수정 (카드 1회 → 이후는 대화)

> 작성: 2026-07-31
> 증상 신고: "3.5에서는 날씨 물어보고 그다음 멀티턴이 자연스러운데, 3.6에서는 계속 날씨 카드만 알려준다."
> 신규 스크립트: `scripts/test-weather-multiturn.ts` (실그래프 · 카드 렌더 턴 관측).

## 요약 (TL;DR)

- **모델 문제가 아니다.** 날씨 인텐트는 `FAST_PASS_INTENTS`라 항상 **2.5-flash 고정**([langchain-path.ts:80-83](../../../../server/agent/nodes/langchain-path.ts#L80-L83))이고, 인텐트 분류기도 `ROUTER_MODEL=flash-lite` 고정이다. 3.5/3.6 은 **카드 재생성 여부를 결정하는 코드 경로를 공유**한다.
- 진짜 원인은 라우터의 **날씨 후속 판정 3종 결함**: ① 카드 맥락이 **직전 1턴만** 유지 ② `newFetch` 정규식 오탐("**이런** 날씨", 시점 토큰 단독) ③ 영화에 있는 **후속 억제 지시가 날씨엔 부재**(+ base 프롬프트 `[WEATHER FORMATTING]`이 후속 턴에도 5일 표를 강제).
- 3곳(router · state · generator) 수정 후 **3.6/3.5/2.5 × 8턴 = 24/24 통과**, 오승격(`Weather intent rescue`) **0건**.

## 1. 증상과 첫 가설의 기각

신고는 "3.6만 그렇다"였으나, 코드 경로를 따라가면 모델 의존 지점이 없다.

| 단계 | 사용 모델 | 모델 선택 영향 |
|---|---|---|
| 인텐트 분류 (`routerNode`) | `flash-lite` 고정 | ❌ 없음 |
| 날씨 카드 생성 (LangChain fast-pass) | **2.5-flash 고정**(tool intent) | ❌ 없음 |
| 후속 답변 (SDK path, general) | 사용자 선택 모델 | ⭕ 문장 스타일만 |

또 SDK 경로에 바인딩된 툴은 `googleSearch` 하나뿐이므로, **general 로 가면 카드가 새로 생길 수 없다**. 즉 **카드가 다시 떴다 = 인텐트가 다시 weather 로 갔다**는 뜻이고, 그 판정은 모델과 무관하다.

초기 재현(후속 6종 × 3.5/3.6)에서도 카드 재생성률은 두 모델 동일했다. 다만 **5일 마크다운 표 재출력은 3.5가 3/6, 3.6이 1/6** 로 오히려 3.5가 잦아, "3.6만 카드가 나온다"는 체감은 표/카드 구분이 섞인 것으로 보인다.

## 2. 재현 하니스 — 카드가 실제로 뜨는 턴을 관측

기존 `scripts/lib/graph-harness.ts` 는 `on_tool_end` 의 `json:weather` 블록을 합성하지 않아(그건 [route.ts:263-269](../../../../app/api/chat/route.ts#L263-L269) 담당) **카드가 떠도 텍스트가 비어 보인다**. 그래서 route.ts 와 동일하게 툴 블록을 assistant 텍스트에 합성하는 전용 러너를 새 스크립트에 넣었다.

```
npx tsx --import ./scripts/_loader-server-only-shim.mjs scripts/test-weather-multiturn.ts
# 옵션: WM_MODELS=3.6,3.5,2.5   WM_TIMEOUT=90   WM_VERBOSE=1
```

시나리오(8턴, 턴마다 `card: true|false` 기대값):

1. 오늘 서울 날씨 알려줘 → **카드 1회**
2. 5일 중 가장 더운 요일이 언제야? → 카드 없이 **카드 데이터로 답**
3. 그날은 밖에 나가도 괜찮을까? / 4. 습도는 높은 편이야? → 해석·조언
5. 이런 날씨엔 뭐 먹으면 좋아? → 잡담 전환
6. 고마워! 그럼 주말 나들이 계획 좀 짜줘 → **시점 토큰 오탐 방지**(+검색은 살아 있어야 함)
7. 부산 날씨도 알려줘 → **새 도시는 카드 재생성이 정상**
8. 서울이랑 비교하면 어디가 더 시원해? → 두 카드 비교

## 3. 근본 원인 3종

### 3-1. 카드 맥락이 직전 1턴만 유지 (핵심)

```ts
// before
const weatherCardShown = /```json\s*:\s*weather/.test(String(lastAssistantMsg?.content ?? ''));
```

t2에서 "가장 더운 요일?"에 **산문으로** 답하는 순간 직전 assistant 메시지에 카드가 없어진다 → t3부터 `weatherCardShown=false` → 후속 가드가 통째로 비활성 → 날씨 어휘만 스치면 `Weather intent rescue (general→weather)` 가 승격 → **카드 재생성**. 대화가 길어질수록 "계속 카드"가 되는 구조.

수정 전 실측 로그(3턴 창 시험 버전)에서 5번 턴이 정확히 이 경로로 `intent=weather` 승격됐다. 그때 카드가 안 뜬 건 **LLM이 우연히 weatherTool 을 호출하지 않아서**였다 — 동전 던지기.

### 3-2. `newFetch` 정규식 오탐

- `/[가-힣A-Za-z]{1,12}\s*날씨/` → "**이런** 날씨엔 뭐 먹을까?"의 "이런 날씨"까지 **새 도시 조회**로 인식.
- 시점 토큰(`주말|내일|…`) **단독** → "**주말** 나들이 계획 짜줘"까지 새 조회로 승격.

### 3-3. 후속 억제 지시 부재 + `[WEATHER FORMATTING]` 상시 주입

영화는 `movieFollowup` 을 state 로 넘겨 generator 가 "**json:movie 재생성 금지**"를 주입([generator.ts:77-78](../../../../server/agent/nodes/generator.ts#L77-L78))하는데, 날씨는 `weatherFollowup` 이 **라우터 지역 변수로만 존재**해 `needsSearch=false` 에만 쓰이고 버려졌다. 게다가 base 프롬프트의 `[WEATHER FORMATTING]`("날씨 정보를 낼 땐 **ALWAYS** 5일 표 구조", [prompt.ts:115](../../../../server/agent/prompt.ts#L115))이 general 턴에도 살아 있어 후속 답변이 표를 통째로 다시 그렸다.

## 6. 교훈

- **"모델 바꾸니 이상해졌다"는 신고에서 먼저 확인할 것**: 그 경로가 실제로 모델에 의존하는가. 날씨는 툴 인텐트라 2.5 고정이었고, 원인은 모델 승격과 무관한 **기존 라우터 결함**이었다(3.6 승격 커밋 `d439e3d` 은 무고).
- **카드형 UI의 후속 판정은 "직전 1턴"으로 잡으면 안 된다.** 산문 답변 한 번이 맥락을 지운다. 영화(`movieContext`)는 클라이언트가 매 턴 컨텍스트를 보내줘서 이 함정을 피했지만, 날씨는 히스토리 스캔이 유일한 신호였다.
- **후속 억제는 라우팅만으로 부족하다.** 라우팅이 general 로 보내도 base 프롬프트가 "ALWAYS 표"를 지시하면 표가 다시 나온다 — 라우팅(카드) + 프롬프트(표) **두 층 모두** 꺼야 한다.
- 관련 메모리: [[chat-agent-vercel-60s-cap]] (툴 인텐트를 2.5로 고정해 둔 배경), [[35-flash-free-tier-throughput]].

## 7. 【추가 발견】 역할 표기 불일치 — 프로덕션에서 후속 가드가 통째로 죽어 있었다

§1-6 수정 후에도 **하니스는 통과하는데 프로덕션 신고는 설명이 안 되는** 간극이 남아 파고든 결과, 상위 원인을 찾았다.

## 8. 413 Payload Too Large — 일시적 오류가 아니다

모바일에서 간헐 관측된 `Server error: 413`. 413은 **플랫폼이 본문 크기로 요청을 거부**하는 것이라 서버 코드에 닿지도 않고, 같은 대화에서 재시도하면 같은 결과다. "한번씩"으로 보이는 건 세션마다 페이로드가 달라서다.

누적 원인:
1. **히스토리 전량 전송** — [useChatStream.ts:398](../../../../src/hooks/useChatStream.ts#L398)이 `activeSession.messages` 전체를 넘긴다. 서버 `slice(-10)`은 **수신 후**라 전송량이 안 준다.
2. **첨부 base64 잔류** — 이미지는 업로드 후에도 `data`에 base64를 유지한 채 `storageUrl`만 추가하고([useChatStream.ts:202-204](../../../../src/hooks/useChatStream.ts#L202-L204)), 1MB 미만 문서는 아예 inline base64로 남는다([:187-190](../../../../src/hooks/useChatStream.ts#L187-L190)). 그 메시지가 히스토리에 있는 한 **매 턴 재전송**.
3. **기존 413 대응이 절반만** — `stripExtractedText`가 `extractedText`만 지우고 `data`는 그대로 뒀다.
4. **서버가 쓰지도 않는 데이터** — 최근 3턴 밖 첨부는 `[Attached File: …]` 라벨로 강등되므로 그 base64는 보내봐야 버려진다.

### 수정 ([geminiService.ts](../../../../services/geminiService.ts))
- **B**: 전송 전 `slice(-10)` (서버와 동일 규칙, 동작 무변화)
- **A**: 히스토리 첨부 정리 — `storageUrl` 이 있으면 base64 대신 **URL 로 치환**(서버가 http 를 그대로 처리하므로 기능 동일), 최근 6턴 밖은 `'[omitted:history]'` 로 대체(truthy 유지 → 서버 라벨 로직 그대로). 창을 서버의 3보다 넉넉한 6으로 둔 건 필터 차이로 인한 오절단 방지.
- **C**: 전송 전 본문 바이트 측정 — 1MB 초과 시 `history/attachments/webContent` 별 KB 를 콘솔에 남기고(재발 시 범인 특정용), **4.4MB 초과 시 413 대신 사람이 읽는 안내**로 선차단.

## 9. 교훈 (추가)

- **하니스가 프로덕션 경로를 우회하면, 통과는 아무것도 보장하지 않는다.** 이번 역할 버그는 "테스트가 통과하는데 신고는 계속되는" 전형이었고, 매핑을 공용 함수로 빼서 하니스를 그 위로 올린 뒤에야 A/B로 증명됐다.
- **"카드가 안 떴다"를 성공으로 세지 말 것.** 툴 호출은 LLM 변동이라, 라우팅이 이미 틀렸는데 우연히 툴을 안 불러 통과하는 경우가 실제로 있었다. 판정은 **의도한 결정 지점**에서 해야 한다.
- **413은 서버 로그에 안 남는다.** 플랫폼이 거부하므로 클라이언트에서 크기를 계측하지 않으면 영원히 추측만 하게 된다.

## 10. 레퍼런스 검토 — `app2` 코어 (상태·노드·프롬프트 설계)

`reference/Wireless-Value-Added-Agent-main/app2`(LangGraph, 69,672줄) 검토. DEV_260724에서 본 건 `Master-Agent-main`과 상담봇이었고 `app2` 는 미검토 영역이었다. 정리: **[REF_App2_Agent.md](../../guide/REF_App2_Agent.md)**

- **1순위 채택**: 후속 발화 판정을 `is_refinement`/`reset_context` 같은 **구조화 출력 필드로 위임**. 우리 라우터는 이미 JSON을 반환하므로 필드 하나 추가 = **추가 왕복 0**. §1-6에서 두 번 고친 정규식 더미의 성장을 멈춘다. 단 원칙은 유지 — **강한 신호는 코드가 확정, 회색지대만 LLM**(기존 `needsSearch` 3분기 패턴 재사용). 적용 계획은 REF 문서 §6.
- **2순위**: `phase` 개념 → 활성 카드 일반화(`movieContext`/`movieFollowup`/`weatherFollowup` 3필드 + 거의 같은 가드 두 벌을 하나로), 의도별 응답 가이드 교체.
- **프롬프트 구조 차이(핵심)**: app2 는 단계별 파일(`primary_intent`/`tool`/`inquiry_response`) + 의도별 `RESPONSE_GUIDE` **런타임 교체**. 우리는 472줄 단일 인스트럭션 전량 주입 + intent hint 덧붙임 → **§3-3의 `[WEATHER FORMATTING]` 오염이 이 구조의 직접적 부작용**이다. 비용 문제는 아니고(암묵 캐싱 78~98% 할인) **문맥 오염** 문제다.
- **비채택**: `BaseNode` 자동 계측(수신 백엔드 없음·Hobby 로그 1시간), `llm_json_repair`(+1 왕복), `###UI_JSON###` 고정 JSON 응답(산문 토큰 스트리밍 포기 → 60s 캡에서 체감 악화), slot filling 15종(도메인 특화).
