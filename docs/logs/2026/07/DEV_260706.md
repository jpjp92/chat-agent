## 1. 무엇을 했나

전용 날씨 툴을 movie/pharmacy와 동일한 카드 툴 패턴으로 배선했다. "날씨"가 general+`search:true`로 흘러 Google Search grounding + LLM 마크다운 표를 만들던 것을 → **weather intent 전용 툴**이 KMA/OWM를 서버에서 직접 호출해 `json:weather` 블록을 반환하고 카드로 렌더한다.

파이프라인: `router(weather) → generator/langchain-path(weatherTool 바인딩) → ToolNode 실행 → route.ts on_tool_end이 블록 스트리밍 → generator fast-pass(빈 AIMessage) → ChatMessage 파서 → WeatherRenderer`.

## 3. 핵심 설계 결정

### 3-1. 격자: `dfsXyConv` 공식 (하드코딩 표 폐기)
geocoding이 준 lat/lon을 LCC 공식으로 nx/ny 변환 → 전국 커버. 별칭표(`CITY_ALIASES`)는 **geocoding 질의 정규화용으로만** 존치(격자 아님). country=KR 판정도 geocoding 결과로.

### 3-2. i18n은 클라이언트 (툴은 언어 중립)
DrugRenderer 방식 채용 — 툴/코어는 `condition`(clear/rain/…) + `note` 코드 + 숫자만 반환하고, WeatherRenderer가 `language` prop으로 라벨·상태문구·요일(`Intl.DateTimeFormat`)을 매핑. **OWM `lang` 파라미터 불필요**, KMA/OWM 출처 무관하게 동일 경로.

### 3-3. 강수 = 현재 우선 + 예보 fallback
`current>0 → state:'now'` / `else 예보(daily[0])>0 → 'expected'` / `else 'none'`. KMA `RN1`은 비 안 오면 대부분 0이라 예보 fallback 필수. PCP 범위문자열(`30.0~50.0mm`)은 `numericValue`가 중앙값으로 파싱(전주 실측 **40.5mm** — naive replace면 null 되던 폭우 소실 버그 방지).

### 3-4. 라우터 후속 해석 가드
flash-lite가 화면 카드 해석 질문("습도가 높은 편이야?")을 weather로 오분류(DEV_260705 §9 유일 실패)하는 걸 결정론으로 봉합: intent=weather인데 **해석형 어휘 있고 + 새 조회 신호(날씨/기온/비 와/예보/도시·시간) 없으면 → general**. 재조회("부산은?"·"내일은?")는 해석 어휘 없어 weather 유지.

## 4. 예외·에러 처리

- **per-fetch 타임아웃**: 툴 실행엔 상위 타임아웃이 없어 KMA/OWM 행 시 Vercel 60s 캡까지 매달림 → OWM 8s·KMA 9s `AbortSignal.timeout`(정상 ~1.4~3s라 안 잘림).
- **KMA 빈 데이터**: 200이지만 items가 비면(격자 밖·base_time 미스) 0°C 유령카드 대신 throw → OWM 폴백.
- **도시 못찾음/조회실패**: 도시별 try/catch → `{error:true, code}` 블록 → 렌더러 에러카드. 멀티도시 부분 실패 격리.
- **렌더러 가드**: `current`/`daily` 결측 시 ErrorBoundary 대신 에러카드. Suspense+ErrorBoundary 래핑 유지.

## 6. UI 조정 (사용자 피드백)

- 모바일 380px 유지, 웹 540px로 확장(`sm:max-w-[540px]`).
- 말풍선 자체가 좁아 카드 상한이 발현 못 하던 문제 → ChatMessage `hasWeatherBlock`을 movie와 함께 확장 목록에 추가(`sm:w-[92%]`).
- 고정폭 카드가 좌측에 붙어 우측이 비는 문제 → `mx-auto` 가운데 정렬.
- **예보 스트립 모바일 축소** — 좁은 폭에서 예보 셀이 세로로 길쭉하던 문제. 폰트·패딩·행간을 모바일(base)만 축소하고 `sm:` 이상은 현행 유지(이모지 20→16px·셀 패딩 11→8px 등). 겸사 버그 수정: 이모지 여백 `my-[5px_0_4px]`는 Tailwind에서 유효하지 않은 값(무시됨) → `mt-1 mb-0.5`로 교정.
- **예보 셀 정리** — 최고·최저를 한 줄로 통합(5줄→4줄, Apple 날씨식). 순서 `최저 → 최고`(낮→높), 강조는 뒤의 최고에(굵게).
- **호버** — 예보 셀 hover 시 색 변화(200ms). 오늘 셀=액센트 강조 / 다른 요일=뉴트럴 리프트로 **차별화**. 다크모드 특이도 이슈(`dark:bg` 2클래스가 `hover:` 동점) → `dark:hover:` 명시로 해결.
- **위치 아이콘** — 📍 이모지 → FontAwesome `fa-location-dot`(액센트색, Vet/Hospital 렌더러 선례로 아이콘 세트 포함 확인).

## 6-3. 멀티턴 후속 카드 재생성 버그 (초기 설계 우려 지점)

"전주가 서울보다 기온 높네?"처럼 **카드에 대한 코멘트**인데 `기온` 토큰 때문에 weather로 재조회돼 카드가 다시 뜨던 문제. movie는 `movieContext`(클라 주입)로 풀지만, **날씨는 `json:weather`가 이미 대화 히스토리에 있어** 라우터가 직전 assistant 메시지만 보면 카드 표시 여부를 판정 가능 → **클라 배선 불필요**. 

`router.ts`: `weatherCardShown = /json:weather/.test(직전 assistant)`. 카드가 떠 있으면 후속을 2분기:
- **새 조회** 신호(미래 시점·"날씨/예보+요청동사"·"부산은?"·"○○ 날씨") → weather 재조회.
- 그 외(코멘트·해석·비교) → general + `weatherFollowup`(히스토리 카드 데이터로 답, `needsSearch=false`로 재검색 억제).
- 카드 없을 때(첫 발화)는 해석형 오분류만 방어. 구제(general→weather)도 `!weatherCardShown`으로 한정(코멘트 승격 방지).

스팟체크 10/10("전주가 서울보다 높네?"·"우산 챙길까?"·"습도 높은 편?"→general / "부산은?"·"내일은?"·"부산 날씨도"·"주말 날씨"→weather).
