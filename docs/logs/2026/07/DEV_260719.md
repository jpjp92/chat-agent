## 1. 승계 검증 통과 (시나리오 1 — 이 프로젝트의 핵심)

로컬(스테이징 DB 바인딩)에서 실제 Google OAuth 로 게스트→정식 승계를 확인했다.

```
정식  c9b813f1-…          ← 게스트 uuid 그대로 승격
  신원    google(johnnyworld9278@gmail.com)
  프로필  Juan Park · is_guest=false     ← 승격·이름 동기화(§4-a 트리거)
  데이터  세션 1개 · 메시지 4개          ← 게스트 대화 보존
```
같은 uuid · 충돌 없음 · 대화 보존 · 고아 없음. **DEV_260714 §4-a(identity_data 트리거)·§4-b(리다이렉트 에러) 수정이 dev 에서도 정상 동작.**

> 검증 준비 메모: 스테이징에 이전 검증의 잔여 정식 유저 3명(Google 계정 3개 소진)이 남아 매 링크가 `identity_already_exists` 로 튕겼다. `johnnyworld9278`(메시지 0) 유저 1명을 정리해 계정을 비운 뒤 깨끗한 승계를 확인. 정리는 절대 가드(대상이 스테이징 ref 인지 명시 확인) + 삭제 전 이메일·메시지수 재확인 후 진행.

## 2. 🐛 로그아웃 시 "연결 실패" 번쩍임

**증상**: 로그아웃하면 "연결에 실패했습니다" 에러 화면이 한 프레임 뜬 뒤 리다이렉트되어 게스트로 돌아왔다.

**원인**: `signOut()` 이 `supabase.auth.signOut()` → `onAuthStateChange(SIGNED_OUT)` → `setCurrentUser(null)` 을 유발한다. 이때 `isAuthLoading` 은 이미 false 라 App 의 `!currentUser && !isAuthLoading` **에러 화면**([App.tsx](../../../App.tsx))이 참이 된다. `window.location.reload()` 가 즉시가 아니라, 그 프레임이 보인다. **에러 화면이 "인증 진짜 실패"와 "방금 로그아웃함(의도적 null)"을 구분하지 못한 게 근본.**

**수정**:
- `useAuthSession` 에 `isSigningOut` 상태 추가 → 로그아웃 중엔 App 이 에러 대신 **"로그아웃 중" 로딩**(`LoadingScreen`, children 없이 → 애니메이션 점이 말줄임 대신)을 그린다.
- `signOut` 을 `try/finally` 로 견고화 → 네트워크 signOut 이 실패해도 **캐시 정리 + 리로드는 항상** 실행(로그아웃 중 갇힘 방지).

> 이 버그는 최근 변경이 만든 게 아니라 signOut/에러화면 상호작용에 원래 있던 것. **실제 흐름을 태워야만 보이는** DEV_260714 §4 계열 — dev 선검증이 값을 한 사례.

## 3. 충돌 재시도에서 계정을 두 번 고르는 체감

**증상**: 대화 있는 게스트가 이미 쓰인 Google 계정을 링크 → `identity_already_exists` → 충돌 모달 "기존 계정으로 로그인" → **Google 계정을 또 고른다.** "두 번 로그인하는" 느낌.

**분석**: 충돌 감지(1차 링크 트립)와 기존 계정 로그인(2차 signIn 트립)은 **서로 다른 OAuth 요청**이라 구조상 트립 둘이 불가피. 다만 2차에도 `prompt=select_account` 가 걸려 있어 **방금 고른 계정을 또 고르게** 만들던 게 문제.

**수정**: `oauthOptions(chooseAccount = true)` 로 파라미터화. **충돌 재시도(`onSignIn`)에서만 `chooseAccount:false`** → `select_account` 를 빼 Google 이 자동 통과. 첫 링크·0개게스트 로그인·계정 전환은 계정 선택이 필요하므로 그대로 켠다.

**한계(문서화)**: `select_account` 를 빼도, **브라우저에 Google 계정이 여러 개 로그인**돼 있으면 Google 이 자체 판단으로 계정 선택창을 띄운다(우리가 강제하는 게 아님). 완전 제거는 `login_hint:이메일` 이 유일한데, **충돌 에러 리다이렉트에 이메일이 실려오지 않아** 그 계정이 뭔지 코드가 알 수 없다. 이메일을 직접 입력받는 건 선택창 클릭보다 더 번거로워 실익 없음. → **"충돌(엣지) × 계정 여러 개(엣지)" 교집합에서만 한 번 더 묻는 것은 감수.** 계정 하나인 대다수 사용자는 자동 통과.

## 4. 부수 발견 — 테스트 스크립트 프로덕션 가드 오탐
