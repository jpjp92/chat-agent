## 요약 (TL;DR)

- 1~3순위 시나리오 **전부 통과**. 다만 통과보다 값어치 있었던 건 **여기서만 잡힌 결함 4건**이다.
- 그중 2건(수식 구분자 · 차트 결측 패딩)은 **스크립트가 구조적으로 못 잡는 부류** — 텍스트/JSON 유효성만 봤지 **화면에 무엇이 그려지는지, 그 내용이 참인지**는 안 봤다.
- 1건(롯데 지점 폴백)은 오늘 변경과 무관한 기존 버그였고, **3단계로 수정했다**(§3-3-1). 그 과정에서 `광주`→`경기광주`라는 두 번째 오답도 드러났다.
- **첫 세션은 검증 자체가 무효였다** — 프로덕션이 수정 이전 배포본을 돌고 있었다(§1).

## 1. 첫 시도 — 프로덕션이 구버전이었다

날씨 3턴 테스트에서 2턴에 카드가 또 떴다. 로컬 실그래프로 같은 발화를 돌리니 정상이었다(`Weather follow-up (refine rule)` → 텍스트 답변).

```
origin/main (배포 브랜치) = 132caa9
02254cf(날씨 멀티턴 수정)을 포함한 브랜치 = origin/dev 만
```

**버그가 아니라 미배포였다.** 증상(카드 단독·텍스트 없음 = `weatherTool` fast-pass 재실행)이 수정 이전 동작과 정확히 일치했다.

> 교훈: "프로덕션에서 재현됨"은 **배포 리비전을 확인한 뒤에야** 의미가 있다. 영화 테스트는 이때도 통과했는데, 그 발화들이 구버전 규칙으로도 처리되는 것이었기 때문에 **배포 여부를 가리지 못했다**.

## 3. 여기서만 잡힌 결함

### 3-1. 수식이 원문으로 노출 (수정함)

물리 응답의 `$F_g = mg$`가 그대로 보였다. 백슬래시가 `₩`로 보인 건 한글 폰트의 U+005C 표시일 뿐 원인이 아니다.

실제 파이프라인을 돌려 확인했다:

| 표기 | 렌더 |
|---|---|
| `$$...$$` (표 셀·문장 중간·블록) | ✅ |
| `$...$` | ❌ 원문 노출 |
| `$100` (통화) | ✅ 그대로 |

`singleDollarTextMath: false`는 **의도적 설정**(b0d7ccc, 통화 `$` 오인 수정)이라 되돌릴 수 없다. 즉 렌더러는 정상이고 **프롬프트가 구분자를 지정하지 않은 것**이 원인 — 모델은 관례대로 단일 `$`를 골랐고 이 앱에서는 항상 깨진다.

→ `[MATH NOTATION — DELIMITER IS MANDATORY]` 추가. 검증 3발화 전부 `$$` 12~18개 · 단일 `$` 0개.

### 3-2. 차트가 없는 데이터를 그림 (수정함)

"최근 5년 GDP 성장률" 차트가 **0에 붙은 평평한 직선**이었다. 카테고리 23개(분기)에 실값 3개, 나머지 20개가 `null`인데 전부 0으로 렌더됐다.

| 층 | 문제 |
|---|---|
| 렌더러 | `Number(d) \|\| 0` → `Number(null)`이 0 |
| 프롬프트 | `"If data is missing for a point, use 0 instead of null"` — **결측을 0으로 채우라고 지시** |

프롬프트 쪽이 더 나쁘다. 사용자에게 0은 "측정값 0% 성장"으로 읽힌다 — **없는 데이터를 그리는 것**이고 "수치를 지어내지 말 것"이라는 최상위 규칙과 충돌한다. 원본 응답은 전년동기 **명목**성장률(6.5·17.2%)과 전분기 **실질**성장률(0.6·1.8%)을 **한 선에 섞기까지** 했다.

→ 렌더러는 `null` 보존(ApexCharts 선 끊김), 프롬프트는 `[NEVER INVENT DATA POINTS]`로 교체(값 있는 지점만 · 축 패딩 금지 · 점 1~2개면 문장으로 · 한 시리즈에 지표/단위/기준 혼용 금지).

검증: 같은 발화 재실행에서 카테고리=값 개수 일치, null·패딩 0 없음, `-0.7`이 0선 아래로 정상 렌더.

> **단, 재검증의 한계**: 재실행 턴은 `data_viz`로 분류돼 **검색이 꺼진 경로**였다(최초 실패는 `general`+검색). 원래 실패 조건(듬성듬성한 grounding)이 재현되지 않았으므로 완전한 증거는 아니다. 프롬프트 규칙은 두 경로 모두에 들어가고 렌더러 `null` 보존은 경로 무관 안전망이라 방어는 이중이지만, **최신 구간(예: 2026년 분기별)으로 검색 경로를 강제한 재확인이 남아 있다.**

### 3-3. 롯데시네마 지점 폴백 (원인 · 수정은 §3-3-1)

`강남 영화 상영시간표` 후속 질문에 **가산디지털** 회차가 답으로 나왔다. 데이터는 진짜였고(모델이 지어낸 게 아니다), 우리가 잘못 준 것이다.

```
defaultsForRegion('강남') → lotte: 가산디지털
defaultsForRegion('신촌') → lotte: 가산디지털
```

| 체인 | 총 지점 | 강남 | 신촌 |
|---|---|---|---|
| CGV | 177 | 강남 | 신촌아트레온 |
| 메가박스 | 114 | 강남 | 신촌 |
| **롯데시네마** | 133 | **없음** | **없음** |

지점 목록은 정확하다 — 롯데시네마는 실제로 강남역·신촌 상권에 지점이 없다. 문제는 **매칭 실패 시 아무 설명 없이 기본 지점(가산디지털)으로 떨어지는 것**이다. 카드에는 드롭다운이 있어 눈으로는 알아채지만, `movieContext`로 LLM에 넘어갈 땐 "강남 요청"이라는 맥락이 사라진 채 동등하게 섞인다.

→ **처방(A안)**: 지역 매칭 실패 시 그 체인을 카드·`movieContext`에서 생략하고 "이 지역에는 지점이 없습니다"로 표시. 근접 지점 대체(강남→도곡)는 인접성 데이터가 필요해 현 규모에 과하다.

### 3-3-1. 수정 (3단계)

`강남 → 가산디지털`을 그냥 "생략"으로 바꾸는 건 **더 나빴다** — 매칭 실패율이 18/60(30%)이라, `강남역`·`홍대입구`처럼 폴백 덕에 우연히 맞던 케이스가 **빈 카드**가 된다. 실패율을 먼저 낮추고 마지막에 생략을 붙였다.

| 단계 | 내용 | 오답 | 지점없음 |
|---|---|---|---|
| 기준선 | — | **1**/60 (광주→경기광주) | 18/60 (30%) |
| 1 | 정렬에 **질의 prefix 우선** 추가(기존은 짧은 이름 우선) | **0**/60 | 18/60 |
| 2 | 별칭 맵(같은 장소의 다른 표기만) | 0/60 | 15/60 |
| 3 | 매칭 실패 시 `null` → 카드에 "지점 없음" | 0/60 | **13/60 (22%)** |

- **1단계가 광주 버그를 고쳤다.** `광주`(광주광역시)가 4자인 **경기광주**를 고르고 있었다 — 광주금남로·광주상무를 두고 다른 도시를 준 셈이다. 덤으로 `수원`도 서수원 → `수원(수원역)`으로 개선됐다.
- **2단계 별칭은 "같은 장소의 다른 표기"만** 넣었다(강남역→강남, 홍대입구→홍대, 잠실→월드타워, 삼성역→코엑스…). `노원→중계(CGV)` 같은 **인접 동네 대체는 넣지 않았다** — 사용자가 모른 채 다른 동네 시간표를 받는 건 지금 고치는 문제와 같은 성격이다.
- **3단계**: `resolveBranch()`가 `matched` 플래그를 반환하고, `defaultsForRegion()`은 매칭 실패 체인에 `null`을 넣는다. `MovieRenderer`는 그 체인의 **조회를 건너뛰고** "OO는 '강남' 지역에 지점이 없습니다"로 표시하며(드롭다운은 남겨 직접 선택 가능), `setChainShowtimes(chain, null)`로 **movieContext에서도 제외**한다 → LLM이 엉뚱한 지점으로 답하는 근본 경로가 끊긴다.
- 회귀: 영화 멀티턴 8/8 유지.

> 정규식으로 접미사를 깎아 매칭을 개선하려던 시도는 **폐기**했다. `강남→강동`, `서면→매칭실패`를 만들었다(끝 글자 `동`·`면`을 시·군·구 접미사로 오인). 오늘 세 번째로 데인 "영리한 정규식"이라, 별칭은 손으로 적는 맵으로 갔다. 스냅샷 테스트(`scripts/test-theater-match.ts`)가 이 실수를 즉시 잡아줬다.

### 3-4. 한글 조사 앞의 `**` 강조가 안 닫힘 (수정함)

`4a8141a` 배포 후 차트 검증 중에 나왔다. 같은 문단 안에서 갈렸다:

```
성장률은 **1.40%**를 기록했습니다.   → 화면에 `**1.40%**` 원문 노출  ❌
2027년 약 **3.10%**, 2028년 …        → 굵게 정상                    ✅
```

**원인은 모델도 프롬프트도 아니고 CommonMark 규칙이다.** 닫는 `**`는 *우측 플랭킹*이어야 하는데, 그 조건이 "앞이 공백이 아니고, **앞이 구두점이 아니거나 뒤가 공백/구두점**"이다. `%`는 구두점이고 `를`은 문자라 두 조건 모두 어긋난다. 쉼표 앞(`**3.10%**,`)은 뒤가 구두점이라 통과한다. `**28도**입니다`가 멀쩡한 것도 `도`가 구두점이 아니라 애초에 앞 조건에 안 걸리기 때문이다.

즉 **"강조가 구두점으로 끝나고 곧바로 한글 조사가 붙는 경우"에만** 터진다. 한국어에서 "수치+단위+조사"는 흔한 형태라 재발 위험이 높다.

- 수정: [remark-cjk-friendly](https://github.com/tats-u/markdown-cjk-friendly) 를 `remarkPlugins`에 추가([ChatMessage.tsx](../../../../components/ChatMessage.tsx)). CommonMark의 CJK 확장 제안을 구현한 플러그인으로, 파서 규칙만 보정하고 텍스트는 건드리지 않는다.
- 플러그인 순서는 `remarkGfm` → `remarkMath` → `remarkCjkFriendly` (플러그인 README 권장 순서).
- 프롬프트로 "조사 앞엔 굵게 쓰지 마라"를 지시하는 안은 버렸다. 모델이 매번 지킬 수 없는 규칙이고, 원인이 렌더러 쪽에 있다.
- 회귀 고정: `scripts/test-markdown-emphasis.mjs` — 17케이스 전부 통과. **강조가 생기면 안 되는 케이스**(`5 * 3 * 2`, `a_b_c`)와 **`$$`만 수식으로 인정**하는 계약(§3-1)까지 같이 잠근다.

### 3-4-1. 같은 증상 재발 — 진짜 원인은 파서가 아니라 **우리 전처리**였다

§3-4 배포 후에도 `** 37℃**` 가 그대로 노출됐다. 앞과 **다른 버그**다.

```
**다음 주(월~수):** 낮 최고기온이 **37℃**, 아침 최저기온도 **26~27℃** 로
                                    ↑ 이것만 깨짐
```

`ChatMessage.tsx` 에 한글 볼드 보정용 정규식이 세 군데(비스트리밍/스트리밍 visible/remaining) 있었다:

```js
t.replace(/(^|[\s([{"'“‘>:*-])\*\*([^*\n]+?)\*\*(?=[가-힣A-Za-zÀ-ÿ0-9])/g, '$1**$2** ')
```

**앞 강조의 닫는 `**` 와 뒤 강조의 여는 `**` 를 한 쌍으로 오인한다.** 위 문장에서 `다음 주(월~수):` 의 `:` 를 시작 문자로 잡고, `**`(닫는) + ` 낮 최고기온이 ` + `**`(여는) 를 하나의 강조로 매칭한 뒤 **뒤쪽 여는 `**` 뒤에 공백을 삽입**한다. 여는 구분자 뒤 공백은 left-flanking 실패라 강조가 아예 열리지 않는다.

- 조치: 세 군데 모두 **삭제**. `remarkCjkFriendly` 가 파서 단에서 올바르게 처리하므로 이 보정은 불필요해졌고, 남겨두면 이렇게 해를 끼친다.
- 손실 없음 확인: 제거 전/후 강조 추출 결과 비교 — `**1.40%**를`·`**이번 주말:**` 등은 동일, `**37℃**` 만 살아났다.

**이번에도 스크립트가 통과시켰다.** §3-4 에서 만든 `test-markdown-emphasis.mjs` 는 **파서만** 검사했고 전처리를 지나지 않았다. 두 가지를 고쳤다:

1. 테스트가 `ChatMessage.tsx` 의 전처리를 **같이 태우도록** 변경
2. 판정을 "강조가 있는가"에서 **"정확히 몇 개인가"**로 강화 — 세 개 중 두 개만 살아도 유무 판정은 통과였다

> 교훈이 하나 더 붙는다: §4-2 는 "스크립트가 통과시킨 것이 사용자에게 맞는 것은 아니다"였는데, 여기서는 **테스트 경계를 실제 코드 경로보다 좁게 잡은 것**이 원인이었다. 렌더 결과를 검증한다면서 렌더 파이프라인의 앞단을 빼놓았다.

### 3-5. 관찰만 (조치 안 함)

- **날씨 카드 지역명이 한국어 고정** — 영어 UI에서도 `서울`/`부산광역시`. KMA가 주는 지명이라 틀린 정보는 아니다. 고치려면 지명 매핑 테이블 필요, 우선순위 낮음.
- **예보 아이콘이 전부 ☀️** — 현재 날씨가 `Cloudy`(구름 70%)이고 강수확률 20%인데 5일 전부 맑음 아이콘. 하늘상태 코드 매핑 의심. **별건으로 볼 가치 있음**(카드 정보 정확도).
- **검색 on/off에 따라 수치가 흔들림** — 2021년 실질 성장률이 검색 턴에서 4.3%(확정치), 비검색 턴에서 4.1%(속보치). 둘 다 출처가 있는 값이라 오류는 아니다.

## 4. 이 세션의 교훈

1. **배포 리비전 확인이 검증의 0단계다.** 안 하면 한 세션을 통째로 버린다(§1).
2. **스크립트가 통과시킨 것이 사용자에게 맞는 것은 아니다.** 3-1은 "텍스트에 수식이 있다"까지만 봤고, 3-2는 "`json:chart`가 파싱된다"까지만 봤다. 둘 다 통과였고 둘 다 화면은 틀렸다.
3. **프롬프트가 렌더러와 어긋나면 모델 품질과 무관하게 100% 깨진다**(3-1). 프롬프트를 고칠 때 "이 지시를 받는 쪽이 그 형식을 실제로 처리하는가"를 같이 확인해야 한다.
4. **모델이 이상한 답을 하면 우리가 이상한 데이터를 줬는지 먼저 본다**(3-3). 가산디지털은 모델 잘못이 아니었다.
5. 다음 테스트 강화 후보: 렌더러 테스트에 **"값의 절반 이상이 결측/0이면 실패"**, **"단일 `$` 수식이 있으면 실패"** 판정 추가. 둘 다 이번 결함을 스크립트로 잡게 해준다.
6. **모델 출력이 깨져 보인다고 모델·프롬프트 문제인 것은 아니다**(3-4). `**1.40%**`는 모델이 정확히 올바른 마크다운을 썼는데 파서 규칙에서 걸렸다. 판단 근거는 **같은 문단 안의 대조군**이었다 — `**3.10%**,`는 되고 `**1.40%**를`는 안 됐다. 한 응답 안에서 되는 것과 안 되는 것이 갈리면 원인은 모델이 아니라 결정론적 규칙 쪽이다.
