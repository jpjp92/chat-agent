## 1. AI Hub 개방데이터 2종

`reference/08.전문 의학지식 데이터` · `reference/09.필수의료 의학지식 데이터`.
zip 파일명이 CP949 + 절대경로라 `unzip` 이 깨진다 — Python `zipfile` 로 읽었다.

### 1.1 실측 규모 (설명서가 아니라 파일에서 직접 센 값)

| | 08 전문의학 | 09 필수의료 |
|---|---|---|
| Training 라벨링 | 12,228쌍 | 15,360쌍 |
| Validation 라벨링 | 1,528쌍 | 1,920쌍 |
| 원천 문서 | 112,257건 | 52,126건 |
| domain | 1~13 (외과·정신건강의학과 등) | 14~17 (산부인과·소아청소년과·응급의학과·내과) |

라벨링 품질 자체는 깨끗하다 — 파싱 실패 0, `qa_id` 중복 0, train↔val 질문 겹침 0.
q_type 은 양쪽 다 객관식이 81% 이고, 답이 100% `"n) 보기전문"` 형식이라 **정확일치 자동채점이 된다.**

### 1.2 🔴 문서에 없는, 사용을 좌우하는 결함

**① 원천데이터의 `domain` 이 데이터셋 단위 상수다.** 08 은 전 문서가 `1`, 09 는 전 문서가 `2`.
전수 확인했고 예외가 없다. 진료과 필터링이 원천적으로 불가능하며, 실질 메타데이터는
`source_spec` 하나뿐이다.

**② 출처 URL 도 제목도 없다.** 키가 `c_id · content · creation_year · domain · source · source_spec`
6개로 고정이고 원문을 가리키는 필드가 없다. **인용 링크를 만들 수 없다** — 이 레포는 인용 번호와
근거 링크가 핵심 UX 이므로 이 하나로 지식베이스 용도가 막힌다.

**③ content 가 원문이 아니라 LLM 요약체다.**
> "1. 이 약은 분홍색의 원형 씹어먹는 정제로, 명문제약(주)에서 제조합니다. 2. 전문의약품으로…"

저작권 회피에는 유리하나, **검증되지 않은 재서술**을 의학 답변 근거로 쓰는 위험이 남는다.

**④ 09 에 청킹이 깨진 초대형 문서가 있다.** `국문_기타` 1,032건 중 중앙값은 1,894자인데
최대가 **18,976,142자(19MB)** 다. 상위 3건이 전체 4,800만자 중 3,880만자를 차지한다.
중복이 아니라(문장 중복률 0.76%) **서로 다른 문서 수백 개가 한 `c_id` 로 이어붙어 있다** —
세브란스 수술동의서로 시작해 대한소화기학회지 논문과 저널 라이선스 문구까지 한 레코드에 있다.
순진한 문서 단위 로딩은 메모리가 터진다.

**⑤ `c_id` 는 고유 키가 아니다.** 08 내부에서만 112,257건 → 99,549개(중복 12,708건)이고,
08↔09 사이에 17,181개가 충돌하는데 본문은 서로 다르다(본문까지 같은 건 10건).
두 셋을 합칠 때 PK 로 쓸 수 없다.

### 1.3 라이선스 — 판별 불가

수집 기준에 `CC0, CC-BY, CC-BY-SA, **CC-BY-NC**` 가 함께 적혀 있다.
본문에 비영리 문구가 남아 있는 문서를 전수 검색하면 08 은 395건, 09 는 482건(대부분 WHO).
**이건 하한선일 뿐이다** — 정제 과정에서 라이선스 헤더가 대부분 잘려나갔으므로, 문구가 없다고
상업적 이용이 가능하다는 뜻이 아니다. 그리고 **어느 문서가 어느 라이선스인지 식별할 필드가 없다.**

### 1.4 결론

지식베이스로는 부적합하다. 약 정보는 이미 MFDS API 로 실시간 조회하는데, 이 데이터의 nedrug
34,473건은 **같은 출처의 2023년 스냅샷을 LLM 이 요약한 것**이라 모든 면에서 열등하다.
파인튜닝은 API 모델만 쓰므로 애초에 해당 없다.

쓸 값어치가 있는 건 **회귀 평가셋** 하나다. 08+09 Validation 합산 3,448건 중 객관식 2,677건이
자동채점 가능하고 `qa_id` 충돌이 없어 그냥 합쳐진다. 다만 이건 의사국시형 지식 벤치마크라
**모델의 암기 지식만 재고** 우리가 실제로 하는 일(검색 grounding·MFDS 조회·렌더러 라우팅)은
하나도 재지 않는다. "서비스가 좋아졌나"가 아니라 "모델을 바꿔도 되나"에 답하는 도구다.

## 2. NCMIK OpenAPI — 폐기

국립의과학지식센터 <https://library.nih.go.kr/ncmiklib/elib/listOpenAPI.do>.
인증키가 필요 없고 응답도 1초 내라 후보로 봤지만, **검색이 동작하지 않는다.**

```
kwd=고혈압      → totalCnt 652,993 · PB05357534 PB05357551 PB05357554 …
kwd=zzzqqqxx    → totalCnt 652,993 · PB05357534 PB05357551 PB05357554 …
kwd=probiotics  → totalCnt 652,993 · PB05357534 PB05357551 PB05357554 …
```

없는 단어를 넣어도 전체 건수와 결과 ID 가 동일하다. `kwd` 가 배선돼 있지 않다.
`subject` 도 같고, `author` 는 어떤 형식이든 빈 결과다. 동작하는 필터는 `pubYearStart/End` 뿐.

페이지네이션도 죽어 있다 — `retstart` 는 1 외의 값에서 전부 빈 응답이고 `retmax` 는 50 상한이라
**어떤 조건으로도 50건을 넘겨 가져올 수 없다.**

응답에 URL·DOI 가 없어 인용 링크도 못 만든다. 문서 표는 상세 인터페이스의 호출 URL 을
`kSummary.do` 로 잘못 적어놨고, 실제 상세 엔드포인트는 예시 링크에만 있는 `kFetch.do` 다.

> ⚠️ 파라미터를 무시할 때 **에러 없이 조용히** 무시한다. 나중에 고쳐지더라도
> "결과가 조용히 틀릴 수 있는 API" 라는 위험은 남는다.

| 검증 | 결과 |

| 질의마다 건수가 달라지는가 | ✅ probiotics 91 vs stent 21,472 |
| 없는 단어는 0건인가 | ✅ |
| 제목·저널·연도·저자 | ✅ |
| 인용 URL (`pubmed.ncbi.nlm.nih.gov/{pmid}/`) | ✅ |
| DOI | ✅ |
| NCMIK 샘플 논문 수록 여부 | ✅ PMID 23372900 · DOI `10.4082/kjfm.2013.34.1.2` |
| 국내 저널 색인 | ✅ Korean J Fam Med 993건 |

NCMIK 가 주던 바로 그 논문을 **인용 링크와 함께** 찾을 수 있다는 게 §3 의 요지다.

### 3.1 레이트리밋 — `NCBI_KEY` 가 필요한 이유

병렬 6회를 던지면 무키 상태에서 실제로 막힌다.

```
키 없음 → 429 429 200 429 200 200   (3건 차단)
키 있음 → 200 200 200 200 200 200   (0건)
```

무키 3 req/s, 키 10 req/s. Vercel 은 **동시 인스턴스가 egress IP 를 공유**하므로 배포 환경에서는
사실상 필수다. 이름은 레포의 `HOSPITAL_KEY`·`PHARM_KEY`·`VET_KEY` 관례를 따라 `NCBI_KEY`.

> 로컬은 `.env`(Next.js 가 `.env`·`.env.local` 둘 다 읽는다), 배포는 Vercel 대시보드 환경변수.
> 둘 다 등록했다(2026-08-30). 환경변수는 **새 배포부터** 적용된다 — 기존 배포본은 재배포가 필요하다.

프로브 자신도 3 req/s 를 넘겨 429 로 죽었었다. 그래서 호출 간격 제한기(무키 350ms / 키 110ms)와
429 재시도를 넣었는데, **이건 프로덕션 툴에도 그대로 필요한 부품**이다.

### 3.2 🔴 `pubtype` 을 근거 등급으로 곧이곧대로 쓰면 안 된다

카드에 근거 등급 배지를 붙이려던 근거가 `pubtype` 이었는데, 실측에서 무너졌다.

| PMID | 제목이 말하는 것 | 실제 `pubtype` |
|---|---|---|
| 25927096 | Cochrane 리뷰 | `Meta-Analysis`, `Systematic Review` ✅ |
| 23372900 | "**a meta-analysis** of randomized controlled trial studies" | `['Journal Article']` 🔴 |
| 42354894 | "**Randomized, Double-Blind, Placebo-Controlled** Clinical Trial" | `['Journal Article']` 🔴 |

NLM 의 MeSH publication type 색인은 **큐레이터가 나중에 붙이므로**, 최근 논문과 일부 저널
레코드에는 없다. 메타분석을 "일반 논문" 으로 표시하면 의학 맥락에서 조용히 오도한다.

**대응**: `pubtype` 이 없으면 **배지를 생략**한다. 추측으로 등급을 붙이지 않는다.

> 처음엔 "제목/초록 패턴으로 보조 판정" 을 중간 단계로 두려 했으나 **폐기했다** — 240건 중
> 3건(1%)만 건진다. 경위는 [§6.4](#64-구현하며-뒤집힌-판단-2가지).

## 4. CrossRef — 보조

키 불필요, 국내 의학저널 수록, 전건 DOI. 같은 논문을 `10.4082/kjfm.2013.34.1.2` 로 찾아온다.

다만 **DOI 등록소지 큐레이션된 색인이 아니다.** "probiotics common cold" 에 671,784건을 뱉고
상위 결과 품질이 눈에 띄게 떨어진다. → **검색은 PubMed, CrossRef 는 DOI·미수록 저널 보강 전용.**

부하가 걸리면 200 에 빈 본문을 주는 일이 있어 `JSON.parse` 전에 본문을 확인한다.

## 5. 네이버 검색 API — 조건부

`NAVER_CLIENT_ID` / `NAVER_CLIENT_SECRET` 로 전 엔드포인트를 찔러본 결과.

| API | 결과 |
|---|---|
| blog · news · encyc · cafearticle · kin · local · webkr · image | ✅ 200 |
| **doc(전문자료=논문)** · book · shop | 🔴 404 — 폐지 |
| **papago 번역 · 언어감지** · 단축URL | 🔴 404 — 폐지(NCP 유료 이전) |
| DataLab 검색어트렌드 | 🔴 401 — 앱에 별도 이용신청 필요 |

기대했던 둘(국내 논문 보강 `doc`, 4개 언어 번역 `papago`)이 **모두 폐지**됐다.

### 5.1 `local` 은 우리가 가진 것보다 못하다

- `total` 이 5에서 잘린다 — "서울 내과" total=5. 진짜 건수가 아니라 상한.
- `telephone` 이 전부 빈 문자열.
- 진료시간 없음.

`json:hospital` 은 전화번호·종별·의사수·좌표를, `json:pharmacy` 는 요일별 운영시간과
`is_open_now` 까지 갖고 있다. 심평원/공공데이터 쪽이 전 항목 우위다. 도입하면 후퇴다.
(참고: `mapx/mapy` 를 1e7 로 나누면 WGS84 가 맞다 — 세브란스 → 126.9408, 37.5623)

### 5.2 나머지 4종은 의도별로 갈라야 한다

처음엔 blog·news·encyc·cafearticle 을 "UGC 라 위험" 으로 한데 묶었는데 **그건 틀렸다.**
`news` 는 실제 언론사(etoday·ddaily·apnews…)이고 `originallink`·`pubDate` 가 있어 인용이 되며,
`encyc` 도 UGC 가 아니다. 그리고 이들을 *의학 답변 소스* 로만 평가한 것 자체가 좁았다 —
이 레포는 영화·날씨·스포츠·법률까지 다루는 범용 어시스턴트다.

`blog`/`cafearticle` 은 UGC 지만 **구글 기반 grounding 이 네이버 블로그·카페를 잘 못 긁는다.**
중복이 아니라 커버리지 공백이다. `display` 100 상한, `sort=date` 로 당일 글까지 나온다.

`encyc` 만 유보를 유지한다. 실측에서 두 가지가 걸린다.

- **적합도가 나쁘다**: "고혈압 진단기준" → *ARA의 진단기준 · 만성 콩팥병 진단기준 · 존스의 개정진단기준*.
  고혈압 진단기준이 하나도 없다. "진단기준" 에 걸린 키워드 매칭 수준이다.
- **출처를 API 로 알 수 없다**: `cid` 만 다르게 오고(51000·55655·59913·63166…) 어느 사전인지
  응답에 없다. 상세 페이지는 SPA 라 서버에서 출처 표기를 못 읽는다. 실제로 "심근경색" 결과 중
  하나는 *"지난 2009년 8월 아시아의 물개로 불리던 조오련 씨가…"* 로 시작하는 **칼럼**이었다.

**의학 답변에 인용할 때 출처의 권위를 판별할 수 없다**는 게 핵심 제약이다.

### 5.3 도입한다면

라우터가 이미 의도를 분류하므로 소스를 나누면 된다. `search_naver` **로컬 툴 하나**로 붙이고
의도별 화이트리스트를 둔다 — 새 API 라우트는 만들지 않는다(무인증 라우트 6개 유지).

| 의도 | 허용 |
|---|---|
| 의료(약·병원·증상) | ❌ 전부 차단 — MFDS·심평원·PubMed 유지 |
| 뉴스·시사 | ✅ `news` |
| 맛집·지역·제품·후기 | ✅ `blog` `cafearticle` (`sort=date` 필수) |
| 일반 지식 | ⚠️ `encyc` 보조로만, 단독 근거 금지 |

> `blog` 는 기본 정렬이 적합도라 2021·2022년 글이 섞여 나오고, 네이버 블로그 상위는
> 협찬·광고 비중이 높다. `sort=date` 와 "의료 차단" 두 가지가 전제다.

라이브 라우팅 확인: "…논문 찾아줘"·"…연구 결과 알려줘" → `paper_search`,
"타이레놀 성분" → `drug_info`, "강남구 내과" → `hospital_search` (기존 의도를 잠식하지 않는다).

### 6.1 🔴 트리거 경계 — 의학 질문이 아니라 "논문 요청" 이 조건이다

라이브로 재보니 `paper_search` 는 **주제가 의학이어서가 아니라 논문을 요청해서** 걸린다.
PubMed 는 의생명만 색인하는데, 비의생명 주제가 들어와도 **빈손으로 실패하지 않고 그 주제의
보건 분야 단면**을 돌려준다 — "최저임금 인상이 흡연 행동에 미치는 영향"(215건),
"기후변화와 정신건강"(131,888건). 진짜 논문이라 오히려 위험하다.

라우터에 부정 조건을 명시해 머신러닝은 `general` 로 빠지게 했지만 기후·경제는 여전히 샌다
(LLM 라우터는 확률적이다). 그래서 라우팅에 의존하지 않는 층을 두 개 더 뒀다 — 프롬프트가
주제 불일치 시 카드를 내지 않게 하고, **카드 하단이 4개 언어 모두 "PubMed(의생명 분야 문헌)"**
라고 출처 범위를 밝힌다. 하니스가 세 층을 모두 고정한다.

### 6.2 🔴 end-to-end 로 돌려보고 나온 버그 4건

라우터와 도구를 **따로** 확인한 것으로는 아무것도 보장되지 않았다. 그래프를 실제로 돌리자
모델 5종 중 **하나도 제대로 동작하지 않았다.** 배선이 네 군데 빠져 있었다.

| # | 증상 | 원인 |
|---|---|---|
| 1 | Gemini 가 도구 대신 Google 검색으로 답함 | `LANGCHAIN_INTENTS` 에 `paper_search` 누락 → 도구가 바인딩조차 안 됨 |
| 2 | Gemini 가 도구 경로로 가도 자기 기억으로 답함 | `SYNTH_TOOL_INTENTS` 누락 → `forceDomainTool` 이 꺼져 호출을 강제하지 않음 |
| 3 | Gemini 가 "논문 검색 도구를 사용할 수 없다" | `graph.ts` 의 `ToolNode` 에 `paperTool` 미등록 → 호출은 했는데 실행할 도구가 없음 |
| 4 | gpt-5.4-mini 카드 JSON 파손, gpt-5.6-luna `papers` 필드 누락 | **모델에게 카드를 다시 쓰게 한 설계 자체** |

①②③ 은 배선이라 고치면 끝이지만 ④ 는 설계 문제였다. 논문 카드는 5편 × 9필드라 재작성
표면이 넓고, PMID·DOI 가 한 글자만 틀려도 사용자는 엉뚱한 논문으로 간다. 실측에서 **3개 모델 중
1개만** 제대로 냈다.

**대응 — 카드 고정(`pinCardToProse`).** 산문은 모델이 쓰고 **카드는 코드가 도구 출력을 그대로
붙인다.** 모델이 쓴 카드 블록은(닫히지 않은 잘린 블록까지) 걷어낸다. 프롬프트도 뒤집어
"카드를 직접 쓰지 말라"고 지시한다 — 그렇게 바꾸기 전 Gemini 는 산문 없이 카드만 냈다.

결과: **5종 전부 통과**(gemini 3.7·3.6·2.5, gpt-5.4-mini, gpt-5.6-luna). 식별자 변조 0건,
등급 변조 0건, 산문 294~390자.

### 6.3 라우팅 — 정책 정정 · 측정 오염 · 결정적 가드

**① 정책 정정.** 처음엔 기후·경제를 "비의생명 누수" 로 셌는데 틀렸다. PubMed 에는
기후-건강·대기오염·정신건강에 **실체 있는 공중보건 문헌**이 있고, 카드가 이미
"PubMed(의생명 분야 문헌)" 이라고 범위를 밝힌다. 막을 게 아니라 **허용 대상**이다.
프롬프트 백스톱도 "무조건 카드 억제" 에서 **"보건 관점 연구임을 한 마디로 밝히고 보여주기"** 로 바꿨다.

**② 🔴 측정이 오염돼 있었다.** 문구를 세 번 바꿔가며 누수율을 비교하고 "조일수록 핵심 케이스를
놓친다" 고 적었는데 **그 해석은 전부 틀렸다.** 라우터 LLM 이 **429(쿼터 초과)** 로 죽고 있었다 —
무료 키 12개로 45회씩 반복 호출한 탓이다. 라우터가 실패하면 규칙 폴백으로 떨어지는데 거기엔
`paper_search` 규칙이 없어 **논문 질의가 통째로 `general` 로** 갔다.

증거는 내 수정과 무관한 `medical_qa` 항목("고혈압에 좋은 음식"·"감기 걸렸는데")까지 동시에
`general` 로 무너진 것이다. 문구 비교 결과(6/0 → 3/1 → 6/1)는 폐기했다.

**③ 유료 키로 재측정.** `API_KEY_TIER1` 은 `/^API_KEY\d*$/` 에 안 걸려 기본 로테이션 풀에서
빠져 있다. 프로브에 `TIER1=1` 스위치를 넣어 유료 키 단독으로 돌리니 429 가 사라졌고, 그제야
**진짜 경계**가 보였다 — 라우터는 **분야를 가리지 않고** 논문 요청을 전부 `paper_search` 로
보낸다(CS·공학 **9/9 누수**). "머신러닝은 걸러진다" 던 앞선 관측도 429 폴백의 산물이었다.

**④ 결정적 가드.** 프롬프트로는 안 잡히므로 `isNonBiomedicalPaperTopic()` 을 만들어 라우터에서
`paper_search → general` 로 강등한다. PubMed 는 이런 질의에 **빈손으로 실패하지 않고** 그 주제의
의생명 응용을 돌려주므로(트랜스포머 → 단일세포 오믹스) 조용히 엉뚱한 근거가 나간다.
⚠️ 보건과 겹치는 말은 넣지 않았다 — `AI 의료영상` 은 진짜 의생명 문헌이 있다.

**⑤ 규칙 폴백.** 라우터 LLM 이 429 로 죽어도 논문 질의가 잡히도록 `intentRules.ts` 에 규칙을 넣었다.
`논문` 단독은 일부러 안 받는다 — "논문 써줘"(작문)가 걸린다.

**⑥ 분야를 넓히니 블록리스트가 무너졌다.** 21개 분야로 재보니 차단 대상 **10종 전부 누수**했다 —
문학·예술사·음악학·거시경제·금융·역사·법학·토목·CS. 키워드 목록에 없는 말은 못 잡는데
**비의생명 분야의 공간은 무한하다.** 반대로 기존 의학 어휘(`hasMedicalIntentKeyword`)를 양성
게이트로 써보니 정당한 14건 중 12건을 막았다. 어느 쪽 리스트도 답이 아니었다.

그리고 이 누수는 **무해하지 않다.** PubMed 는 어떤 질의에도 0건을 주지 않는다:

| 질의 | PubMed 가 돌려준 것 |
|---|---|
| 셰익스피어 비극 | "Ophelia syndrome 재고" (의학) |
| 헌법 개정 | "파키스탄 보건체계와 18차 개정" — `constitution`(체질)에 매칭돼 21만 건 |
| 인상주의 회화 | **"인상주의 회화 속 여성의 BMI"** (비만 연구) |

미술사를 물었는데 비만 연구가 근거로 나간다.

**⑦ 해법 — 라우터 JSON 에 두 칸.** 추가 LLM 호출 없이, 이미 하는 라우터 호출의 출력에
`"topic_field"` 와 `"pubmed_topic"` 을 더 받는다. 17개 의도 중 고르며 예외를 지키는 것보다
**"이 주제가 PubMed 에 있나" 라는 좁은 예/아니오**가 훨씬 잘 맞는다. 키워드 가드는 라우터 LLM 이
죽었을 때를 위해 남겨둔다.

**⑧ 판정 기준은 분야 목록이 아니라 규칙이다.** 첫 판은 `pubmed_topic` 기준을 분야 열거로 적었다
— "심리학·간호학·수의학은 true, 문학·예술사·거시경제는 false". 21분야 측정은 통과했지만 그건
**측정 세트가 내가 적어둔 목록과 같았기 때문**이다. 목록에 없는 분야(고고학·언어학·건축학·
지질학·회계학)는 여전히 모델의 감에 맡겨져 있었다 — ⑥ 에서 실패한 블록리스트와 같은 구조다.

그래서 판정을 **2단계**로 나눴다:

1. `topic_field` — 발화의 주제를 학문 분야로 **먼저 명명**한다("art history", "reinforcement
   learning", "monetary policy"). 매 턴 출력하며 강등 로그에 남아 사후 진단이 된다.
2. 그 분야에 규칙 **하나**를 적용한다 — *"그 분야가 연구하는 대상이 **살아있는 몸**인가:
   생물, 그 구조·기능·질병·돌봄인가?"* 반대편도 규칙으로 정의한다 — 연구 대상이 **텍스트·
   예술품·시장·제도·기계·추상**이면 false다. 사람이 만들었고 사람이 등장해도 마찬가지다.
   읽기·거래·입법·건설·계산은 신체 기능이 아니다. 명명할 수 없으면 false(누수가 놓침보다 해롭다).

같은 단어가 양쪽에 걸릴 때는 **대상이 가른다** — 음악치료는 환자를 치료하고(true) 음악학은
음악을 연구한다(false). 스포츠의학/스포츠사도 같다. 이건 예시가 아니라 규칙의 적용 시범이다.

**무오염 최종 측정 (TIER1)**

```
(2분기 시절 측정 — arXiv 추가 후 수치는 §6.5)
기본 15종 × 3회 = 45회   → 누수 0 · 놓침 0
분야 21종 × 3회 = 63회   → 누수 0 · 놓침 0
미등장 14종 × 3회 = 42회 → 누수 0 · 놓침 0   ← 규칙이 일반화하는지의 시험
  허용 8분야(심리·간호·음악치료·운동과학·노년·산업보건·수의·식품위생)  8/8
  차단 10분야(문학·예술사·음악학·경제·금융·역사·법학·토목·CS)        10/10
  경계 3종 — 경제·교육·도시녹지 전부 general
  허용 5분야(해양생물·식물병리·곤충·치의학·언어병리)  5/5   ← 프롬프트에 이름 없음
  차단 7분야(고고·언어·건축·지질·정치·회계·로봇)      7/7   ← 프롬프트에 이름 없음
```

미등장 세트가 핵심이다. **라우터 프롬프트에 한 번도 나오지 않는 분야 14종**을 넣어
목록 암기가 아니라 규칙 적용인지 확인한다(`--unseen`). 목록 방식이라면 여기서 무너진다.

> ⚠️ 라우터 LLM 이 429 로 죽은 **성능저하 모드**에서는 규칙 폴백 + 키워드 가드만 남아
> 일부(강화학습·셰익스피어)가 통과한다. 블록리스트를 무한히 늘리는 대신 한계로 남긴다.

```
의생명 5종                    15/15 ✅
medical_qa·drug_info 잠식      0    ✅
허용 대상(기후-건강·미세먼지)   6/6  ✅
차단 대상(CS·공학)             0/9  ✅  ← 강등 가드
```

하니스 §4b(규칙 폴백)·§4c(강등 가드)가 네트워크 없이 이 경계를 고정한다.

### 6.4 구현하며 뒤집힌 판단 2가지

**① 근거 등급 보조 판정 — 폐기.** §3.2 에서 "제목/초록으로 보조 판정" 을 대안으로 적었는데,
실제로 재보니 240건 중 **3건(1%)** 만 건진다. 배지 스타일을 하나 더 만들 값어치가 없다.
`evidence: null` 은 그대로 두고 렌더러가 **아무것도 그리지 않는다**.

**② 이해상충 배지 — 폐기.** 시안에 넣었다가 뺐다. `<CoiStatement>` 는 존재만으로 판정이
안 되고(대부분이 "없음" 선언), 본문을 규칙으로 분류하니 실제 41건에서 **양방향 오분류 20% 초과**.
`"has received research grant support"` 를 없음으로, `"in the absence of any commercial
relationships"` 를 있음으로 잡는다. 저자 편향 플래그가 5건 중 1건 틀리면 안 된다.
두 결정 모두 하니스가 되살아나는 걸 막는다(§3·§4).

### 6.5 arXiv 추가 — "의생명이 아니면 arXiv" 는 아니다

`none` 으로 강등된 질의를 다시 보니 **절반은 버릴 이유가 없었다.** arXiv 는 키 없이 열려 있고
그 절반을 정확히 답한다. 실측(각 질의 1위 결과):

| 질의 | arXiv 1위 | |
|---|---|---|
| 강화학습 보상함수 | `cs.AI` *From Reward Shaping to Q-Shaping* | ✅ |
| 이족보행 로봇 제어 | `cs.RO` *Sim-to-Real Transfer for Bipedal Locomotion* | ✅ |
| 인플레이션 통화정책 | `econ.EM` *Effectiveness of US Monetary Policy* | ✅ |
| 주식시장 변동성 · 반도체 · 교량 내진 · 화산암 | `cs.CE` / `cond-mat` / `physics.geo-ph` | ✅ |

**🔴 그런데 나머지 절반은 PubMed 때와 똑같은 함정이다.** arXiv 도 빈손으로 실패하지 않는다:

| 질의 | arXiv 가 돌려준 것 |
|---|---|
| 한국어 통사론 | `astro-ph` **Korean VLBI Network**(전파망원경) 770,886건 |
| 한국 현대문학 | `cs.CL` 감정분류 데이터셋 |
| 조선시대 신분제 | `cs.SI` 소셜 추천시스템 |
| 인상주의 회화 미술사 | `cs.CV` *Collaborative Neural Painting* |
| 고대 토기 편년 | `physics.ed-ph` 고대 지중해 항해 |

그래서 **판정은 2분기가 아니라 3분기**다. ⑧ 의 규칙에 갈래를 하나 더 두는 것으로 끝난다 —
분야를 명명한 뒤 *그 분야가 무엇을 연구하는가* 를 묻는 구조는 그대로다:

| 갈래 | 연구 대상 | 예 |
|---|---|---|
| `pubmed` | 살아있는 몸 — 생물, 그 구조·기능·질병·돌봄 | 생리·약리·간호·수의·공중보건 |
| `arxiv` | 형식·물리·계산 체계 — 모델링·측정·제작이 되는 것 | 수학·물리·알고리즘·기계·계량경제 |
| `none` | 사람의 기록 — 텍스트·작품·사건·제도·법 | 문학·미술사·역사·법학·회계 |

경계는 여전히 **대상**이 가른다: 계산언어학은 언어모델을 만들고(arxiv) 한국어 통사론은
문법을 연구한다(none).

**설계 결정 두 가지**

① **`arxiv_search` 를 프롬프트 의도 목록에 넣지 않는다.** 처음엔 넣었다가 뺐다 — 모델이
   "논문 요청인가" 와 "어느 분야인가" 를 **두 번** 판단하게 되고 두 판단이 어긋난다.
   의도는 `paper_search` 하나로 받고, `paper_source === "arxiv"` 일 때 **코드가** 파생시킨다.
   같은 이유로 `paper_search` 설명에서 분야 얘기를 통째로 뺐다("do NOT judge the field here").

② **arXiv 에 근거 등급 배지를 재사용하지 않는다.** 종합분석·임상시험·논문리뷰는 NLM 큐레이터가
   연구 **설계**를 분류한 값이고 arXiv 에는 그런 분류가 없다. 여기서 말할 수 있는 사실은
   `journal_ref`/`doi` 존재 여부 하나 — **게재됨 / 프리프린트**만 표시한다. 프리프린트는 회색
   중립색이다(등급이 낮은 게 아니라 심사 전이라는 뜻). 하단 문구도 4개 언어 모두 "동료심사를
   거치지 않은 글이 포함된다"고 밝히고, 프롬프트는 결과·벤치마크·안전 주장을 다룰 때 산문에서
   한 번 짚게 한다. 실제로 gemini-3.7 이 요청 없이 *"아직 동료 심사를 거치지 않은 프리프린트일
   수 있습니다"* 로 시작했다.

**측정 (TIER1, 3회 반복)**

```
기본 15종 → 45회   오배송 0 · 미발송 0
분야 21종 → 63회   오배송 0 · 미발송 0
미등장 14종 → 42회  오배송 0 · 미발송 0
                     ─────────────────
                     150/150
```

*오배송* = 엉뚱한 DB 로 갔거나 어느 DB 에도 없는데 카드가 나감(더 해롭다 — 사용자는 근거를
받았다고 믿는다). *미발송* = 해당 DB 가 있는데 카드가 안 나감.

E2E(`live-paper-card.mts`)는 gemini-3.7 · gpt-5.4-mini 양쪽에서 arXiv ID·심사여부·요약이
도구 출력 그대로 유지되는 걸 확인했다(5/5). PubMed 경로 회귀 없음.

**되돌린 것 하나** — `paper_search` 설명에 *"논문을 요청하지 않은 의학 질문은 medical_qa"* 를
넣었더니 **"음악치료 불안 완화 연구 있어?"** 가 3/3 `medical_qa` 로 샜다. `논문` 이라는 단어가
없는 논문 요청("연구 있어?", "연구된 거 있어?")을 그 문장이 삼킨 것이다. 구분 문장에 그
표현들을 명시적으로 되돌려 붙여 해결했다.

### 6.6 🔴 카드가 만들어지는 것과 화면에 도달하는 것은 다르다

사용자가 같은 질의를 gemini-3.7 과 gpt-5.6-luna 로 돌린 결과를 나란히 보내왔다. luna 는 카드와
인용 번호가 다 나왔는데 **3.7 은 산문만** 나왔다. 모델 품질 차이로 보이지만 아니었다 —
3.7 의 산문은 *"학령기 아동의 감기 증상과 결석"* 을 언급하는데, 이건 코크런 초록의
`cold-related school absence` 다. **도구는 호출됐고 모델은 결과를 읽어 산문까지 썼다.**

원인은 `route.ts` 의 한 줄이다:

```js
if (msgText && !fullAiResponse) { fullAiResponse = msgText; sendEvent({ text: msgText }); }
```

Gemini 는 산문을 **토큰 단위로 스트리밍**해 `fullAiResponse` 를 먼저 채운다. 카드는 그 뒤
`pinCardToProse` 가 **최종 메시지**에 붙인다. 그래서 `!fullAiResponse` 조건에 걸려 최종 메시지가
통째로 버려졌다 — **카드만 화면에 도달하지 않는다.** OpenAI 는 이 경로로 스트리밍하지 않아
`fullAiResponse` 가 비어 있었고, 그래서 **우연히** 멀쩡했다.

`streamEvents` 를 route.ts 와 같은 순서로 소비해 재현했다:

```
스트리밍 본문 248자 · 카드 포함? false
generator 최종 메시지에 카드 있음? true      ← 카드는 만들어졌다
route.ts 가 사용자에게 보냈나? false          ← 그런데 안 보냈다
```

**두 번째 결함 — 인용 번호도 지워졌다.** 스트리밍 원문에 `[1]`·`[2]` 가 2개 있었는데 화면엔
없다. `stripFabricated` 가 `(` 가 안 따라오는 `[n]` 을 지운다 — Gemini 가 지어내는 가짜 인용을
막던 방어인데, 논문 프롬프트는 그 마커를 **일부러 요구**한다(도구가 준 목록 순번이다).
논문 턴은 `allTools=[paperTool]` 뿐이라 grounding 이 아예 안 붙고, 그래서 이 방어가 원래 막으려던
"grounding URL 을 가리키는 가짜 번호" 가 생길 경로 자체가 없다 → 그 턴만 끈다.

**⚖️ 하니스가 이 버그를 가리고 있었다.** `live-paper-card.mts` 가 최종 메시지를 우선 읽었다:

```ts
const text = (최종 메시지 내용) || streamed;   // ← "만들어졌는가" 만 본다
```

그래서 3/3 통과로 넘어갔다. **"사용자에게 도달하는가" 를 봐야 했다.** route.ts 와 같은 이벤트
소비 순서로 고쳤고, 전송 판정은 `pendingCardBlocks()` 하나로 빼 **route.ts 와 하니스가 같은
함수를 쓰게** 했다(복제하면 또 놓친다). 고의 파손으로 확인 — 하니스가 정확히 그 증상으로 실패한다.

⚠️ **`stripFabricated` 는 한 줄 형태를 유지해야 한다.** `test-gemini-citations` 가 route.ts
소스에서 **정규식을 추출**해 쓰기 때문이다(규칙을 복사해 두면 route.ts 가 되돌아가도 통과해
버리므로 그렇게 설계돼 있다). 게이트는 함수를 고치지 말고 **호출부**(`stripCitations`)에 건다.
처음에 함수 모양을 바꿨다가 그 하니스 3건이 깨져 알았다.

**검증** — 두 모델 전부 통과, 카드 블록 중복 없음(각 1개), `npm test` 전 하니스 통과.

### 6.7 검색어 길이가 후보를 붕괴시킨다

두 결함을 고치고 다시 돌린 결과에서 **모델별 검색어 길이 차이**가 남았다. gemini-3.7 은
`probiotics common cold prevention`(3단어), gpt-5.6 은 연구설계어까지 붙여 12단어를 만든다.
**PubMed 는 모든 용어를 AND 로 묶으므로** 후보가 급격히 붕괴한다(실측):

| 주제 | 짧은 검색어 | 긴 검색어 |
|---|---|---|
| 프로바이오틱스 감기 | 54 | **4** |
| 아토피 소아 유산균 | 398 | **1** |
| 말더듬 언어치료 | 865 | **1** |
| 음악치료 불안 | 2,489 | 6 |

한 단어만 더 붙으면 **0건**이 되고, 그러면 수백 건이 존재하는데도 *"논문을 찾지 못했습니다"* 가
나간다 — 조용히 틀리는 쪽이라 두 겹으로 막았다:

1. **프롬프트** — 핵심 개념 2~4개로 쓰고, 사용자가 그 설계를 콕 집어 요청하지 않는 한
   연구설계어(`randomized controlled trial`·`systematic review`·`meta-analysis`)를 붙이지 말라고
   지시한다(설계는 배지가 이미 알려준다).
2. **도구** — `total === 0` 일 때 **한 번만** 앞 4개 핵심어로 넓혀 재시도한다(`broadenQuery`).
   넓힌 결과가 원본과 같으면(이미 짧으면) 재시도하지 않는다. 실측 회복:
   아토피 과잉 12단어 0건 → **183건**, 메트포르민 과잉 0건 → **16,646건**.

넓히는 방식은 두 안을 재보고 골랐다. *연구설계어만 제거* 는 메트포르민 사례에서 여전히 1건에
그쳐(사실상 붕괴 유지) 구제가 안 됐고, *앞 4개 핵심어* 는 두 사례 모두 크게 회복했다.
발동 조건이 `0건` 뿐이라 이미 막다른 상태에서만 동작하므로 거칠어도 손해가 없다.

⚖️ **한 번 잘못 짚었다.** 무의미 질의(`존재하지 않는 가상의 질환 zzzqqq`)가 논문 1건을 물어오는
걸 보고 "넓히기가 만든 회귀" 라고 판단했는데, 재보니 **원본 그대로도 1건이 나온다**(넓히기는
발동조차 하지 않았다). 로그를 잘못 읽었다.

🔴 그러다 진짜를 찾았다 — **PubMed 는 매칭되지 않는 단어를 조용히 버린다.**
`qwertyzzz syndrome treatment` 는 0건이 아니라 **855,923건**이다(`syndrome treatment` 만 남는다).
그래서 "존재하지 않는 주제" 로 0건을 만드는 게 생각보다 어렵고, REF_Paper 의 0건 테스트 케이스가
**실제로는 0건이 아니었다**. 실측 0건인 `zzzqqq disease` 로 교체했다.

### 6.8 가독성 — 문장 수를 주면 한 덩어리가 나온다

실사용 화면에서 산문이 **한 덩어리**로 붙어 나왔다. 처음엔 CSS를 의심했는데 아니었다:

- `ChatMessage.tsx` 의 `p` 렌더러는 이미 `mb-4 leading-relaxed` 를 준다 — 빈 줄만 오면 간격은 정상이다
- 스트리밍·인용마커 제거 어디에도 개행을 지우는 코드가 없다(`gateStreamingTables` 는 표 꼬리만 건드린다)

원인은 프롬프트였다. `INTENT_FOCUS_HINTS` 가 **분량만 주고 모양을 주지 않았다**:

```
write ONLY a short prose answer in the user's language (3-5 sentences)
```

문장 수는 제약이지 구조가 아니다. 모델은 자연스럽게 한 문단으로 쓴다.

**3박자 계약으로 교체했다** — 논문 답변은 실제로 세 박자로 나뉜다.

| 문단 | 내용 | 이유 |
|---|---|---|
| 1 | 결론 한 문장 | 여기서 멈추는 독자가 다수다 — 단독으로 답이 돼야 한다 |
| 2 | 연구가 실제로 보인 것과 한계 (2~3문장) | 인용 마커 `[1][2]` 는 여기 |
| 3 | 마무리 한 문장 | 의료진 상담 / 확인할 것 |

두 가지를 명시했다. **빈 줄이 구분자다**(홑개행은 ReactMarkdown 이 문단으로 끊지 않아 화면에선
여전히 한 덩어리다). 그리고 **헤딩·불릿 금지** — 불릿으로 쓰면 카드와 내용이 겹쳐 두 번 읽힌다.
`3-5 sentences total` 상한은 남겼다. 문단을 나누라는 것이지 길게 쓰라는 게 아니다.

전역 `[FORMATTING & QUALITY]` 에 넣는 안도 있었지만 논문 의도에만 적용했다. 전역은 표·날씨 등
문자열 골든을 잡은 하니스들을 흔들 수 있어 별도 측정이 필요하다.

**검증** — `test-paper-card.mts §4f` 가 두 힌트에서 계약 5가지를 고정하고(계약을 지우면 실패하는지
고의 파손으로 확인), `live-paper-card.mts` 가 실제 출력의 문단 수(≥3)와 첫 문단 길이(≤200자)를 본다.
3.7·luna·arXiv 경로 모두 3문단 통과.

🔴 이 과정에서 하니스 자체 결함 하나를 발견했다. "요약도 도구 출력 그대로다" 검사가
`summaryTranslated === card.papers.length` 였는데, 재조회 정렬이 흔들려 대조 못 한 논문은
`continue` 로 건너뛰어 분자만 줄었다 — **정렬만 흔들려도 절대 통과할 수 없는 거짓 실패**다.
분모를 실제 대조 건수(`compared`)로 고쳤다.

### 6.9 🔴 인용 번호를 다시 매기는 모델 — 참이면서 틀린 답

문단 구조를 고친 뒤 실물을 대조하다 발견했다. 같은 질의·같은 카드(5건)에서:

| 모델 | 마커 | 실제로 인용한 논문 | 판정 |
|---|---|---|---|
| gemini-3.7 | `[5]` `[4]` `[2]` | 5·4·2 | ✅ 3/3 |
| gpt-5.6-luna | `[1]` `[2]` | **4·5** | 🔴 2/2 어긋남 |

luna 의 문장은 **내용이 정확했다**. 4번 메타분석의 `marginal effect` 도, 5번 소아 RCT 의
`school absenteeism` 도 제대로 옮겼다. 다만 번호를 **자기가 언급한 순서로 다시 매겼다** —
처음 언급 → `[1]`, 두 번째 → `[2]`. 카드를 참조 목록이 아니라 자기 각주 목록으로 본 것이다.

사실 오류가 아니라 **귀속 오류**라 위험하다. 산문만 읽으면 완벽하고, 카드에서 1번을 열어본
사용자만 엉뚱한 연구(비타민C·에키네시아 종설)를 만난다. `[n](url)` 형태가 아니라 평문이라
잘못된 이동은 없지만, 사용자가 대조하는 순간 신뢰가 깨진다.

**프롬프트** — `[CITATION NUMBERING]` 블록을 두 힌트에 추가했다. 핵심은 셋이다:
번호는 각주가 아니라 **카드에서의 위치**다 · **건너뛰기가 정상**이다(`[5]…[4]…[2]` 가 옳은
답이고 1·3 을 언급 안 해도 된다) · 관련도 1위가 질문과 무관하면 **`[1]` 을 습관적으로 붙이지
말고 비워둔다**(실제로 비타민C 종설이 프로바이오틱스 질의의 1위로 왔다).

**하니스** — 오프라인은 계약 4가지를 고정하고, 라이브는 **의미 대조**를 넣었다.
한국어 산문 ↔ 영어 초록이라 키워드 겹침으로는 못 잡아 flash-lite 판정을 쓴다.

질문 형태를 두 번 바꿔야 했다:

| 질문 | 결과 |
|---|---|
| "n번 논문이 이 문장을 뒷받침하는가" | 🔴 **오탐** — 한 문장이 두 논문을 묶어 인용하면(`[3][4]`) 절반만 맞아도 no |
| 위를 느슨하게 완화 | 🔴 **미탐** — 비타민C 종설을 메타분석 자리에 넣어도 yes (실측 2/6 오차) |
| **"이 문장은 몇 번 논문을 말하는가"** (논문 목록 전체를 주고 변별) | ✅ 실측 5/5 정확 |

세 번째만 통한다. 번호 다시 매기기는 **변별 질문에서만** 드러난다 — 판정기가 "4·5번"이라
답하는데 모델이 `[1][2]` 를 썼다는 대비가 곧 결함이다. 검증은 luna 의 실제 오답 2건(어긋남
기대)과 gemini 의 실제 정답 3건(맞음 기대, 묶음 인용 포함)으로 했다.

🔴 문장 분리에서 한 번 더 걸렸다. `(?<=다\.)` 로 끊었는데 **마커가 마침표 앞에 붙는다**
(`...내렸습니다 [4]. 어린이를...`). 그래서 경계를 못 잡고 뒷문장의 번호가 앞문장에 딸려
들어가 멀쩡한 답이 어긋남으로 잡혔다. `(?<=[.!?])` 로 고쳤다.

**적용 후 실측** — 3.7·luna·arXiv 세 경로 모두 통과. luna 는 이제 `[4]` `[5]` 로 쓴다.

**남은 것** — 5건 중 2건(23306139·24468694)의 `summary` 가 빈 문자열이다.

⚖️ 원인을 처음에 틀리게 적었다. "구조화된 결론 섹션이 없어 `parseAbstracts` 가 빈손으로
돌아온다" 고 썼는데, efetch 로 확인하니 **그 두 논문은 초록 자체가 없다**(`AbstractText` 0개,
`OtherAbstract` 도 없음). 추출 결함이 아니라 **PubMed 에 데이터가 없는 것**이고, 도구는 옳게
동작했다. 사용자가 PubMed 페이지를 직접 열어 확인해준 덕에 잡혔다.

빈도 실측(5개 질의 × 상위 5건 = 25건): **2/25건(8%)**. 프로바이오틱스 질의에 몰려 있고
나머지 4개 질의는 0건이었다 — 흔하지는 않지만 한 카드에서 2칸이 비면 눈에 띈다.
남은 판단은 추출이 아니라 **표시**다: 빈칸으로 두는가, "초록 없음" 을 밝히는가.

🔴 이것과 **별개로** 진짜 추출 결함이 하나 있다. 27055821 은 초록이 1,933자로 멀쩡히 있는데
카드에 뜬 요약은 `No in vivo or clinical studies were found that investigate the role of
alkalization or earthing...` — 논문의 결론이 아니라 **초록 맨 끝의 곁가지 문단**이다.
`CONCLUSION` 라벨이 없는 초록에서 "마지막 2문장" 을 결론으로 삼는 방식의 한계다.
처음엔 이 둘을 "같은 뿌리" 라고 묶었는데 아니다 — 하나는 데이터 부재, 하나는 추출 방식이다.

### 6.10 🔴 프롬프트로 못 막는 것 — 철회 논문과 초록 없는 논문

카드가 **사실이 아닌 걸 사실처럼 보여주는** 결함 두 개를 같이 잡았다. 뿌리는 다르지만
막는 방법이 같은 것으로 드러났다.

**(1) 철회된 논문이 근거로 인용됐다.**
PMID 40323973 은 `RETRACTED:` 로 시작하는 제목의 철회된 메타분석인데, `종합분석` 배지를
달고 근거 카드 1번에 떴고 모델이 "한 메타분석에서는 ... 위험을 유의하게 낮춘다고
보고했습니다 [1]" 로 인용했다. 등급 배지가 신뢰 신호로 읽히는 자리에서 가장 나쁜 실패다.

판정 자체는 공짜였다 — `pubtype` 에 `Retracted Publication` 이 이미 들어 있다. 추가 호출이
필요 없다. ⚠️ `Retraction of Publication` 은 **뜻이 정반대**(남의 철회 공고)라 같이 잡으면
정상 문헌을 깎는다. `Expression of Concern` 도 철회가 아니다 — 편집자 우려 표명이다.

**(2) 초록이 없는 논문의 공백이 연구 내용으로 둔갑했다.**
PubMed 에 초록이 없는 논문이 실측 8%(5개 질의 × 상위 5건 중 2건). 이때 `summary: ""` 를
보냈더니 모델이 이렇게 썼다:

> 하지만 일부 검토 논문 [1, 3]에서는 프로바이오틱스에 대한 구체적인 결론을 제시하지 않았습니다.

3번(24468694)은 **PubMed 에 초록이 등록돼 있지 않을 뿐**이다. 논문이 결론을 안 냈다는 건
거짓이고, 전문에는 단호한 결론이 있을 수 있다. 데이터 부재를 연구 결과로 옮겨 적은 것이다.

**🔴 둘 다 프롬프트로는 못 막았다 — 이게 이번의 핵심 발견이다.**

| 시도 | 철회 | 초록 없음 |
|---|---|---|
| PROSE RULES 목록 안의 한 줄 | 1/1 실패 | — |
| 전용 블록으로 승격(`[RETRACTED PAPERS]` 등) | **3회 중 2회 실패** | **3회 중 3회 실패** |
| 도구가 `papers` 배열에서 분리 | **3/3 통과** | **3/3 통과** |

세 번 중 한 번은 지시를 지켰다("철회된 메타분석 [3]은 ... 라고 보고했지만"). 지시가 안 읽히는
게 아니라 **확률적으로 읽힌다**. 안전 이슈에 2/3 은 쓸 수 없는 수치다.

그래서 구조로 바꿨다. 인용 마커 `[n]` 은 `papers` 배열의 순번이므로, **배열에서 빼면 모델은
번호로 가리킬 방법이 없다.** 카드를 모델에게 다시 쓰게 하지 않고 코드가 붙이기로 한 것과
(§6.6) 정확히 같은 판단이다 — 모델이 틀릴 수 있는 표면을 지운다.

```ts
return {
    total,
    papers:     papers.filter(p => !p.retracted && p.summaryKind !== 'none').slice(0, limit),
    retracted:  papers.filter(p =>  p.retracted),
    noAbstract: papers.filter(p => !p.retracted && p.summaryKind === 'none'),
};
```

**화면에서까지 지우지는 않는다.** 사용자에게는 둘 다 쓸모가 있다 — 다른 데서 그 논문을
만났을 때 철회 사실을 아는 것, 초록 없는 논문의 원문을 여는 것. 번호 없는 별도 칸으로 내린다.

⚖️ **두 칸을 합치지 않았다.** 철회는 "믿지 마라", 초록 없음은 "우리가 요약을 못 한다" 로 뜻이
전혀 다르다. 한 상자에 담으면 멀쩡한 논문에 철회의 색이 묻는다. 그래서 빨강 상자와 회색
상자를 따로 뒀다. 미분류 배지를 아예 안 그리기로 한 것(§3.2)과 같은 원칙이다.

부수 효과 하나: 목록에서 빠지는 만큼 근거 목록이 얇아진다(프로바이오틱스 질의는 5건 중
2건이 초록 없음 → 3건). `retmax` 를 `limit + 3` 으로 넉넉히 받고 필터 뒤에 `limit` 으로 자른다.

**요약 출처를 이름 붙였다** — `summaryKind: 'conclusion' | 'excerpt' | 'none'`.
`CONCLUSION` 라벨이 붙은 초록만 진짜 결론이고, 라벨 없는 통짜 초록에서 뽑은 것은 **위치로
집은 추측**이다. 27055821(§6.9 정정 참조)이 그 사례였다. 꼬리 보일러플레이트(후속연구 권고,
등록번호, 저작권 문구)를 걷어내고 "In conclusion" 류 신호가 있으면 거기서부터 집도록
고쳤지만, 결론이 아예 없는 종설에서는 여전히 곁가지를 집는다. **못 고치는 건 숨기지 말고
이름을 붙인다** — 카드에 `초록 발췌` 라벨을 달아 "결론"이라고 말하지 않게 했다.

`null` 대신 `'none'` 을 쓴 것도 같은 이유다. JSON 의 `null` 은 모델이 "값 없음" 으로 흘려
읽지만, `'none'` 은 이름이 붙은 상태다.

**하니스에 남긴 것**
- `tests/test-paper-card.mts` §2a(꼬리 보일러플레이트) · §2c(철회 판정, 정반대 값 포함) ·
  §4g(분리·렌더·프롬프트 배선 20종). 결함 3종을 재주입해 4건이 실패하는 것까지 확인했다.
- `tests/manual/probe-retraction.mts` — 실제 4개 PMID 로 도는 라이브 프로브. 규칙이 아니라
  **PubMed 응답**을 본다.
- `tests/manual/live-paper-card.mts` — "번호 매기는 목록에 철회/초록없음 논문이 없다",
  "산문이 PMID 로 우회 인용하지 않았다" 추가. 판정기가 429 외에 **503** 으로도 죽던 것과
  `{"papers": [2, ]}` 같은 깨진 JSON 에 하니스가 통째로 터지던 것도 고쳤다.

### 6.11 검증 라운드 (2026-08-31) — 하니스를 고치니 결함이 더 나왔다

§6.10 을 넣고 나서 "계속 검증" 으로 한 바퀴 더 돌렸다. **고친 것보다 새로 찾은 게 많았다.**

**🔴 렌더러 검사가 전부 정규식이었다.** `test-paper-card.mts` §4 는 소스를 정규식으로 본다 —
"그 코드가 파일에 있다" 까지만 말해준다. 조건이 틀려 영영 안 그려지는 칸도, 한 언어만 깨진
문구도 통과한다. `react-dom/server` 로 **실제 렌더한 HTML** 을 보는 `render-paper-card.mts` 를
새로 만들었다(무네트워크·무자격증명이라 `npm test` 에 들어간다). 결함 3종을 재주입하니 **10건**이
실패했다 — 정규식 하니스는 같은 결함에 4건만 잡았다. 두 검사는 겹치지 않는다.

**🔴 조회 실패가 "논문을 찾지 못했습니다" 로 나가고 있었다.** `error` 필드를 인터페이스에
선언만 해두고 렌더러가 읽지 않았다. PubMed 가 죽어서 아무것도 못 받은 것과 조건에 맞는 논문이
정말 없는 것은 사용자에게 **정반대 뜻**이다 — 앞은 다시 시도하면 되고 뒤는 근거가 없다는
판단이다. 심평원에서 이미 고쳤던 병(`2271bc0`)이 여기서 되살아나 있었다. 호스트를 죽여
실제로 걸어보니 프롬프트를 고친 뒤 두 경로 모두 옳게 답한다:

> gemini: "PubMed 데이터베이스에 연결하는 데 문제가 발생했습니다. 잠시 후 다시 시도해 주십시오."
> luna: "PubMed 데이터베이스에 연결하지 못해 논문 확인에 실패했습니다. 따라서 … 판단할 수 없습니다."

**⚖️ 0건에서 하니스가 멀쩡한 답을 3건 실패로 잡았다.** 없는 병명(`zzzqqq 병`)에 모델은
"알려진 질병명이 아닙니다" 한 문단으로 옳게 답했는데, 하니스가 3문단·인용 번호를 요구했다.
**검사가 틀린 것이지 답이 틀린 게 아니다.** 0건은 실패가 아니라 다른 계약이고, 거기서 지킬 것은
정반대다 — 없는 근거를 지어내지 않았는가(인용 0개·PMID 0개·분리 칸 비었나).

같은 자리에서 **주석과 코드가 어긋나 있었다.** `paper-tool.ts` 는 "0건이면 빈 카드를 띄우지
않는다" 고 적혀 있었지만 코드는 항상 카드를 만든다. 코드를 주석에 맞추려다 멈췄다 — 도구가
카드 없는 평문을 돌려주면 `pinCardToProse` 가 호출되지 않아(`toolMsg` 를 카드 문자열로 찾는다)
**모델이 지어낸 카드가 그대로 통과한다.** 지어낸 논문이 나가는 쪽이 훨씬 나쁘므로 주석을 고쳤다.

**⚖️ 라우팅 흔들림은 라우팅 문제가 아니었다.** `트랜스포머 어텐션 최적화 논문 찾아줘` 가 3회
연속 `general` 로 가길래 §7 에 라우팅 회귀로 적었는데, 유료 키 단독으로는 **12/12 정상**이었다.

| | 트랜스포머 어텐션 | +최적화 | +`arXiv 에서` | 어텐션 최적화 |
|---|---|---|---|---|
| `TIER1=1` (유료) | 3/3 | 3/3 | 3/3 | 3/3 |
| 무료 키 회전 | 2/3 | 2/3 | 2/3 | 3/3 |

실제 체인은 이랬다: **무료 키 일일 쿼터(RPD) 소진 → 라우터 LLM 429 → 규칙 폴백 → 폴백엔
`paper_source` 가 없다 → 비의생명 가드가 `general` 로 강등.** 로컬 개발 환경의 키 상태였고
코드는 멀쩡했다. 라우팅 하니스에만 있던 `TIER1=1` 장치를 카드 하니스에도 붙이고, 폴백을
감지하면 **하니스가 스스로 경고하게** 했다(`console.log` 만 감싸면 놓친다 — 폴백은 `warn`,
쿼터 소진은 `error` 로 나간다).

> ⚠️ 관련해서 열어둘 질문: 규칙 폴백에서 `paper_search` + `isNonBiomedicalPaperTopic` 이면
> 그건 **arXiv 주제라는 강한 신호**다(패턴에 인문·사회 어휘가 하나도 없다 — 전부 ML·반도체·
> 토목이다). `general` 로 버리는 대신 `arxiv_search` 로 보내는 게 나을 수 있다. 다만 문서화된
> 계약(§4c "PubMed 밖 주제는 카드를 만들지 않는다")을 바꾸는 일이라 측정 없이 뒤집지 않았다.

**🔴 멀티턴 — 논문 카드에는 후속 가드가 없다.** REF_Paper §I 를 처음으로 실제로 돌렸다
(신규 `live-paper-multiturn.mts`). 두 결함이 **모델과 무관하게** 재현된다:

| 턴 | 기대 | gemini-3.7 | gpt-5.6-luna |
|---|---|---|---|
| "세 번째 논문 좀 더 설명해줘" | 카드 재조회 없이 산문 | 🔴 `paper_search` → 재검색 → **6건짜리 새 카드** | 🔴 `paper_search` → 재검색 → 1건짜리 새 카드 |
| "지금까지 나온 논문들 표로 정리해줘" | 재조회 없이 표 | 🔴 재검색 → **전혀 다른 논문 5건** 카드 | 🔴 재검색 → 다른 논문 2건 카드 |

화면의 카드를 두고 "세 번째 논문" 을 물었는데 **다른 목록의 카드가 새로 뜬다.** 이번엔 우연히
3번이 같은 논문이었지만 순서가 밀리면 `[3]` 이 딴 논문을 가리킨다 — §6.9 에서 없앤 귀속 오류가
멀티턴으로 되돌아오는 경로다. "표로 정리해줘" 는 더 나쁘다: 재구성 요청인데 **새로 검색해서
지금까지 얘기한 적 없는 논문 카드를 붙인다.**

약국·병원·동물병원·법률 카드는 `cardFollowup` 으로 이 턴들을 `general` 로 보내 카드 원문만
근거로 답하게 돼 있다. 검색 게이트(`shouldSuppressSearchForFollowup`)도 "방금 알려준 거 표로
정리해줘" 를 이미 OFF 로 잡는다. **논문 카드만 어느 쪽에도 연결돼 있지 않다.**
고치려면 그 기계에 `paper` 를 태워야 하는데, 새 주제(`그럼 비타민D 논문은?` — 이건 재검색이
맞다)와 가르는 판정이라 다른 카드들이 그랬듯 전용 측정이 필요하다. §7 로 넘긴다.

**부수 수확 — 하니스 자체의 결함 4건.** ⓐ 판정기가 429 외에 **503** 에 죽었다 ⓑ 판정기가
`{"papers": [2, ]}` 같은 깨진 JSON 을 뱉으면 하니스가 통째로 터졌다 ⓒ "다른 논문으로 새지
않는다" 검사가 무른 어휘 비교라 같은 주제 논문에 오탐했다 ⓓ 제목 어휘만 보는 검사가 **한국어로
풀어 쓰는 모델**(luna)을 오탐했다. 전부 고쳤다. 카드 건수 표기도 `· 1` 에서 `· 1건` 으로
(한국어만) 단위를 붙였다 — 실제 렌더를 보고서야 발견했다.

### 6.12 멀티턴 후속 가드와 "가리킬 곳 없는 마커" (2026-08-31)

§6.11 이 찾아낸 두 결함을 고쳤다. 둘 다 **멀티턴에서만** 드러난다.

**(1) 논문 카드에 후속 가드가 없었다.**
약국·병원·동물병원·법률은 `decideLocationCardFollowup` 이 "화면 카드를 두고 묻는 턴" 을
`general` 로 보내 카드 원문만 근거로 답하게 한다. 논문만 어디에도 안 붙어 있어서, 화면의
카드를 두고 "세 번째 논문 좀 더 설명해줘" 라고 물으면 **PubMed 를 다시 검색해 다른 목록의
새 카드**가 떴다. "표로 정리해줘" 는 더 나빴다 — 재구성 요청인데 얘기한 적도 없는 논문
카드를 새로 붙였다.

`decidePaperCardFollowup(text, paperCardShown)` 를 만들어 날씨 카드와 같은 방식으로 붙였다
(`activeCards` 에 논문이 없으므로 **창 안의 assistant 메시지**를 스캔한다). 판정은 셋:

```
새로 찾아와 신호(`다른 논문`·`더 찾아`·`재검색`)  → new   (우선)
카드 항목 지목(`세 번째`·`2번`·`[3]`·`그 논문`)   → discuss (조회 동사가 없을 때만)
재구성(`표로`·`정리해`·`비교해`·`쉽게`)            → discuss (조회 동사가 없을 때만)
그 외                                              → new
```

⚖️ **조회 동사가 가른다.** `3번 염색체 관련 논문 찾아줘` 는 숫자가 지목이 아니라 주제어다.
⚖️ `그럼 비타민D 논문은?` 은 재조회가 맞다 — 가드가 대화를 가두면 안 된다.
⚠️ 논문 의도일 때만 본다. 논문 카드가 떠 있어도 `오늘 서울 날씨?` 는 날씨로 가야 한다(하니스 5턴).

`discuss` 턴은 `needsSearch=false` 로 간다 — 검색을 켜면 카드에 없는 논문을 끌어와 인용
번호가 가리키는 대상이 어긋난다(날씨 카드와 같은 이유).

**(2) 지난 턴 카드의 번호가 넘어왔다.** 새 카드가 1건뿐인 턴에 모델이 이렇게 답했다:

> 이전 검색 결과에서 비타민 D에 대해 언급된 논문은 … 논문 **[5]** 입니다

`[5]` 는 지난 턴 카드의 번호다. 이번 카드에는 없으니 **가리킬 곳이 없는 마커**가 된다.

🔴 프롬프트에 "마커는 이번 턴 카드만 가리킨다" 를 넣고 재측정했지만 **2회 중 2회 그대로**였다.
철회 논문·초록 없는 논문에 이어 **세 번째**다. 확률적으로만 지켜지는 지시는 계약이 아니다.

그래서 카드를 코드가 붙이는 자리에서 계약도 코드가 지키게 했다 —
`dropMarkersOutsideRange(prose, count)` 로 **1..count 밖 번호만** 걷어낸다.

⚖️ 하지 않은 것 셋. **문장은 지우지 않는다**(그 문장은 논문을 제목으로도 부르고 있어 마커만
빠지면 뜻이 온전하다. 문장을 지우면 모델이 한 말을 우리가 바꾸는 것이다) · **`[3](url)` 은
건드리지 않는다**(grounding 인용 링크지 카드 마커가 아니다) · **카드를 못 읽으면 손대지 않는다**.
⚠️ 범위 **안**의 잘못된 번호(지난 카드 3번을 뜻하는 `[3]`)는 결정적으로 판정할 방법이 없어
못 잡는다. 여기서 없애는 건 눈에 보이는 파손뿐이다.

**🔴 `pinCardToProse` 만으로는 절반만 고쳐진다.** 그건 **최종 메시지**에 걸린다. Gemini 는
산문을 토큰으로 흘려 route.ts 가 **사용자에게 먼저 보내므로** 그 경로에서는 이미 늦다 —
가드를 넣고도 라이브에서 `[5]` 가 그대로 남았다(OpenAI 는 통짜 전송이라 막혔다). §6.6 에서
겪은 "만들어지는 것과 도달하는 것은 다르다" 가 반대 방향으로 다시 나온 것이다.

이벤트 순서를 실측해보니 **도구 종료(#19)가 본문 첫 토큰(#24)보다 먼저**였다. 그래서
route.ts 가 `on_tool_end` 에서 건수를 잡아 스트림에도 같은 규칙을 건다:

```ts
const stripCitations = (t: string) => PINNED_CARD_INTENT_SET.has(detectedIntent)
    ? dropMarkersOutsideRange(t, pinnedPaperCount) : stripFabricated(t);
```

건수를 못 잡으면 0으로 남아 아무것도 하지 않는다 — 오늘 동작 그대로다. 청크 경계는 기존
`incompletecitation` 버퍼가 이미 처리한다(마커가 쪼개진 채로 규칙에 닿지 않는다).
`stripFabricated` 의 한 줄 형태는 유지했다 — `test-gemini-citations` 가 route.ts 소스에서
정규식을 **추출**해 쓰므로 모양을 바꾸면 그 하니스가 규칙을 못 찾는다.

**하니스도 같이 고쳤다.** `live-paper-card.mts`·`live-paper-multiturn.mts` 가 route.ts 의 마커
처리를 재현하지 않아 **사용자가 보지 않는 글을 검사하고 있었다.** 규칙을 복제하지 않고
`dropMarkersOutsideRange` 를 그대로 import 한다.

**측정**

| | gemini-3.7 | gpt-5.6-luna | gpt-5.4-mini |
|---|---|---|---|
| 멀티턴 7턴 (가드 전) | 🔴 2건 실패 | 🔴 2건 실패 | 🔴 1건 실패 |
| 멀티턴 7턴 (가드 후) | ✅ | ✅ | ✅ |

오프라인은 `§4h`(판정 18케이스) · `§4e2`(마커 16케이스) · `§4e3`(스트림 배선 8케이스).
결함 재주입 검증: 판정 함수 무력화 4건 · 마커 규칙 3종 재주입에 8·1·1건 적발.

⚖️ 하니스의 검사 하나가 두 번 틀렸다. "3번 논문을 설명했는가" 를 **제목 어휘**로 보다가
ⓐ `children` 이 `schoolchildren` 안에 들어 있어 정답을 오탐하고 ⓑ 한국어로 풀어 쓰는
모델(luna·gpt-5.4-mini)이 영어 제목을 인용하지 않아 미탐했다. gpt-5.4-mini 는 "학령기 아동,
두 균주, 하루 2회 3개월, 결석 감소" 로 정확히 설명했는데 제목 한 단어도 안 겹쳤다.
`live-paper-card.mts` 에서 검증된 **LLM 변별 판정기**로 갈아끼우니 3경로 모두 3번을 맞혔다.

### 6.13 🔴 arXiv 는 단어를 OR 로 묶는다 (2026-08-31)

화면에서 잡혔다. "트랜스포머 어텐션 최적화 논문 찾아줘" 의 카드 5건 중 2건이 **"optimization" 하나만
걸린 무관 논문**이었다 — 다항식 최적화(math.OC), 프레임 구조 설계(cs.CE). `all:<질의>` 는 공백을
OR 로 해석한다.

실측 비교(2026-08-31, arXiv 차단 해제 후):

| 질의 | `all:<전체>` (OR) | AND 로 묶기 |
|---|---|---|
| transformer attention optimization | 576,986건 · 상위 5 중 **2건 무관** | 2,776건 · 상위 5 전부 관련 |
| semiconductor lithography defect detection | 317,319건 · 3위가 *자성 반도체 초격자* | 3건 · 전부 관련 |
| bridge seismic design | 334,543건 · 상위 3에 **교량 논문 0건** | 10건 · 전부 교량 |
| monetary policy inflation | 80,600건 | 98건 |
| reinforcement learning reward shaping | 604,500건 | 1,089건 |

`all:"구문 전체"` 는 다섯 질의 모두 **0건**이라 대안이 못 된다. 따옴표 색인이 없다.

`buildArxivSearchQuery(query)` — 순수 함수로 분리해 조립을 테스트 가능하게 뒀다:
- 단어별로 `all:` 을 붙여 ` AND ` 로 잇는다
- 기능어(`is`·`the`·`for`·`all`·`using`…)는 뺀다 — arXiv 가 색인하지 않아 AND 에 끼우면 통째로 0건이 된다
- 이미 arXiv 문법이면(`cat:`·`ti:` 같은 필드 접두사, `AND`/`OR`) **손대지 않는다.** 한 번 더 감싸면 `all:all:` 이 된다

🔴 **0건을 OR 로 넓히지 않는다.** 처음엔 희소 질의를 구하려고 폴백을 넣었다가 뺐다:
`sourdough fermentation microbiome kinetics` 는 AND 0건인데 **그게 정답이다**(arXiv 에 없는 분야).
넓히면 "kinetics" 하나만 걸린 논문이 근거로 올라온다. 무의미어는 더 심해서
`zzqqxx nonexistent topic` 이 35,416건의 토픽모델링 논문을 물어 왔다. §3 의 "arXiv 는 PubMed 처럼
빈손으로 실패하지 않는다" 가 바로 이 실패인데, 폴백이 그걸 **되살리고 있었다.** 빈손이 낫다.

이 결함은 하니스가 전부 초록색인 채로 살아 있었다. 모든 검사가 **산문↔카드** 일치만 보고
**카드↔질문** 관련도는 아무도 보지 않았기 때문이다. 관련도는 지금도 자동 검사가 없다 —
`§4d2` 는 조립된 질의 문자열만 고정한다.

### 6.14 🔴 하니스가 재구현한 루프는 하니스가 아니다 (2026-08-31)

카드 6종(약국·병원·동물병원·법률·영화·날씨)이 통째로 화면에 도달하지 않는 회귀를 **배포했다.**
하니스 16종이 전부 초록이었고, 사용자 로컬에서 날씨가 `empty_model_response` 로 죽어서 잡혔다.

원인은 한 줄이었다. §6.9 배선을 넣으며 `on_tool_end` 를 이름 없이 잡았는데:

```
263  else if (on_tool_end)                                    ← 새로 넣은 분기
320  else if (on_tool_end && ['pharmacyTool'…'weatherTool'])  ← 죽음
331  else if (on_tool_end && ['search_web', …])               ← 죽음
```

else-if 체인이라 앞 분기가 뒤를 **삼켰다.** 날씨는 카드가 곧 본문인 fast-pass 라
`fullAiResponse` 가 비어 502 로 터졌고, 나머지 5종은 카드만 조용히 사라졌을 것이다.

**하니스가 왜 못 봤나.** 이 이벤트 루프는 `route.ts` 의 `ReadableStream` 안에 인라인이라
import 가 불가능했다. 그래서 `test-gemini-citations` 는 소스에서 정규식을 **뽑아** 루프를
흉내 냈고, 나머지도 각자 재구현했다. 흉내 낸 루프에는 결함이 사는 **분기 순서가 없다.**
복사된 규칙이 위험하다는 건 `tests/README.md` 에 적혀 있었는데, 재구현도 같은 병이라는 건
적혀 있지 않았다.

**고친 방식 — 테스트를 늘리지 않고 코드를 옮겼다.** 루프 119줄을
`server/agent/stream-dispatch.ts` 의 `createStreamDispatch(sendEvent)` 로 뺐다. 상태
(`fullAiResponse`·`allSources`·`detectedIntent`·`lcCitationBuffer`·`pinnedPaperCount`)는
`state` 로 노출하고 route.ts 는 `for await (const event of streamEvents) dispatch.handle(event)`
한 줄만 남는다(403줄 → 254줄).

동작 보존은 **눈이 아니라 diff 로** 확인했다 — 이동 전후를 변수 참조와 들여쓰기만 정규화해
비교하니 119/119 동일. `continue` 3개가 `return` 이 된 것만 다르고, 셋 다 분기 선두라 의미가 같다.

`test-stream-dispatch.mts` 가 진짜 `createStreamDispatch` 에 가짜 이벤트를 먹이고 **나온
프레임**을 본다(22건, 모델·네트워크 없음). 회귀를 재주입하니 **11건이 동시에 빨개졌다** —
카드 6종 + 웹 출처 + law_search + 본문 채움. 원래 사고 때 초록이던 자리들이다.

덤으로 하니스 3종의 재구현본을 지우고 진짜 코드를 부르게 했다(`test-gemini-citations` §6,
`test-card-followup`, `test-chat-models`). §4e3 의 소스 정규식 검사도 걷어냈다 — 그건 내가
**이미 아는** 회귀만 잡았고, 다음 번 분기 순서 사고는 못 잡는다.

⚖️ 남는 것: 소스 검사 한 줄만 남겼다 — *루프가 route.ts 로 되돌아오지 않았는가*. 되돌아가는
순간 하니스가 다시 눈이 멀기 때문이다.

### 6.15 🔴 화면 카드가 다음 턴을 끌어당긴다 — 라우팅 3건 (2026-08-31)

§6.14 리팩터링 후 사용자가 카드 8종을 로컬에서 훑다가 나온 것들이다. **셋 다 기존 결함**이고
(오늘 라우터 diff 는 `validIntents` 에 논문 2종 추가와 로그 한 줄뿐) 셋 다 성격이 같다 —
**LLM 이 규칙을 뒤집는데 아무도 말리지 않는다.**

| # | 증상 | 원인 | 성격 |
|---|---|---|---|
| A | 날씨 카드가 뜨면 "서초구 소아과"·"오디세이 영화정보" 가 weather 로 | 라우터 프롬프트가 카드 존재를 알려주니 지명을 새 도시로 읽음 | LLM 2/2 |
| B | 법률 카드가 뜨면 **무엇을 물어도** law_search | `decideLawInteraction` 의 catch-all `return 'lookup'` | 결정적 100% |
| C | "서초구 소아과" → 빈 **약국** 카드 | 규칙은 hospital_search 인데 LLM 이 pharmacy_search | LLM 3/3 고정 |

#### A · 날씨 흡입 — 대조군이 원인을 확정했다

```
날씨 카드 있음: "서초구 소아과"    → weather          llmFollowUp=new
카드 없음:     "서초구 소아과"    → pharmacy_search
날씨 카드 있음: "오디세이 영화정보" → weather
카드 없음:     "오디세이 영화정보" → movie_search
```

카드의 **존재 자체**가 원인이다. `decideWeatherFollowup` 은 날씨 어휘가 없어 `none` 을 돌려주고
아무 교정도 하지 않았다 — 그 함수의 관심사가 아니다. `강남역 근처 약국`·`근처 동물병원` 은
안 끌려갔다(`llmFollowUp=unrelated`). **지명 + 약한 카테고리 신호**일 때만 발생한다.

`resolveWeatherStickiness` — 카드가 떠 있고 **규칙이 다른 카드 의도를 확언**할 때만 뒤집는다.
`general` 이면 판단 근거가 없다는 뜻이라 LLM 을 믿는다("내일은?"·"부산은?" 이 여기 속하고,
이걸 뒤집으면 날씨 멀티턴이 통째로 깨진다). 날씨 규칙이 날씨 어휘를 요구하므로, 규칙이 다른
카드 의도를 냈다는 건 그 문장에 날씨 어휘가 **없다**는 뜻이기도 하다.

#### B · 법률은 비대칭이었다

날씨 후속 판정에는 `unrelated` 가 있는데 법률에만 없었다. `오늘 서울 날씨 어때?` 조차
`lookup` 을 반환한다. 진입 조건이 `lawCardShown && latest === 'law'` 를 포함하므로,
법률 카드가 화면에 있는 동안 **모든 턴**이 law_search 였다.

`LAW_SIGNAL`(조문 번호·법령명·법률 어휘)과 `LAW_CARD_REF`(이 조항·위 규정)를 두고,
진입 근거가 카드뿐일 때(`intentIsLaw=false`) 신호가 없으면 `unrelated` 로 빠진다.
법령명 매칭은 조사를 허용해야 한다 — `[가-힣]{2,}법(?![가-힣])` 은 "산업안전보건법**은**" 을
놓친다. 뒤에 조사를 허용하고 앞에 `방`·`요`·`문` 등을 lookbehind 로 막았다(해결방법·치료요법·문법).

#### C · 진료과명을 약국으로 읽는다

```
"서초구 소아과"·"강남 이비인후과"·"분당 피부과"·"근처 치과"  → 3/3 전부 pharmacy_search
"서초구 정형외과"·"서초구 내과 알려줘"·"서초구 안과 어디 있어" → 3/3 정상
```

흔들림이 아니라 **고정된** 오분류다. 동사가 붙으면 맞는 걸 보면 "지역 + 진료과" 라는 모양에
걸리는 듯하다. 화면에는 빈 약국 카드가 떴다.

⚖️ 왜 프롬프트가 아니라 코드인가. 약국 규칙은 `약국`/`pharmacy` 라는 **말 자체**를 요구하고
병원 규칙은 진료과명을 명시 열거한다 — 이 충돌에서 규칙이 더 정밀하다. 규칙이 병원이라고
말하는 순간 텍스트에 약국이라는 말이 **없다**는 뜻이다. `resolveClinicIntent` 는 약국→병원
**한 방향**만 본다. 반대는 실측에 없었고, 넓히면 LLM 이 맥락으로 옳게 고른 경우까지 되돌린다.

#### 확인

셋 다 실제 라우터(TIER1)로 전후를 재현했다: A 8/8(1건은 기대치가 틀렸던 것 — `내일 비와?` 의
`refine` 은 5일 예보가 카드에 있으니 재조회 없이 답하는 설계다), B 4/4, C 7/7.
가드 3개를 무력화해 재주입하니 `test-intent-rules` 6건 + `test-card-followup` 1건이 실패한다.

### 6.16 🔴 병원 도구 — 진료과가 없었고, 종별 코드표가 한 칸 밀려 있었다 (2026-08-31)

§6.15 로 라우팅을 고치자 다음 층이 드러났다. "서초구 소아과 알려줘" 가 이제 hospital_search 로
제대로 가는데, **화면엔 치과병원 4곳**이 나왔다.

#### 원인 1 — 진료과 파라미터가 아예 없었다

도구 스키마에 `sido_name`·`sigungu_name`·`dong_name`·`hospital_name`·`hospital_type`(종별)만
있었다. 모델은 "소아과" 를 넣을 자리가 없자 `hospital_type='의원'` 으로 **바꿔 넣었고**,
진료과는 그대로 증발했다. 심평원 API 는 `dgsbjtCd`(진료과목코드)를 받는다 — 실측(서초구):

| 코드 | 과 | 건수 | 코드 | 과 | 건수 |
|---|---|---|---|---|---|
| 01 | 내과 | 309 | 12 | 안과 | 88 |
| 05 | 정형외과 | 157 | 13 | 이비인후과 | 147 |
| 10 | 산부인과 | 98 | 14 | 피부과 | 468 |
| 11 | 소아청소년과 | 150 | 15 | 비뇨의학과 | 98 |

`subject` 인자를 추가하고 `DGSBJT_CODE` 로 매핑했다. **모델이 또 종별 자리에 진료과를 넣을 것**을
전제해, `clCd` 가 안 나왔는데 진료과 코드가 나오면 그걸 진료과로 건진다 — 실측으로 두 경로 모두
같은 결과를 낸다.

정렬도 손봤다. `dgsbjtCd` 필터만으로는 그 과를 **운영하는** 종합병원이 의사수 순으로 상위를
독식한다(서울성모병원은 실제로 소아과가 있다 — 틀린 결과가 아니다). 다만 "소아과 알려줘" 에
대학병원 5곳은 사용자가 기대한 답이 아니라, 이름에 과가 들어간 곳에 가산점을 준다.

#### 원인 2 — 🔴 종별 코드표의 뒤쪽이 통째로 한 칸 밀려 있었다

응답의 `clCdNm` 과 대조하니:

| 우리 표 | 실제 | | 우리 표 | 실제 |
|---|---|---|---|---|
| 의원 → 41 | **치과병원** | | 치과의원 → 61 | **조산원** |
| 치과병원 → 51 | **치과의원** | | 한의원 → 92 | **한방병원** |
| 정신병원 → 31 | **의원** | | | |

사용자 스크린샷의 "서초구 **의원** 병원 검색 → 치과병원 5곳" 이 정확히 이것이다.
서울 응답으로 하나씩 확인해 고쳤다: `01 상급종합 · 11 종합병원 · 21 병원 · 28 요양병원 ·
29 정신병원 · 31 의원 · 41 치과병원 · 51 치과의원 · 61 조산원 · 71 보건소 · 72 보건지소 ·
92 한방병원 · 93 한의원`.

⚖️ **조용히 틀리는 종류라 오래 남았다.** 카드는 정상으로 보이고, 병원 목록도 진짜 병원이며,
주소도 맞다. 사용자가 "의원을 물었는데 왜 치과병원이지" 를 알아채야만 드러난다. 하니스도
못 잡았다 — 네트워크를 안 타므로 `clCdNm` 을 볼 수 없고, 코드값은 그냥 상수였다.
그래서 **값 자체를 골든으로 고정**했다(8종). 표가 다시 밀리면 실패한다.

#### 원인 3 — 🔴 나도 코드표를 기억으로 적었다

`DGSBJT_CODE` 에 15개를 적었는데 **절반이 측정이 아니라 기억이었다.** 바로 위(원인 2)에서
"코드표가 한 칸 밀려 있었다" 를 잡아 놓고 옆에 검증 안 된 표를 새로 심은 것이다.

이름 일치율로 역산해 보니 **흔한 과일수록 판별이 안 된다** — 코드 01 을 서울 의원 4,756곳이
신고한다. 내과의원이 아닌 곳도 내과를 **부수 과목**으로 달기 때문에 이름 일치율이 희석된다.
`12 안과`(2위 대비 24.9배)·`10 산부인과`(11배)·`03 정신건강의학과`(7.3배)는 확정됐지만
`01 내과`·`04 외과`·`05 정형외과`·`09 마취통증의학과`는 추론으로 확정 불가였다.

**답은 API 안에 있었다.** `MadmDtlInfoService2.8/getDgsbjtInfo2.8` 이 `ykiho` 로 병원별
진료과목을 준다(목록 API 에는 진료과목 필드가 아예 없다 — 이름·주소·의사수·좌표뿐이다).
큰 병원 몇 곳을 조회하니 **코드-이름 쌍 43개**가 그대로 나왔다. 같은 계정 키를 쓴다.

독립 교차검증도 통과했다. "간판이 하나뿐인 의원을 과별로 골라 어느 코드가 그 병원을
돌려주는지" 보는 방법(코드 00~26 전수)의 결과가 상세 API 표와 **전부 일치**한다 —
신경과[02] · 영상의학과[16] · 비뇨의학과[15] · 피부과[14] · 소아청소년과[11] 는 단일 코드로
떨어졌고, 여러 과를 신고한 표본도 전부 정답 코드를 포함했다.

#### 표에 없는 과는 버리지 않는다

코드가 43개여도 사용자는 아무 말이나 할 수 있다("통증클리닉"). 그때 **조용히 버리는 게
원래 결함**이었으므로, 코드가 없으면 간판 이름으로 거른다(`yadmNm` 부분일치). 이름에 과가
없는 곳은 놓치지만, 엉뚱한 병원을 근거처럼 내미는 것보다 낫다.

0건 문구도 갈랐다. "못 찾았습니다" 로 끝내면 사용자가 다음에 뭘 할지 모른다 —
진료과를 물었는데 0건이면 **그 지역에 그 과가 없다**는 뜻이므로 그렇게 말하고 범위를
넓히라고 안내한다(구 → 시/도). 조회 **실패**와는 다른 상황이라 문구도 달라야 한다.

#### 확인

`subject=소아과` → 연세곰돌이·반포키즈·파스텔연세 소아청소년과의원.
`hospital_type=소아과`(모델 실수 경로) → 같은 결과. `종별=의원` → 성형외과·영상의학과 의원.
`치과의원`·`한의원`·`종합병원` 전부 해당 종별만 나온다.
`재활의학과`(21)·`가정의학과`(23)·`치과교정과`(52)·`한방소아과`(82) 도 해당 과만 나온다.
`통증클리닉`(표에 없음) → 0건 + "인접 지역이나 더 넓은 범위로" 안내.

### 6.17 🔴 상태를 둘로 가른 리팩터링 · 영화 규칙의 구멍 (2026-08-31)

사용자가 §6.15 시퀀스를 로컬에서 그대로 돌려 두 건을 더 잡았다.

#### A · 답변이 두 번 찍혔다 — **내가 낸 회귀**

"2026년 노벨 물리학상 수상자 알려줘" 의 답변이 화면에 그대로 두 번 나왔다.

§6.14 에서 이벤트 루프를 빼면서 `fullAiResponse` 가 **둘로 갈렸다**. route.ts 의
`trackingEvent`(그래프가 노드 안에서 직접 부르는 전송 콜백)는 route.ts 지역 변수에 쌓는데,
디스패치는 자기 `state.fullAiResponse` 를 보고 "아직 아무것도 안 나갔다" 고 판단해
`on_chain_end generator` 에서 최종 메시지를 **다시** 보냈다. 인라인이던 시절엔 같은 변수라
성립하던 판정이 옮기면서 깨진 것이다.

→ **콜백도 디스패치가 만든다**(`dispatch.trackingEvent`). 상태가 하나여야 그 판정이 성립한다.
route.ts 에는 이제 `fullAiResponse`·`allSources` 지역 변수가 없다.

⚖️ 새 하니스가 이걸 못 잡은 이유가 중요하다. `test-stream-dispatch` 는 디스패치**만** 태웠고
route.ts 와의 접점은 여전히 밖이었다 — §6.14 와 **같은 사각지대가 한 층 위로 옮겨간** 것이다.
콜백을 디스패치 안으로 들이면서 그 접점이 하니스 안으로 들어왔고, 재주입하니 화면에서 본
그 문자열이 그대로 재현된다("…발표됩니다.…발표됩니다.").

#### B · "오디세이 영화" 가 날씨로 갔다

화면에 **"도시를 찾지 못했어요 '오디세이'"**(날씨 카드의 빈 상태)가 떴다. §6.15 의 흡입 가드가
있는데도 새어 나갔다 — 가드는 **규칙이 다른 카드 의도를 확언할 때만** 뒤집는데,
`classifyIntentByRules("오디세이 영화")` 가 `general` 이었다.

영화 규칙이 `영화 + 상영/정보/예매` 를 요구해서 **제목이 앞에 오는 모양**을 못 잡았다:
`오디세이 영화` · `영화 오디세이` · `영화 오디세이 정보` · `듄 파트2 영화` 전부 general.

⚠️ 오탐 비용이 크므로(잘못 잡으면 검색 OFF + 렌더러 스펙 주입) **제목처럼 생긴 짧은 질의만**
잡도록 좁혔다 — 토큰 2개 이하 + 일반 수식어 제외. `인생 영화 추천해줘` · `무서운 영화 보고
싶다` · `한국 영화 역사` · `영화 같은 인생이네` · `영화 산업 전망은?` 는 그대로 general 이다.

**규칙과 가드가 물려 있다**는 게 이번 교훈이다. 가드를 보수적으로("규칙이 확언할 때만") 짠
대가로, 규칙의 구멍이 곧 가드의 구멍이 된다. 가드를 넓히는 대신 규칙을 정확히 하는 쪽을
택했다 — 가드를 넓히면 `내일은?`·`부산은?` 같은 진짜 날씨 후속까지 위험해진다.

### 6.18 🔴 검색 턴에는 화면이 모델에게 안 갔다 — 영화 바꿔치기 (2026-08-31)

3턴 시퀀스에서 나왔다:

```
1턴  "영화 오디세이"            → 상영표 카드 (CGV 강남 22:40 / 롯데 가산디지털 20:50)
2턴  "오디세이 영화 줄거리"      → "상영표에는 없어요. 웹에서 검색해 드릴까요?"
3턴  "ㅇㅇㅇ 검색해서 설명해줘"   → 🔴 "'오디세이'라는 제목의 영화는 찾기 어렵지만,
                                   '마션'이라는 영화가 …" + 마션 줄거리
```

**화면과 정면으로 모순된다.** 오디세이는 바로 위 카드에서 두 극장에 걸려 있다.

**확정된 것.** `general` + 검색 턴은 우리 `search_web` 이 아니라 Gemini 내장 grounding
(`tools: [{ googleSearch: {} }]`)을 쓴다 — **검색어를 모델이 직접 짓는다**(화면의 [1][2][3] 칩과
tistory·나무위키 출처가 그 증거다). 그리고 웹에는 내용이 넘친다: `search_web('오디세이 영화
줄거리')` 첫 결과가 "놀란 2026년작 · 8월 5일 국내 개봉 · 오디세우스(맷 데이먼)" 다.
즉 **검색이 못 찾은 게 아니라 오디세이를 검색하지 않았다.** 오디세이는 2026-07/08 개봉이라
모델 학습 시점 이후이고, "그런 영화 없다" 고 판단하면 검색어 자체가 마션이 된다.

**확정 안 된 것 — 재현 실패(8/8).** 주입 게이트가 원인이라고 썼다가 정정한다. `generator.ts` 가
`movieContext` 를 `movieFollowup` 일 때만 넣어 검색 턴에는 화면 상영작이 전달되지 않는 것은
사실이지만, **그게 마션 사고의 원인이라는 건 확인하지 못했다.** 대조군(카드 주입 끈 상태 =
수정 전)으로 8회 돌렸고 **8회 모두 오디세이를 정확히 답했다**:

| 조건 | 횟수 | 결과 |
|---|---|---|
| 되묻기 메시지만 · TIER1 | 3 | 3/3 정상 |
| 되묻기 메시지만 · 무료키 | 2 | 2/2 정상 |
| **실제 3턴 히스토리 전체**(카드 블록 + 되묻기) · TIER1 | 3 | 3/3 정상 |

사용자가 "그냥 물어보면 잘 대답한다" 로 확인한 것과 합치면, **모델이 오디세이를 모르는 게
아니다** — 개봉일·출연진·촬영·흥행까지 출처 6개로 정확히 답한다. 그러니 "학습 시점 이후라
모른다" 가설은 기각된다.

남은 가설은 grounding 의 확률적 실패다. 첫 시도에서 한 번 `Grounding stage1 empty — retrying
once with next key` 로그를 봤고, 1단계가 빈손이면 모델이 자기 지식으로 조용히 메운다.
그때 학습에 없는 제목이면 비슷한 작품(마션 = 화성 생존기)으로 갈아탄다 — 증상과 맞는다.
다만 그 로그와 사고를 **같은 실행에서** 본 적이 없으므로 이것도 아직 추정이다.

⚖️ 재현이 안 됐어도 §6.18 수정은 유지한다. 검색 턴에 화면 데이터가 안 가는 것은 원인 규명과
무관하게 그 자체로 결함이고(모델이 사용자가 보는 것을 못 본다), 이 실패 모드를 **덜** 나게 한다.
다만 "이게 원인이었다" 고는 말할 수 없다.

→ `movieSearchTurn` 플래그를 state 에 추가하고(라우터가 `forceSearch` 를 그대로 내보낸다),
generator 의 게이트를 `movieFollowup || movieSearchTurn` 으로 넓혔다. 실측 확인:
2턴 `movieFollowup=true·search=false`, 3턴 `movieSearchTurn=true·search=true`.

⚖️ 프롬프트 규칙도 한 줄 붙였다 — "화면에 표시된 제목은 실재하는 상영작이며, 검색 결과가
부실해도 다른 영화로 바꿔 답하지 말 것". 이번 주에 프롬프트로 세 번 졌지만 여기는 성격이
다르다: 저 세 번은 모델이 **볼 수 있는** 데이터를 오독한 경우였고, 이번엔 데이터가 아예
전달되지 않았다.

🔴 **남은 일 — 근본 원인 미확정.** 재현되지 않았으므로 이 사고는 닫히지 않았다. 다음에 같은
증상을 보면 `Grounding stage1 empty` 로그를 함께 확인할 것. 확률적 실패가 맞다면 고칠 곳은
프롬프트가 아니라 **grounding 1단계가 빈손일 때의 처리**다(지금은 조용히 모델 지식으로 메운다).
그때는 우리 `search_web` 결과를 대신 넣는 쪽이 옳다 — 위에서 봤듯 그쪽은 정확히 찾아온다.

### 6.19 🔴 맞는 데이터가 무겁다 — 코드표 수정의 부작용 (2026-08-31)

### 6.20 🔴 규칙이 침묵하면 LLM 이 원칙을 뒤집는다 — "내일은?" (2026-08-31)

`부산 날씨 어때?` 뒤의 `내일은?` 이 카드를 다시 그렸다. 처음엔 설계상 "미래 시점 = 새 조회"
라고 적었는데, 코드를 따라가 보니 **그 반대**였다. `weather-followup.ts` 가 스스로 적어 둔
원칙은 이것이다:

> 새 조회의 유일한 근거는 **다른 지역이 지목됐는가**다.
> ① 카드는 이미 +5일 예보를 담고 있다 — "내일 비와?"에 재조회해도 **같은 데이터**가 온다.

즉 `내일은?` 은 refine 이 옳다. 그런데 그 발화에는 **규칙 신호가 하나도 없다**:

| 신호 | `내일 비와?` | `내일은?` |
|---|---|---|
| 지역 지목 | 없음 | 없음 |
| 날씨 어휘(`비와`) | **있음 → strongRefine** | 없음 |
| 결과 | refine (rule) | **LLM 판정으로 떨어짐** |

`내일` 은 `TIME_TOKEN` 이라 지역 후보에서 정확히 걸러진다 — 규칙은 제 일을 했다. 문제는 그
다음이다. 규칙이 침묵하면 LLM 판정이 그대로 결론이 되고, LLM 이 `new` 를 고르면 **문서에
적힌 원칙이 뒤집힌다.** 사용자에게는 같은 카드가 한 번 더 그려지므로 아무 일도 안 일어난 것처럼
보인다(5일 예보가 이미 카드에 있으니 내용도 같다).

→ 시점만 옮긴 **단독 재질의**(`내일은?`·`모레는?`·`주말은?`)를 `strongRefine` 에 넣었다.
도시 판정과 시점 판정이 **같은 정규식**(`REASK`)을 보게 상수로 올렸다 — 복제하면 갈라진다.
지역 재질의(`부산은?`)는 `newFetch` 가 먼저 잡으므로 영향이 없다.

실측: `내일은?`·`모레는?` → `refine rule` · `general` · 검색 off. `서울은?` → `weather` 유지.
기존 27케이스 회귀 0.

⚖️ 오늘 세 번째로 같은 모양이다 — §6.15(날씨 흡입)·§6.17(영화 규칙 구멍)·여기.
**규칙과 LLM 이 물려 있는 구조에서는, 규칙의 침묵이 곧 LLM 의 자유다.** 가드를 보수적으로
짤수록(= 규칙이 확언할 때만 개입) 규칙의 빈칸이 그대로 결함이 된다.

### §6.21 "성남" 상영표에 **울산성남**이 떴다 — 부분문자열 매칭의 사각

사용자 관측: `성남 영화 상영표` → CGV 칸에 **울산성남**. 울산 남구 지점이다.
`resolveBranch` 는 `b.nm.includes(q)` 로 후보를 찾는다 — 다른 도시의 지점이 질의를
부분문자열로 품고 있어도 통과한다.

**고치기 전에 blast radius 부터 쟀다.** 질의형 지명 106종(시도·서울 25구·주요 상권)
× 3체인 = 318회 전수. 비접두 매칭(질의로 **시작하지 않는** 지점이 선택된 경우) 22건 중
실제 오답은 **4건**이었다:

| 질의 | 나온 지점 | 왜 오답인가 |
|---|---|---|
| 성남 × CGV | 울산성남 | 울산 남구. CGV 는 성남시에 지점이 없다 |
| 하남 × CGV | 광주하남 | 광주광역시 하남산단 ≠ 경기 하남시 |
| 양주 × 메가 | 평내호평역(구.남양주) | 남양주시 ≠ 양주시 |
| 성동 × 롯데 | 마산(합성동) | 창원 마산 ≠ 서울 성동구 |

나머지 18건은 **정상**이었다 — 동수원·북포항·프리미엄안동(같은 도시 안), 강남역→강남·
잠실→월드타워·삼성역→코엑스(의도된 별칭), 에비뉴엘(명동)·프리미엄해운대(장산역).

🔴 **규칙으로는 못 가른다.** 처음엔 "질의가 알려진 다른 도시명 뒤에 붙으면 배제" 를 생각했는데
4건 중 2건만 잡는다. 구조를 봐도 마찬가지다 — `북포항`(정답)과 `남양주`(오답)는 둘 다
`방위+질의` 모양이고, `동수원`(정답)과 `합성동`(오답)은 둘 다 질의가 토큰의 접미어다.
같은 모양을 가르는 건 지명 지식뿐이라, `REGION_ALIASES` 와 같은 이유로 **관측된 4건의
손 관리 배제 목록**(`BRANCH_EXCLUDE`)으로 갔다. 규칙인 척하는 규칙보다 정직하다.

**덤으로 나온 것 — 시·도 단위 질의.** `경기` → 메가박스 **상암월드컵경기장**(서울)이었다.
"경기도" 가 아니라 "경기장" 을 문 것이다. 도 안의 아무 지점을 주는 것(`경기`→경기광주,
`충북`→충북혁신, `경북`→경북도청, `경남`→프리미엄경남대)도 답이 아니다 — 사용자는 그걸
자기 지역 회차로 읽는다. `PROVINCE_ONLY` 는 매칭 실패로 떨어뜨려 "지점 없음" 안내를 태운다.
`제주`·`광주`·`대구` 처럼 도이면서 시인 이름은 넣지 않았다(실제 지점이 있다).

**테스트가 없던 파일이었다.** `tests/test-theaters.mts` 신규(28검사). 적용 **전에** 먼저 짜서
12건이 빨간 걸 확인하고 고쳤다 — 그 과정에서 내 기댓값 하나(`광주`→광주금남로)가 틀린 것도
드러났다(실제·정답은 광주상무, 더 짧다). 사후 전수 재측정: 비접두 매칭 22→15건, 남은 15건은
전부 같은 도시이거나 별칭이다.

### §6.22 판정은 맞았는데 아무 일도 안 일어났다 — `paperFollowup` 배선 누락

멀티턴 3턴 실측(gpt-5.6-luna). 잘 된 것부터: 서수 지목이 카드 3번을 정확히 집었고,
2·3턴 모두 **재검색이 없었다**(§4h 가드가 의도대로 작동). 인용 번호도 카드 순서와 맞았다.

🔴 그런데 2턴 답변이 이렇게 나갔다:

> **주요 결과** — 연구에서 확인하려 한 주요 결과는 다음과 같습니다.
> · 감기에 걸린 횟수 · 증상 지속 기간 또는 중증도 · 발열·기침·콧물 등 증상
> · 감기로 인한 학교 결석 · 복용과 관련된 이상반응

카드가 가진 초록은 **한 문장**이다 — `A two-strain probiotic combination given twice a day
for 3 months was able to reduce the symptoms of the co…`. 맞게 쓴 부분(두 균주·3개월·하루 2회)은
전부 이 문장에서 나왔고, 5개 항목은 "RCT 라면 이랬겠지" 다. 그걸 **사실로** 말했다.

**원인은 판정이 아니라 배선이었다.** `router.ts` 의 `paperFollowup` 은 지역 변수로 끝난다:

```ts
return { …, movieFollowup, movieSearchTurn, weatherFollowup, reformatTurn };
//                                                        ↑ paperFollowup 이 없다
```

`needsSearch = false` 만 하고 state 로 나가지 않으니, generator 는 이 턴이 카드 대화인 줄 모른다.
`weatherFollowup`·`movieFollowup`·`cardFollowup` 이 전부 받는 근거 고정 규칙을 **논문만** 못 받았다.
정적 프롬프트에도 없다(논문 관련 규칙은 "카드를 직접 쓰지 마라" 2건뿐).

⚖️ **§6.20 까지의 교훈과 모양이 다르다.** 거기서는 규칙이 침묵해서 LLM 이 자유로웠다.
여기서는 규칙이 **말을 했는데 전선이 안 이어져 있었다.** `reformatTurn` 이 같은 사고였다
(라우터가 `refine` 을 판정하고도 state 로 안 넘겨 generator 가 몰랐다 — DEV_260815 §2-2).
같은 실수를 반복하는 자리라서, 판정 함수가 아니라 **state 어노테이션이 있는가**를 테스트에 넣었다.

**고친 것**: `state.paperFollowup` 어노테이션 · 라우터 반환 추가 · generator 주입.
규칙 본문은 `buildPaperFollowupRules()` 로 빼 `card-followup.ts` 에 뒀다 — 하니스가
**임포트해서 문구를 검사**하기 위해서다. 규칙은 카드 밖 지식을 금지하지 않는다("RCT 가 뭐야"
까지 막으면 답이 죽는다). 대신 초록에서 온 것과 일반 지식을 문장 안에서 가르게 한다 —
실측에서 모델이 맨 끝에 자발적으로 붙였던 고지를 우연이 아니라 규칙으로 만든 것이다.

**하니스가 한 번 공짜로 통과했다.** 초안은 `/지어내지|추측하지|만들지/` 로 느슨하게 봤는데,
핵심 문장을 "그 논문의 사실로 **쓸 수 있습니다**" 로 뒤집어도 다른 줄의 "추측" 에 걸려 초록이었다.
계약 문장을 직접 못 박게 고친 뒤 4갈래 무력화(라우터 반환·generator 주입·핵심 문장·표 규칙)에
전부 빨간불을 확인했다. `npm run verify` exit 0.

⚠️ **남은 것 둘.** ① 카드 1번(2011 CAM 리뷰)에 probiotics 가 초록에 한 번도 안 나온다 —
PubMed relevance 랭킹 자체의 문제라 질의가 아니라 결과 필터를 손대야 한다(산문도 `[1]` 을
인용하지 않았다). ② 3턴 표에서 PMID·DOI 가 사라지고 제목이 가로 스크롤로 잘린다 — 규칙에
"표에도 남겨라"를 넣었지만 렌더러 폭 문제는 별개다.

### §6.23 카드에 무관한 논문이 섞인다 — 커버리지가 아니라 주제어로 가른다

§6.22 화면에서 딸려 나온 것. `프로바이오틱스 감기 논문` 카드 5건 중 **2건에 probiotics 가
초록에 한 번도 안 나왔다** — 1번은 비타민C·에키네시아 리뷰, 4번은 "Earthing accelerates
immune response"(접지) 발췌였다. 산문이 인용한 건 `[2][3][5]` 로, **정확히 그 둘만 빠졌다.**
모델의 인용이 이미 관련도 판정을 하고 있었던 셈이라, 프로브의 정답 라벨로 쓸 수 있었다.

**① 평면 용어 커버리지는 못 쓴다 — 순위가 뒤집힌다.**

| | #1 무관 | #3 관련 | #4 무관 | #5 관련 |
|---|---|---|---|---|
| 커버리지 | 75% | 75% | 75% | **50%** |

`common cold prevention` 은 결과 전건이 공유한다 — PubMed 가 그걸로 매칭했으니 당연하다.
프로브 50건에서도 75% 구간에 관련 13건과 무관 2건이 같이 들어 있었다. 임계값이 존재하지 않는다.

**② 가르는 건 주제어 하나다.** `probiotics` 유무가 5/5 정확히 일치했다. 주제어는
**코퍼스에 가장 적게 실린 용어**로 고른다 — probiotics 66,551 vs prevention 3,684,125.
esearch 의 count 가 IDF 를 직접 준다.

**③ 공짜 방법을 시도했다가 버렸다.** "결과 내 등장 빈도가 가장 낮은 용어" 로 고르면 API 를
한 번도 더 안 불러도 된다. 10질의로 재보니 **일치 1 · 불일치 6** 이었다 —
`elderly`·`outcomes`·`clinical`·`randomized` 같은 맥락어를 골랐다. 우연히 맞은 게 아니라
원리가 틀렸다(초록마다 빠지는 맥락어는 주제와 무관하다). 코퍼스 호출로 갔다.
`NCBI_KEY` 가 있어 용어당 110ms 이고, 맥락어는 모듈 캐시에 남아 두 번째부터 공짜다.

**안전판 둘 (fail-open).** 판별 용어가 2개 미만이면 안 거른다. 주제어가 결과의 **절반 미만**에만
있으면 안 거른다 — 그건 개별 논문이 아니라 질의가 코퍼스와 어긋난 것이고, 거기서 걸러 버리면
카드가 통째로 빈다. 프로브 10질의에서 한 번도 발동하지 않았다(최저 3/5).

**어간 근사의 하한.** `probiotic`↔`probiotics`, `prevention`↔`preventing` 을 이으려고 어미를
깎는데, 그대로 두면 `lesion`→`les` 가 "unless"·"lesser" 에, `series`→`ser` 가 "serum" 에 걸린다.
깎은 결과가 4자 미만이면 원형을 쓴다.

**결과.** 프로브 재측정 **5/50 → 0/49**. 실호출 로그도 정확히 둘만 뺐다:
`[paperTool] 주제어 "probiotics" 없는 논문 2건 제외: 21322286, 27055821`.
제거는 철회·초록없음을 걸러낸 뒤 `limit` 로 자르기 **전**에 해서, `retmax=limit+3` 의 여유분이
자리를 메우게 했다 — 렌더러는 손대지 않았다.

⚖️ **하니스 두 개가 내 리팩터링에 잘못 빨개졌다.** 철회·초록없음 검사가
`papers: papers.filter(…).slice(0, limit)` 라는 **표현식을 정규식으로** 보고 있었다. 계약은
"철회·초록없음이 papers 에 없다" 이지 그 한 줄이 아니다. `partitionPapers()` 로 빼서 행동
검사로 승격했다 — 라이브 3회 중 2회가 철회 논문을 인용했던, 값이 큰 계약이다.

무력화 6갈래(fail-open 가드·주제어 방향·어간·4자 하한·철회 분리·라우터 배선)에 전부 빨간불을
확인했다. 특히 어간 검사는 **처음엔 안 깨졌다** — 픽스처 논문들의 제목에 이미 복수형이 있어
어간 처리를 거치지 않았다. 단수형만 있는 논문을 따로 세우고 나서야 이빨이 생겼다.

### §6.24 카드 흡입 전수 측정 — 다른 카드는 깨끗했고, 어제 내가 만든 구멍이 하나 나왔다

§6.15 는 날씨·법률만 고쳤고 근거는 "2/2 재현" 이었다. 나머지 카드는 안 쟀다. 하니스를 짜서
**카드 7종 × 무관 질의 8 × 3회 = 168회** 를 대조군(카드 없음)과 나란히 돌렸다
(`tests/manual/live-card-suction.mts`, `TIER1=1` 필수).

측정값은 셋이다 — `intent` · `needsSearch` · 카드 후속 플래그. **intent 만 보면 놓친다**:
§6.22 가 정확히 그랬다(의도는 `general` 로 맞았고 근거 고정만 조용히 빠져 있었다).

**✅ 약국·병원·동물병원·영화 카드는 깨끗했다.** 날씨·약품·주식·프로그래밍 질의가 전부
대조군과 동일했다. 걱정했던 확산은 없었다.

어휘가 겹치는 함정에서는 카드가 **오히려 도왔다**:

| 질의 | 대조군 | 카드 있음 |
|---|---|---|
| 강아지 사료 추천해줘 | 🔴 `vet_search` | ✅ `general` |
| 변호사 비용 얼마나 들어? | 🔴 `law_search` | ✅ `general` |

카드 없이 물으면 동물병원·법령을 조회하러 간다. **이건 카드와 무관한 별개 결함 후보다**(§7).

**🔴 결함은 논문 카드 하나였고, 어제 내가 만든 것이었다.**

```
논문 카드 + "리액트 훅 쉽게 설명해줘" → general/검색OFF/paperFollowup
대조군                              → general/검색OFF
```

지시어가 하나도 없는 무관 질의에 "화면 논문 카드가 근거다, 초록 밖을 사실로 쓰지 마라" 가
주입된다. 원인은 LLM 이 아니라 결정적 정규식이다 — `PAPER_REFORMAT` 이 `쉽게` 한 단어로 걸렸다.
§6.22 에서 가드를 `general` 까지 넓히면서 이 정규식의 넓이가 그대로 노출됐다.
`이 사진 쉽게 설명해줘` 는 더 나쁘다 — 이미지를 첨부한 턴이 논문 카드에 물린다.

**고침**: 재구성 어휘 + **목적어 없음** 을 함께 요구한다(`isBareReformat`). 재구성 지시어와
카드 지칭어를 걷어내고 남는 게 있으면 새 주제다 — `표로 정리해줘`(남는 것 없음) → 카드 대화,
`서울 맛집 목록으로 보여줘`(서울 맛집) → 새 질의. 14케이스 고정.

⚖️ **43% 라는 첫 숫자는 내가 부풀린 것이었다.** 무관 질의 8종 중 둘(`3번 항목 자세히 알려줘`,
`이 내용 표로 정리해줘`)에 **지시어가 들어 있었다.** 화면에 카드가 있을 때 그걸 후속으로 보고
검색을 끄는 건 설계대로 맞는 동작이고, 오히려 카드 없는 대조군이 검색을 켜는 쪽이 이상하다
(정리할 대상이 없는데). 두 질의를 관찰용으로 강등하고 나니 진짜 결함은 논문 카드 하나였다.
**테스트 케이스가 기대값을 틀리게 들고 있으면 결함이 아닌 것이 결함으로 보고된다.**

⚖️ **무력화 실험이 하나를 구분하지 못했다.** 지시어를 관형사 위치로만 지우는 것(`(^|\s)(이|그|저)(?=\s)`)과
전역 치환은 이 판정에서 **결과가 같다** — 한 글자만 지우므로 2자 이상 낱말이 비지 않고, 비는 건
낱말이 정확히 `이`/`그`/`저` 일 때뿐이라 어차피 지시어다. 억지 케이스를 만들어 초록을 칠하는 대신
주석에 동치임을 적었다. 나머지 4갈래(목적어 검사·지칭어 목록·재구성 어휘 목록·라우터 배선)는
전부 빨간불을 확인했다.

### §6.25 곁칸은 필터를 안 거쳤다 — 감기 질문에 위장 논문이 "철회됨" 딱지로 떴다

§6.23 필터를 넣은 뒤 화면 확인에서 나왔다. 카드 `retracted` 칸에 이게 있었다:

```
Alternative Treatments for Minor GI Ailments   (34007566, 철회)
  "…dietary habits and specific food types … GI disorders…"
```

`probiotics` 가 제목에도 초록에도 없다. 필터를 `citable` 에만 걸고 `retracted`·`noAbstract` 는
그대로 내보냈기 때문이다. 모델이 인용할 수는 없으니(배열이 다르다) 사실 오류는 아니지만,
질문과 무관한 경고는 잡음이고 §6.23 의 계약이 여기엔 안 걸려 있었다.

**먼저 재고 정했다.** "철회 논문을 아예 빼자" 는 안이 나왔는데, 10질의 실측 결과 **철회 0건**이었다
(그 위장 논문은 한 번 나왔다 다음 실행엔 안 나왔다 — PubMed 순위가 실행마다 흔들린다).
거의 안 뜨는 패널이라 두 안의 실질 차이가 없고, 남는 건 손대는 면적이다:
필터는 `paper-tool.ts` 한 줄, 제거는 렌더러·i18n 4개 언어·§4g 테스트까지 번진다. 필터로 갔다.

⚖️ **`noAbstract` 에는 걸지 않는다.** `summary` 가 빈 문자열이라 제목만 남는다. 실측 3건 중
`Prevention and treatment of the common cold: making sense of the evidence` 는 제목에
probiotics 가 없어도 질문과 관련 있는 논문이다. **판단 근거가 없으면 판단하지 않는다.**

⚖️ **`splitOffTopic` 을 그대로 못 쓴다.** 곁칸은 보통 1~2건이라 "주제어가 절반 미만이면 fail-open"
규칙이 **항상** 발동해 아무것도 안 걸러진다. 주제어의 타당성은 본 목록에서 이미 검증됐으므로
(`applied === true` 일 때만) 곁칸은 건별로 본다 — 그래서 `splitOffTopic` 에 `applied` 를 추가했다.

🔴 **또 배선을 안 봤다.** 순수 함수 7검사를 짜고 초록을 받았는데, 무력화 실험에서
①(곁칸 필터를 반환에 연결하지 않음)과 ③(fail-open 인데 곁칸에 주제어를 씀)이 **둘 다 통과했다.**
판정을 만들어 놓고 연결을 검사하지 않은 것 — §6.22 와 똑같은 실수를 이틀 만에 반복했다.
`searchPapers` 는 네트워크를 타서 임포트할 수 없으므로 **배선만** 소스로 보게 3검사를 덧댔다
(계약은 행동으로, 배선은 소스로 — 둘을 섞으면 §6.23 에서처럼 리팩터링에 잘못 빨개진다).
이후 3갈래 전부 빨간불 확인.

📌 **교훈을 규칙으로**: 순수 함수를 새로 빼면 **호출부 연결을 같은 커밋에서 검사한다.**
이번 주에 두 번 당했다(§6.22 `paperFollowup`, 여기 `filterOffTopicAside`). 둘 다 판정은 맞았고
아무 일도 일어나지 않았다.

### §6.26 "두번째 논문 설명해줘" 에 빈 arXiv 카드 — 논문만 `activeCards` 보호가 없었다

화면 확인에서 나왔다. 여러 턴을 테스트한 뒤 물었더니 답변 본문은 정확한데(학교 아동 RCT를
제대로 설명했다) 아래에 **빈 arXiv 카드**가 붙었다 — "조건에 맞는 논문을 찾지 못했습니다".

```json:paper
{"query":"probiotics common cold prevention respiratory tract infection randomized controlled trial",
 "source":"arxiv","total":0,"papers":[]}
```

**재현은 못 했다.** 판정 함수는 정상이고(`decidePaperCardFollowup('두번째 논문 설명해줘', true)
=== 'discuss'`), 라우터로 3턴을 재현해도(이미지 턴을 사이에 끼워도) `paperFollowup=true` 가 나왔다.
남는 설명은 `paperCardShown` 이 false 였다는 것뿐인데 — **그 값이 로그에 없었다.**

🔴 **구조적 구멍은 확실했다.** 서버가 받는 히스토리는 최근 10개인데 클라이언트는 최근
20개(`CARD_WINDOW`)로 판정해 `activeCards` 로 보내 준다. 그 간극을 메우려고 만든 장치이고
날씨·약국·병원·동물병원·법률이 전부 쓴다. **논문만 창 스캔뿐이었다.**

router.ts 의 옛 주석은 이렇게 정당화하고 있었다:

> 창(최근 10개)을 벗어나면 자연히 false 가 되고, **그때는 재조회가 맞다**(카드가 화면에서 밀려났으므로).

틀렸다. **밀려난 건 서버의 창이지 사용자의 화면이 아니다.** 사용자는 카드를 보면서
"두번째 논문" 이라고 물었다. 대화가 5턴만 지나면 지시가 통하지 않게 된다.

**고침**: `activeCards.paper` 를 클라 → sanitize → state → 라우터까지 배선하고, 진단을 위해
`paperCardShown` 을 라우터 로그에 넣었다. 다음에 또 나면 로그가 바로 가른다.

⚖️ 이번엔 **배선 3검사를 처음부터 넣었다**(라우터 우선순위·클라 전송·서버 sanitize).
§6.25 에서 순수 함수만 검사했다가 두 갈래를 놓친 직후라, 무력화 3갈래 전부 빨간불을 확인했다.
📌 §6.25 의 교훈이 바로 값을 했다 — 이 고침은 **순수 함수가 하나도 없고 전부 배선**이다.

⚠️ 근본 원인 미확정으로 남긴다. `paperCardShown=false` 였다는 것까지만 좁혔고, 그게 창 밖으로
밀린 탓인지 다른 이유인지는 로그가 없어 못 가린다. 이제 로그가 있으니 다음 발생에 확정된다.

### §6.27 주제어를 질병어에 뺏긴다 — fail-open 이 옳게 발동한 경우와 아쉽게 발동한 경우

`그럼 비타민D 논문은?` 카드에 **요로감염 논문**이 남았다.

```
[4] Prevention of urinary tract infections with vitamin D supplementation
[1] Zinc Supplementation Reduces Common Cold Duration      ← 아연 논문
```

산문은 `[5]`·`[2]` 만 인용했다 — **모델이 안 쓴 카드 = 무관한 카드** 신호가 세 번째로 맞았다.

**버그가 아니다. §6.23 의 fail-open 이 설계대로 발동했다.**

```
cold:250,148  vitamin:512,555  tract:615,340  respiratory:975,279  …
주제어 = cold (최희귀) → 결과 5건 중 1건에만 등장 → 절반 미만 → 필터 미적용
```

원인은 두 겹이다. ① 질의의 진짜 주제는 `vitamin D` 인데 `D` 가 1글자라 용어 목록에서 빠진다.
② 남은 `vitamin`(512k)이 질병어 `cold`(250k)보다 흔해 **주제어를 뺏긴다.** 프로바이오틱스
질의는 주제어가 곧 최희귀어라 우연히 잘 맞았던 것이다.

**프로브를 18질의·89건으로 넓혀 재봤다**(`--subject`, 개입어가 흔한 질의 8종 추가).

- **fail-open 은 2종(11%)에서만 발동**했다. 16종은 주제어가 4/4~5/5 로 정상 작동한다.
- 🔴 두 발동 중 **하나는 옳았다.** `iron deficiency anemia fatigue` 는 주제어가 `fatigue`(1/5)인데
  결과 5건이 전부 철결핍빈혈 논문이었다 — 걸렀다면 4건을 잘못 버렸다. **fail-open 이 그걸 막았다.**
- 나머지 하나가 비타민D 건이다.

**대안 ③ 을 같이 쟀다 — "결과의 절반 이상에 등장하는 용어 중 최희귀".**
현행(①)은 최희귀어가 소수면 통째로 포기하는데, ③ 은 포기 대신 한 칸 흔한 용어로 **물러선다.**

| | ① 현행 | ③ 대안 |
|---|---|---|
| 정상 16종 | 주제어 = 최희귀어 | **동일** (최희귀어가 이미 다수파라 같은 답) |
| 비타민D | `cold`(1/5) → 포기 | `vitamin` → 아연 논문 1건 제외 ✅ |
| 철결핍빈혈 | `fatigue`(1/5) → 포기 | `anemia` → 제외 0건 (전건이 빈혈 논문, 옳다) |

③ 은 ① 의 **일반화**다 — ① 의 주제어가 다수파일 때는 정의상 "다수파 중 최희귀" 와 같고,
소수파일 때만 갈린다. 측정상 **회귀 0, 이득 1건(89건 중)**. 규칙도 둘(최희귀 + fail-open)에서
하나로 준다.

⚠️ ③ 도 **요로감염 논문은 못 잡는다**(`vitamin D` 가 들어 있다). 2건 중 1건만이다. 잡으려면
"개입어 + 질병어 둘 다" 를 요구해야 하는데 그러면 `[5]`(vitamin ✅ / cold ❌ — 산문이 실제로
근거로 쓴 논문)가 잘린다. **과필터가 더 해롭다.**

### §6.28 라우터 모델 flash-lite → 2.5-flash — 79% → 100%, 지연 +431ms

사용자 화면: `강아지 사료 추천해줘` 에 **동물병원 빈 카드**, `변호사 비용 얼마나 들어?` 에
**법령 빈 카드**가 떴다. 둘 다 산문 0줄이다.

**규칙 분류기는 무죄였다.** `classifyIntentByRules` 는 셋 다 `general` 로 정확히 판정한다.
규칙은 라우터 LLM 이 429/503 으로 죽었을 때만 쓰는 폴백이라 평소엔 LLM 판정이 이긴다.

프롬프트 설명도 멀쩡했다 — `"vet_search": finding a veterinary hospital … for pets or animals`.
`강아지 사료` 는 병원을 찾는 게 아니다. **모델이 `강아지`·`변호사` 라는 단어에 반응한 것이다.**
`temperature: 0` · `thinkingBudget: 0` 이라 **3/3 일관되게** 틀렸다 — 흔들림이 아니라 그 모델의 답이다.

`tests/manual/live-intent-routing.mts` 신규(19질의 × 3회 = 57회, 정확도 + **지연**을 함께 잰다).
라우터는 매 턴 serial-blocking 이라 정확도만 보고 모델을 올리면 안 된다.

| | gemini-2.5-flash-lite | gemini-2.5-flash |
|---|---|---|
| 정확도 | **45/57 (79%)** | **57/57 (100%)** |
| 오분류 | 강아지 사료→vet · 변호사 비용→law · 변호사 시험→law · 강아지 산책→medical_qa | 없음 |
| 진짜 조회 12종 | 12/12 | 12/12 (회귀 0) |
| 지연 중앙값 | 783ms | **1,214ms** (+431ms) |
| p90 | 791ms | 1,311ms |

오분류 4종은 전부 3/3 고정이었고 flash 에서 3/3 정상으로 뒤집혔다. `SUMMARY_MODELS`(대화 제목)는
flash-lite 그대로다 — 별개 상수이고 성격도 다르다.

⚠️ **대가는 매 턴 +431ms 다.** 라우터는 응답 시작 전에 직렬로 도니 사용자가 그대로 체감한다.
프롬프트 반례를 먼저 시도하는 안도 있었으나, 반례는 적어 둔 것만 막고 새 어휘는 다시 샌다
(§6.15·§6.17·§6.20 에서 세 번 겪은 "규칙의 침묵" 과 같은 모양이다). 모델을 올리면 규칙이 아니라
판단이 바뀐다.

⚠️ **무료티어 쿼터를 지켜볼 것.** 라우터는 매 턴 호출이라 RPD 소모가 가장 빠른 자리다.
`config.ts` 가 RPD 429 를 24h 비활성으로 다루고 키를 로테이션하지만, flash 가 flash-lite 보다
먼저 마르면 규칙 폴백이 늘고 §6.11 에서 겪은 측정·동작 오염이 재발한다. 실사용 로그에서
`daily quota exhausted` 빈도를 볼 것.

🔴 **오분류를 고쳐도 남는 문제가 있다** — 조회가 실패하면 카드가 **답변 전체를 대체하고 산문이
0줄**이다. 두 번째 화면은 질문을 그대로 되받아 에러 문구에 넣었다("변호사 비용 얼마나 들어?
관련 법령을 찾을 수 없습니다"). 의도가 맞아도 결과가 0건이면 같은 막다른 길이다 —
"울릉도 약국", 심평원 백엔드 장애, 법령 API 실패 전부. §7 에 별건으로 남긴다.

### §6.29 카드가 답을 삼킨다 — fast-pass 가 **빈 카드에도** 최종 생성을 건너뛰고 있었다

`변호사 수임료는 보통 얼마나 될까?` · `이혼 소송 비용 얼마나 들어?` · `강아지 사료 추천해줘`
— 전부 **카드만 뜨고 산문이 0줄**이었다. 법령 카드는 질문을 그대로 되받아 에러 문구에 넣기까지 했다:
"변호사 선임비용이 얼마나 될까? 변호사 보수 관련 법령 **관련 법령을** 찾을 수 없습니다."

🔴 **라우팅 문제가 아니었다.** 원인은 `langchain-path.ts` 의 fast-pass 다:

```ts
if (toolContent.includes('```json:law')) {
    console.log('[LangGraph] Fast-passing lawTool: Bypassing final LLM generation');
    return { messages: [new AIMessage("")] };   // ← 산문 0줄이 설계다
}
```

카드 **펜스만** 보고 최종 LLM 생성을 건너뛴다. 결과가 있을 땐 옳은 최적화(모델 호출 하나 절약)지만
**카드가 비어도 똑같이 건너뛴다.** 6종(약국·병원·동물병원·법령·영화·날씨) 전부 같았다.

⚖️ **오분류만의 문제가 아니다.** 의도가 맞아도 0건(`울릉도 약국`)이거나 백엔드가 죽으면 같은
막다른 길이다. 날씨도 실패 시 `{error:true}` 카드로 나가 같은 경로를 탄다.
라우터를 아무리 올려도 100% 는 없으므로 **틀렸을 때 복구되는 구조**가 진짜 방어선이다.

**고침 두 겹.**
1. `cardHasResults(toolContent)` — 카드 payload 를 파싱해 `count`/목록/`error` 로 판정한다.
   fast-pass 6곳에 전부 걸었다. **모르는 모양이면 `true`**(현행 유지) — 과하게 false 를 내면
   멀쩡한 카드 턴마다 모델 호출이 붙어 지연이 는다.
2. `buildEmptyCardRules()` — fast-pass 를 끄면 모델이 불리지만 **무엇을 말할지**는 여전히 없다.
   지시가 없으면 카드 안내문만 되풀이한다.

⚖️ **규칙을 셋으로 나눠 적었다.** 빈 카드는 원인이 셋이고 정답이 다르다:

| 원인 | 예 | 정답 |
|---|---|---|
| 조회 인자가 없다 | `변호사 수임료`·`강아지 사료` | **질문 자체에 답한다.** 지역·법령명을 되묻는 건 우리 오분류를 사용자에게 떠넘기는 것이다 |
| 조회했는데 0건 | `울릉도 약국` | 없다고 말하고 다음 수를 안내. **웹 검색으로 뒤집지 않는다** — 공식 등록부가 권위다 |
| 백엔드 장애 | 심평원 다운 | 확인 못 했다고 밝힌다. **실패를 "결과 없음" 으로 바꿔 말하지 않는다** |

"빈 카드는 전부 검색으로" 도, "전부 고정 문구로" 도 셋 중 둘을 틀린다.

⚠️ **법령 도구가 모델 인자를 사용자 문구에 그대로 넣는다.** `notice: ${searchQuery} 관련 법령을…`
인데 `query` 인자 설명이 "사용자 질의 원문 또는 검색 키워드" 라 모델이 질문 전체를 넣는다.
그래서 `관련 법령` 이 두 번 나왔다. 규칙에 "질문을 그대로 되받아 적지 마세요" 를 넣었지만
**문구 조립 자체는 아직 안 고쳤다**(§7).

무력화 6갈래(fast-pass 배선·error 처리·모르는 모양 기본값·generator 주입·빈 카드 조건·핵심 문장)
전부 빨간불 확인. 이번에도 **배선 검사를 처음부터** 넣었다 — §6.22·§6.25 에서 두 번 당한 뒤로 습관이 됐다.

### §6.30 세 번째 층 — 카드 선전송이 생성기의 산문을 삼킨다 (그리고 화면만 보고 세 번 헛짚은 기록)

§6.29 에서 fast-pass 를 두 곳(`langchain-path`·`openai/chat`) 고쳤는데 **화면이 안 바뀌었다.**
`이혼 소송비용 얼마나 들까?` 는 계속 카드만 떴다. 세 번 다시 봤고 세 번 다 빗나갔다:

1. "dev 서버가 옛 코드다" → 재시작해도 같음
2. "모델이 빈 응답을 낸다" → 그러면 `OpenAI returned empty response text` 예외가 난다. 탈락
3. "네 번째 경로가 있다" → generator 를 다 읽어도 이른 출구가 없음

**화면 대신 그래프를 통째로 태우니 한 번에 나왔다**(`compileAgentGraph` + `createStreamDispatch`
를 route.ts 와 같은 방식으로 호출):

```
[event]    on_tool_end lawTool · fullAiResponse=0자
[sendEvent] text 169자: "\n```json:law…"          ← 카드를 먼저 보낸다 → fullAiResponse=169
[OpenAI]   빈 카드 복구 followup → 산문 504자        ← 모델은 답을 썼다
[event]    on_chain_end generator · fullAiResponse=169자
                                     ↑ `msgText && !st.fullAiResponse` 가 false → 산문 통째 폐기
사용자에게 도달: 169자 (카드만)
```

`on_tool_end` 가 카드를 **선전송**하면서 `fullAiResponse` 를 채우고, 그 값이 "이미 답을 보냈다" 는
신호가 돼 generator 의 최종 메시지를 삼켰다. 바로 위에 **같은 이유의 `law_qa` 예외가 이미 있었다** —
"중간 json:law 를 먼저 스트리밍하면 fullAiResponse 가 채워져 generator 의 최종 설명이 억제된다".
빈 카드에는 그 예외가 없었을 뿐이다.

**고침**: `if (blockMatches && cardHasResults(toolOutput))`. 결과가 있으면 종전대로 즉시 보내
지연 이득을 지키고, 비면 보내지 않는다 — 최종 메시지에 `pinCardToProse` 가 카드를 붙여 오므로
카드도 잃지 않는다(Gemini 경로는 `pendingCardBlocks` 가 붙인다).

실측 결과: 사용자 도달 **169자(카드만) → 679자(산문 535 + 카드)**.

📌 **교훈 — 화면은 진단 도구가 아니다.** 같은 결함이 세 층(langchain fast-pass · openai
fast-pass · 스트림 선전송)에 있었고, 앞의 둘을 고쳐도 화면은 **한 글자도 안 바뀌었다.**
층이 겹친 결함은 화면으로는 진척이 안 보이므로 "안 고쳐졌다" 와 "덜 고쳐졌다" 를 못 가른다.
그래프를 실제로 태워 **어느 단계에서 값이 사라지는지**를 봤어야 했고, 그 한 번이 세 번의 추측을
대신했다. 다음에 같은 모양이면 재현 하니스부터 만든다.

📌 두 fast-pass 는 **필요했지만 충분하지 않았다.** 앞선 두 수정이 없으면 모델이 애초에 안 불린다.
세 층 전부가 있어야 산문이 화면에 닿는다 — 그래서 "앞의 수정이 헛수고였다" 는 아니다.

### §6.31 빈 카드는 화면에 붙이지 않는다 — 같은 말을 두 번 하고, 하지도 않은 요구를 담는다

§6.30 으로 산문은 살아났는데 화면이 이렇게 됐다:

```
(산문)  이혼 소송비용 관련 법령을 찾을 수 없습니다. 법령명을 더 구체적으로 입력해 주세요.
(카드)  이혼 소송비용 관련 법령을 찾을 수 없습니다. 법령명을 더 구체적으로 입력해 주세요.
```

**같은 말이 두 번**이고, 둘 다 쓸모가 없다. 게다가 그 문구는 사용자가 하지도 않은 요구를 담는다 —
`이혼 소송비용` 을 물은 사람은 법령을 조회한 적이 없다. 그건 **우리 오분류의 흔적**일 뿐이다.

**고침 둘.**

1. **화면에서 뺀다.** `pinCardToProse`·`pendingCardBlocks` 가 `cardHasResults` 로 거른다.
   ⚖️ **모델 컨텍스트에서는 지우지 않는다** — 도구 출력은 그대로 가서 "조회했으나 없었다" 를
   알려주고 `buildEmptyCardRules` 가 그걸 읽고 답한다. 지우는 건 **화면뿐**이다.
   ⚖️ `noAbstract`·`retracted` 를 `CARD_LIST_KEYS` 에 넣었다 — 인용 목록이 비었어도 그 칸에는
   보여줄 값이 있다(초록 없는 논문의 원문, 철회 사실). 안 넣으면 그 카드가 통째로 숨는다.

2. **산문이 안내문을 복창하지 못하게 한다.** 실측에서 모델은 카드 문구를 그대로 옮겨 적고 끝냈다.
   규칙에 두 줄을 더했다 — "조회 실패 안내만으로 끝나서는 안 된다", 그리고 **주제만 말한 발화**
   (`이혼 소송비용`·`변호사 수임료`·`강아지 사료`)는 조회 요청이 아니라 그 주제에 대한 질문이다.

**실측(그래프 전체)**:

| 질의 | 결과 |
|---|---|
| `이혼 소송비용` | 542자 · 카드 없음 — 인지대·송달료·변호사비용·감정비용을 항목별로 설명 |
| `변호사 수임료` | 968자 · 카드 없음 — 상담료~항소심까지 표로 |

⚠️ 기존 하니스 2건이 이 변경에 빨개졌다. 픽스처가 `{"papers":[]}` 빈 카드였는데, 그 절은
**전송 메커니즘**을 보는 자리라 결과 있는 카드로 바꾸고 빈 카드 검사를 따로 세웠다.
계약이 바뀐 게 아니라 픽스처가 새 계약과 충돌한 경우다.

📌 이로써 §6.28~§6.31 의 결론: **라우터 오분류는 화면에서 사라졌다.** 분류는 여전히 틀리지만
(`이혼 소송비용` 은 라우터가 `general` 로 갔고 `변호사 선임비용` 류는 아직 `law_search` 로 샌다)
틀려도 사용자는 답을 받는다. 분류 정확도를 좇는 것보다 **틀렸을 때 복구되는 구조**가 값이 컸다.
