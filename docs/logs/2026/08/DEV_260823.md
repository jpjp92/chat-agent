# URL Fetch 장애 후속 검증 및 공급자 정책 확정

> 날짜: 2026-08-23  
> 범위: GeekNews, Wikidocs, Brunch, OpenAI Web Search, ScrapingBee, browserless, Jina, Puppeteer/Cheerio

## 1. 최종 결론

URL 수집 장애는 하나의 원인이 아니었다.

1. GeekNews는 오래된 `Chrome/120` User-Agent를 거부했다. `Chrome/141`로 바꾸면 유료 공급자 없이 direct fetch가 된다.
2. Wikidocs는 Cloudflare challenge 때문에 direct, Jina, 일반 Puppeteer/browserless로는 안정적으로 읽히지 않는다.
3. 기존 ScrapingBee 키는 trial 1,000 credits를 초과해 `401`을 반환했다. 교체한 키와 `render_js=true + premium_proxy=true + country_code=kr` 조합은 Wikidocs 신규 글을 통과했다.
4. OpenAI Web Search는 검색에 색인된 일부 과거 Wikidocs 글은 읽지만 신규·미색인 글의 실시간 fetch를 대신하지 못했다. 모델을 바꿔도 같은 Web Search 접근 한계가 유지됐다.
5. Brunch 실주소는 현재 범용 폴백에서 성공한다. `/@other/999`는 회귀 하니스가 URL 불일치를 검증하려고 만든 가짜 URL이므로 실사이트 장애 표본으로 쓰면 안 된다.

현재 운영 정책은 다음과 같다.

```text
Wikidocs: cache → ScrapingBee render/premium/KR → browserless → 실패 안내
일반 URL: cache → direct → ScrapingBee static → ScrapingBee render/premium/KR → browserless → 실패 안내
OpenAI URL fallback: 기본 OFF, OPENAI_URL_FALLBACK_ENABLED=true일 때만 최후단에서 실행
ScraperAPI: 체인에서 제외
```

## 2. 사이트별 실측

| 사이트/URL | 방법 | 결과 | 판정 |
|---|---|---|---|
| GeekNews `topic?id=32713` | direct, Chrome/120 | 403 · 10 bytes | 낡은 UA 차단 |
| GeekNews `topic?id=32713` | direct, Chrome/141 | 200 · 169ms · `article` · 본문 7,604자 | 기본 경로로 채택 |
| GeekNews `topic?id=32713` | browserless `/unblock` | 200 · 4.4s · 본문 7,604자 | direct 실패용 보조 수단 |
| ZDNet 표본 | direct, Chrome/141 | 200 · 137ms · 본문 2,541자 | direct 정상 |
| Brunch `/@ghidesigner/532` | Node direct | `redirect count exceeded` | direct 불가 |
| Brunch `/@ghidesigner/532?codex_doc_probe=260823` | 로컬 `/api/fetch-url` | 200 · 8.89s · 본문 4,507자 · `provider=scrapingbee-static` | 범용 폴백 정상 |
| Brunch `/@other/999` | 실 URL 호출 | 502 | 테스트용 가짜 URL이므로 실패 정상 |
| Wikidocs `/blog/@aidevelopermm/29145/` | direct | 403 Cloudflare challenge | direct 불가 |
| 같은 Wikidocs 글 | ScrapingBee render/premium/KR | 200 · 5.66s · `article` · 본문 12,460자 · cost 25 | Wikidocs 1순위로 채택 |
| 같은 Wikidocs 글 | 변경 후 로컬 `/api/fetch-url` | 200 · 6.10s · 본문 13,085자 · fresh fetch | 종단 배선 정상 |

Brunch의 쿼리 파라미터는 캐시를 우회해 현재 공급자를 확인하기 위한 진단용이었다. Supabase `url_cache.provider`가 `scrapingbee-static`으로 저장된 것을 확인했다. 기존 쿼리 없는 캐시에는 과거 `browserless` 성공 결과가 남아 있었으므로, 화면 성공만 보고 현재 공급자를 추정하지 않았다.

## 3. Wikidocs 공급자 비교

### 3.1 실패한 경로

- direct Node fetch: `403`, `cf-mitigated: challenge`
- 일반 Puppeteer/Browserless: Cloudflare `Just a moment` 또는 403
- residential 옵션을 준 Browserless 표본: 동일하게 challenge
- Cheerio: 브라우저가 아니므로 받은 challenge HTML 이상의 정보를 만들 수 없음
- Jina Reader: HTTP 자체는 200이어도 본문이 `Performing security verification`인 보안 페이지
- ScrapingBee premium/JS에서 `country_code=kr`을 빼거나 조합을 달리한 표본: 500 또는 timeout

### 3.2 성공한 ScrapingBee 조합

```text
render_js=true
premium_proxy=true
country_code=kr
```

신규 키로 `/blog/@aidevelopermm/29145/`를 호출한 결과 HTTP 200, 약 5.66초, 본문 12,460자, `article`, `spb-cost=25`였다. 따라서 Wikidocs는 static과 direct를 생략하고 이 조합부터 시작한다.

기존 키의 실패 원인은 사이트가 아니라 계정이었다. 대시보드에서 `1,006 / 1,000` credits를 확인했고 API는 `401 Monthly API calls limit reached: 1000`을 반환했다. 라우터는 이제 401/402/429를 일반 본문 실패와 별도로 로깅한다.

## 4. OpenAI Web Search 검증

### 4.1 파라미터 수정

`gpt-5-mini`에 `reasoning.effort=minimal`과 `web_search`를 함께 보내면 400이 발생했다.

```text
The following tools cannot be used with reasoning.effort 'minimal': web_search
```

모델 capability를 `low`로 수정한 뒤 API 요청 자체는 완료됐다. 응답의 HTTP 200은 OpenAI Responses API가 완료됐다는 뜻이지, 대상 Wikidocs가 HTTP 200을 반환했다는 뜻이 아니다.

### 4.2 URL별 결과

| URL | 모델 | 결과 |
|---|---|---|
| Wikidocs `/156176` | GPT-5 mini, low | 실행 시점에 따라 실패/성공; 검색 색인 의존 |
| Wikidocs `/blog/@jaehong/8745/` | GPT-5 mini, low | 성공 · 본문 4,082자 · 약 25.6s · 10,619 tokens |
| Wikidocs `/blog/@jaehong/27125/` | GPT-5 mini, low | 실패 · `OPENAI_WEB_FETCH_FAILED` |
| Wikidocs `/blog/@aidevelopermm/29145/` | GPT-5 mini, low | 실패 · status completed/200이나 본문 없음 · 4,977 tokens |
| 같은 신규 글 | GPT-5.6 Luna, reasoning none | 실패 · 4,738 tokens · 약 2.06s |

과거 글 `/8745/`는 검색 결과에 본문이 색인돼 있었고 신규 두 글은 정확 URL 검색 결과가 없었다. 따라서 OpenAI는 브라우저형 실시간 스크래퍼가 아니라 색인된 문서를 일부 회수하는 보조 수단으로만 판단한다. 모델 교체로 해결되지 않았으므로 현재 기본값은 OFF다.

```text
OPENAI_URL_FALLBACK_ENABLED=false
```

구현과 회귀 하니스는 향후 재평가를 위해 유지한다. 명시적으로 `true`를 설정한 환경에서만 ScrapingBee와 browserless가 모두 실패한 뒤 호출한다.

## 5. 현재 라우팅과 남은 항목

### Wikidocs

```text
cache → ScrapingBee render/premium/KR → browserless → (OpenAI OFF) → FETCH_ERROR
```

### GeekNews

현재 코드는 일반 URL 체인을 사용하지만 Chrome/141 direct가 성공하므로 정상 시 유료 공급자를 호출하지 않는다.

```text
cache → direct → 성공
direct 실패 시 현재 구현: ScrapingBee static → render → browserless
```

검증상 더 싼 전용 순서는 `direct → browserless`지만, `news.hada.io` 호스트 특례는 아직 구현하지 않았다.

### Brunch

```text
cache → direct(redirect loop) → ScrapingBee static(검증 성공) → render → browserless
```

### 남은 위험

- 일반 URL 최악 예산은 direct 10s + static 15s + render 40s + browserless 30s로 95s다.
- 클라이언트 제한 65s보다 길어 공급자가 모두 느리게 실패하면 클라이언트가 먼저 중단할 수 있다.
- `url_cache`가 다시 사라지거나 쓰기 실패하면 모든 요청이 유료 공급자를 타므로 캐시 오류 로그를 유지해야 한다.
- Chrome/141 UA도 시간이 지나면 낡는다. 특정 사이트만 다시 403이면 최신 UA A/B를 먼저 수행한다.

## 7. 채팅 모델 선택지 확장

URL fetch용 OpenAI 실험과 채팅 모델 선택은 분리했다. URL 원문 fetch는 색인 의존 문제 때문에
기본 OFF지만, 일반 채팅용 Responses API는 별도 어댑터로 연결했다.

현재 선택 목록:

| 공급자 | 모델 | 상태 | 비고 |
|---|---|---|---|
| Google | Gemini 3.7 Flash | 선택 가능 | 기본 모델 전환 전 관찰 단계 |
| Google | Gemini 3.6 Flash | **기본값 유지** | 기존 운영 기준선 |
| OpenAI | GPT-5.4 mini | 선택 가능 | `reasoning.effort=none`, `store=false` |
| OpenAI | GPT-5.6 Luna | 선택 가능 | `reasoning.effort=none`, `store=false` |
| 이전 모델 | Gemini 3.5 / 2.5 Flash | 선택 가능 | 스크롤 아래 별도 그룹 |

OpenAI 채팅 어댑터는 Responses API를 사용하며 텍스트·이미지·웹 검색·출처 변환을 지원한다.
`OPENAI_API_KEY_TIER1`은 서버 환경변수에서만 읽고 요청에는 `store=false`를 명시한다.

라이브 테스트 결과:

| 모델 | 결과 | 응답 시간 |
|---|---|---:|
| GPT-5.4 mini | 성공 | 약 1.19s |
| GPT-5.6 Luna | 성공 | 약 2.67s |

라이브 테스트는 비용이 발생하므로 `npm test`에서 제외하고 `npm run test:openai-live`로만 실행한다.

## 8. 현재 모델 라우팅 정책과 구현 차이

목표 정책은 다음과 같다.

```text
텍스트·URL 본문·웹 검색·이미지·일반 intent → 사용자가 선택한 모델 유지
YouTube 자막 확보 → 자막 텍스트를 선택한 모델로 처리
YouTube 원본 영상·업로드 영상/오디오 → Gemini 2.5 capability fallback
GPT 쿼터/API 오류 → Gemini 자동 전환 금지, 사용자 안내
로컬 도구 intent → 장기적으로 선택 공급자의 function calling 사용
```

하지만 현재 구현은 완전히 공급자 독립적이지 않다.

- 초기 intent router는 선택 모델과 무관하게 Gemini 2.5 Flash Lite를 사용한다.
- `/api/chat`이 스트림 시작 전 `API_KEYS.length`를 검사한다.
- generator도 OpenAI 분기 전에 Gemini `getNextApiKey()`를 호출한다.
- 약품·약국·병원·동물병원·법령·영화·스포츠·날씨 intent는 아직 Gemini LangChain 도구 경로다.

따라서 **Gemini 키가 모두 소진된 뒤 GPT로 수동 전환해도 텍스트 요청이 막힐 수 있다.** 반대 방향인
GPT 소진 후 Gemini 전환은 Gemini 키가 정상이라면 다음 요청부터 가능하다. GPT-5.4 mini와 GPT-5.6
Luna는 같은 OpenAI 프로젝트의 크레딧·지출·사용량 한도를 공유하므로, 영구 한도 소진이면 GPT 모델만
바꿔도 복구되지 않는다. 모델별 RPM/TPM 제한일 때만 다른 GPT 선택이 도움이 될 수 있다.

상세 후속 계획은 [PLAN_MULTI_PROVIDER_ROUTING_260823](../../../plans/PLAN_MULTI_PROVIDER_ROUTING_260823.md)에 둔다.

## 9. 오류 정보 공개 정책

공급자 오류 원문은 서버 로그와 사용자 UI를 분리했다.

```text
서버 로그: model, status, code, type, name, raw message
사용자 UI: 등록된 ko/en/es/fr 안내 문구만 노출
```

UI에서 차단한 기술 문자열 예:

- `LLM returned empty response`
- `No API keys found in server environment`
- `Server error: 429`
- OpenAI/Gemini가 반환한 원문 오류 메시지와 내부 오류 코드

OpenAI 영구 소진 분류에는 다음 코드를 포함한다.

- `insufficient_quota`
- `credit_balance_exhausted`
- `organization_spend_limit_exceeded`
- `project_spend_limit_exceeded`
- `organization_usage_limit_exceeded`

일시적 429는 영구 소진과 분리해 잠시 후 재시도 안내를 표시한다. 게스트 메시지 제한은 기술 오류가
아니라 로그인 모달 전환 신호이므로 기존 동작을 유지한다.

## 10. 모델 선택·첫 화면 UI 정리

- 모델 메뉴를 `Google Gemini` / `OpenAI` / `이전 모델` 그룹으로 분리했다.
- 기본 펼침 높이에는 Google과 OpenAI 그룹을 모두 보여주고 이전 모델은 스크롤해서 확인한다.
- 모바일은 높이를 `60vh`로 제한한다.
- 모델 메뉴 스크롤은 인디고/바이올렛 계열 커스텀 스타일을 적용했다.
- 공급자 구분은 강한 배경색 대신 Gemini=인디고, OpenAI=에메랄드의 섹션 점·라벨·hover·체크에만 적용했다.
- 사이드바 스크롤은 별도 4px 반투명 스타일로 분리했다.
- 첫 화면 추천 칩을 기능명 중심에서 목적 중심으로 변경했다.

| 이전 | 변경 |
|---|---|
| 실시간 검색 | 최신 AI 뉴스 |
| 영화 상영표 | 오늘 볼 영화 |
| 약 정보 | 약 복용 확인 |
| 코드 작성 | Python 자동화 |

Python 예시는 `Python으로 엑셀 파일의 중복된 행을 제거하는 코드 작성해줘`로 바꿨고, 네 언어의
의미를 동일하게 맞췄다.

렌더러 프롬프트처럼 이번 변경과 무관한 문서는 수정일을 일괄 변경하지 않고, 코드와 실제로 충돌한
문서만 수정했다.

- `docs/guide/README.md` 신규: 핵심 아키텍처, 도구·렌더러, 분석 문서의 우선순위와 유지 규칙
- `REF_DB.md`: nickname/service-role/RLS 비활성 구조를 현재 Supabase Auth + user-scoped client + RLS로 교체. `profiles`, UUID `user_id`, UID Storage prefix, Gemini/OpenAI 출처, 모델 메타데이터 미저장을 반영
- `REF_Document.md`: GPT 이미지 지원과 영상·오디오·PDF/fileData의 Gemini 2.5 capability fallback, Bearer 인증, UID 경로 정규식, 공개 버킷 Phase 2 한계를 반영
- `REF_Weather.md`, `REF_Movie.md`: 추적 하니스를 `tests/` 경로로 정정하고 실제 극장 데이터 424개(CGV 177·롯데 133·메가박스 114)로 통일
- `REF_Law.md`: 저장소에 없는 `LAW_API_TEST.md` 깨진 링크를 실제 개발 로그로 교체
- `REF_App2_Agent.md`, `REF_ExternalAgents.md`: 과거 외부 검토와 현재 멀티 공급자 계약을 분리하고 chat route 300초를 반영
- `REF_CICD.md`, `db/README.md`: 현재 워크플로와 실행 순서를 2026-08-23 기준으로 재확인

`scripts/test-*`는 로컬 비추적 프로브라는 표시는 보존했다. 추적 가능한 자동 회귀는 `tests/`, 외부
네트워크 프로브는 `tests/manual/`이 기준이다.
