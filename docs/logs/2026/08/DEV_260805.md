- 거기서 진짜 결함 1건이 나왔고(홑 달러 노출), 프롬프트 규칙의 **구조적 구멍**을 고쳤다(§4).

- 통과 덕에 규칙 다국어화는 **기각**했고, 대신 **렌더러 12종 전수 조사**로 진짜 공백을 찾아 고쳤다 — 정상 6 · **죽은 i18n 1** · 미구현 5(§8-5).

## 1. 🔴 main Vercel 에 스테이징 값이 들어가 있었다

인증 브랜치가 요구하는 신규 변수 `NEXT_PUBLIC_SUPABASE_URL`·`NEXT_PUBLIC_SUPABASE_ANON_KEY` 를 등록하면서, 로컬 `.env.local` 의 값을 그대로 옮겼다. 그런데 `.env.local` 은 **스테이징**을 가리킨다.

```
main Vercel (사고 당시):
  SUPABASE_URL                   gaomgqnpsjtabrvwnpad   ← 프로덕션 (예전부터 있던 값)
  NEXT_PUBLIC_SUPABASE_URL       ghdpnuwbvlrxmxcazzci   ← 🔴 스테이징
  NEXT_PUBLIC_SUPABASE_ANON_KEY  role=anon          ref=ghdpnuwbvlrxmxcazzci
  SUPABASE_SERVICE_ROLE_KEY      role=service_role  ref=ghdpnuwbvlrxmxcazzci
```

### 왜 아직 안 터졌나

Vercel 은 env 를 **배포 시점에 함수에 굽는다.** 마지막 프로덕션 배포(1h 전)가 env 등록(36m 전)보다 앞서 있어서, 돌고 있는 함수는 변경 이전 스냅샷을 쓰고 있었다. 발견 시점에 **재배포 금지**를 먼저 확정한 이유다.

### 배포됐다면 무엇이 깨졌나

- `SUPABASE_SERVICE_ROLE_KEY` 는 **인증 머지 전 현재 main 코드도 이미 읽는다**([server/supabase.ts:10](../../../../server/supabase.ts#L10) → create-signed-url · parse-document). 프로덕션 URL + 스테이징 서명 키 = 서명 불일치 → **파일 업로드·문서 파싱만 실패.** 채팅은 멀쩡해서 원인이 env 라는 걸 알아채기 어렵다.
- 머지 후엔 클라이언트와 `createRouteClient` 가 통째로 스테이징을 본다 → 대화는 스테이징에, 서버 일부는 프로덕션에. **에러 없이 조용히 갈라진다.**

### 조치

| 변수 | 조치 | 근거 |
|---|---|---|
| `SUPABASE_SERVICE_ROLE_KEY` | **삭제** | 지우면 폴백으로 `SUPABASE_KEY`(82일째 프로덕션에서 쓰던 값)를 쓴다. dev 는 이 변수 없이 15일 돌았다 — **검증된 경로**다. 값 교체보다 삭제가 낫다 |
| `NEXT_PUBLIC_SUPABASE_URL` | 프로덕션 값으로 교체 | `SUPABASE_URL` 과 같은 ref 여야 한다 |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | 프로덕션 anon 키로 교체 | |

### 교훈 — 이름이 같으면 출처가 사라진다

세 프로젝트가 **같은 변수 이름**을 쓴다. 그래서 값만 보면 어디 것인지 판별이 안 되고, 복사·붙여넣기 한 번에 사고가 난다. 값 자체가 20자 랜덤 ref 라 눈으로도 안 걸러진다.

→ 런북 §E-2 에 **대조 절차**를 체크리스트로 넣었다. 두 가지를 본다:

```bash
# 1) URL 두 개의 ref 가 같은가 (SUPABASE_URL ↔ NEXT_PUBLIC_SUPABASE_URL)
# 2) 키의 role·ref 디코드 — 네트워크 안 탐
echo '<키>' | cut -d. -f2 | base64 -d 2>/dev/null | grep -oE '"(role|ref)":"[^"]*"'
#    → "role":"anon"  "ref":"gaomgqnpsjtabrvwnpad"
```

`role` 확인이 특히 중요하다. service_role 키를 `NEXT_PUBLIC_` 에 넣으면 **RLS 를 전부 우회하는 키가 브라우저 번들에 실린다.**

## 2. 부수 발견 — `VITE_` 레거시에 service_role 키가 있었다

env 비교 중 발견. main 에만 있던 두 변수:

```
VITE_SUPABASE_ANON_KEY   →  이름은 anon 인데 payload 는 role=service_role
VITE_SUPABASE_URL        →  ref 는 프로덕션도 스테이징도 아닌 제3의 옛 프로젝트 axpvmgndefueicehdetu
```

`VITE_` 접두사는 Vite 시절 "클라이언트 번들에 굽는다"는 뜻이었다. 그때 빌드된 적이 있다면 **RLS 우회 키가 브라우저로 배포됐던** 셈이다.

현재 코드 영향은 없다 — 두 브랜치 모두 `VITE_` 참조 0건, `import.meta.env` 는 [PLAN_NEXTJS_MIGRATION](../../../plans/PLAN_NEXTJS_MIGRATION.md) 문서에만, `vite.config`·`index.html` 은 트래킹된 파일에 없다. Next.js 는 `NEXT_PUBLIC_` 만 번들에 굽는다.

**Vercel 에서 삭제 완료.** 단 삭제가 키를 무효화하지는 않는다 — 그 프로젝트가 살아 있으면 **rotate 가 별도로 필요**하다(런북 §5-2).

미사용 변수 `JINA_API_KEY`(참조 0건)·`HOSPITAL_KEY`(코드는 `PHARM_KEY` 사용)도 같은 항목으로 남겼다. 컷오버 blocker 아님.

## 3. dev 화면 검증 — DEV_260801 이 남긴 4건

### 3-1. ⚠️ 수식 — 테스트 케이스가 잘못돼 있었다

DEV_260801 §5 가 지정한 프롬프트는 `경사면 힘 분석 그림으로 설명해줘` 였다. 돌려보니 응답에 **`$$` 가 하나도 없었다.** KaTeX 경로가 아예 실행되지 않았다.

버그가 아니다. [prompt.ts](../../../../server/agent/prompt.ts) 가 "simple expressions 는 plain Unicode 도 acceptable" 이라고 허용하고 있고, `mg sinθ` 정도는 실제로 유니코드가 더 읽기 좋다. 모델이 그 조항을 따른 것이다.

**문제는 케이스 선정이다.** 경사면 문제는 분수·적분·합이 안 나와서 LaTeX 를 강제하는 조건(`fractions, summations, integrals…`)에 걸리지 않는다. 몇 번을 돌려도 KaTeX 가 안 걸린다.

→ 케이스를 `정규분포 확률밀도함수 설명해줘` 로 교체. 분수·제곱근·지수·적분·그리스 문자가 전부 나온다.

**재실행 결과 — 세 위치 모두 통과:**

| 위치 | 예 |
|---|---|
| 인라인 | `평균이 $$\mu$$이고 …` → 문장 중간 정상 |
| 블록 | `$$f(x) = \frac{1}{\sigma\sqrt{2\pi}} e^{…}$$` → 분수·제곱근·지수 중첩 정상 |
| 표 셀 | `\| $$x$$ \| 확률변수 \|` → 정상 |

표 셀은 프롬프트가 "된다"고 주장만 하고 실측된 적이 없던 항목이었다. 이번에 닫혔다.

### 3-2. ✅ 마크다운 강조 — 최악 조건 통과

같은 응답에서 원래 버그의 재현 조건이 여러 번 나왔고 전부 굵게 렌더됐다:

```
**정규분포(Normal Distribution)**의        닫는 ** 앞 `)` + 뒤 한글조사
**확률밀도함수(…, PDF)**는                  동일
**'밀도'**를                                닫는 ** 앞 작은따옴표 + 뒤 한글
약 **95.45%**가                             `%` + 조사 — 최초 신고 형태
```

[DEV_260801 §3-4](DEV_260801.md)·[§3-4-1](DEV_260801.md) 의 두 수정(remark-cjk-friendly 도입 + 전처리 정규식 제거)이 실제 응답에서 확인됐다.

### 3-3. ✅ 극장 매칭 — 두 케이스 다 통과

## 4. 🔴 여기서만 잡힌 결함 — 홑 달러 노출

`정규분포…` 응답의 마지막 문단:

```
구간 $[a, b]$에 속할 확률은 …
      ↑ 홑 달러 → 화면에 원문 그대로 노출
```

[ChatMessage.tsx:703](../../../../components/ChatMessage.tsx#L703) 이 `singleDollarTextMath: false` 라 홑 달러는 수식이 아니다. 같은 응답의 나머지 40여 개는 전부 `$$` 를 제대로 썼는데 여기 한 번만 샜다.

### 왜 코드로 막지 않았나

세 가지 방법이 다 지금보다 나쁘다:

| 방법 | 문제 |
|---|---|
| `singleDollarTextMath: true` | `$100`·`$5` 통화 표기가 전부 수식이 된다. 통화는 **검색 결과·크롤링 문서에서도 들어와** 프롬프트로 통제 불가 |
| 전처리로 `$…$` → `$$…$$` | [§3-4-1](DEV_260801.md) 에서 두 번 데인 패턴. `"가격은 $100에서 $200 사이"` 에서 `$100에서 $` 가 수식이 된다. 게다가 이번 케이스(`$[a, b]$`)엔 백슬래시가 없어 **좁은 규칙으로는 못 잡고, 넓히면 통화가 깨진다** |
| 프롬프트 강화 | 채택 (아래) |

드물고 가벼운 결함(읽을 수는 있고 기호만 보임)을 흔하고 무거운 결함(가격·환율 질문마다 깨짐)으로 교환할 이유가 없다. `singleDollarTextMath: false` 는 그 트레이드오프를 의식하고 고른 값이고, 이번 관찰은 그 선택의 근거에 가깝다.

### 프롬프트의 구조적 구멍

원인을 보니 강조가 부족한 게 아니라 **규칙의 축이 잘못돼 있었다.**

```
기존:  Write ALL mathematical notation
       (fractions, summations, integrals, Greek letters, subscripts/superscripts)
       in LaTeX wrapped in DOUBLE dollar signs
```

**내용 기준** 규칙이다. `[a, b]` 는 분수도 적분도 그리스 문자도 아니다 → 모델 입장에선 "그 목록에 없으니 MUST 대상이 아니다" 로 읽는 게 자연스럽다. 실제로 샌 것도 이 부류뿐이었다.

게다가 마지막 줄의 "simple expressions 는 plain Unicode 도 acceptable" 이 **"간단한 건 느슨하게 해도 된다"** 는 도피처로 읽힌다.

### 수정 — 축을 "내용"에서 "구분자"로

```
THE RULE IS ABOUT THE DELIMITER, NOT ABOUT WHETHER THE CONTENT "COUNTS AS" MATH.
If you type a `$` for any reason other than a currency amount, it MUST be a double `$$`.
```

"이게 수식인가?" 를 판단할 필요를 없앴다. 추가로 **새는 부류를 명시**했다(전부 이번에 관찰된 유형 — 짧고 기호가 아닌 조각):

```
구간·범위     $[a, b]$   → $$[a, b]$$
집합·튜플     ${1, 2}$, $(x, y)$
문장 중 변수   $x$, $n$, $f(a)$
조건·비교      $x > 0$, $n \ge 1$
```

유니코드 허용은 **유지**하되(표 셀에선 실제로 더 읽기 좋다), 홑 달러의 근거로 오독되지 않게 못 박았다:

```
this is a choice between `$$...$$` and plain Unicode — never a license to use a single `$`
```

**⚠️ 프롬프트 변경은 검증이 확률적이다.** 배포 후 같은 질문을 두세 번 돌려 재발 여부를 봐야 한다.

**→ 2026-08-08 배포 후 확인: 유출 0건** ([DEV_260808 §5-4](DEV_260808.md)). 구간 `$$(-\infty < x < \infty)$$`, 부등식 `$$\sigma > 0$$`, 맨 숫자 `$$3.14159$$` `$$68.27\%$$`, 표 셀 안까지 전부 이중 달러. **"수식 같지 않은" 것들이 이중 달러로 나온 게 축 재작성이 통했다는 근거다** — 판단을 묻지 않게 만들자 판단 실수가 사라졌다. 다만 확률적 검증이라 한 번의 통과가 종결은 아니다.

## 5. 이 세션의 교훈

1. **"통과"와 "검증이 성립함"은 다르다.** §3-1 은 응답이 정상이라 통과처럼 보였지만, 검증하려던 코드 경로는 실행조차 안 됐다. 테스트가 **무엇을 실행시켰는지**를 먼저 확인해야 한다.
2. **규칙이 안 지켜지면 강조를 더하기 전에 규칙의 구조를 본다.** §4 의 원인은 "덜 강하게 말해서" 가 아니라 "판단 기준을 모델에게 넘겨서" 였다.
3. **이름이 같으면 출처가 사라진다.** §1 은 사람의 실수가 아니라 이름 설계의 결과다. 대조 절차를 절차로 만들어야 재발이 막힌다.
4. **배포 검증 전에 `origin/<branch>` 부터 본다.** §3-4 에서 "고쳤는데 안 보임" 의 정체는 미푸시였다.
5. **삭제와 무효화는 다르다.** §2 의 키는 Vercel 에서 지워도 살아 있다. rotate 가 별도로 필요하다.

| 9 | **렌더러 i18n** — Diagram prop 1줄 + 도구 카드 5종 `T` 맵 (§8-5) | 코드 `+257/-90` |
| 10 | [PLAN_LANG_COVERAGE_260805](../../../plans/PLAN_LANG_COVERAGE_260805.md) 신설 — 측정 설계·결과·조치 | 문서 |

### SQL 두 개에 대한 메모

`cutover-prod.sql` 은 `auth-mvp-schema.sql` 을 **복제하지 않는다.** 340줄을 복사해두면 원본이 바뀔 때 갈라지고, 그건 `ChatMessage.tsx` 에서 렌더러 목록이 4번 중복 선언돼 있는 것과 같은 실수다([PLAN_CHATMESSAGE_REFACTOR](../../../plans/PLAN_CHATMESSAGE_REFACTOR_260801.md)). rename 과 트랜잭션 경계만 제공하고 본문은 붙여넣게 했다.

`verify-prod.sql` 은 **두 항목을 자동 판정에서 뺐다.** Supabase 가 프로젝트 생성 시 `alter default privileges … grant all … to anon` 을 걸어두기 때문에, 정상 적용 상태에서도 anon 권한이 붙을 수 있다. 기대값을 0 으로 박으면 **가짜 FAIL** 이 뜬다 — 유지보수 창에서 가짜 경보만큼 나쁜 게 없다. 참고 조회로 분리하고 이유를 파일에 적었다.

> **둘 다 실제 DB 에서 실행해보지 않았다**(Supabase MCP 미인증). 구문 검사만 했다. 컷오버 전에 **스테이징에서 verify 를 리허설**해 쿼리 자체의 오류를 걸러낼 것 — 기대값은 "2번(`_legacy` 백업)만 FAIL, 나머지 13개 PASS" 다.

## 8. 비한국어 경로 측정 (es/fr)

계획·상세: [PLAN_LANG_COVERAGE_260805](../../../plans/PLAN_LANG_COVERAGE_260805.md)

앱은 4언어를 **선언**하는데([ChatSidebar.tsx](../../../../components/ChatSidebar.tsx) · [lang.ts](../../../../server/agent/lang.ts)) 실측은 ko/en 뿐이었다. [DEV_260801 §6](DEV_260801.md) 의 4순위 잔여 항목.

### 8-1. 🔴 하니스가 잘못된 것을 재고 있었다 (측정 전에 발견)

**둘 다 돌리기 전에 코드를 읽어서 잡았다.** 그냥 실행했으면 통과 기록만 남고 결론은 틀렸을 것이다.

| 하니스 | 결함 | 실제로 재고 있던 것 |
|---|---|---|
| `test-weather-multiturn.ts` | `const SCENARIO = LANG === 'ko' ? TURNS : TURNS_EN` | `WM_LANG=es` = **"영어로 묻고 스페인어로 답하기"** |
| `test-movie-multiturn.ts` | `getSystemInstruction('Korean')` 하드코딩 + `compileAgentGraph` 에 `langName` **미전달**(날씨는 전달함) | 언어 스위치 자체가 없음 |

조치: 날씨는 `SCENARIOS` 맵 + ES/FR 시나리오 추가, 영화는 `MM_LANG` + EN 시나리오 + 배선을 날씨와 동일하게.

> **§5 교훈 1번("통과와 검증 성립은 다르다")이 같은 날 두 번 반복됐다.** §3-1 은 테스트 케이스가 코드 경로를 안 건드렸고, 여기는 하니스가 다른 조건을 재고 있었다. 공통점은 **테스트를 돌리기 전에 그 테스트가 무엇을 실행시키는지 읽지 않으면 결과를 못 믿는다**는 것.

### 8-2. 결과 — 전부 통과

gemini-3.6-flash 기준:

| 측정 | 결과 | 회귀 | 회색지대 |
|---|---|---|---|
| 날씨 **es** | **11/11** | 8/8 | 3/3 |
| 날씨 **fr** | **11/11** | 8/8 | 3/3 |
| 영화 **en** | **8/8** | 5/5 | 3/3 |
| 영화 ko(회귀 재확인) | **8/8** | 5/5 | 3/3 |

마지막 행은 하니스에 `langName` 배선을 추가한 변경이 **기준선을 건드리지 않았는지** 본 것이다.

핵심은 회색지대다 — **강한 규칙이 전부 미스인 상태에서 LLM `follow_up` 판정만으로 정확했다.** 영화 라우터 로그가 근거를 그대로 보여준다:

```
Which movie starts earliest?        → refine    (상영표로 답)
What's the nearest subway station?  → unrelated (검색 유지 — 약한어휘 오탐 방지)
How about Sinchon?                  → new       (지역만 교체)
```

### 8-3. 규칙 다국어화는 **하지 않는다**

`MOVIE_FOLLOWUP_QUESTION`·`MOVIE_STRONG_TERMS`·`MOVIE_WEAK_TERMS` 를 4언어로 늘리면 세 벌이 4배가 되는데, 얻는 건 **이미 맞고 있는 판정을 규칙으로도 맞히는 것**뿐이다.

게다가 규칙은 LLM 판정보다 **우선순위가 높다.** 잘못 만들면 지금 맞는 것을 틀리게 만든다 — [REF_App2_Agent §7-5](../../../guide/REF_App2_Agent.md) 에서 `[?？]` 를 강한 신호로 뒀다가 `신촌은 어때?` 가 깨졌던 그 구조다.

**비용 절약이 아니라 위험 회피다.** 안 고쳐도 되는 것을 고치면 회귀만 생긴다.

라우터 프롬프트 다국어 예시 A/B 도 **조건 미충족** — 분리 측정할 실패 사례가 없다(§9 의 "효과 미검증" 표시는 유지).

### 8-4. 🔴 대신 나온 진짜 공백 — 도구 카드 렌더러 4종

측정이 아니라 **코드를 읽어서** 나왔다. [ChatMessage.tsx:640-685](../../../../components/ChatMessage.tsx#L640-L685) 의 렌더러 호출부 전수:

```tsx
<PharmacyRenderer data={part.data} />   ← language 없음   한글 리터럴 11종
<HospitalRenderer data={part.data} />   ← language 없음   8종
<LawRenderer      data={part.data} />   ← language 없음   7종
<MovieRenderer    data={part.data} />   ← language 없음   6종
<WeatherRenderer  data={part.data} language={language} />   ← 있음
```

처음엔 영화만인 줄 알았는데 **넷 다였다.** 그리고 이 넷이 정확히 **"도구 카드" 의도**(약국·병원·법령·영화)다 — 우연이 아니라, 데이터가 전부 한국 공공 API 에서 오고 [§8](DEV_260801.md) 에서 렌더러 JSON 스펙을 0으로 뺀 그 의도들이라 만들 때부터 "한국어 사용자용"이라는 암묵 가정이 있었다.

스페인어로 물어도 드롭다운에 `지점 선택`, 법령 카드에 `소관부처 정보 없음` 이 뜬다. **측정할 필요가 없다 — 코드가 곧 증거다.**

### 8-5. 조치 — 렌더러 i18n (구현 완료)

전수 조사 결과 세 부류였다. **"영화 하나" → "도구 카드 4종" → "12종 중 6종"** 으로 범위가 두 번 커졌다.

| 부류 | 렌더러 | 조치 |
|---|---|---|
| ✅ 정상 6 | Bio·Chart·Chemical·Constellation·Drug·Weather | 없음 |
| 🔴 **죽은 i18n** 1 | **Diagram** | prop 한 줄 |
| 🔴 미구현 5 | Pharmacy·Hospital·Vet·Law·Movie | `T` 맵 신설 |

> "한글 리터럴 개수"로 세면 오해한다 — 정상 6종도 한글이 많다(Drug 58, Weather 32). 전부 `ko:` 브랜치 안이다. **판정 기준은 JSX 에 직접 박힌 한글**이다.

#### 🔴 죽은 i18n 이 가장 나빴다

`DiagramRenderer` 는 `language?: 'ko'|'en'|'es'|'fr'` 를 받고 es/fr 번역까지 **완비**돼 있는데, [ChatMessage.tsx](../../../../components/ChatMessage.tsx) 가 prop 을 안 넘겨 기본값 `'ko'` 로 흡수되고 있었다. **번역이 작성된 채 사장**된 상태.

미구현보다 나쁜 이유는 **코드만 읽으면 "i18n 완료"로 보이기 때문**이다 — 아무도 다시 확인하지 않는다. 그리고 **타입이 안 잡아준다**(`language?:` 가 옵셔널).

→ 재발 방지는 [PLAN_CHATMESSAGE_REFACTOR](../../../plans/PLAN_CHATMESSAGE_REFACTOR_260801.md) 의 레지스트리로 **공통 prop 전달을 한 곳에 모으는 것**이다. 렌더러 목록이 4번 중복 선언된 문제와 뿌리가 같다.

#### 구현 — 4단계, `+257 / -90`

| 단계 | 한 일 | 메모 |
|---:|---|---|
| 0 | Diagram 에 `language={language}` | 1줄, 번역이 이미 있어 즉시 효과 |
| 1 | 도구 카드 5종 호출부 prop 추가 | **prop 을 넣자마자 tsc 가 미구현 4종을 정확히 짚었다** — 컴파일러가 진행 상황을 추적해줬다 |
| 2 | API 계약값 상수화 | 아래 |
| 3 | 5종 × 4언어 `T` 맵 + 표시 치환 | JSX 직접 한글 0 |

`tsc --noEmit` 0 · `npm run build` 성공.

#### 🔴 함정 — 한글이 제어 흐름 키였다

순진하게 치환하면 깨지는 자리가 실제로 있었다:

```tsx
if (hoursToday === '휴무') return false;              // 약국 영업 판정
const TYPE_STYLE = { '상급종합': {…violet}, … };       // 병원 뱃지 색상 맵
h.type.includes('상급종합') ? 'bg-violet-500' : …      // 색상 분기
v.status === '영업' || v.status === '영업중'           // 동물병원 상태
```

→ **API 계약값은 상수로 뽑고 한글 그대로 두었다.** 표시만 별도 맵으로 옮겼다:

```tsx
const API_CLOSED_DAY = '휴무';        // 🔴 번역 금지 — 비교용
if (hoursToday === API_CLOSED_DAY) …
<p>{tt.dayOff}</p>                    // 표시만 언어별
```

**미지값은 원문 통과**시킨다(`TYPE_LABEL[lang][raw] ?? raw`). API 가 예상 밖 분류값을 줄 수 있어 전수 매핑이 원리적으로 불가능하다.

#### 번역 기준 — "API 가 줬느냐"가 아니라 "고유명사냐"

| 종류 | 예 | 처리 |
|---|---|---|
| 고유명사·주소·전화 | `종로약국` · `서울 종로구 …` | 🔴 한글 유지 |
| 분류값(enum) | `상급종합` · `휴무` · `영업중` | ✅ 표시만 번역 (비교 키는 한글) |
| UI 크롬 | `지점 선택` · `이전/다음` | ✅ 번역 |

고유명사를 유지하는 이유는 **사용자를 특정하면 나온다** — 스페인어로 한국 약국을 묻는 사람은 거의 확실히 **한국에 있는 외국인**이고, 약국명을 택시기사에게 보여주고 주소를 카카오지도에 넣는다(카드에 이미 그 링크가 있다). `종로약국` → `Farmacia Jongno` 는 번역이 아니라 **훼손**이다.

#### 조사 문제 — 문장 단위로 키를 잡는다

`MovieRenderer` 의 "지점 없음" 문구는 조사가 박혀 있었다:

```tsx
{nm}는 {region ? `'${region}' 지역에` : '이 지역에'} 지점이 없습니다. 위 목록에서…
```

토막을 이어붙이면 다른 언어에서 어순이 깨진다 → 자리표시자 + **문장 단위 키**:

```
ko: "{chain}는 '{region}' 지역에 지점이 없습니다. 위 목록에서…"
en: "{chain} has no location in '{region}'. Pick another one from the list above."
```

#### 본보기는 이미 코드 안에 있었다

`PharmacyRenderer` 의 요일이 **키와 라벨을 이미 분리**해 뒀다 — `{ key: 'mon', label: '월' }`. 키는 데이터, 라벨만 언어별. 나머지 렌더러를 이 형태에 맞췄고, 주석으로 그 사실을 남겼다.

### 8-6. 화면 검증 결과 + 부수 발견 (CGV 0건)

**한국어 회귀 — 우려했던 두 가지 모두 통과.** 상수화가 제어 흐름을 안 건드렸다:

| 카드 | 확인 |
|---|---|
| 약국 | `10:00~17:00` → **영업중**(조회 13:41, 구간 내) · 요일 색상(토=파랑·일=빨강·공휴=주황) · 오늘 `●` 하이라이트 |
| 병원 | 상급종합=**보라**, 종합병원=**파랑** 뱃지·스트라이프 — `TYPE_STYLE` 키 상수화 후에도 동일 |
| 영화 | `'강남'에는 지점이 없습니다` · 자리표시자 문장이 한국어에서 **글자 단위로 동일** |
| 법령·다이어그램 | 정상 |

**스페인어 — 전 카드 통과:**

```
10 encontradas · abiertas ahora 10    Abierta    Lun/Mar/Mié/Jue/Vie/Sáb/Dom/Fest    Cerrado
Top 10 resultados (por número de médicos)   Terciario / Hospital general   1,331 médicos · fund. 1994.06.13
Elegir sede · Sin sedes en '강남'  ·  롯데시네마 no tiene sedes en '강남'. Elige otra…
Texto de la ley · 개인정보보호위원회
```

의도대로 **지명·약국명·병원명·법령명·지점명은 한글로 남았다.** 특히 `Sin sedes en '강남'` 처럼 **번역된 문장 안에 한글 고유명사가 박히는 형태**가 목표한 그림이다.

`Cerrado`(공휴일 휴무)가 여기서 처음 나와 **`API_CLOSED_DAY` 경로도 확인**됐다 — 한국어 테스트에서는 휴무일 있는 약국이 안 걸려 미검증이었다.

#### 🟡 기존 버그 — 동물병원 상태 색상

뱃지·스트라이프가 전부 **주황**(=영업도 폐업도 아님)이다. 영업 중이면 청록이어야 한다.

```ts
const API_OPEN = '영업';  const API_OPEN_NOW = '영업중';
isOpen = v.status === API_OPEN || v.status === API_OPEN_NOW;
```

화면의 `status_detail` 이 `정상` 인 걸 보면 행안부 API 의 `SALS_STTS_NM`([vet-tool.ts:194](../../../../server/agent/vet-tool.ts#L194))이 `'정상'` 계열이라 어느 조건에도 안 맞는다. **내 변경 전후 조건이 글자 단위로 동일**하므로(상수 이름만 붙였다) 회귀가 아니라 **원래부터 그랬다.**

부수 효과로 `정상` 이 `STATUS_LABEL` 에 없어 **스페인어에서도 `정상` 이 그대로** 나온다(미지값 원문 통과 — 설계대로 동작한 것이지만 번역은 안 된다).

→ `API_OPEN_NORMAL = '정상'` 을 조건과 라벨 맵 양쪽에 추가하면 되지만, API 가 실제로 어떤 값들을 주는지(`휴업` 포함) 확인이 먼저다. i18n 범위 밖이라 별건으로 둔다.

#### 🔴 부수 발견 — CGV 스크래핑 실패가 "상영 없음"으로 보인다

스페인어 화면에서 CGV 만 `0 películas · 0 funciones`. 언어 탓이 아닌지 API 를 직접 쳐서 확인했다:

```
1차   movies=0  cached=stale  age=373초   ← 화면이 본 값
2차   movies=3  total=22  ms=25361  cached=fresh
3차   movies=3  total=22  cached=fresh
```

같은 시각 메가박스는 정상(`movies=4`). **6분 뒤 스스로 복구**됐다 — 즉 일시적 스크래핑 실패였고 그 빈 결과가 캐시에 박혀 있었다.

CGV 만 browserless 로 긁고(롯데·메가박스는 JSON API 직접), 실패 경로가 **전부 빈 배열로 수렴**한다 — `if (!d.rows) return []`. 그래서 **실패와 "진짜 상영 없음"이 화면상 구분되지 않는다.** 게다가 그 값이 캐시돼 새로고침으로도 안 고쳐진다.

→ [BACKLOG A3](../../../plans/PLAN_BACKLOG_260801.md) 로 등록. 처방은 실패 시 `throw` → `payload.error`(카드에 "조회 실패" UI 가 이미 있다) + **실패는 캐시에 넣지 않기**.

> **언어와 무관하다.** 한국어 테스트 때는 CGV 섹션이 스크롤 밖이라 안 보였고, 스페인어 테스트가 마침 stale 캐시 구간에 걸렸을 뿐이다. i18n 배포의 회귀가 아니다.
