## 판정 근거 확인법

Vercel Functions 로그에 턴마다 **한 줄**이 남는다. 게이트별로 흩어져 있던 로그를 합친 것이라,
이 줄만 보면 "누가 왜 이겼는지"가 끝난다.

```
[SearchPolicy] ON by user-explicit(300) "사용자가 검색·출처를 명시 요청" | trace: router-llm=on(100), followup-guard=off(100)
[SearchPolicy] OFF by url-content(200) "URL 본문이 근거" | trace: router-llm=on(100)
```

화면상 판별: 검색이 붙으면 응답에 **출처/그라운딩 표기**가 나오고 응답이 느리다(2.5 + 합성 2콜).
검색이 없으면 즉답에 가깝다. `"실시간 웹 검색 기능이 제공되지 않습니다"` 문구가 나오면 **검색 OFF**다.

## A. 이번 결함 — 반드시 통과해야 함 🔴

멀티턴이라 **1턴 세팅이 필수**다. 1턴에서 검색이 실제로 일어나야 가드 조건(`prevSearched`)이 선다.

| # | 턴 | 입력 | 기대 |
|---:|---|---|---|
| A0 | 1턴 | `오늘 AI 뉴스 알려줘` | 검색 ON (세팅용) |
| **A1** | 2턴 | `그럼 모티프 모델 구체적으로 찾아서 정리해보자` | **검색 ON** ← 스크린샷 재현 케이스 |
| A2 | 2턴 | `검색해서 정리해줘` | 검색 ON |
| A3 | 2턴 | `출처 찾아서 정리해줘` | 검색 ON + 출처 표기 |
| A4 | 2턴 | `구글에 찾아보고 비교해줘` | 검색 ON |

A1~A4는 매번 A0부터 새 대화로 시작할 것. **A1이 OFF면 배포 롤백 대상**이다.

단일턴(가드 무관, 정규식 갭이었던 어형):

| # | 입력 | 기대 |
|---:|---|---|
| A5 | `모티프 모델 찾아줘` | ON |
| A6 | `모티프 모델 조사해줘` | ON |
| A7 | `AI 모델 알아보자` | ON |

## B. 반대 방향 회귀 — 과잉검색이 생겼는가 🟡

A만 보면 "검색을 더 잘 붙인다"로 착각하기 쉽다. 가드가 죽었으면 **불필요한 재검색으로 느려진다.**
1턴은 전부 `오늘 AI 뉴스 알려줘`(검색 ON) 이후.

| # | 입력 | 기대 | 관찰 포인트 |
|---:|---|---|---|
| B1 | `방금 알려준 거 표로 정리해줘` | **OFF** | 즉답이어야 함. 느리면 가드 죽은 것 |
| B2 | `아까 검색 결과 다시 요약` | **OFF** | 과거참조 |
| B3 | `기존개념부터 최근 검색한 내용 비교 요약해줘` | **OFF** | 과거참조 |
| B4 | `아까보다 더 최신 걸로 다시 알려줘` | **ON** | 새 최신요구 — 억제되면 안 됨 |

## C. B2 변경 — 최우선 관찰 대상 🔴

**이번 재설계에서 유일하게 위험 방향으로 움직인 변경이다.**
URL이 붙은 상태에서 사용자가 검색을 명시 요청하면 이제 grounding이 켜진다(tier 300 > 200).
과거 사고 이력: 해외 IP에서 짧은 HTML이 반환되면 모델이 **전혀 다른 기사를 요약**했다.

한국 뉴스 URL(네이버 등)을 써야 재현 조건에 가깝다.

| # | 입력 | 기대 | 관찰 포인트 |
|---:|---|---|---|
| C1 | `<뉴스 URL> 이 기사 요약해줘` | OFF | 기존과 동일. URL 본문 기반 |
| **C2** | `<뉴스 URL> 이 기사 검색해서 팩트체크 해줘` | **ON (신규)** | 🔴 **응답이 그 기사 내용인가.** 다른 기사를 요약하면 실패 |
| C3 | 1턴 URL 요약 → 2턴 `그거 표로 정리해줘` | OFF | Fix A 보존 |
| C4 | 1턴 URL 요약 → 2턴 `오늘 환율 얼마야?` | ON | Fix A — URL 첨부 후 검색이 영구히 꺼지면 안 됨 |

C2가 깨지면 tier를 되돌리는 게 아니라 **grounding + URL 본문을 함께 주는 프롬프트**를 손대는 쪽이 맞다.

### A그룹 — 통과

`오늘 AI 뉴스 알려줘` → `그럼 모티프 모델 구체적으로 찾아서 정리해보자` → `검색해서 정리해줘` → `출처 찾아서 정리해줘`.
4턴 모두 검색 ON + 출처 표기. **스크린샷의 원래 증상(`실시간 웹 검색 기능이 제공되지 않습니다`)이 재현되지 않는다.**

> 이 넷은 전부 "검색이 켜져야 정상"인 케이스다. **A만 보고 과잉검색을 판단할 수 없다** — B그룹이 짝이다.

## 🔴 1차 테스트에서 발견 — `prevSearched` 근사가 서는 대화 / 못 서는 대화

`인공타액제 알려줘` → `표로 정리해줘` 시나리오를 프로브로 재현하다 찾았다.

```
prev="인공타액제 알려줘"    → classifySearchNeed=gray → prevSearched=false
prev="타이레놀 부작용 알려줘" → classifySearchNeed=gray → prevSearched=false
prev="오늘 AI 뉴스 알려줘"   → classifySearchNeed=on   → prevSearched=true

가드("표로 정리해줘"): prevSearched=true → 억제 / false → 억제 안 함
```

**의약 질의는 `medical_qa`가 tier로 검색을 강제해서 켜진다. 정규식이 `on`을 내서 켜지는 게 아니다.**
그래서 실제로는 검색이 일어났는데 `prevSearched` 근사는 `false`로 본다 → 가공형 후속에 가드가 **아예 서지 않는다.**

같은 구멍이 **룰이 아니라 intent로 검색이 결정되는 모든 경로**에 있다 (medical_qa, 카드 계열 등).

### 왜 화면은 정상이었나

출처 칩 없이 직전 답변에서 파생된 표가 나왔다 → 실제로는 OFF였을 가능성이 크다.
프로브는 `needsSearch=true`(라우터 LLM 실패 = 최악조건)를 넣었고, 프로덕션에선 **라우터 LLM이 `false`를 반환해 막아준 것**으로 보인다.

> **지금은 가드가 아니라 라우터 LLM 운에 기대고 있다.** 무료티어 503이 나면 그대로 재검색이 붙는다.
> `35-flash-free-tier-throughput` 기록대로 503은 드문 일이 아니다.
