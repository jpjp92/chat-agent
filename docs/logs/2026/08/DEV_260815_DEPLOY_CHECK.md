## 판정 근거 확인법

Vercel Functions 로그에 턴마다 **한 줄**이 남는다. 게이트별로 흩어져 있던 로그를 합친 것이라,
이 줄만 보면 "누가 왜 이겼는지"가 끝난다.

```
[SearchPolicy] ON by user-explicit(300) "사용자가 검색·출처를 명시 요청" | trace: router-llm=on(100), followup-guard=off(100)
[SearchPolicy] OFF by url-content(200) "URL 본문이 근거" | trace: router-llm=on(100)
```

화면상 판별: 검색이 붙으면 응답에 **출처/그라운딩 표기**가 나오고 응답이 느리다(2.5 + 합성 2콜).
검색이 없으면 즉답에 가깝다. `"실시간 웹 검색 기능이 제공되지 않습니다"` 문구가 나오면 **검색 OFF**다.

## 🔴 1차 테스트에서 발견 — `prevSearched` 근사가 서는 대화 / 못 서는 대화

`인공타액제 알려줘` → `표로 정리해줘` 시나리오를 프로브로 재현하다 찾았다.

```
prev="인공타액제 알려줘"    → classifySearchNeed=gray → prevSearched=false
prev="타이레놀 부작용 알려줘" → classifySearchNeed=gray → prevSearched=false
prev="오늘 AI 뉴스 알려줘"   → classifySearchNeed=on   → prevSearched=true

가드("표로 정리해줘"): prevSearched=true → 억제 / false → 억제 안 함
```

**의약 질의는 `medical_qa`가 tier로 검색을 강제해서 켜진다. 정규식이 `on`을 내서 켜지는 게 아니다.**
그래서 실제로는 검색이 일어났는데 `prevSearched` 근사는 `false`로 본다 → 가공형 후속에 가드가 **아예 서지 않는다.**

같은 구멍이 **룰이 아니라 intent로 검색이 결정되는 모든 경로**에 있다 (medical_qa, 카드 계열 등).

### 왜 화면은 정상이었나

출처 칩 없이 직전 답변에서 파생된 표가 나왔다 → 실제로는 OFF였을 가능성이 크다.
프로브는 `needsSearch=true`(라우터 LLM 실패 = 최악조건)를 넣었고, 프로덕션에선 **라우터 LLM이 `false`를 반환해 막아준 것**으로 보인다.

> **지금은 가드가 아니라 라우터 LLM 운에 기대고 있다.** 무료티어 503이 나면 그대로 재검색이 붙는다.
> `35-flash-free-tier-throughput` 기록대로 503은 드문 일이 아니다.

[PLAN §5](../../../plans/PLAN_SEARCH_POLICY_260815.md) **Step 6(실제 검색 여부 영속화)을 Step 5보다 먼저** 수행한다.

### 2차 발견 — `인공 타액제`가 general로 새면서 MFDS 경로를 우회

dev에서 `인공 타액제 알려줘` → 제품 나열 시퀀스가 실제와 다른 제품명을 냈다.
**로컬 실그래프로 같은 시퀀스를 돌리면 정상이다:**

```
턴1  intent=drug_info  24.6s   ← LangChain 툴 경로(search_drug_info → MFDS)
턴2  intent=drug_info   4.8s   → 제로바액 / 드라이문트겔 / 제로미아액
턴3  intent=general     2.9s   [SearchPolicy] OFF by router-llm(100) → 같은 3개를 그대로 가공
```

갈린 지점은 **intent 분류 하나**다. `drug_info`면 MFDS 실데이터를 쓰고, `general`로 새면
프롬프트의 약 정보 방어([L280](../../../../server/agent/prompt.ts#L280) "학습 지식으로 채우지 마라",
[L282](../../../../server/agent/prompt.ts#L282) "각인은 환자 안전")가 **통째로 빠진다** — 전부 `drug_info` 전용이라서다.

[router.ts](../../../../server/agent/nodes/router.ts)의 복구 장치는 `hasImage`일 때 하나뿐이었다.
**텍스트 약 질문이 general로 새면 되돌릴 방법이 없었다.**

두 갈래 모두 룰 쪽 문제다:

| | 시나리오 | 조치 |
|---|---|---|
| a | 라우터 LLM이 `general` 반환 | 텍스트 복구 신설 (제형 어휘일 때만) |
| b | LLM이 429/503 실패 → 룰 폴백이 `general` | `classifyIntentByRules`에 제형 어휘 추가 |

`hasMedicalIntentKeyword`(효과·성분 등 범용어 포함)로 뒤집으면 `"이 마케팅 전략 효과 있어?"`가
끌려가므로, **고정밀 제형 어휘 전용 패턴**(`hasDosageFormKeyword`)을 따로 뒀다.

제외한 것: `산제`("산제 발표 자료"), `정제`(refine), `캡슐`(캡슐호텔). `연고`는 緣故(연고지·연고자·연고권)를
lookahead로 배제. **남은 위험: `"그 지역에 연고가 있어?"`는 여전히 걸린다** — 접미로 구분되지 않는 용법이라
정규식으로 못 가른다. 관측되면 `연고제`만 남긴다.

```
제형 탐지 23/23 · 룰 폴백 7/7 · 검색정책 · verify · rules · tsc   전부 exit 0
```

> **복구 분기 자체는 실그래프로 못 밟았다.** 세 번 다 라우터 LLM이 `drug_info`로 맞게 분류해
> `general`이 나오지 않았다. 단위 테스트로만 검증된 상태다 → 배포 후 H그룹으로 확인한다.

| H2 | H1 후 → `구체적으로 대표적인 제품들은 뭐야?` | `drug_info` | **제로바액·드라이문트겔·제로미아액** 계열이 나오는가 |
| H3 | H2 후 → `표로 정리해줘` | `general` 무방 | 턴2 제품명이 **그대로** 유지되는가 |
| H4 | `후시딘 연고 어디에 발라?` | `drug_info` | 제형 어휘 |
| H5 | `점안액 넣는 방법 알려줘` | `drug_info` | 제형 어휘 |
| H6 | `타이레놀 부작용 알려줘` | `drug_info` | 기존 경로 회귀 |

H2가 실제 제품명을 내는지가 핵심이다. 처음 보는 브랜드가 나오면 **검색해서 실존 여부를 확인**할 것 —
지어낸 의약품명은 이 앱에서 가장 위험한 실패다.

### H-오탐 — 끌려가면 안 되는 것

| # | 입력 | 기대 |
|---:|---|---|
| H7 | `이 마케팅 전략 효과 있어?` | 약 카드 없이 일반 답변 |
| H8 | `데이터를 정제하는 방법 알려줘` | 일반 답변 (정제=refine) |
| H9 | `캡슐 호텔 예약하고 싶어` | 일반 답변 |
| H10 | `연고지가 어디세요?` | 일반 답변 (緣故地) |

H7은 `효과`가 원래부터 `KOREAN_MEDICAL_KEYWORDS`에 있어 룰 폴백에서는 `drug_info`가 나온다 —
**이번 변경과 무관한 기존 동작**이다. 실제로는 라우터 LLM이 general로 보내므로 화면상 문제는 없어야 한다.

## I. 프롬프트 침묵화

| # | 입력 | 기대 | 관찰 포인트 |
|---:|---|---|---|
| **I1** | `인공 타액제 알려줘` | 문구 **없음** | 🔴 `"실시간 검색 없이 학습된 지식 기준으로"`가 앞에 붙으면 실패 |
| I2 | `양자컴퓨터 원리 설명해줘` | 문구 없음 | 일반 지식 질문 |
| I3 | `오늘 비트코인 시세 알려줘` (검색 OFF로 떨어지면) | 끝에 한 문장 | 실시간 데이터는 예외 — **맨 앞이 아니라 맨 끝** |
| I4 | `검색해서 알려줘` (검색이 안 붙었다면) | 끝에 한 문장 | 명시 요청 예외 |

I3·I4는 검색이 실제로 켜지면 해당 없음(문구 자체가 안 나온다). 그때는 통과로 본다.

## 우선순위 (2차)

시간이 없으면 **H1 → H2 → I1 → B1** 넷.
각각 라우팅 복구 / 실데이터 확인 / 문구 제거 / 과잉검색을 대표한다.
