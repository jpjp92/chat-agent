## 🔴 1차 테스트에서 발견 — `prevSearched` 근사가 서는 대화 / 못 서는 대화

`인공타액제 알려줘` → `표로 정리해줘` 시나리오를 프로브로 재현하다 찾았다.

```
prev="인공타액제 알려줘"    → classifySearchNeed=gray → prevSearched=false
prev="타이레놀 부작용 알려줘" → classifySearchNeed=gray → prevSearched=false
prev="오늘 AI 뉴스 알려줘"   → classifySearchNeed=on   → prevSearched=true

가드("표로 정리해줘"): prevSearched=true → 억제 / false → 억제 안 함
```

**의약 질의는 `medical_qa`가 tier로 검색을 강제해서 켜진다. 정규식이 `on`을 내서 켜지는 게 아니다.**
그래서 실제로는 검색이 일어났는데 `prevSearched` 근사는 `false`로 본다 → 가공형 후속에 가드가 **아예 서지 않는다.**

같은 구멍이 **룰이 아니라 intent로 검색이 결정되는 모든 경로**에 있다 (medical_qa, 카드 계열 등).

### 왜 화면은 정상이었나

출처 칩 없이 직전 답변에서 파생된 표가 나왔다 → 실제로는 OFF였을 가능성이 크다.
프로브는 `needsSearch=true`(라우터 LLM 실패 = 최악조건)를 넣었고, 프로덕션에선 **라우터 LLM이 `false`를 반환해 막아준 것**으로 보인다.

> **지금은 가드가 아니라 라우터 LLM 운에 기대고 있다.** 무료티어 503이 나면 그대로 재검색이 붙는다.
> `35-flash-free-tier-throughput` 기록대로 503은 드문 일이 아니다.

### 2차 발견 — `인공 타액제`가 general로 새면서 MFDS 경로를 우회

dev에서 `인공 타액제 알려줘` → 제품 나열 시퀀스가 실제와 다른 제품명을 냈다.
**로컬 실그래프로 같은 시퀀스를 돌리면 정상이다:**

```
턴1  intent=drug_info  24.6s   ← LangChain 툴 경로(search_drug_info → MFDS)
턴2  intent=drug_info   4.8s   → 제로바액 / 드라이문트겔 / 제로미아액
턴3  intent=general     2.9s   [SearchPolicy] OFF by router-llm(100) → 같은 3개를 그대로 가공
```

갈린 지점은 **intent 분류 하나**다. `drug_info`면 MFDS 실데이터를 쓰고, `general`로 새면
프롬프트의 약 정보 방어([L280](../../../../server/agent/prompt.ts#L280) "학습 지식으로 채우지 마라",
[L282](../../../../server/agent/prompt.ts#L282) "각인은 환자 안전")가 **통째로 빠진다** — 전부 `drug_info` 전용이라서다.

|---|---|---|

lookahead로 배제. **남은 위험: `"그 지역에 연고가 있어?"`는 여전히 걸린다** — 접미로 구분되지 않는 용법이라
정규식으로 못 가른다. 관측되면 `연고제`만 남긴다.

```

```

## 3차 (2026-08-16) — 로컬 검증에서 나온 것들

### 🔴 재구성 요청 턴이 무방비였다

`인공 타액제 알려줘` → `대표 제품들은?` → `표로 정리해줘` 시퀀스에서, **표에 직전 답변에 없던 제품이 붙었다.**

| 회차 | 턴2 | 턴3(표) |
|---|---|---|
| 1 | 제로바액 · 드라이문트겔 | + **드라이아웃액** |
| 2 | (빈 응답, len=0) | **제로바액 · 드라이마우스스프레이 · 드라이에프액 · 바이오텐 드라이마우스** |

2회차가 특히 나쁘다 — **가공할 원본이 아예 없는데 제품 4개짜리 표를 만들었다.**

`드라이아웃액`은 사용자 확인 결과 **실존하지만 다한증(땀) 외용제**다. 인공타액제가 아니다.
순수 환각보다 까다롭다 — 이름이 실존해서 검색 검증은 통과하고, 틀린 건 **분류**다.
겨드랑이용 수렴제를 구강 보습제 표에 올린 셈이다.

### 원인 — 라우터가 판정하고 버렸다

```
[LangGraph] Router decided: ... llmFollowUp=refine     ← 판정은 정확했다
return { nextNode, intent, needsSearch, movieFollowup, weatherFollowup };
                                                        ↑ llmFollowUp은 여기 없다
```

generator는 이번 턴이 "형식만 바꿔달라"는 요청인지 **모른 채** 수백 줄짜리 정적 프롬프트에 판단을 맡기고 있었다.
[DEV_260815 §2-2](./DEV_260815.md)에서 검색 판정을 두고 적은 것과 같은 병리다 —
**결정을 좁혀서 넘기면 하위 레이어는 추측을 시작한다.**

그리고 이 턴들은 `intent=general` + 툴 없음 + 검색 없음이라, **모델이 추가한 내용을 검증할 장치가 하나도 없다.**
drug 툴에 넣은 "제품명 나열 금지"도 툴이 안 도니 존재하지 않는다.

### 조치 — 2단

| # | 위치 | 내용 |
|---|---|---|
| 1 | [prompt.ts](../../../../server/agent/prompt.ts) `[REFORMAT REQUESTS]` | 정적 규칙. 라우터 LLM이 죽어 `refine` 판정이 없을 때의 폴백 |
| 2 | `state.reformatTurn` → generator 주입 | 해당 턴에만 강하게 못 박음 |

1만으로는 **안 먹혔다**(2회차 실패가 1 적용 후에 나왔다). 2가 실질적인 방어다.

주입 지시의 핵심 한 줄: **"직전 답변이 비어 있거나 실패했다면 재구성할 대상이 없다고 말하세요. 없는 원본을 상상해서 만들지 마세요."**

### 검증 (실그래프 4회)

| 회차 | 턴2 | 턴3 | 판정 |
|---|---|---|:---:|
| 0 | 제로미아액·제로바액·드라이문트겔 | 동일 3개 | ✅ |
| 1 | 동일 | 동일 3개 | ✅ |
| 2 | 동일 | 동일 3개 | ✅ |

3회차는 라우터가 턴2를 `drug_info`가 아닌 `general`+검색으로 보냈고, 추출기가 그 형식을 못 읽었다.
`희석 글리세린`은 제품명이 아니라 성분이라 검색 결과에서 왔을 가능성이 높지만 **원문 대조 없이 단정 못 한다.**

## 🔴 진단 로그가 프로덕션에 존재한 적이 없었다

`[SearchPolicy]`·`[LangGraph] Router decided`를 Vercel 로그에서 계속 못 찾았다. 이유:

```ts
// next.config.ts
compiler: { removeConsole: { exclude: ['error'] } }
```

**이 설정은 클라이언트뿐 아니라 서버 코드에도 적용된다.** `console.log`·`warn`이 빌드에서 제거되고
`console.error`만 남는다. 이번 세션 내내 "로그 한 줄이면 갈린다"고 하면서 **그 줄을 한 번도 못 본 이유**다.

실측: 클라이언트 `console.log` = **0개**, 서버 = **64개**.
→ 이 설정이 브라우저에서 지우는 것은 사실상 없고, **서버 진단 로그만 지우고 있었다.**

**조치**: `KEEP_LOGS=1`이면 `compiler` 키 자체를 빼는 env 게이트.
끌 때 `removeConsole: false`나 `compiler: {}`(빈 객체)로 두면 안 된다 — 둘 다 Turbopack이 받지 못한다.

### 부수 — dev 서버가 죽던 진짜 이유는 OOM이었다

`removeConsole` 설정을 의심했으나 오진이었다. 커널 로그:

```
Out of memory: Killed process (next-server)  anon-rss 930~1052MB   × 9회
MemTotal 3,840MB / available ~600MB / Swap 1,024MB 거의 소진
```

WSL2 메모리가 3.8GB인데 VS Code 서버가 1.7GB를 쓴다. `.next`를 지운 뒤 콜드 컴파일 피크가 한도를 넘겨
매번 SIGKILL 당했다. 에러 메시지가 없던 이유다.

근본 조치는 Windows `.wslconfig`의 `memory=8GB` + `wsl --shutdown`. **미적용 상태.**

> **교훈: 판정 로직 검증에 dev 서버가 필요 없었다.** `scripts/probe-drug-search.ts`는 Next를 거치지 않고
> 그래프를 직접 실행한다 — `removeConsole`도 OOM도 로그인도 무관하고 로그가 전부 보인다.
> 처음부터 이걸로 확인했어야 했다.

### 왜 2턴에 검색이 안 붙었나 — 구조

`drug_info`는 [generator.ts:124](../../../../server/agent/nodes/generator.ts#L124) `LANGCHAIN_INTENTS`에 속한다.
`decideGoogleSearch()`와 `tools:[{googleSearch:{}}]`는 **SDK 분기에만** 있다.
→ **`drug_info` 턴에는 게이트 레벨 grounding이 아예 붙지 않는다.** 검색은 툴 내부에서만 일어난다:

```
search_drug_info(약이름)
  → MFDS 알약식별 DB          ← 인공 타액제는 알약이 아니라 항상 miss
  → Google Search leg          ← 이 경로의 유일한 검색
  → DuckDuckGo leg
  → 전부 실패 시 buildDrugFallbackInstruction
```

`[SearchPolicy]` 로그도 출처 칩도 이 경로엔 안 나온다. **검색 판정 재설계와 무관한 별도 축이다.**

그리고 2턴이 제품명을 거부한 직접 원인은 검색 유무가 아니라 **1턴 툴이 넣은 `noBrandRule`**이다
("상표명은 검색으로만 확인되는 사실이며 지금은 확인할 수 없습니다 … 제형별 분류로 답하고").
이 지시문이 history에 남아 2턴까지 이어진다.

### 🟡 함께 드러난 UX 공백

사용자가 **"검색해서"라고 직접 말해야** 제품명을 얻는다. 2턴 모델은 "확인하기 어렵습니다"로 끝내고
**검색하면 된다는 것을 알려주지 않는다.**

→ 이것이 [PLAN_SEARCH_SUGGEST_CHIPS_260816](../../../plans/PLAN_SEARCH_SUGGEST_CHIPS_260816.md)이 해결하려던 바로 그 문제다.

### 진짜 원인 — 우선순위 1이 전부를 삼켰다
`router.ts`의 후속 판정은 4계층(강한규칙 new → 강한규칙 refine → LLM → 폴백)인데,
`newFetch` 조건 두 개가 너무 넓어 **모든 자연스러운 발화가 1계층에서 끝났다.**

| 조건 | 문제 |
|---|---|
| `(날씨\|예보) && (알려\|보여\|어때\|줘…)` | 날씨를 묻는 **모든** 발화에 걸림. `부산 날씨 알려줘`와 `날씨 추세 알려줘`를 구분 못 함 |
| `timeShift && weatherWord` | 카드에 이미 +5일 예보가 있다. 재조회해도 **같은 데이터** |
| `cityWeatherRequest`의 거부목록 | `날씨` 앞 아무 단어나 도시로 판정. `아니 날씨…`의 `아니`가 도시가 됨 |

결과적으로 `strongRefine`과 LLM 판정(3계층)은 **사실상 죽은 코드**였다.

## 부수 — `/api/sessions 404` 는 코드 결함이 아니었다 (2026-08-17)

```
GET /api/sessions?offset=0&limit=30 404
[browser] Failed to load sessions Error: Failed to fetch sessions: 404
    at fetchSessions (services/geminiService.ts:89:27)
```

`app/api/sessions/route.ts` 의 `GET` 에는 **404 를 반환하는 경로가 없다**(유일한 404 는 `PATCH` 의 타인 세션).
인증 실패는 `unauthorized()` → **401** 이다.

재현해보니 `/api/sessions` 뿐 아니라 **모든 API 라우트가 404** 였다 — `/api/chat` 까지. 그런데 그 사이
앱은 정상 동작 중이었으므로 라우트 하나의 문제일 수 없었다. 로그가 원인을 갖고 있었다:

```
⚠ Port 3000 is in use by an unknown process, using available port 3001 instead.
⨯ Another next dev server is already running.  - PID: 17152
```

**dev 서버 두 인스턴스가 같은 `.next` 를 공유하면 라우트 매니페스트가 깨진다.**
전부 정리하고 하나만 띄우니:

| 라우트 | 상태 |
|---|---|
| `/` | 200 |
| `/api/sessions` | **401** (토큰 없음 — 정상) |
| `chat`·`upload`·`speech`·`pill-search`·`fetch-url` | 405 (POST 전용 — 정상) |
| `showtimes` | 400 (파라미터 없음 — 정상) |

404 가 하나도 없다. `/api/chat` 의 **405 가 등록 증거**다(라우트는 있고 GET 만 없다).

**다시 나면**: `ss -ltn | grep :300` 으로 3000·3001 동시 점유 확인 → `pkill -f "next-server"` → 재시작.
그래도 남으면 `rm -rf .next`.

> 붙여준 스택트레이스(`geminiService.ts:89`)는 원인이 아니라 **결과**다. `response.ok` 를 정직하게
> 검사해 404 를 던진 것이고, 그 자리는 올바르게 동작했다. **에러가 난 줄이 결함이 있는 줄은 아니다.**

## 6차 (2026-08-17) — 산문을 켰더니 드러난 것: "내일"에 오늘 값을 답한다

L그룹 후속 테스트(서울)에서 나왔다. **구조는 전부 정상**이었다 — L5·L7·L8 통과,
`금요일은 선선해지는거 같네?` 답변은 카드와 완전 일치(금 26°/26°, 주중 32~33°).
그런데 **날짜가 하루씩 밀렸다.**

서울 카드: **오늘** 60%·19mm·30° / **화(내일)** 30%·32°

| 모델 답변 | 실제 |
|---|---|
| "내일 서울에 비 소식… **60%**, 약 **19mm**" | 내일(화)은 **30%**, 맑음 |
| "부산 내일 최고 **28도**, 서울 **30도**" | 둘 다 **오늘** 값(내일은 31°/32°) |
| "부산은 **모레(18일)**까지" | 18일은 **내일** |

마지막 항목이 결정적이다 — 18일을 모레라 부른 건 **오늘을 16일로 여긴다**는 뜻이다.

### 이 수정이 만든 게 아니라 드러낸 것

예전엔 이런 턴이 전부 카드만 뜨고 산문이 없었다 → **틀릴 기회 자체가 없었다.**
산문을 켠 순간 원래 있던 문제가 보인 것이다.

> ⚠️ 5차에서 "재서술 중 왜곡 없음"이라고 기록했는데, **그건 오늘만 물었던 케이스였다.**
> 내일을 묻는 케이스가 검증에 없었다. 통과 기록의 **적용 범위를 좁게 적어야** 한다.

### 원인은 날짜 지식이 아니라 대응 계산

`[CURRENT_SYSTEM_TIME]`은 이미 주입된다([generator.ts](../../../../server/agent/nodes/generator.ts) `now`/`tz`).
5차 전주 테스트에서 모델은 `오늘(17일)`이라고 **정확히** 말했다. 날짜를 모르는 게 아니다.
`daily[].date`(YYYY-MM-DD)와 "내일"의 대응은 **별개의 계산**이고, 카드에서 가장 눈에 띄는
히어로 블록(= 오늘 강수)을 그냥 집는 쪽으로 샜다.

### 조치 — 계산을 묻지 않고 표를 준다

`weatherFollowup` 턴에 **서버가 만든 날짜 대응표**를 주입한다(`buildDateLadder`).

```
[날짜 대응표 — 이번 턴, 이 값이 정답입니다]
- 오늘 = 2026-08-17(월)
- 내일 = 2026-08-18(화)
...
- 🔴 `current`와 강수 히어로 블록은 오늘 값입니다. 내일·모레를 물으면 절대 쓰지 말고 daily에서 찾으세요.
```

DEV_260805의 **"판단을 묻지 않게 하자 판단 실수가 사라졌다"** 와 같은 처방이다.

### 검증 — 잴 수 있는 것만 쟀다

모델 산문의 정확도는 하니스로 못 잰다. 하지만 **대응표 자체는 결정론**이라 잴 수 있다.
`buildDateLadder`를 순수 함수로 두고 4케이스 추가: 실측 시나리오 · 월말 · 연말 ·
**UTC 15:00 = KST 익일 00:00**(서버 로컬 타임존이 아니라 `tz` 기준으로 끊기는지).

```
npx tsx scripts/test-weather-followup.mts   # 27/27, 회귀 0
npx tsc --noEmit                            # 0
```

> 표가 맞다고 답변이 맞는다는 보장은 없다 — **L2 재실행이 실제 판정**이다.

### 부수 관측 — 첨부 이미지 분석

회귀 하니스가 없는 영역이라 실측에서 우연히 드러난 것들을 남긴다.

- **표 전사는 정확했다.** 벤치마크 표 14행의 수치가 전부 일치했다.
- **축약어는 반올림한다.** 같은 값을 표에서 읽을 땐 `65,536` 으로 정확히 옮겼는데,
  본문의 `64k max output tokens` 는 "64,000" 으로 풀었다. 원문이 그러니 오류는 아니지만
  **숫자의 출처(표 vs 산문)에 따라 정밀도가 달라진다**는 행동 패턴이다.
- 🔴 **스크린샷 밖으로 잘린 행까지 채웠다**(`Live API`·`Search grounding`·`ARC-AGI-2`).
  원본 이미지엔 있었을 테니 이번엔 문제가 아니지만, **없었다면 환각이었을 자리**다.
  → 첨부 분석 회귀 하니스를 만든다면 **잘린 표**가 첫 케이스여야 한다.
