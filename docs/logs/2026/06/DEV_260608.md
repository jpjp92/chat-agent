# DEV_260608

## 1. 작업 개요

사이드바에서 이전 대화를 다시 열 때 **멀티턴 질의응답 중 일부 턴이 불러와지지 않는** 현상 점검 → 원인 규명 후 로딩 로직 수정.

증상: 일부 세션만 그러함(전부는 아님). DB 저장 누락이 의심됐으나, 점검 결과 **저장은 정상이고 로딩(캐시) 경로의 문제**로 확인.

---

## 2. 데이터 흐름 추적

| 단계 | 위치 | 동작 |
|------|------|------|
| 저장(user) | `app/api/chat/route.ts:117-121` | 매 요청마다 user 메시지 insert (fire-and-forget) |
| 저장(assistant) | `app/api/chat/route.ts:241-250` | 스트림 완료 후 assistant 메시지 insert (await) |
| 조회 | `app/api/sessions/route.ts:15-19` | `session_id`로 전체 메시지 `created_at` 오름차순, **limit 없음** |
| 캐시 hydration | `src/hooks/useChatSessions.ts:141` | 마운트 시 localStorage 캐시를 초기 state로 |
| 병합 | `src/hooks/useChatSessions.ts:119-137` | DB 세션 + 로컬 state 병합 (로컬 메시지 우선) |
| 클릭 로드 | `src/hooks/useChatSessions.ts:265-289` | `messages.length > 0`이면 DB 재조회 스킵 |

→ DB에는 매 턴이 빠짐없이 저장되고, 조회 API도 전체를 반환. 문제는 그 사이의 **localStorage 캐시**.

---

## 3. 근본 원인

**localStorage 세션 캐시(`chat_sessions_cache_v1`)가 1턴 스냅샷에 고정되고, 로딩 경로가 그 부분 캐시를 DB보다 우선**했다.

1. **캐시가 1턴에서 멈춤** — `src/hooks/useChatStream.ts:482`의 `writeSessionsCache` 호출이 `latestHistory.length <= 2`(첫 턴) 조건에서만 실행. 2턴부터는 이 블록을 건너뛰어 캐시가 영원히 `[u1, m1]` 상태로 고정. 스트림 완료 후 캐시를 갱신하는 코드가 없음.

2. **병합이 부분 캐시를 채택** — `mergeSessionsPreservingLocalMessages` (`:130`)가 `localSession.messages.length > 0 ? local : db`. DB 세션은 `messages: []`(`:200`)로 오므로, 캐시에 남은 `[u1, m1]`이 채택됨.

3. **클릭 시 DB 재조회 스킵** — `selectSession` (`:269`)의 `if (session.messages.length > 0) return` 가드. 캐시 때문에 `length === 2 > 0`이라 DB의 나머지 턴을 절대 불러오지 않음.

### 왜 "일부만"인가
이 브라우저에서 직접 대화한 + 캐시 상위 30개(`:115`) 안에 든 세션만 깨짐. 다른 기기에서 한 대화나 캐시에서 밀려난 세션은 캐시가 비어 있어 가드를 통과 → DB에서 전체 로드. 그래서 세션마다 증상이 들쭉날쭉했음.

---

## 4. 수정

**채택안**: 캐시는 세션 목록 메타만 보관하고, **메시지는 DB(`chat_messages`)를 단일 출처로 lazy-load**.

다른 후보 대비 효율적인 이유:
- DB·캐시 이중 저장 자체를 없애 "어긋날 대상"을 제거 → 버그 한 종류를 통째로 해결.
- 매 턴 캐시 갱신(2안)은 localStorage 쿼터 초과 + 동기화 지점 누락으로 재발 위험.
- 가드만 완화(3안)는 병합이 여전히 부분 캐시를 채택해 반쪽 해결.

### 4-1. `writeSessionsCache` — 메시지 제외 후 캐시

**`src/hooks/useChatSessions.ts:113-121`**

```diff
 export const writeSessionsCache = (sessions: ChatSession[]) => {
   try {
-    localStorage.setItem(SESSIONS_CACHE_KEY, JSON.stringify(sessions.slice(0, 30)));
+    // 메시지는 캐시하지 않는다 — DB(chat_messages)가 메시지의 단일 출처.
+    // 과거엔 부분 스냅샷(1턴)만 캐시에 남아 멀티턴 재로드 시 나머지 턴이 가려졌다.
+    // 세션 목록 메타(title 등)만 캐시해 즉시 렌더하고, 메시지는 selectSession에서 DB lazy-load.
+    const metaOnly = sessions.slice(0, 30).map(session => ({ ...session, messages: [] }));
+    localStorage.setItem(SESSIONS_CACHE_KEY, JSON.stringify(metaOnly));
   } catch {}
 };
```

`writeSessionsCache`는 모든 캐시 쓰기의 단일 통로이므로, 이 한 곳만 바꾸면 모든 호출부(create/load/remove/rename/스트림)가 자동 적용됨.

### 4-2. 의도적으로 유지한 부분

- **`selectSession`의 `messages.length > 0` 가드** — 라이브 채팅 중 state에 쌓인 메시지를 보호. 캐시가 메시지를 안 넣으므로, 재로드 후엔 `length === 0`으로 가드를 통과해 DB fetch가 정상 동작.
- **`mergeSessionsPreservingLocalMessages`의 메시지 보존 로직** — 초기 로드 레이스에서 진행 중인 대화의 in-memory 메시지를 DB의 빈 배열로 덮어쓰지 않게 보호. 제거 시 회귀 발생하므로 유지.
- **`lastActiveDoc`** — 문서 후속질문 컨텍스트. 기존처럼 캐시에 남겨 재로드 후 동작 보존(`...session` 스프레드로 유지).

---

## 5. 동작 흐름 (수정 후)

1. 재로드 → 캐시→state에 `messages: []`만 들어옴.
2. 사이드바 세션 클릭 → `selectSession` 가드 통과(`length 0`) → `fetchSessionMessages`로 DB 전체 멀티턴 로드.
3. 라이브 채팅은 state에 직접 메시지를 쌓고, 병합 로직이 보호하므로 영향 없음.

### 9-6. CGV 심층 공략 — 완전 진단 (`test-cgv-showtime.mjs`, `test-cgv-api.mjs`)

레거시 실패 원인부터 신규 API 인증 게이트까지 단계적으로 해독:

1. **레거시 폐기**: `iframeTheater.aspx`는 2024 개편으로 사실상 폐기 — 응답이 Next.js SPA 앱 셸(title "깊이 빠져 보다, CGV")만 반환, 시간표 HTML 없음. 이전 spike의 "성공"은 홈 리다이렉트 오탐이었음.
2. **차단 정체 = Cloudflare**: direct/datacenter는 403(Cloudflare 커스텀 에러 `mets01081`). ScraperAPI residential은 **현재 플랜 미지원**("premium proxies not allowed").
3. **Cloudflare 우회 성공**: `scrapedo super=true&geoCode=kr`가 통과 → 200 앱 셸 수신.
4. **신규 API 완전 식별**: 앱 셸의 JS 청크 48개를 받아 grep → base `https://api.cgv.co.kr`, GET, params `siteNo`/`scnYmd`/`regnCd`.
   - 시간표: `/cnm/atkt/searchMovScnInfo`, `/cnm/atkt/searchSscnsSchdCntList`, `/cnm/atkt/searchSscnsSchdExistList`
   - 극장목록: `/cnm/site/searchAllRegionAndSite`
5. **인증 정체 = Bearer 아님, 요청별 HMAC 서명**: 게스트는 `Authorization` 불필요(인터셉트 결과 auth 헤더 0건). 대신 모든 `api.cgv.co.kr` 요청에 `X-TIMESTAMP`(unix 초) + `X-SIGNATURE`(base64 HMAC-SHA256)가 붙음.
6. **서명 알고리즘 완전 해독** (browserless 인터셉트로 SPA 요청 헤더 캡처 → 청크에서 서명 함수 추출):
   ```
   msg = `${timestamp}|${pathname}|${body}`   // pathname은 query 제외, GET이면 body=""
   X-SIGNATURE = HmacSHA256(msg, "ydqXY0ocnFLmJGHr_zNzFcpjwAsXq_8JcBNURAkRscg").toString(Base64)
   ```
   (CryptoJS, 클라이언트 axios request 인터셉터. 시크릿은 JS 청크에 평문 하드코딩.)
7. **Node 재현 → 200 확인**: CF 통과한 browserless 컨텍스트에서 Web Crypto로 서명 계산해 호출 → **401 해소**. 필수 쿼리 `coCd=A420`(CGV 회사코드) 추가 후:
   - `/cnm/site/searchAllRegionAndSite?coCd=A420` → **200** (서울 37·경기 69 극장)
   - `/cnm/atkt/searchSscnsSchdCntList?coCd=A420&siteNo=&scnYmd=&rtctlScopCd=` → **200** (사이트별 회차수)
   - `/cnm/atkt/searchMovScnInfo` → 처음엔 400(`rtctlScopCd` 빈값 거부).
8. **마지막 파라미터 확정 — `rtctlScopCd="08"`**: UI 인터셉트(취약)를 시도하다, 더 확실하게 **SPA 청크를 직접 grep**(`test-cgv-grep-chunks.mjs`). 결정적 라인:
   ```js
   tp = { coCd: d.RxL /*A420*/, siteNo: M, scnYmd: I, scnsNo:"", scnSseq:"",
          rtctlScopCd:"08", custNo: y };
   useQuery({ queryKey:["searchMovScnInfo", tp], queryFn:()=>u.c$(tp), enabled: !!M && !!I });
   ```
   → `rtctlScopCd`는 **하드코딩 상수 "08"**. 전체 파라미터 = `coCd=A420 · siteNo · scnYmd · scnsNo="" · scnSseq="" · rtctlScopCd="08" · custNo=""`.
9. **회차 확보 — 200 + 실데이터**(`test-cgv-signed-browser.mjs`, siteNo=0056 강남):
   ```
   {"statusCode":0,"data":[{"siteNm":"CGV 강남","scnsNm":"1관 (Laser)","movNm":"군체",
     "movkndDsplNm":"2D","cratgClsNm":"15세이상관람가","scnsrtTm":"2320","scnendTm":"2532",
     "stcnt":"144","frSeatCnt":"136","physcFilePathnm":"030001/30001046/30001046_185.jpg"}, …]}
   ```
   필드 매핑: `movNm`(영화) · `scnsNm`(상영관) · `scnsrtTm`/`scnendTm`(HHMM, 25:32=익일 01:32) · `cratgClsNm`(등급) · `movkndDsplNm`(2D/IMAX) · `frSeatCnt`/`stcnt`(잔여/총좌석) · `physcFilePathnm`(포스터 경로).

**결론**: **CGV 완전 함락.** Cloudflare 우회(browserless) + HMAC 서명 재현 + `coCd=A420` + `rtctlScopCd="08"`로 `searchMovScnInfo` 200·실회차 확보. 롯데/메가박스와 동급(영화·상영관·시작/종료·등급·잔여좌석). 포스터도 해결(§9-8): `physcFilePathnm` → `https://cdn.cgv.co.kr/cgvpomsfilm/Movie/Thumbnail/Poster/{physcFilePathnm}`.

**전송(transport)**: api.cgv.co.kr은 Cloudflare 뒤. browserless 컨텍스트(CF 통과)에서 Web Crypto 서명이 가장 안정적. 무브라우저는 scrapedo `super`+`customHeaders`로 서명 헤더 포워딩 가능하나 ROTATION_FAILED 간헐 → 재시도 필요. 서명은 Node `crypto.createHmac('sha256', SECRET)`로 재현.

스크립트: `test-cgv-showtime.mjs`(매트릭스) · `test-cgv-api.mjs`(API 식별) · `test-cgv-render.mjs`(렌더) · `test-cgv-intercept.mjs`/`test-cgv-capture.mjs`/`test-cgv-ui.mjs`(요청 캡처) · `test-cgv-grep-chunks.mjs`(청크 grep→`rtctlScopCd="08"` 확정) · `test-cgv-signed.mjs`(Node 서명+scrapedo) · `test-cgv-signed-browser.mjs`(✅ 회차 200 확보). 원시응답 `scripts/movie-spike-output/cgv/`.

### 9-7. 3대 멀티플렉스 통합 스크립트 + 카드 UI (`test-multiplex-showtimes.mjs`)

세 체인을 한 번에 조회 → 공통 스키마 정규화 → 카드형 HTML 생성하는 통합 PoC 완성.

```bash
node scripts/test-multiplex-showtimes.mjs            # 오늘(심야면 자동 내일 폴백)
node scripts/test-multiplex-showtimes.mjs 20260610   # 특정 날짜(YYYYMMDD)
```

**체인별 조회 방식** (`Promise.all` 동시 실행):
| 체인 | 방식 | 비고 |
|------|------|------|
| 롯데시네마 | Node direct POST `GetPlaySequence` | 무료·프록시 불필요, 포스터+잔여좌석 |
| CGV | browserless `/function` + 재현 HMAC 서명 | `searchRegnList`로 극장(강남) 탐색 → `searchMovScnInfo?…rtctlScopCd=08` |
| 메가박스 | browserless `/function` 렌더 + DOM 파싱 | `td[rpst-movie-no]` 회차 + `button[data-movie-no/nm]` 영화명 매핑 |

**공통 스키마**: `{ chain, cinema, movie, poster, rating, format, date, showtimes:[{start,end,screen,left,total}] }`

**구현 중 해결**:
- **날짜 폴백**: 심야엔 오늘 잔여회차 0 → 각 체인 자동으로 내일 조회, 카드에 `내일` 배지.
- **메가박스 영화명 매핑**: 타임테이블 뷰엔 영화명이 없음(td엔 `rpst-movie-no`만) → 영화 필터의 `<button data-movie-no data-movie-nm>`(실제 DOM, JS 템플릿 아님)에서 `movieNo→{nm,img}` 맵 구성해 복원. 셀렉터는 `<a>`가 아니라 `<button>`/`[data-movie-no]`.
- **메가박스 렌더 안정화**: `networkidle2`는 광고/롱폴링으로 nav 타임아웃 잦음 → `domcontentloaded` + `waitForSelector('td[rpst-movie-no]')` + **최대 2회 재시도**. 극장 링크(`/theater?brchNo=`) 클릭은 페이지 이탈 유발하므로 제외.
- **카드 UI**: 다크 테마, 체인 컬러 배지(CGV `#e6002d`/롯데 `#ed1c24`/메가박스 `#3a1f5d`), 포스터 썸네일(`onerror` 시 🎬 플레이스홀더), 회차 칩(시각·상영관·잔여/총좌석), 잔여<15% 빨강 표시.

**산출물** (`scripts/movie-spike-output/`): `showtimes.html`(카드 UI) · `showtimes.json`(정규화 데이터) · `showtimes.png`(browserless `/screenshot`로 렌더 검증).

**실행 검증** (20260608 심야): CGV 강남 1영화 2회차(오늘 심야) · 롯데 가산 6영화 32회차(내일) · 메가박스 코엑스 1영화 25회차. 롯데·메가박스 포스터 정상 hotlink.

### 9-9. 카드 디자인 검토 — 포스터 늘어짐 해결안 비교 (`_design-compare.mjs`)

**문제**: 카드가 가로 flex(`align-items` 기본 `stretch`)라, 회차 칩이 많아 카드가 길어지면 폭 고정(80~96px) 포스터 칸이 카드 전체 높이로 늘어나 `object-fit:cover`가 세로로 길쭉하게 크롭 → 얇은 띠처럼 보임.

**비교 방법**: 같은 데이터(CGV 군체)를 회차 3/10/24개 × 5개 디자인으로 나란히 렌더 → `design-compare.html`/`.png`(browserless screenshot).

| 디자인 | 방법 | 24회차일 때 | 평가 |
|--------|------|-------------|------|
| 현재 (stretch) | `.card{display:flex}` 기본 | 포스터 얇고 길게 늘어짐 | ❌ 문제 |
| **A. 포스터 비율 고정** | `align-items:flex-start` + `.poster{aspect-ratio:2/3;height:auto}` | 포스터 정상, 단 아래 여백 | 늘어짐 해결, 여백 |
| **A+float** | 포스터 `float:left` → 칩이 포스터 아래로도 흐름 | 공간 꽉 채움 | 공간 효율 ↑ |
| **B. 칩 제한** | 8개 노출 + `+N개 더`(점선 칩) | 카드 높이 균일 | ✅ 그리드 가장 깔끔 |
| C. 세로 카드 | 포스터 상단 풀폭(2:3) + 칩 아래 | 포스터 큼·카드 키 큼 | 포스터 강조형 |

**결정**: **B(칩 제한)가 가장 깔끔** — 모든 카드 높이가 균일해져 그리드 일람성 최고. 전체 회차는 `+N개 더` 토글/툴팁으로 노출. (대안: 모든 회차 항상 노출 + 공간 효율을 원하면 A+float, 또는 A+float에 cap 12 결합.)

> 미적용(검토 단계). 실제 `showtimes.html` 생성기 반영은 후속. 핵심 CSS: `B` = 칩 슬라이스 + `.chip.more` / `A` = `.card{align-items:flex-start}` + `.poster{aspect-ratio:2/3}`.

### 9-10. 카드 UI 디자인 반영 — B2 + 테마(라이트/다크) + 채팅 앱 배경
