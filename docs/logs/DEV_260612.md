# DEV_260612

> 영화 통합(86a2d68) 배포 후 **프로덕션 전용 라우팅 버그** 진단·수정 + README 반영. 통합 본류: [DEV_260611](DEV_260611.md) §6.

## 1. 증상 — 프로덕션에서 영화 질의가 일반 검색 응답으로 폴백

배포된 Vercel 앱에서 "영화정보" 질의 시 `json:movie` 카드 대신 **Google Search two-track의 일반 표 응답**(상영작/개봉예정 표) 반환. **로컬은 정상** — 카드 잘 뜸.

런타임 로그의 결정적 라인:

```
[LangGraph] Semantic Router LLM failed, falling back to heuristics: 400
[LangGraph] Router decided: intent=general, needsSearch=true
[LangGraph] Two-track enabled: stage1(2.5+search) -> stage2(3.5+minimal)
```

## 2. 진단 — 2단 라우팅 구조의 빈틈 노출

라우팅은 **1차 LLM 라우터(flash-lite) → 실패 시 2차 정규식 폴백** 구조.

| 환경 | 1차 LLM 라우터 | 2차 정규식 | 결과 |
|------|------|------|------|
| 로컬 | ✅ 성공 → `movie_search` | (안 탐) | 카드 정상 |
| 프로덕션 | ❌ **400 실패** | "영화정보" 미매칭 | `general`+검색 폴백 |

- "정규식 보강 없이도 로컬은 잘 됐다"의 이유: 로컬은 폴백 자체를 안 탔기 때문. 정규식은 LLM 실패 시에만 노출되는 안전망이라, 약국·법률처럼 키워드가 견고한 intent는 그동안 폴백으로도 버텼지만 영화 정규식의 빈틈("영화+정보" 조합 부재)이 이번에 드러남.
- **400의 정체(추정)**: 로컬 `.env` 키 12개를 flash-lite REST로 전수 점검 → **전부 OK**. 프로덕션(Vercel Sensitive 키셋, pull로 대조 불가)에 죽은 키가 섞여 있을 가능성. 결정적 구조 버그 — **Gemini는 무효 API 키를 401이 아닌 `400 API_KEY_INVALID`로 반환**하는데, 기존 코드는 401/403만 `markKeyInvalid` 처리 → **죽은 키가 로테이션에 영구 잔존**하며 호출을 무작위 오염(이번엔 라우터가 죽은 키, 제너레이터가 정상 키를 뽑아 검색은 동작). 기존 라우터 로그는 status만 찍어 메시지 확인 불가했음.
