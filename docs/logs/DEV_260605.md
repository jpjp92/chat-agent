# DEV_260605

## 1. Wikidocs Playwright fallback 실제 대화 플로우 검증

트리거:

- `/api/fetch-url` wikidocs Playwright fallback 적용 후 실제 UI 대화 흐름에서 동작 여부 확인.
- 테스트 URL: `https://wikidocs.net/blog/@jaehong/10121/`

공유 로그 요약:

```text
[fetch-url] Playwright fallback succeeded {
  url: 'https://wikidocs.net/blog/@jaehong/10121/',
  status: 200,
  selector: 'article',
  textChars: 4964
}
POST /api/fetch-url 200 in 3.7s

[LangGraph] URL content provided — Google Search disabled to use full article text
[LangGraph] Starting SDK stream | model: "gemini-3.5-flash" | useGoogleSearch: false
POST /api/chat 200 in 9.5s
```

확인 결과:

- `wikidocs.net` direct fetch 실패 이후 Playwright fallback이 정상 실행됨.
- 블로그형 페이지에서 `article` selector로 본문 4,964자를 추출함.
- `/api/fetch-url`는 200으로 종료했고 전체 소요 시간은 3.7초.
- 이후 `/api/chat`에서 `[URL_CONTENT]`가 제공된 것으로 판정되어 Google Search가 비활성화됨.
- Gemini 3.5 Flash는 검색 보강 없이 제공된 원문 기반으로 응답 생성 경로에 진입함.

판단:

- 의도한 전체 플로우가 실제 대화 경로에서도 정상 동작했다.
- 모델 선택과 무관하게 fetch 단계에서 본문이 주입되므로, Gemini 3.5 Flash에서도 동일하게 활용됨.
- 현재 남은 확인은 Vercel Preview/Production 환경에서 `@sparticuz/chromium` 실행, function size, cold start 로그를 보는 것이다.

성능 메모:

| 단계 | 결과 |
| --- | --- |
| `/api/fetch-url` | 200 / 3.7초 |
| Playwright 추출 | `article` / 4,964자 |
| `/api/chat` | 200 / 9.5초 |
| Google Search | 비활성화 |
