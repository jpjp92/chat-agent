# DEV_260605

## 1. Wikidocs Playwright fallback 실제 대화 플로우 검증

트리거:

- `/api/fetch-url` wikidocs Playwright fallback 적용 후 실제 UI 대화 흐름에서 동작 여부 확인.
- 테스트 URL: `https://wikidocs.net/blog/@jaehong/10121/`

공유 로그 요약:

```text
[fetch-url] Playwright fallback succeeded {
  url: 'https://wikidocs.net/blog/@jaehong/10121/',
  status: 200,
  selector: 'article',
  textChars: 4964
}
POST /api/fetch-url 200 in 3.7s

[LangGraph] URL content provided — Google Search disabled to use full article text
[LangGraph] Starting SDK stream | model: "gemini-3.5-flash" | useGoogleSearch: false
POST /api/chat 200 in 9.5s
```

확인 결과:

- `wikidocs.net` direct fetch 실패 이후 Playwright fallback이 정상 실행됨.
- 블로그형 페이지에서 `article` selector로 본문 4,964자를 추출함.
- `/api/fetch-url`는 200으로 종료했고 전체 소요 시간은 3.7초.
- 이후 `/api/chat`에서 `[URL_CONTENT]`가 제공된 것으로 판정되어 Google Search가 비활성화됨.
- Gemini 3.5 Flash는 검색 보강 없이 제공된 원문 기반으로 응답 생성 경로에 진입함.

판단:

- 의도한 전체 플로우가 실제 대화 경로에서도 정상 동작했다.
- 모델 선택과 무관하게 fetch 단계에서 본문이 주입되므로, Gemini 3.5 Flash에서도 동일하게 활용됨.
- 현재 남은 확인은 Vercel Preview/Production 환경에서 `@sparticuz/chromium` 실행, function size, cold start 로그를 보는 것이다.

성능 메모:

| 단계 | 결과 |
| --- | --- |
| `/api/fetch-url` | 200 / 3.7초 |
| Playwright 추출 | `article` / 4,964자 |
| `/api/chat` | 200 / 9.5초 |
| Google Search | 비활성화 |

## 2. Vercel 배포 런타임 누락 파일 수정

트리거:

- Vercel `/api/fetch-url` 호출 중 `playwright-core` external module 로딩 실패.

에러:

```text
Failed to load external module playwright-core-f386a448524c7e9d:
Error: Cannot find module '/var/task/node_modules/playwright-core/browsers.json'
Require stack:
- /var/task/node_modules/playwright-core/lib/coreBundle.js
```

원인:

- `playwright-core/lib/coreBundle.js`가 런타임에 `packageRoot/browsers.json`을 require한다.
- Next/Vercel output file tracing이 `coreBundle.js`는 포함했지만 `playwright-core/browsers.json`은 자동 포함하지 않았다.
- 따라서 Vercel 함수 번들에서만 external import 실패가 발생했다.

수정:

- `next.config.ts`의 `/api/fetch-url` 전용 `outputFileTracingIncludes`에 아래 파일 추가.

```ts
'./node_modules/playwright-core/browsers.json'
```

검증:

- `npm run build` 성공.
- `.next/server/app/api/fetch-url/route.js.nft.json` 재확인:
  - trace size: 약 `74.82MB`
  - files: `219`
  - `node_modules/playwright-core/browsers.json` 포함 확인
  - 기존 Chromium Brotli 파일 3종(`chromium.br`, `al2023.tar.br`, `fonts.tar.br`) 포함 유지

남은 확인:

- 수정 후 재배포에서 동일 에러가 사라지는지 확인.
- 다음 에러가 발생한다면 동일 방식으로 런타임 require 파일을 trace include에 추가할 수 있다.

후속 에러:

```text
[fetch-url] Playwright fallback error {
  url: 'https://wikidocs.net/blog/@jaehong/12473/',
  error: "ENOENT: no such file or directory, open '/var/task/node_modules/@sparticuz/chromium/bin/swiftshader.tar.br'"
}
```

판단:

- `chromiumBinary.setGraphicsMode = false`를 설정했지만, Vercel 런타임에서 `@sparticuz/chromium.executablePath()`가 여전히 `swiftshader.tar.br` 파일 접근을 시도했다.
- 서버리스 패키징 안정성을 위해 `swiftshader.tar.br`도 `/api/fetch-url` trace include에 되돌리는 것이 안전하다.

추가 수정:

```ts
'./node_modules/@sparticuz/chromium/bin/swiftshader.tar.br'
```

재검증:

- `npm run build` 성공.
- `.next/server/app/api/fetch-url/route.js.nft.json` 재확인:
  - trace size: 약 `78.23MB`
  - files: `220`
  - `swiftshader.tar.br` 포함 확인
  - `playwright-core/browsers.json` 포함 유지

## 3. Vercel Playwright 실행 후 wikidocs 403 진단

트리거:

- 패키징 누락 문제 해결 후 Playwright는 실행됐지만 wikidocs 본문 추출 실패.

Vercel 로그:

```text
[fetch-url] Playwright fallback failed {
  url: 'https://wikidocs.net/blog/@jaehong/12473/',
  status: 403,
  selector: 'body',
  textChars: 158
}
```

로컬 비교:

- 같은 URL을 `scripts/audit-sparticuz-playwright-comparison.mjs`로 테스트.
- `@sparticuz/chromium + playwright-core` 로컬 결과:
  - status: `200`
  - selector: `article`
  - textChars: `3925`
  - title: `중국, 메타의 AI 스타트업 마누스 인수를 막다: '싱가포르 세탁'의 종말 - 박재홍의 실리콘밸리`

판단:

- URL 자체나 selector 문제가 아니다.
- Vercel 함수 환경에서 Chromium은 실행되지만 wikidocs가 Vercel egress IP 또는 serverless/headless fingerprint를 403으로 차단하는 케이스다.
- 즉 패키징 단계 문제에서 런타임 접근 차단 문제로 넘어왔다.

추가 수정:

- Playwright context에 실제 브라우저에 가까운 header 추가:
  - `Accept`
  - `Accept-Language`
  - `Cache-Control`
  - `Pragma`
  - `Upgrade-Insecure-Requests`
- timezone을 `Asia/Seoul`로 지정.
- Chromium launch args에 `--disable-blink-features=AutomationControlled` 추가.
- 실패 로그에 `title`과 본문 `sample`을 추가해 다음 Vercel 로그에서 403 페이지 내용을 확인할 수 있게 함.

검증:

- `npm run build` 성공.
- 현재 로컬 dev server가 꺼져 있어 `/api/fetch-url` 직접 POST 재검증은 수행하지 못함.
- 별도 비교 스크립트 기준으로 같은 URL은 로컬 Sparticuz/Playwright에서 200 성공.

다음 판단 기준:

- Vercel 재배포 후 성공하면 header/fingerprint 보강으로 해결.
- 계속 403이면 Vercel IP 차단으로 판단하고, 다음 선택지는 별도 worker(Railway/Render/VPS) 또는 외부 브라우저/proxy/OpenAI web_search fallback이다.
