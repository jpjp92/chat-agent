- 조문 카드에는 원문 조문을 강조 영역으로 노출해 본문 가독성 개선.
- 조문 accordion 확장/축소 시 카드 폭이 흔들리지 않도록 `LawRenderer` 컨테이너 폭을 고정하고 긴 텍스트 줄바꿈 처리.
- 조문이 5개를 초과하면 하단 `이전/다음` 페이지네이션으로 5개 단위 탐색.
- 본문/조문 카드의 각 조항 헤더에 공개 `원문` 링크 추가. `제5조의2` 같은 가지조문 번호 표시 보정.
- 법령 목록 모드는 제목 중심 compact 카드로 정리하고, 5개 초과 시 하단 `이전/다음` 페이지네이션으로 탐색.
- 프로세스 점검 중 `sourceUrl`에 `LAW_OC`가 포함되어 클라이언트 응답/DB 메시지에 노출될 수 있는 경로 제거. 카드 링크는 공개 `/법령/...` URL만 사용.
- 문장형 질의에서 `law_name` 추출이 실패해도 `관련 법안`, `주요 조항`, `보여줘` 같은 요청어를 제거한 검색어로 재시도. 관련도 점수 0건이면 앞쪽 조문 fallback.
- 배포 웹에서 `개인정보 보호법 설명해줘`가 조회 오류로 응답한 케이스 기준으로 `설명/요약/해줘/해주세요/해달라고` 등 요청어 제거 보강, `개인정보 보호법` 공식 후보 강제 추가.
- 법률 질의 하이브리드 해석 구조로 변경. Router는 `law_search`까지만 판단하고, `lawTool` 내부에서 Gemini 2.5 Flash가 `{mode, law_name, article_no, query}`를 정규화한 뒤 Open API 호출. Gemini 해석 실패 시 기존 fallback plan 사용.

### 하이브리드 조회 방식

- 목록 검색: `lawSearch.do?target=law`
- 본문/조문 조회: `lawService.do?target=law`
- 특정 조문: `JO` 6자리 코드 사용 (`제44조` → `004400`)
- 검색 결과와 조문 단위 모두 객체/배열 응답을 정규화.
- 조번호가 있는 질의는 `article` 모드, 법령 목록 질의는 `list` 모드, 법령 본문/주제 질의는 `body` 모드로 처리.

### 주제형 질의 보강

“도로교통법 신호위반”처럼 조번호가 없는 질의에서 앞쪽 조문만 잘리는 문제를 줄이기 위해 관련도 필터를 추가.

- `신호위반` → `신호`, `지시`, `제5조`, `제156조` 키워드 확장
- `음주운전` → `술에`, `혈중알코올`, `제44조`, `제148조` 키워드 확장
- 조문 제목, 조문내용, 항/호 내용을 통합 검색해 관련 조항을 우선 반환
