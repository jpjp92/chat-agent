## API 파라미터 차이

### temperature / topP / topK

| 모델 | 사용 여부 | 이유 |
|---|---|---|
| 2.5-flash | ✅ 사용 (`temperature: 0.2, topP: 0.8, topK: 40`) | 지원하며 샘플링 제어에 유효 |
| 3.5-flash | ❌ 제거 | Google 공식 가이드: "기본 설정 그대로 사용하는 것이 추론 성능에 가장 좋음". 값을 넣으면 오히려 reasoning 품질 저하 |

### thinkingConfig

| 모델 | 파라미터 | 경로별 적용값 |
|---|---|---|
| 3.5-flash | `thinkingLevel` (enum) | YouTube 네이티브 영상 → `"minimal"` / 그 외 모든 경로 → `"low"` |
| 2.5-flash | `thinkingBudget` (number) | YouTube → `0` / medical_qa → `3000` / 그 외 → `undefined` (모델 기본값) |

> **주의**: 3.5-flash에서 `thinkingBudget`은 deprecated. 사용 시 간헐적 500 오류 발생 확인 (테스트 3회 중 1회).  
> 2.5-flash에서 `thinkingLevel`은 미지원일 수 있으므로 교차 적용하지 않는다.

## Google Search (grounding) 차이

| 항목 | 2.5-flash | 3.5-flash |
|---|---|---|
| 무료 티어 grounding 지원 | ✅ | ❌ (미지원) |
| Google Search 선택 시 동작 | 직접 grounding 단일 패스 | **Two-track**: Stage1(2.5 grounding) → Stage2(3.5 synthesis) |

**Two-track 아키텍처** (3.5-flash + Google Search 선택 시):
```
Stage1: 2.5-flash + Google Search
  → 그라운딩된 사실 텍스트 + groundingSources 수집
  → 8000자 초과 시 truncate

Stage2: 3.5-flash (synthesis only, thinkingLevel: "minimal")
  → [GROUNDING_NOTES_FROM_STAGE1] + [SYNTHESIS_RULES] 합성 프롬프트
  → Stage2 quota 소진 → 2.5-flash 합성 fallback
  → 최종 실패 → Stage1 텍스트 직접 사용
```

## 오늘 추가 수정사항 (2026.05.21 오후)

### 1. `isDailyQuotaError` 수정 — free tier RPD 오탐 수정

**증상**: `gemini-2.5-flash-lite` 일일 한도(20 req/day) 소진 시 RPM으로 잘못 분류 → 60s 쿨다운 후 재시도 반복

**원인 분석**:
- 실제 에러 메시지: `"quotaId":"GenerateRequestsPerDayPerProjectPerModel-FreeTier"` (JSON 문자열)
- `details = JSON.stringify(err?.errorDetails || err?.details || '')` → `err`에 `errorDetails`/`details` 프로퍼티 없음 → `details = '""'`
- `details.includes('perday')` → camelCase 원문 `PerDay`에서 FALSE (대소문자 불일치)
- `msg` (소문자화된 전체 message)에는 `"generaterequestsperdayperprojectpermodel-freetier"` 포함 → 여기서 검사해야 함

**수정** (`api/_lib/config.ts`):
```ts
// msg(소문자화)에 camelCase 패턴 추가
msg.includes('perday') ||    // GenerateRequestsPerDay...
msg.includes('freetier') ||  // FreeTier
```

### 2. `fetch-url.ts` — 직접 fetch throw 시 Jina 폴백 연결

**증상**: `[fetch-url] Failed: fetch failed` 로그 → outer catch 직행, Jina 시도 없이 `[FETCH_ERROR]` 반환

**원인**: `try...finally` (catch 없음) 구조 → fetch가 네트워크 오류·타임아웃으로 throw하면 Jina 경로 진입 불가

**수정**: catch 추가
```ts
} catch (fetchError: any) {
    console.warn('[fetch-url] Direct fetch threw:', fetchError.message);
    directFetchBlocked = true; // → Jina 폴백 경로로 진입
}
```

### 3. `fetch-url.ts` + `useChatStream.ts` — Jina 보안 챌린지 페이지 감지

**증상**: wikidocs.net 등 Cloudflare 차단 사이트에서 Jina가 챌린지 페이지를 그대로 반환 → 모델이 garbage 콘텐츠 수신 → `LLM returned empty response` 오류, 응답 없이 죽음

**원인**:
- Jina가 `200 OK`로 응답하지만 내용은 "Just a moment... / Performing security verification" 등 챌린지 페이지
- 현재 코드는 `jinaRes.ok && length >= 100` 조건만 검사 → 통과 후 모델에 전달

**수정 1** — `fetch-url.ts` `isJinaSecurityBlock()` 감지 함수 추가:
```ts
const isJinaSecurityBlock = (text: string): boolean => {
    const t = text.toLowerCase();
    return (
        t.includes('just a moment') ||
        t.includes('performing security verification') ||
        t.includes('security service to protect') ||
        t.includes('warning: target url returned error 403') ||
        t.includes('warning: this page maybe requiring captcha') ||
        t.includes('verifying you are not a bot') ||
        t.includes('please enable cookies')
    );
};
```
- 직접 차단 Jina 폴백 경로 + SPA 단본문 Jina 경로 양쪽 적용
- 감지 시 `[FETCH_ERROR: 보안 인증이 필요한 페이지로 내용을 가져올 수 없습니다.]` 반환

**수정 2** — `useChatStream.ts` 보안 차단 컨텍스트 분리:
- `fetchUrlContent` → `fetchUrlData` 전환 (raw content 직접 접근)
- `[FETCH_ERROR: 보안 인증이 필요한...]` 감지 시 `[URL_SECURITY_BLOCKED]` 태그 주입:
  ```
  [URL_SECURITY_BLOCKED: url]
  이 URL은 보안 인증(CAPTCHA/Cloudflare 차단)으로 인해 서버에서 직접 접근할 수 없습니다.
  사용자에게 이 사실을 알리고, 페이지 본문을 직접 붙여넣거나 접근 가능한 URL을 제공해달라고 안내하세요.
  ```
- 일반 fetch 실패는 기존 `[URL_FETCH_FAILED]` 유지

### 4. BioRenderer 모바일 호버 툴팁 미동작 수정

**증상**: 데스크톱에서는 단백질 구조 위에 마우스 올리면 잔기 정보 툴팁 정상 표시. 모바일에서는 터치해도 툴팁 미표시.

**원인 분석**:

| | 데스크톱 | 모바일 (수정 전) |
|---|---|---|
| 발생 이벤트 | `mousemove` | `touchmove` (mousemove 없음) |
| NGL `hovered` 발화 | ✅ | ❌ |
| 좌표 추적 | `mouseX/mouseY` 업데이트 | 0, 0 유지 |

- NGL은 내부적으로 `mousemove` 이벤트만 리스닝해 `stage.signals.hovered` 발화
- 모바일에서는 터치 이동 중 `mousemove`가 발생하지 않아 NGL picking이 트리거되지 않음
- `mouseX/mouseY`도 업데이트되지 않아 좌표 0,0 상태

**수정** (`components/BioRenderer.tsx`):

```ts
const stageEl = stageRef.current;
const handleTouchMove = (e: TouchEvent) => {
    const touch = e.touches[0];
    if (!touch) return;
    mouseX = touch.clientX;
    mouseY = touch.clientY;
    // NGL이 mousemove만 인식하므로 synthetic 이벤트로 picking 트리거
    stageEl?.dispatchEvent(new MouseEvent('mousemove', {
        clientX: touch.clientX,
        clientY: touch.clientY,
        bubbles: true,
    }));
};
const handleTouchEnd = () => setHoverInfo(null);
stageEl?.addEventListener('touchmove', handleTouchMove, { passive: true });
stageEl?.addEventListener('touchend', handleTouchEnd);
```

- `touchmove` 시 좌표 업데이트 + canvas에 synthetic `mousemove` 디스패치 → NGL picking 트리거

### 5. Intent routing fallback 분리 + 3.5 Search two-track 시각화 오분기 보정

**증상**: 3.5 선택 상태에서 별자리 시각화 요청(예: `물고기자리 시각화`)이 `astronomy` 렌더러 경로로 가지 않고, 2.5 Search fallback 결과를 3.5가 요약하는 일반 검색 응답으로 귀결되는 케이스 발생.

**원인 분석**:
- Router LLM 실패/쿼터/JSON parse 실패 시 사용하는 fallback heuristic이 `drug`/`pharmacy`/`hospital`/`vet`/`law` 중심이라, 과학·시각화 intent를 복구하지 못함.
- 3.5 + Google Search 선택 시 `generator.ts`의 Two-track 경로가 활성화됨:
  - Stage1: 2.5 + Search가 검색 요약 생성
  - Stage2: 3.5가 Stage1 notes를 합성
  - 이 구조에서는 `json:constellation` 등 renderer JSON 생성 지시가 약해지고 검색 요약으로 흐를 수 있음.

**수정 1** — `intentRules.ts` 신규 추가:
```ts
export const hasMedicalIntentKeyword = (text: string): boolean => { ... };
export const classifyIntentByRules = (text: string, hasImage: boolean): IntentType => { ... };
```

- Router 내부에 있던 fallback keyword rule을 `api/_lib/agent/intentRules.ts`로 분리.
- `router.ts`는 LLM routing과 rule fallback 호출만 담당.
- fallback rule은 제품 핵심 intent 기준으로 관리:
  - `law_search`
  - `pharmacy_search`
  - `hospital_search`
  - `vet_search`
  - `astronomy`
  - `biology`
  - `chemistry`
  - `physics`
  - `data_viz`
  - `drug_id` / `drug_info`

**수정 2** — fallback rule 다국어 보강:
- 사용자 언어 옵션(`ko`, `en`, `es`, `fr`) 기준 핵심 키워드 추가.
- 한국어 의료 키워드는 기존 부분 문자열 매칭 유지.
- 영어/스페인어/프랑스어 의료 키워드는 단어 경계 기반 Unicode regex 사용:
  - `drugstore` 내부의 `drug` 같은 오탐 방지
  - `pill`, `dosage`, `side effects`, `medicamento`, `posologie`, `effets secondaires` 등 처리

**수정 3** — renderer intent의 Google Search 기본 비활성화:
```ts
const rendererIntents = new Set(['astronomy', 'biology', 'chemistry', 'physics', 'data_viz']);
const explicitSearchRequested = /(검색|찾아|조사|출처|근거|최신|최근|실시간|뉴스|latest|recent|search|source|cite)/i.test(latestUserText);
if (rendererIntents.has(state.intent) && !explicitSearchRequested) {
    useGoogleSearch = false;
}
```

- `astronomy`/`biology`/`chemistry`/`physics`/`data_viz`는 기본적으로 구조화 JSON 렌더러 응답을 우선.
- 사용자가 `검색`, `출처`, `최신`, `최근`, `실시간`, `뉴스`, `latest`, `source` 등을 명시한 경우에만 Google Search 허용.
- 기대 흐름:
  ```
  "물고기자리 시각화해줘"
  → router: astronomy
  → generator: Google Search off
  → 3.5 single-pass
  → json:constellation
  → ConstellationRenderer
  ```

**검증**:
- `npx tsc --noEmit` 통과.
- `touchend` 시 툴팁 초기화
- `passive: true` — 스크롤/핀치줌 차단 없음
- cleanup에서 두 리스너 모두 제거

### 6. 3.5 Search two-track Stage2 합성 포맷 보정

**증상**: 3.5 선택 + Google Search 필요 경로에서 Stage2 합성 응답이 다음과 같은 메타 서문으로 시작하는 경우 발생.

```txt
제시된 정보를 바탕으로 ...
제공된 정보를 바탕으로 ...
Based on the provided information ...
```

이 문구는 사용자에게 내부 2단계 처리 흔적처럼 보이고, 응답 구조도 단순 요약 나열에 가까워짐.

**원인 분석**:
- Stage2 synthesis prompt가 `GROUNDING_NOTES_FROM_STAGE1`를 입력으로 사용한다는 사실을 모델이 표면화함.
- 기존 `[SYNTHESIS_RULES]`는 "grounded notes만 사용" 정도만 지시해, 답변 시작 방식과 섹션 구조를 충분히 제한하지 못함.

**수정** (`api/_lib/agent/nodes/generator.ts`):
- Stage2 합성 규칙에 메타 서문 금지 추가:
  - `제시된 정보를 바탕으로`
  - `제공된 정보를 바탕으로`
  - `Based on the provided information`
  - `Based on the sources`
  - 스페인어/프랑스어 유사 문구
- "과정/소스 handoff를 언급하지 말고 바로 본문으로 시작" 지시 추가.
- 기본 응답 구조를 다음처럼 고정:
  1. `한 줄 요약` — 정확히 1문장
  2. `주요 내용` — 구체적인 하위 섹션으로 정리
  3. `고려 사항` — tradeoff/제약/리스크가 있을 때만 포함
- 섹션 라벨은 현재 응답 언어에 맞춰 번역하도록 지시.

**기대 결과**:
```txt
### 한 줄 요약
Amazon Bedrock은 AWS 환경에서 다양한 파운데이션 모델과 RAG, 에이전트, 가드레일을 서버리스로 조합해 생성형 AI 애플리케이션을 구축하게 해주는 관리형 플랫폼입니다.

### 주요 내용
...
```

- `npx tsc --noEmit` 통과.
