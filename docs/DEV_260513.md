# DEV 2026-05-13

## 1. 동물병원 상세정보 보강 방향 정리

### 배경

- 행정안전부 동물병원 API는 현재 카드에 필요한 기본 위치 정보 중심으로 활용 중.
- 실제 반환/표시 가능한 정보는 병원명, 주소, 전화번호, 영업상태, 인허가일자 정도.
- 운영시간, 휴무일, 홈페이지, 리뷰, 진료 특화 정보는 공공 인허가 데이터만으로 안정적으로 제공하기 어려움.

### 검토

- 웹검색으로 병원별 상세정보를 보강할 수는 있음.
- 다만 동물병원 결과 3~10개 각각에 대해 자동 웹검색을 붙이면 응답 지연이 크게 증가할 수 있음.
- 현재 `vetTool`은 fast-pass로 `json:vet` 블록을 바로 스트리밍하는 구조라, 자동 보강을 넣으면 빠른 카드 렌더링 장점이 약해짐.
- 웹검색 결과는 병원별 최신성/정확도 편차도 있어, 기본 카드 결과를 대체하기보다 보조 정보로 다루는 것이 적절함.

### 방향

- 기본 동물병원 검색은 지금처럼 공공데이터 기반으로 빠르게 유지.
- 자동 웹검색 상세 보강은 기본 검색 경로에 넣지 않음.
- 상세정보가 필요한 경우 다음 방식 중 하나로 별도 검토:
  - 사용자가 특정 병원을 선택했을 때 1곳만 웹검색으로 보강.
  - 카드에 `상세 정보 찾기` 액션을 추가해 수동 실행.
  - 자동 보강이 필요하면 상위 1~3개까지만 제한하고, 실패해도 기본 카드 결과는 유지.
- 우선순위는 낮음. 현재는 동 단위 검색 보정과 빠른 기본 결과 품질이 더 중요함.

## 2. 모바일 첫 쿼리 후 빈 화면 레이스 보정

### 증상 재정리

- 모바일에서 앱 진입 직후 첫 쿼리를 입력하면 화면이 비거나 아무 응답이 없는 것처럼 보이는 케이스가 있음.
- 새로고침 후 사이드바를 열면 해당 세션의 제목과 응답은 정상 생성되어 있음.
- 따라서 서버 응답 생성, DB 메시지 저장, 제목 생성은 완료되고 있었고, 프론트 로컬 세션 상태가 중간에 어긋나는 문제로 판단.

### 원인

- 앱 초기화 시 `useChatSessions.loadUserSessions()`가 백그라운드에서 세션 목록을 불러옴.
- 사용자가 이 로딩이 끝나기 전에 첫 쿼리를 보내면 `useChatStream.handleSendMessage()`가 새 세션을 만들고 `setCurrentSessionId(session.id)`와 함께 로컬 `sessions`에 사용자 메시지를 추가함.
- 이후 늦게 도착한 `loadUserSessions()`가 `setSessions(mappedSessions)`로 DB 세션 목록을 통째로 덮어쓰면, 방금 생성한 로컬 세션/메시지가 배열에서 사라질 수 있음.
- 이 경우 `currentSessionId`는 새 세션 ID를 가리키지만 `sessions.find(...)`가 실패해 현재 화면은 빈 상태처럼 보임.
- 반면 `/api/chat`은 `session_id`를 이미 받아 DB에 사용자/모델 메시지를 저장하고, 스트림 후 제목 생성 API도 실행되므로 새로고침 후에는 사이드바에서 정상 세션처럼 보임.

### 수정

- `src/hooks/useChatSessions.ts`
  - `loadUserSessions()`가 DB 목록을 로컬 상태에 반영할 때 기존 `setSessions(mappedSessions)` 방식으로 덮어쓰지 않도록 변경.
  - `mergeSessionsPreservingLocalMessages()`를 추가해 DB 세션과 로컬 세션을 병합.
  - 동일 ID 세션은 로컬 메시지/`lastActiveDoc`을 우선 보존.
  - DB에 아직 반영되지 않았거나 로딩 응답에 누락된 로컬 전용 세션도 유지.
  - 병합 결과를 세션 캐시에 저장.

### 검증

- `npx tsc --noEmit` 성공.
- 모바일 수동 검증 필요:
  - 앱 새로고침 직후 사이드바 로딩이 끝나기 전에 첫 쿼리 입력.
  - 화면에 사용자 메시지와 모델 응답이 계속 표시되는지 확인.
  - 새로고침 후 동일 세션의 제목/응답이 유지되는지 확인.
