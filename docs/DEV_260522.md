# DEV_260522 — 3.5 Flash 멀티턴 포맷 보정 (3종)

> 작성일: 2026-05-22

---

## 문제 요약

3.5 Flash 모델에서 멀티턴 대화 시 발생하는 세 가지 버그.

---

## 버그 1 — Two-track 멀티턴 고정 포맷 반복

### 증상

3.5 Flash + Google Search 선택 시 활성화되는 Two-track 경로(Stage1: 2.5 grounding → Stage2: 3.5 synthesis)에서, **멀티턴 대화 중에도 고정 포맷이 반복**되는 현상.

Stage2 `synthesisInstruction`이 대화 턴 수에 무관하게 항상 동일한 3단 구조를 강제:
1. `한 줄 요약` — 정확히 1문장
2. `주요 내용` — 하위 섹션
3. `고려 사항` — 조건부

**증상 예시**: 사용자가 "그거 더 설명해줘", "예시 들어줘", "짧게 정리해줘" 같은 후속 질문을 해도 동일한 요약 포맷이 반복되어 대화가 어색해짐.

### 원인

`generator.ts` Stage2 synthesis 지시(`synthesisInstruction`)가 히스토리 유무와 무관하게 항상 동일하게 적용됨.

- Two-track 여부만 분기 (`useGoogleSearch && needsSearchFallback`)
- 멀티턴 여부 (`sdkContents.length`) 분기 없음

### 수정

**파일**: `api/_lib/agent/nodes/generator.ts`

```ts
// Multi-turn detection (shared by thinkingConfig and Stage2 synthesis)
const isMultiTurn = sdkContents.length > 1;
```

`synthesisInstruction` 포맷 지시를 `isMultiTurn` 기준으로 분기:

| 조건 | 포맷 지시 |
|---|---|
| `isMultiTurn = false` (1턴) | 기존 유지: 한 줄 요약 → 주요 내용 → 고려 사항 |
| `isMultiTurn = true` (2턴+) | 고정 섹션 없이 대화 흐름에 맞는 자연스러운 응답 |

멀티턴 포맷 지시 내용:
- `"This is a follow-up turn in an ongoing conversation. Respond naturally and conversationally — do NOT use a fixed section structure"`
- `"Match the tone and depth the conversation has established. Answer the user's specific follow-up directly."`
- `"Use formatting (bullet points, bold, short paragraphs) only when it genuinely aids clarity."`

## 버그 2 — PDF/URL 멀티턴에서 검색 경로 오분기

### 증상

PDF·URL 분석 후 후속 질문(예: "표로 정리해봐")을 하면, 3.5 Flash가 문서 내용 대신 Google Search 결과로 답변.

**로그 예시**:
```
[LangGraph] useGoogleSearch: true → Two-track enabled: stage1(2.5+search) -> stage2(3.5+minimal)
```

1턴에서 URL/PDF를 분석할 때 `hasUrlContent = true` → `useGoogleSearch = false`로 올바르게 작동하지만,  
2턴에서는 현재 메시지에 URL이 없어 `hasUrlContent = false` → `useGoogleSearch = true`로 잘못 전환됨.

### 원인

`hasUrlContent`는 `state.webContent.includes('[URL_CONTENT:')` 기반으로 **현재 턴**의 웹 컨텐츠만 참조.  
이전 턴에서 URL을 분석했던 히스토리는 반영되지 않음.

### 수정

**파일**: `api/_lib/agent/nodes/generator.ts`

`hasUrlContent` 블록 직후에 히스토리 스캔 추가:

```ts
if (hasUrlContent) useGoogleSearch = false;

// Follow-up turns after URL analysis: keep single-pass path
const historyHasUrl = state.messages.slice(0, -1)
    .filter((m: any) => m._getType() === 'human')
    .some((m: any) => {
        const text = Array.isArray(m.content)
            ? (m.content as any[]).filter((p: any) => p.type === 'text').map((p: any) => p.text).join('')
            : String(m.content);
        return /https?:\/\/\S+/.test(text);
    });
if (historyHasUrl) useGoogleSearch = false;
```

이전 사용자 메시지에 URL이 하나라도 있으면 `useGoogleSearch = false` 유지 → single-pass 경로 유지.

### 동작 흐름

```
[1턴] user: "https://arxiv.org/abs/... 논문 분석해줘"
→ hasUrlContent = true → useGoogleSearch = false → single-pass

[2턴] user: "표로 정리해봐"
→ hasUrlContent = false (현재 턴에 URL 없음)
→ historyHasUrl = true (이전 턴 URL 감지)
→ useGoogleSearch = false → single-pass 유지 (수정 후)
```

## 버그 3 — Stage2에서 사용자 포맷 요청 무시

### 증상

두 버그 1+2가 수정된 상태에서도, Two-track이 활성화되는 경우(신규 검색 필요 follow-up 등) Stage2가 사용자의 명시적 포맷 요청(표, 목록, 코드 등)을 무시하고 텍스트로만 응답.

### 원인

Stage2 `synthesisInstruction`에 사용자의 실제 질문이 포함되지 않음.  
Stage2 입력은 Stage1 grounding notes + synthesis rules만으로 구성되어, 모델이 사용자가 무엇을 원하는지 알 수 없음.

### 수정

**파일**: `api/_lib/agent/nodes/generator.ts`

`synthesisInstruction` 배열 최상단에 `[USER_REQUEST]` 섹션 추가:

```ts
const synthesisInstruction = [
    `[USER_REQUEST]\n${latestUserText}\n`,
    '[GROUNDING_NOTES_FROM_STAGE1]',
    stage1Text,
    ...
].join('\n');
```

Stage2 모델이 사용자 요청("표로 정리해줘" 등)을 직접 수신하여 포맷을 준수.

## sdkContents 구조

`sdkContents`는 `state.messages`를 순서대로 변환한 배열:

| 턴 수 | sdkContents 길이 | 예시 |
|---|---|---|
| 1턴 (첫 질문만) | 1 | `[user]` |
| 2턴 (1회 교환 + 후속) | 3 | `[user, model, user]` |
| 3턴 | 5 | `[user, model, user, model, user]` |

→ `sdkContents.length > 1` 이면 이전 교환이 있는 멀티턴으로 판단.
