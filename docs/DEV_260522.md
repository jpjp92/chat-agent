## 버그 1 — Two-track 멀티턴 고정 포맷 반복

### 증상

3.5 Flash + Google Search 선택 시 활성화되는 Two-track 경로(Stage1: 2.5 grounding → Stage2: 3.5 synthesis)에서, **멀티턴 대화 중에도 고정 포맷이 반복**되는 현상.

Stage2 `synthesisInstruction`이 대화 턴 수에 무관하게 항상 동일한 3단 구조를 강제:
1. `한 줄 요약` — 정확히 1문장
2. `주요 내용` — 하위 섹션
3. `고려 사항` — 조건부

**증상 예시**: 사용자가 "그거 더 설명해줘", "예시 들어줘", "짧게 정리해줘" 같은 후속 질문을 해도 동일한 요약 포맷이 반복되어 대화가 어색해짐.

### 원인

`generator.ts` Stage2 synthesis 지시(`synthesisInstruction`)가 히스토리 유무와 무관하게 항상 동일하게 적용됨.

- Two-track 여부만 분기 (`useGoogleSearch && needsSearchFallback`)
- 멀티턴 여부 (`sdkContents.length`) 분기 없음

### 수정

**파일**: `api/_lib/agent/nodes/generator.ts`

```ts
// Multi-turn detection (shared by thinkingConfig and Stage2 synthesis)
const isMultiTurn = sdkContents.length > 1;
```

`synthesisInstruction` 포맷 지시를 `isMultiTurn` 기준으로 분기:

| 조건 | 포맷 지시 |
|---|---|
| `isMultiTurn = false` (1턴) | 기존 유지: 한 줄 요약 → 주요 내용 → 고려 사항 |
| `isMultiTurn = true` (2턴+) | 고정 섹션 없이 대화 흐름에 맞는 자연스러운 응답 |

멀티턴 포맷 지시 내용:
- `"This is a follow-up turn in an ongoing conversation. Respond naturally and conversationally — do NOT use a fixed section structure"`
- `"Match the tone and depth the conversation has established. Answer the user's specific follow-up directly."`
- `"Use formatting (bullet points, bold, short paragraphs) only when it genuinely aids clarity."`

## 버그 2 — PDF/URL 멀티턴에서 검색 경로 오분기

### 증상

PDF·URL 분석 후 후속 질문(예: "표로 정리해봐")을 하면, 3.5 Flash가 문서 내용 대신 Google Search 결과로 답변.

**로그 예시**:
```
[LangGraph] useGoogleSearch: true → Two-track enabled: stage1(2.5+search) -> stage2(3.5+minimal)
```

1턴에서 URL/PDF를 분석할 때 `hasUrlContent = true` → `useGoogleSearch = false`로 올바르게 작동하지만,  
2턴에서는 현재 메시지에 URL이 없어 `hasUrlContent = false` → `useGoogleSearch = true`로 잘못 전환됨.

### 원인

`hasUrlContent`는 `state.webContent.includes('[URL_CONTENT:')` 기반으로 **현재 턴**의 웹 컨텐츠만 참조.  
이전 턴에서 URL을 분석했던 히스토리는 반영되지 않음.

### 수정

**파일**: `api/_lib/agent/nodes/generator.ts`

`hasUrlContent` 블록 직후에 히스토리 스캔 추가:

```ts
if (hasUrlContent) useGoogleSearch = false;

// Follow-up turns after URL analysis: keep single-pass path
const historyHasUrl = state.messages.slice(0, -1)
    .filter((m: any) => m._getType() === 'human')
    .some((m: any) => {
        const text = Array.isArray(m.content)
            ? (m.content as any[]).filter((p: any) => p.type === 'text').map((p: any) => p.text).join('')
            : String(m.content);
        return /https?:\/\/\S+/.test(text);
    });
if (historyHasUrl) useGoogleSearch = false;
```

이전 사용자 메시지에 URL이 하나라도 있으면 `useGoogleSearch = false` 유지 → single-pass 경로 유지.

### 동작 흐름

```
[1턴] user: "https://arxiv.org/abs/... 논문 분석해줘"
→ hasUrlContent = true → useGoogleSearch = false → single-pass

[2턴] user: "표로 정리해봐"
→ hasUrlContent = false (현재 턴에 URL 없음)
→ historyHasUrl = true (이전 턴 URL 감지)
→ useGoogleSearch = false → single-pass 유지 (수정 후)
```

## 버그 3 — Stage2에서 사용자 포맷 요청 무시

### 증상

두 버그 1+2가 수정된 상태에서도, Two-track이 활성화되는 경우(신규 검색 필요 follow-up 등) Stage2가 사용자의 명시적 포맷 요청(표, 목록, 코드 등)을 무시하고 텍스트로만 응답.

### 원인

Stage2 `synthesisInstruction`에 사용자의 실제 질문이 포함되지 않음.  
Stage2 입력은 Stage1 grounding notes + synthesis rules만으로 구성되어, 모델이 사용자가 무엇을 원하는지 알 수 없음.

### 수정

**파일**: `api/_lib/agent/nodes/generator.ts`

`synthesisInstruction` 배열 최상단에 `[USER_REQUEST]` 섹션 추가:

```ts
const synthesisInstruction = [
    `[USER_REQUEST]\n${latestUserText}\n`,
    '[GROUNDING_NOTES_FROM_STAGE1]',
    stage1Text,
    ...
].join('\n');
```

Stage2 모델이 사용자 요청("표로 정리해줘" 등)을 직접 수신하여 포맷을 준수.

## sdkContents 구조

`sdkContents`는 `state.messages`를 순서대로 변환한 배열:

| 턴 수 | sdkContents 길이 | 예시 |
|---|---|---|
| 1턴 (첫 질문만) | 1 | `[user]` |
| 2턴 (1회 교환 + 후속) | 3 | `[user, model, user]` |

→ `sdkContents.length > 1` 이면 이전 교환이 있는 멀티턴으로 판단.

## 버그 4 — `**볼드**` 마커가 렌더링되지 않고 그대로 출력

### 증상

모든 모델(2.5, 3.5)에서 간헐적으로 `**굵게**` 마커가 HTML bold로 렌더링되지 않고 `**` 기호가 그대로 표시됨.

특히 한국어 조사가 볼드 직후에 붙는 패턴에서 재현율이 높음:
```
**자가 추론 학습**이 핵심입니다.   ← ** 그대로 출력
**지식 증류** 방식을               ← 정상 렌더링
```

### 원인

CommonMark 파서 규칙 충돌. 닫는 `**`가 유효한 closer로 인정받으려면:

> right-flanking AND (left-flanking이 아님 OR 앞이 구두점)

`**text**이`에서 닫는 `**` 뒤에 `이`(글자)가 오면 → left-flanking도 됨 → 앞이 글자(구두점 아님) → **closer로 인정 안됨** → `**` 기호 그대로 출력.

| 패턴 | 결과 |
|---|---|
| `**text**이` / `**text**를` | ❌ 렌더 실패 (조사가 글자) |
| `**text** 방식` | ✅ 정상 (공백) |
| `**text**,` / `**text**.` | ✅ 정상 (구두점) |
| `**text**)` | ✅ 정상 (구두점) |

한국어 외에도 동일 원리로 실패하는 케이스:
- 영어: `**noun**s` (복수형 -s), `**bold**word` (공백 없이 연결)
- 프랑스어: `**résultat**s sont`
- 스페인어: `**resultado**s`, `**texto**del`

### 수정

**파일**: `components/ChatMessage.tsx` — `renderContent` 텍스트 전처리 3곳

닫는 `**` 뒤에 한글·라틴 문자가 올 때 공백을 삽입:

```typescript
// **content** 전체를 패턴으로 잡고 뒤에 글자가 오면 공백 삽입
// → 닫는 ** 앞 문자(글자·따옴표·괄호 등)와 무관하게 동작
text = text.replace(/\*\*([^*\n]+?)\*\*(?=[가-힣A-Za-zÀ-ÿ])/g, '**$1** ');
```

**정규식 설계 근거**:
- `\*\*([^*\n]+?)\*\*` — 완성된 `**content**` 스팬 전체 매칭 (비탐욕, `*`·개행 불포함)
- `(?=[가-힣A-Za-zÀ-ÿ])` — 뒤에 글자가 올 때만 보정 (구두점·공백은 이미 정상)
- 여는 `**` (` **`, `(**`, 줄 시작) → 스팬 전체 패턴이 아니라서 unaffected

닫는 `**` 앞 문자 유형에 상관없이 커버:
- 글자로 끝: `**학습**이` → `**학습** 이` ✓
- 따옴표로 끝: `**'샤크로보틱스'**와` → `**'샤크로보틱스'** 와` ✓
- 괄호로 끝: `**(Learning)**이` → `**(Learning)** 이` ✓

**이전 시도 실패 케이스**:
- `[^*\n]` 사용 → 공백도 포함돼 여는 `**` 앞도 매칭 → `** 텍스트**` 식으로 렌더링 파괴
- `[^\s*\n]` 사용 → `(` 포함 → `(**bold**이)` 에서 여는 `**` 파괴
- `[a-zA-Z가-힣\d]` 사용 → 따옴표·괄호로 끝나는 볼드 미커버 (`**'text'**와` 누락)

### 검증

12개 케이스 전체 통과:

| 케이스 | 수정 전 | 수정 후 |
|---|---|---|
| 한국어 조사 이/가/을/는 | ❌ | ✅ |
| 따옴표 뒤 조사 (`**'text'**와`) | ❌ | ✅ |
| 영어 복수 -s | ❌ | ✅ |
| 프랑스어/스페인어 복수 | ❌ | ✅ |
| 공백·구두점 뒤 (정상 케이스) | ✅ | ✅ (불변) |
| 여는 `**` (공백·괄호·줄 시작 앞) | ✅ | ✅ (불변) |
| 줄 시작 `**헤딩**` | ✅ | ✅ (불변) |

## 버그 5 — `gemini-3.5-flash` renderer intent 빈 응답 + 타임아웃

### 증상

`gemini-3.5-flash` 선택 후 `astronomy`·`data_viz` 인텐트 쿼리 시 두 가지 실패 패턴:

1. **빈 응답 패턴**: `SDK returned empty response text` 에러 → LangChain 폴백 (응답은 오지만 비스트리밍)
2. **타임아웃 패턴**: `Starting SDK stream` 로그 이후 아무 로그도 없이 Vercel 60s timeout → 함수 kill

Two-track 경로(Google Search 활성)에서는 Stage2가 `gemini-3.5-flash` + `thinkingLevel: "minimal"` 조합으로 정상 작동. single-pass 경로만 실패.

### 원인 분석

**빈 응답 원인**:
- `thinkingLevel: "low"` 상태에서 구조화 JSON(별자리 좌표, 차트 데이터) 생성 시 thinking budget이 소진되어 실제 text output 없이 종료되는 경우 발생.
- 응답 추출 코드의 `??` 연산자 버그: `@google/genai` SDK의 `response.text` getter는 파트가 없으면 `null`/`undefined`가 아닌 `""` 반환 → `"" ?? singleParts...`에서 단락 평가되어 singleParts 필터링 경로가 dead code.

**타임아웃 원인**:
- Two-track Stage2 vs single-pass의 핵심 차이: Stage2는 `systemInstruction` 없이 synthesis prompt만 content로 전달. single-pass는 `finalInstruction`(긴 시스템 프롬프트 + intent hint) + `thinkingConfig`가 함께 전달됨.
- `gemini-3.5-flash` + 긴 systemInstruction + structured JSON 생성 조합이 60s 초과.

### 수정

**파일**: `api/_lib/agent/nodes/generator.ts`

**Fix 1 — renderer intent `thinkingLevel` 강등 (`"low"` → `"minimal"`)**:

```typescript
// rendererIntentSet 정의를 effectiveModel 이전으로 이동
const rendererIntentSet = new Set(['astronomy', 'biology', 'chemistry', 'physics', 'data_viz']);

const thinkingConfig = is3xModel
    ? ((isYoutubeRequest && hasVideoData) || rendererIntentSet.has(state.intent))
        ? { thinkingLevel: "minimal" as const }   // YouTube + renderer: thinking 최소화
        : isMultiTurn
        ? { thinkingLevel: "medium" as const }
        : { thinkingLevel: "low" as const }
```

**Fix 2 — `??` → `||` (빈 문자열 fallback 보장)**:

```typescript
// 변경 전: response.text가 "" 반환 시 singleParts 경로 무시
responseText = (singlePassResponse.text ?? singleParts.filter(...).join('')).trim();

// 변경 후: "" 일 때도 singleParts 필터링 시도
responseText = (singlePassResponse.text || singleParts.filter(...).join('')).trim();
```

## 버그 6 — 레이더 차트 시리즈 과다로 판독 불가

### 증상

시리즈 5개(삼성·애플·샤오미·구글·모토로라) 레이더 차트가 중앙에 작게 뭉쳐 레이블과 선이 겹쳐 판독 불가.

### 원인

레이더 차트는 시리즈 3개 이상이면 색상과 면이 겹쳐 가독성이 급격히 저하됨. 모델에 제약이 없어 사용자가 여러 항목 비교를 요청하면 그대로 시리즈를 생성.

### 수정

**파일 1**: `api/_lib/agent/prompt.ts` — 모델 지시 추가

```
**Multivariate/Skills** → "radar". **RADAR LIMIT: max 3 series and max 6 categories.**
If the user requests more than 3 entities to compare, switch to "bar" chart instead
— radar with 4+ series becomes unreadable.
```

**파일 2**: `components/ChartRenderer.tsx` — 클라이언트 사이드 가드

```typescript
// Radar chart guard: cap at 3 series to prevent unreadable overlapping
if (isRadarType && rawSeries.length > 3) {
    rawSeries = rawSeries.slice(0, 3);
}
```

모델이 제약을 무시하더라도 렌더러에서 상위 3개만 표시.

### 6. 다운로드 버튼 PNG 실제 동작

**파일**: `components/ChartRenderer.tsx`

기존 `exportToSVG()`는 파일 저장 다이얼로그가 뜨지 않는 ApexCharts 내부 메서드. `dataURI()`로 base64 PNG를 추출해 `<a>` 태그로 실제 저장:

```typescript
const { imgURI } = await chartInstance.current.dataURI();
const a = document.createElement('a');
a.href = imgURI;
a.download = `${title || 'chart'}.png`;
a.click();
```

실패 시 `exportToSVG()` fallback.

### 7. 차트 하단 스크롤바 항상 표시 버그

**파일**: `components/ChartRenderer.tsx`

`overflow-x-auto`가 항상 적용되어 ApexCharts 렌더링 1~2px 오차로 스크롤바가 항상 노출. 데이터 10개 초과 시에만 스크롤 활성화:

```typescript
className={`w-full ${dataCount > 10 ? 'overflow-x-auto custom-scrollbar' : 'overflow-x-hidden'}`}
```
