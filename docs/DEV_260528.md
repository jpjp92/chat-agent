# DEV_260528 — 2.5 Flash URL 패칭 / 빈 응답 처리 / 렌더링 버그 수정

> 작성일: 2026-05-28

---

## 1. 현상

텍스트 중간에 URL이 포함된 메시지를 입력했을 때:

- **3.5 Flash**: URL을 텍스트 참조로 처리 → 정상 분석
- **2.5 Flash**: URL을 패칭/검색 대상으로 인식 → 엉뚱한 결과 또는 불필요한 웹 조회 발생

---

## 2. 원인 분석

### 원인 1 — `historyHasUrl` 의 blind spot (`generator.ts`)

```typescript
// 기존 코드
const historyHasUrl = state.messages.slice(0, -1)  // ← 현재 메시지 제외!
    .filter((m: any) => m._getType() === 'human')
    .some((m: any) => /https?:\/\/\S+/.test(text));
if (historyHasUrl) useGoogleSearch = false;
```

`slice(0, -1)`로 히스토리만 스캔하기 때문에 **현재 턴(첫 번째 메시지)**에 URL이 있어도 `historyHasUrl = false` → Google Search가 비활성화되지 않음.

### 원인 2 — Google Search grounding 가용성 차이

| 모델 | Google Search | 경로 |
|------|--------------|------|
| 2.5 Flash | 사용 가능 (무료 티어) | Single-pass: 원본 메시지 + Google Search 직접 노출 |
| 3.5 Flash | 무료 티어 불가 (`needsSearchFallback = true`) | Two-track: Stage2(3.5)는 Stage1 요약 텍스트만 수신, 원본 URL 미노출 |

### 원인 3 — 모델 특성

2.5 Flash는 thinking 기반 추론 모델 특성상, Google Search가 활성화된 상태에서 URL을 발견하면 "이 URL의 내용을 검색해서 답해야 한다"고 추론하는 경향이 강함.

## 3. 수정 — `generator.ts`

`historyHasUrl` 체크에 현재 메시지 URL 감지(`currentMsgHasNonYtUrl`)를 추가.

YouTube URL은 영상 분석 기능에 영향을 주지 않도록 제외.

```typescript
// 현재 메시지도 URL 체크 (slice(0,-1)이라 현재 턴 누락 보완)
const currentMsgHasNonYtUrl = (() => {
    const lastMsg = state.messages[state.messages.length - 1];
    if (!lastMsg || lastMsg._getType() !== 'human') return false;
    const text = Array.isArray(lastMsg.content)
        ? (lastMsg.content as any[]).filter((p: any) => p.type === 'text').map((p: any) => p.text).join('')
        : String(lastMsg.content);
    return /https?:\/\/\S+/.test(text) && !/(?:youtube\.com|youtu\.be)/.test(text);
})();
if (historyHasUrl || currentMsgHasNonYtUrl) useGoogleSearch = false;
```

**수정 파일**: `server/agent/nodes/generator.ts`

**효과**:
- 2.5 Flash도 텍스트 내 URL을 텍스트 그대로 분석 (패칭 시도 없음)
- YouTube URL은 제외 → 영상 native 분석 동작 유지
- 3.5 Flash two-track 경로는 기존과 동일하게 동작

## 4. 2.5 Flash 멀티턴 "제공된 정보에 따르면" 반복 수정

### 현상

멀티턴 대화에서 2.5 Flash가 응답을 "제공된 정보에 따르면", "제시된 정보를 바탕으로" 등의 문구로 시작하는 경향 발견. 웹보다 모바일에서 더 빈번하게 관찰됨.

- **3.5 Flash**: 정상 (해당 문구 없음)
- **2.5 Flash**: 멀티턴 진행 시 반복적으로 발생

### 원인 분석

`generator.ts`가 시스템 프롬프트에 `[PROVIDED_SOURCE_TEXT]` 태그를 주입하면, 2.5 Flash가 해당 컨텍스트를 읽고 자연스럽게 "제공된 정보에 따르면"으로 응답을 시작하는 모델 특성이 원인.

| 경로 | 금지 규칙 존재 여부 |
|------|-------------------|
| 3.5 Flash two-track Stage2 (`synthesisInstruction`) | ✅ 있음 (line 426) |
| 2.5 Flash 직접 SDK 경로 (`getSystemInstruction`) | ❌ 없음 |

모바일에서 더 빈번한 이유: 캐시 문제가 아닌, 모바일 세션에서 멀티턴 대화가 더 길게 이어지는 사용 패턴 때문.

### 수정 — `server/agent/prompt.ts`

`getSystemInstruction`의 `[FORMATTING & QUALITY]` 섹션에 서두 문구 금지 규칙 추가.

```typescript
// 추가된 규칙 (한/영/스/불 + 변형 포함)
- NEVER start a response with source attribution phrases such as
  "제공된 정보에 따르면", "제시된 정보를 바탕으로", "제공된 정보에 의하면",
  "Based on the provided information", "Based on the information provided",
  "According to the provided information",
  "Según la información proporcionada", "D'après les informations fournies",
  or any equivalent. Start directly with the answer content.
```

**수정 파일**: `server/agent/prompt.ts`

**효과**:
- 2.5 Flash 멀티턴에서 "제공된 정보에 따르면" 문구 제거
- 3.5 Flash에도 동일하게 적용 (기존 two-track 금지 규칙과 이중 방어)
- 4개 언어(한/영/스/불) 및 변형 패턴 모두 커버

## 5. 멀티턴 서두 문구 금지 규칙 개선 — "정보" → "내용" 변형 대응

### 현상

## 6. 빈 응답(empty response) 처리 강화

### 현상 (에러 로그)

```
[LangGraph] SDK call failed: undefined SDK returned empty response text
[LangGraph] SDK path failed for intent: general — falling back to LangChain (no streaming)
[browser] Chat streaming failed Error: LLM returned empty response.
```

`gemini-3.5-flash` 멀티턴(`thinkingLevel: "medium"`)에서 SDK가 빈 텍스트 반환 → LangChain fallback도 빈 응답 → 클라이언트 에러.

### 원인 분석

`finishReason` / `safetyRatings` 로그가 없어 원인 진단 불가. 가능한 원인:
1. `thinkingLevel: "medium"` → thinking 토큰이 모든 출력 토큰을 소진, 텍스트 파트 없음
2. `finishReason === 'SAFETY'` → 콘텐츠 안전 필터 차단

### 수정 — `server/agent/nodes/generator.ts`

**① thinking exhaustion 자동 재시도**: 빈 응답 + 3.5 모델 + non-minimal thinkingLevel이면 `"minimal"` 로 재시도 후 그래도 빈 응답 시 LangChain fallback.

```typescript
if (!responseText && is3xModel && thinkingConfig && thinkingConfig.thinkingLevel !== 'minimal') {
    console.warn('[LangGraph] Empty response — retrying with minimal thinking');
    // thinkingLevel: 'minimal' 로 재호출
}
```

**② finishReason / safetyRatings 로깅**: 빈 응답 시 원인 진단 로그 추가.

```
[LangGraph] Empty response - finishReason: SAFETY | safetyRatings: [...]
```

**③ SAFETY 차단 즉시 propagate**: `safetyBlock` 플래그 에러 생성, 키 재시도 없이 즉시 throw.

### 수정 — `app/api/chat/route.ts`

`CHAT_ERRORS`에 `safety` 타입 추가 (4개 언어), 에러 분류 로직에 `safetyBlock` 체크 우선 적용.

```typescript
safety: { ko: '안전 정책에 의해 응답이 차단되었습니다. 질문을 다르게 표현해보세요.', ... }
```

## 7. 마크다운 렌더링 버그 2종 수정 — `ChatMessage.tsx`

### 버그 1 — `<br>` 태그 그대로 노출

**원인**: `rehypeRaw` 미설치 → 마크다운 테이블 셀 내 `<br>` HTML이 텍스트 노드로 처리됨.

**수정**: 텍스트 전처리 3곳(`textPart`, `processedVisible`, `processedRemaining`)에서 `<br>` → ` · ` 변환.

```typescript
textPart = textPart.replace(/<br\s*\/?>/gi, ' · ');
```

### 버그 2 — `**` 볼드 마커 노출 (숫자 뒤 한글 패턴)

**원인**: 기존 lookahead `(?=[가-힣A-Za-zÀ-ÿ])`가 숫자(`0-9`)를 포함하지 않아 `**25% 수준의 GPU 자원**만으로` 같은 패턴 미처리.

**수정**: lookahead에 `0-9` 추가.

```typescript
// 변경 전
textPart.replace(/\*\*([^*\n]+?)\*\*(?=[가-힣A-Za-zÀ-ÿ])/g, '**$1** ')
// 변경 후
textPart.replace(/\*\*([^*\n]+?)\*\*(?=[가-힣A-Za-zÀ-ÿ0-9])/g, '**$1** ')
```

## 8. 표 셀 간결성 규칙 강화 — `prompt.ts`

### 현상

표 내용 컬럼이 `~입니다 / ~합니다` 형태의 완전한 서술 문장으로 생성되어 스캔 가독성 저하.

### 수정

`[CELL CONTENT LIMIT]` 규칙 강화:

- **≤12 words** 상한 (기존 ≤25 words)
- `~입니다 / ~합니다 / ~있습니다 / ~됩니다` 등 서술 어미 금지
- **키워드·구절 스타일** 강제 (fragment/note style)
- `→ ↑ ↓ ·` 압축 표기 권장
- 12단어 초과 내용은 표 아래 산문으로 분리

**기대 출력 변화**:

| 구분 | 이전 | 이후 |
|------|------|------|
| 핵심 메커니즘 | 이미지에 미세한 독성 패턴을 주입해 AI가 전혀 다른 객체로 인식하도록 왜곡을 유도합니다. | 독성 픽셀 주입 → AI 오인식 유도 |
| 강도 | 독성 주입 강도를 조절하며, 값이 높을수록 원본과의 시각적 차이가 커질 수 있습니다. | 높을수록 원본 시각 차이↑ |
