## 문제

앱은 **4개 언어를 지원한다고 선언**한다 — [ChatSidebar.tsx:71-74](../../components/ChatSidebar.tsx#L71-L74) 가 한국어·English·Español·Français 를 고르게 해주고, [lang.ts](../../server/agent/lang.ts) 의 `LangCode`·`LangName` 도 4종이다.

그런데 **실측은 ko/en 뿐이다.** es/fr 는 타입이 맞아서 컴파일이 통과할 뿐, 실제로 무엇이 나오는지 한 번도 본 적이 없다.

이게 위험한 이유는 §9 에서 이미 겪었기 때문이다:

> LLM 은 `new` 를 정확히 내고 있었고, **그 판정이 쓰이지 않았다.** 한국어가 멀쩡했던 건 후속 발화마다 "날씨"가 반복돼 intent 분류가 대신 잡아준 덕이다 — 언어가 원인이 아니라, **한국어가 버그를 가리고 있었다.**

즉 **주 언어가 부 언어의 결함을 은폐한다.** ko 가 11/11 이어도 es 가 같다는 보장이 전혀 없고, 실제로 en 에서 8/11 이 나왔던 전례가 있다.

### 공백-1. 렌더러 12종 전수 조사 (2026-08-05)

처음엔 영화 하나인 줄 알았고, 다음엔 도구 카드 4종인 줄 알았다. **전수로 세어보니 세 부류였다.**

| 렌더러 | `language` prop | 4언어 맵 | JSX 직접 한글 | 판정 |
|---|:---:|:---:|:---:|---|
| Bio · Chart · Chemical · Constellation · Drug · Weather | ✅ | ✅ | **0** | ✅ 정상 |
| **Diagram** | ❌ | ✅ | 0 | 🔴 **죽은 i18n** |
| Pharmacy | ❌ | ❌ | 11 | 🔴 미구현 |
| Hospital | ❌ | ❌ | 8 | 🔴 미구현 |
| Law | ❌ | ❌ | 7 | 🔴 미구현 |
| Movie | ❌ | ❌ | 6 | 🔴 미구현 |
| **Vet** | ❌ | ❌ | 3 | 🔴 미구현 |

> "한글 리터럴 개수"만 세면 오해한다 — 정상 6종도 한글이 많지만(Drug 58, Weather 32) 전부 `ko:` 브랜치 안이다. **판정 기준은 JSX 에 직접 박힌 한글이 있는가**다.

#### 🔴 죽은 i18n — Diagram (가장 나쁜 종류)

번역이 **다 되어 있는데 한 번도 쓰이지 않는다.**

```tsx
// DiagramRenderer.tsx:39·45·51-52 — 완비돼 있다
language?: 'ko' | 'en' | 'es' | 'fr';
export const DiagramRenderer = ({ data, language = 'ko' }) => {
  es: { reset: 'Reiniciar', inclined: 'Plano Inclinado', … }
  fr: { reset: 'Réinitialiser', inclined: 'Plan Incliné', … }

// ChatMessage.tsx:622 — prop 을 안 넘긴다
<DiagramRenderer data={part.data} />
```

기본값 `'ko'` 로 흡수돼 **es/fr 번역이 작성된 채 사장**돼 있다. 미구현보다 나쁜 이유는 **코드만 읽으면 "i18n 완료"로 보이기 때문**이다 — 아무도 다시 확인하지 않는다.

**고치는 건 한 단어**(`language={language}`)이고 번역이 이미 있어 **즉시 효과가 난다.** 이 계획에서 가장 싼 항목.

> 재발 방지: prop 을 안 넘기는 실수는 **타입이 안 잡아준다**(`language?:` 가 옵셔널이라). 렌더러가 12종이고 호출부가 한 파일에 몰려 있으므로, [PLAN_CHATMESSAGE_REFACTOR](PLAN_CHATMESSAGE_REFACTOR_260801.md) 의 `lib/renderers.ts` 레지스트리로 옮길 때 **공통 prop 전달을 한 곳으로** 모으면 구조적으로 사라진다.

#### 미구현 5종 = 도구 카드 (Vet 포함)

**이 다섯이 정확히 "도구 카드" 의도**다(약국·병원·동물병원·법령·영화). 우연이 아니다 — [REF_App2_Agent §8](../guide/REF_App2_Agent.md) 에서 이 의도들은 렌더러 JSON 스펙을 0으로 뺐고, 데이터가 전부 **한국 공공 API**(HIRA·법령정보센터·CGV/롯데/메가박스)에서 온다. 그래서 만들 때부터 "한국어 사용자용"이라는 암묵 가정이 있었다.

**측정할 필요가 없다** — 스페인어로 물어도 드롭다운에 `지점 선택`, 법령 카드에 `소관부처 정보 없음`, 동물병원 카드에 `폐업` 이 뜬다. 코드가 곧 증거다.

Vet 은 `영업`·`영업중`·`폐업` 셋뿐이라 가장 작고, `영업중` 은 Pharmacy 와 겹치므로 **같은 번역을 재사용**한다.

> ⚠️ **그렇다고 "API 값은 전부 한글 유지"는 아니다.** 병원명·주소는 유지하지만 `상급종합`·`휴무` 같은 **분류값은 번역해야** 읽힌다. 기준은 "API 가 줬느냐"가 아니라 **고유명사냐**다 — 상세는 [§조치 A](#-무엇을-번역하는가--기준은-api-가-줬느냐가-아니다).

## 🔴 원칙 — 측정 전에 규칙을 늘리지 않는다

[BACKLOG C1](PLAN_BACKLOG_260801.md) 이 이미 못 박은 규칙이고, 이 계획도 그대로 따른다.

날씨 때 "규칙이 한국어 전용이라 그렇다"고 **오진**했다가 실제 원인이 히스토리 창 크기였다. 그때 규칙을 4언어로 늘렸다면 문제는 안 고쳐진 채 코드만 4배가 됐을 것이다.

→ 각 측정은 **무엇이 관측되면 어떤 원인인지**를 미리 적어둔다(아래 판정표). 관측 후에 원인을 지어내지 않기 위해서다.

관측 메모:
- 회색지대 3종(주제 이탈 `unrelated` · 재표시 `new` · 도시만 교체 `new`)이 **LLM 판정만으로** 전부 정확했다. 규칙이 한국어 전용인데도 통과했다는 뜻이다.

- 마지막 턴이 `실제카드=true(히스토리 복사)` 로 통과한 경우가 있다 — 새 조회가 아니라 모델이 이전 카드를 복사한 것. 화면 기준으로는 정상이지만 **수치가 낡을 수 있다**([BACKLOG D2](PLAN_BACKLOG_260801.md)의 기존 항목, 언어 무관).

**사전 등록한 판정표**(측정 전에 적어둔 것 — 관측 후 원인을 지어내지 않기 위해):

| 관측 | 판정 |
|---|---|
| 11/11 | ← **실제 관측.** 배선·프롬프트·`activeCards` 가 언어 무관하게 동작 |
| 회색지대만 실패 | LLM 후속 판정이 비한국어에서 약함 → 라우터 프롬프트 예시 문제(§9 에서 **효과 중립**으로 측정된 그 예시들). 이때 비로소 A/B 가치가 생긴다 |
| 전 구간 실패 | 언어 배선 자체 — `toLangName` 이나 프롬프트 주입을 먼저 본다. 규칙 문제가 아니다 |

> ⚠️ 하니스는 **텍스트만** 본다. 카드가 화면에 그려지는지, 그 안의 라벨이 번역됐는지는 못 본다 → 측정 3 이 필요한 이유.

### 측정 2. 영화 후속 판정 — en — ✅ **8/8**

BACKLOG C1 은 2턴 최소 확인을 제안했지만, **기존 하니스의 8턴 전체**를 돌렸다. 회색지대 3종이 이미 설계돼 있어 2턴보다 신호가 훨씬 많고, 추가 비용은 6번의 호출뿐이다.

## 조치 (측정 결과에 따라)

### A. 렌더러 i18n — 죽은 i18n 1종 + 미구현 5종 — ✅ **구현 완료 (2026-08-05)**

측정으로 기각되지 않은 유일한 항목이고, 코드만으로 확실했다(§공백-1).

**결과**: 렌더러 12/12 가 `language` 를 받고, 6종 모두 **JSX 직접 한글 0건**. `tsc --noEmit` 0 · `npm run build` 성공. 변경 규모 `+257 / -90` (6파일).

| 단계 | 한 일 | 확인 |
|---:|---|---|
| 0 | `DiagramRenderer` 에 `language={language}` | **1줄** — 사장돼 있던 es/fr 번역이 즉시 살아남 |
| 1 | 도구 카드 5종 호출부에 prop 추가 | prop 을 넣자마자 **tsc 가 미구현 4종을 정확히 짚어줬다** — 컴파일러가 진행 상황을 추적 |
| 2 | API 계약값 상수화 | `API_CLOSED_DAY='휴무'` · `API_TERTIARY='상급종합'` 외 4 · `API_OPEN/API_CLOSED` — 전부 **한글 그대로**, 비교문에서만 사용 |
| 3 | 5종에 `T` 맵 + 표시 치환 | 5종 × 4언어 |

**미지값은 원문 통과**시킨다(`TYPE_LABEL[lang][raw] ?? raw`). API 가 예상 밖 분류값을 줄 수 있어 전수 매핑이 원리적으로 불가능하다.

#### 패턴은 이미 있다 — 새로 만들지 않는다

[WeatherRenderer.tsx:60-67](../../components/WeatherRenderer.tsx#L60-L67) 이 확립한 형태를 그대로 쓴다:

```tsx
const T: Record<Lang, Record<string, string>> = {
  ko: { humidity: '습도', … },
  en: { humidity: 'Humidity', … },
  es: { humidity: 'Humedad', … },
  fr: { humidity: 'Humidité', … },

const LOCALE: Record<Lang, string> = { ko: 'ko-KR', en: 'en-US', es: 'es-ES', fr: 'fr-FR' };

export const WeatherRenderer: React.FC<Props> = ({ data, language = 'ko' }) => {
  const lang: Lang = (['ko','en','es','fr'].includes(language as string) ? language : 'ko') as Lang;
  const tt = T[lang];
```

미지값 폴백까지 포함된 검증된 형태다. 4종에 같은 구조를 복사한다.

#### 단계

| 단계 | 내용 | 위험 |
|---:|---|---|
| **0** | `DiagramRenderer` 에 `language={language}` — **1줄, 번역은 이미 있다** | 낮음 — 유일하게 표시가 즉시 바뀌지만, 바뀌는 방향이 "한국어로 나오던 게 사용자 언어로" 라 되돌릴 이유가 없다 |
| 1 | [ChatMessage.tsx](../../components/ChatMessage.tsx) 호출부 **5곳**에 `language={language}` 추가 | 낮음 — 변수는 이미 그 스코프에 있다 |
| 2 | API 계약값(`'휴무'`·`'상급종합'` …)을 **상수로 추출** + 번역금지 주석 | 낮음 — 동작 불변, 아래 함정의 선행 조치 |
| 3 | 5종에 `Props.language` + `T` 맵 추가, **표시 지점만** `tt.*` 로 치환 | 중 — 제어 흐름 키를 건드리면 영업 판정이 깨진다 |
| 4 | 화면 확인(§측정 3) | — |

**1·2 는 동작이 안 바뀐다** — prop 은 기본값 `'ko'` 로 흡수되고, 상수 추출은 같은 문자열의 이름만 바뀐다. 둘 다 무해한 선행 커밋이라 **컷오버 전에 넣어도 된다.** 실제 표시가 바뀌는 건 3 부터이고, 렌더러별로 나눠도 중간 상태가 깨지지 않는다.

#### 🔴 단순 키 치환이 안 되는 것 하나

[MovieRenderer.tsx:238·248](../../components/MovieRenderer.tsx#L238) 의 "지점 없음" 문구는 **조사가 붙은 문장 조립**이다:

```tsx
{!branch ? `${region ? `'${region}'에는 ` : ''}지점이 없습니다`
{nm}는 {region ? `'${region}' 지역에` : '이 지역에'} 지점이 없습니다. 위 목록에서…
```

`에는`·`는`·`지역에` 가 문자열에 박혀 있어 영어로 옮기면 어순이 깨진다. → **자리표시자 방식**으로 바꾼다. WeatherRenderer 가 `kmaDays: 'KMA +{n}일'` 로 이미 쓰는 형태다:

```
ko: noBranchIn: "'{region}'에는 지점이 없습니다"
en: noBranchIn: "No {chain} location in '{region}'"
```

문장 단위로 키를 잡아야 하고, 토막을 이어붙이면 안 된다.

#### 🔴 무엇을 번역하는가 — 기준은 "API 가 줬느냐"가 아니다

이 카드들은 데이터가 전부 한국 공공 API 에서 온다. 그래서 "API 값은 한글 유지"로 단순화하고 싶어지는데, **그러면 틀린다.** 기준은 **고유명사인가**다.

| 종류 | 예 | 화면 표시 | 코드 내부 |
|---|---|---|---|
| **고유명사·주소·전화** | `종로약국` · `서울 종로구 …` · `02-123-4567` | 🔴 **한글 그대로** | — |
| **분류값(enum)** | `상급종합` · `휴무` · `12세관람가` | ✅ **번역** | 🔴 비교 키는 **한글 유지** |
| **UI 크롬** | `지점 선택` · `영업중` · `이전/다음` | ✅ 번역 | — |

**왜 고유명사를 유지하나** — 사용자를 특정하면 답이 나온다. 스페인어로 **한국** 약국·병원·법령·영화관을 묻는 사람은 거의 확실히 **한국에 있는 외국인**이다. 스페인에 앉아 서울 약국 영업시간을 물을 이유가 없다. 그 사람이 카드로 하는 일은:

- 약국명을 **택시기사에게 보여주기**
- 주소를 **카카오지도에 입력하기**(카드에 이미 그 링크가 있다 — [HospitalRenderer.tsx:161](../../components/HospitalRenderer.tsx#L161))
- 지점명으로 **현장 간판 찾기**

`종로약국` → `Farmacia Jongno` 로 바꾸면 카드가 **쓸모없어진다.** 번역이 아니라 훼손이다. 주소를 한글로 두는 것도 타협이 아니라 **의도**다 — 지도 앱과 택시기사가 읽는 건 한글이다.

#### 🔴 함정 — 한글이 **제어 흐름 키**로 쓰이고 있다

순진하게 치환하면 깨지는 자리가 실제로 있다.

```tsx
// HospitalRenderer — 한글이 색상 맵의 키이자 분기 조건
const HOSPITAL_TYPE = { '상급종합': {…violet}, '종합병원': {…blue}, '의원': {…} };
h.type.includes('상급종합') ? 'bg-violet-500' : …      // API 값과 직접 비교

// PharmacyRenderer — '휴무' 가 영업 판정에 쓰인다
if (!hoursToday || hoursToday === '휴무') return false;
const isOff = val === '휴무' || !val;
```

→ **원칙: API 가 주는 한글은 키로 그대로 두고, 화면에 찍는 지점에서만 라벨을 갈아끼운다.**

```tsx
// ❌ 영업 판정이 통째로 깨진다
if (hoursToday === tt.closed) …

// ✅ 키는 한글, 표시만 번역
const HOURS_CLOSED = '휴무';        // API 계약값 — 🔴 번역 금지
if (hoursToday === HOURS_CLOSED) …
<p>{tt.closed}</p>
```

API 계약값은 **상수로 뽑고 "번역 금지" 주석**을 단다. 안 그러면 다음 사람이 `T` 맵으로 옮기다가 조용히 깨뜨린다.

> **이미 맞게 된 곳이 하나 있다** — [PharmacyRenderer.tsx:31-33](../../components/PharmacyRenderer.tsx#L31-L33) 의 `DAY_LABELS` 가 `{ key: 'mon', label: '월' }` 로 키와 라벨을 분리해 뒀다. `label` 만 언어별로 만들면 끝난다. **이 패턴이 정답이고 나머지도 여기에 맞춘다.**

#### 하지 않을 것

- **고유명사 번역** — 위 표.
- **영문 데이터를 API 에서 가져오기** — 법제처에 영문법령이, KOBIS 에 영문 제명이 실제로 있다. 그래도 안 한다: ① 호출이 늘어 [60s 천장](PLAN_BACKLOG_260801.md)을 압박한다(법령·영화는 이미 느린 경로) ② 영문 커버리지가 불완전해 폴백 분기가 는다 ③ **애초에 원하는 게 아니다** — 위 사용자는 한글 원문을 원한다.
- **영업 판정·색상 매핑 로직 변경** — 라벨만 옮기고 로직은 건드리지 않는다.

### B. 영화 후속 규칙 다국어 — ❌ **하지 않는다** (2026-08-05 확정)

측정 2 가 8/8(회색지대 3/3)로 통과했다. 강한 규칙이 전부 미스인 상태에서 **LLM `follow_up` 판정만으로 정확했다.**

규칙을 4언어로 늘리면 `MOVIE_FOLLOWUP_QUESTION`·`MOVIE_STRONG_TERMS`·`MOVIE_WEAK_TERMS` 세 벌이 4배가 되는데, 얻는 건 **이미 맞고 있는 판정을 규칙으로도 맞히는 것**뿐이다. 게다가 규칙은 LLM 판정보다 **우선순위가 높아서**, 잘못 만들면 지금 맞는 것을 틀리게 만든다 — [REF_App2_Agent §7-5](../guide/REF_App2_Agent.md) 에서 `[?？]` 를 강한 신호로 뒀다가 `신촌은 어때?` 가 깨졌던 그 구조다.

> 이 결론은 **비용 절약이 아니라 위험 회피**다. 안 고쳐도 되는 것을 고치면 회귀만 생긴다.
