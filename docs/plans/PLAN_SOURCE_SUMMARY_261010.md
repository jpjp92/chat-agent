# 자료 요약 템플릿 통합 — 한 줄 요약은 "새 자료 + 요약 의도"일 때만

> 작성일: 2026-10-10 · 상태: 기획 (미구현)
> 현황 정리: [REF_OneLineSummary](../guide/REF_OneLineSummary.md) · 이력: [DEV_261009](../logs/2026/10/DEV_261009.md) §1 #4·§2-1, [DEV_261010](../logs/2026/10/DEV_261010.md) §2-3

## 1. 문제

1. **판단을 모델에게 맡기고 있다.** `[ONE-LINE SUMMARY FORMAT]` 이 **모든 응답 프롬프트에 전역으로** 들어가고, "언제 쓰나"는 SCOPE 문장으로 모델에게 부탁한다. GPT-6 은 따르고 Gemini 3.7 은 일반 질문·카드 답변에도 붙인다(10-09·10-10 실측). 프롬프트에 있으면 쓴다.
2. **멀티턴에서 반복된다.** 문서를 올리고 "요약해줘" 다음에 "3장은 무슨 얘기야?"라고 물어도 같은 문서 컨텍스트가 계속 실리므로 매 턴 `한 줄 요약`이 다시 나올 수 있다 — 대화가 아니라 보고서 반복처럼 읽힌다.
3. **템플릿이 경로마다 다르거나 없다.** URL·영상(직접 시청)은 3단 고정, YouTube 자막 경로는 소개·섹션·결론, 이미지·문서·붙여 넣은 텍스트는 템플릿 없음 → 같은 "요약해줘"의 첫 화면이 경로마다 다르다.

## 2. 원칙

> **한 줄 요약 = 이 턴에 새로 들어온 자료를, 사용자가 요약·분석해 달라고 할 때 한 번.**
> 그 뒤 같은 자료에 대한 질문은 대화다 — 헤딩 없이 바로 답한다.

- 판단은 **코드가 결정적으로** 한다. 프롬프트에는 "쓸 때의 템플릿"만 **그 턴에만** 넣는다. 일반 턴 프롬프트엔 한 줄 요약이라는 말 자체가 없다 → "쓰지 마라" 문구(SCOPE)가 필요 없어진다.
- 템플릿은 **한 함수**에서 만든다. 뼈대(한 줄 요약 → 주요 내용 → 핵심 포인트)는 공통, 자료 종류마다 "주요 내용" 지침만 다르다.

## 3. 판정 — `decideSummaryShape` (순수 함수)

### 3-1. 입력 신호 (전부 이미 코드에 있다)

| 신호 | 출처 | 의미 |
|---|---|---|
| `[URL_CONTENT: …]` | [useChatStream.ts](../../src/hooks/useChatStream.ts) — 이 메시지의 URL 을 가져온 본문 | **새 자료** (URL) |
| `[EXTRACTED_CONTENT: …]` | 같은 파일 — 이번 메시지 첨부의 추출 텍스트 | **새 자료** (문서) |
| 이번 메시지 이미지 첨부 | `attachments` mimeType `image/` | **새 자료** (이미지) |
| YouTube URL·영상 파일 | `videoTurn` ([video-turn.ts](../../server/agent/video-turn.ts)) | **새 자료** (영상) |
| `[PREVIOUSLY_UPLOADED_DOCUMENT_CONTENT: …]` | 이전 턴 문서를 다시 실은 것 | **후속** |
| `[VIDEO_ANALYSIS_SUMMARY: …]` | 1차 영상 분석 결과를 다시 실은 것 | **후속** |
| 긴 붙여 넣기 텍스트 | 사용자 메시지 길이(기준 §6-1) | **새 자료** (텍스트) |

### 3-2. 요약 의도

- **요약 요청**: `요약|정리|분석|설명해|무슨 내용|핵심|훑어|summar|overview|tl;dr|résum|resum` 류.
- **자료만 보냄**: 메시지가 비었거나 URL·첨부뿐(예: URL 한 줄만 붙여 넣음) → 요약 요청으로 본다(지금 URL 동작과 같음).
- **구체 질문**: 그 외 — "이 표에서 3월 매출?", "이 알약 뭐야", "2페이지 오타 찾아줘".
- **다시 요약**: 후속 턴의 `다시 요약|전체 요약|처음부터 정리|한 줄로` 류.

### 3-3. 결과

| 이 턴 | 의도 | 결과 | 예 |
|---|---|---|---|
| 새 자료 | 요약 요청 / 자료만 | 🟢 **`template`** — 종류별 3단 | URL 붙여 넣기, "이 PDF 요약해줘", 이미지 + "분석해줘" |
| 새 자료 | 구체 질문 | ⚪ **`direct`** — 헤딩 없이 답 | 알약 식별, 표 추출, "이 사진 어디야?" |
| 후속(이전 자료) | 일반 질문 | ⚪ **`direct`** | "3장은 무슨 얘기야?", "더 쉽게 설명해줘" |
| 후속(이전 자료) | 다시 요약 | 🟢 **`template`** | "전체 다시 요약해줘" |
| 후속(이전 자료) | "한 줄로" | 🟡 **`oneline`** — 블록쿼트 한 문장만 | "한 줄로 정리해줘" |
| 자료 없음 | 무엇이든 | ⚪ **`none`** — `[RESPONSE SHAPE]` | 일반 지식·검색 질문, 카드 후속 |

- 🔴 **멀티턴 어색함은 2·3행이 해결한다**: 같은 자료의 두 번째 질문부터는 템플릿이 프롬프트에 없다.
- 자료 없음(`none`) 은 지금도 의도대로 한 줄 요약이 없다 — 바뀌는 건 전역 규칙이 빠져 Gemini 가 붙일 근거가 사라진다는 점.

## 4. 템플릿 — `buildSourceSummaryTemplate(kind, lbl)`

공통 뼈대(라벨은 `URL_SUMMARY_LABELS` 4개 언어 그대로):

```
**{한 줄 요약}**
> (자료 전체를 1문장으로)

**{주요 내용}**
(종류별 지침 ↓)

**{핵심 포인트}**
- (가장 중요한 것 3~5개)
```

| kind | 주요 내용 지침 | 핵심 포인트 | 비고 |
|---|---|---|---|
| `url` | 본문 섹션 2~4개 헤딩, 섹션마다 불릿. 수치·인용·사실 굵게 | takeaway 3~5 | **현재 템플릿 그대로** |
| `document` | 문서 구조(장·절)를 따라 2~4개 헤딩. 표·수치는 표/굵게, 페이지·장 번호 언급 | 3~5 | 신규. 스프레드시트는 "데이터 개요(행·열·기간) → 주요 수치" |
| `text` | 붙여 넣은 글의 흐름대로 2~3개 묶음 | 3 | 신규. 짧으면 핵심 포인트 생략 가능 |
| `image` | ① 무엇이 보이나(장면·대상) ② 글자·수치(OCR) ③ 맥락·해석 — 해당 없는 항목은 생략 | 2~4 | 신규. 차트·도표면 ②를 표로 |
| `video` | 흐름·장면·오디오 2~4 불릿, 장면 전환에만 `[MM:SS]` | 2~4 | **현재 직접 시청 템플릿 그대로** |
| `youtube` | 번호 섹션 3~4 + 불릿, 헤딩·요점마다 타임스탬프 링크 | 3~5 | 🔴 **변경**: 소개 문단 → 한 줄 요약으로, 결론 → 핵심 포인트로. 타임스탬프 규칙은 유지 |

- 공통 금지: 템플릿 앞 인사말("이 영상은 …를 보여줍니다"), 끝의 마무리 요약 반복.
- `oneline` 은 템플릿 없이 "블록쿼트 한 문장" 한 줄 지시.

## 6. 착수 전 확인

1. **붙여 넣은 텍스트 기준** — 길이 몇 자부터 "자료"인가(후보 800자 또는 줄 15개). 짧은 글 + "요약해줘"는 일반 질문으로 둔다.
2. ✅ (§6-1 실측) **이미지 턴 신호가 조립부까지 오는가** — 이미지 첨부는 `webContent` 가 아니라 parts 로 간다. 🔴 [prompt-integrity.ts](../../server/agent/prompt-integrity.ts) 주석에 **전역 규칙을 조건부로 바꿨다가 이미지 경로가 빠져 되돌린 이력**이 있다 → 같은 실수 방지가 1순위. 하니스에 "이미지 + 요약 요청 → template" 행을 반드시 둔다.
3. ✅ (§6-1) **이전 이미지 후속** — `lastActiveDoc` 은 이미지를 잡지 않는다(extractedText·PDF 만). 이미지는 히스토리 미디어 창으로만 남고 **2턴까지만** 보인다.
4. **판정 위치** — route(initialState) vs router 노드. `webContent` 는 route 에서 정해져 턴 내내 고정이므로 route 가 후보.

### 6-1. 이미지 멀티턴 실측 (10-10, [test-image-multiturn](../../tests/test-image-multiturn.mts))

| 턴 | 모델이 이미지를 받나 | 이번 턴 새 이미지 | `hasMultimodalContent` |
|---|---|---|---|
| 1 (이미지 + "분석해줘") | ✅ | ✅ | true |
| 2 (후속) | ✅ 히스토리로 재전송 | ❌ | **true** |
| 3 (후속) | ❌ `[Attached File: chart.png]` 라벨로 강등 | ❌ | false |
| 4 (후속) | ❌ | ❌ | false |

- **판정 신호는 "현재 메시지에 이미지 파트가 있나"로 한다.** `hasMultimodalContent` 는 히스토리 이미지에도 true 라 새 자료 신호로 쓰면 2턴에도 한 줄 요약이 다시 나온다(바로 이 기획이 없애려는 반복).
- 🔴 **이미지는 후속 1턴까지만 보인다.** `buildHistoryMessages` 의 `mediaWindow 3` 은 주석("최근 3턴")과 달리 **메시지 3개**(사용자·모델 섞임)다 → 3번째 질문부터 모델은 이미지를 못 보고 파일명만 받는다. 클라 `KEEP_MEDIA_LAST=6` 주석도 "route 최근 3"을 턴으로 이해하고 있다.
- ⚖️ 창을 넓히면 공짜가 아니다: 이미지가 실린 턴은 **Google 검색이 꺼지고**(`hasMultimodalContent`), 무료 키에선 **2.5 + thinking off 로 고정**된다(`isMediaTurn`). 창을 늘리면 그 제약이 더 많은 후속 턴에 걸린다 — 06-20 "이미지 후속 검색 가짜 출처"(`dropImageForSearch`)도 이 축의 문제였다.
- 결론: **요약 기획은 현재 구조 그대로 진행 가능**(새 이미지 판정이 정확함). 창 크기는 **별건**으로 결정 — 후보 ① 유지(2턴까지) ② 사용자 턴 기준 3턴(=메시지 6) ③ 마지막 이미지 1장만 사용자 턴 3까지 유지.

### 6-2. 실기기 매트릭스

| 시나리오 | 기대 |
|---|---|
| URL 붙여 넣기 → "3번째 섹션 자세히" | 1턴 3단 / 2턴 헤딩 없음 |
| PDF + "요약해줘" → "결론만 다시" → "전체 다시 요약" | 3단 / 직접 / 3단 |
| 이미지 + "분석해줘" → "글자만 뽑아줘" | image 3단 / 직접 |
| 알약 사진 + "이거 뭐야" | 직접(템플릿 없음) |
| YouTube URL(자막) | 한 줄 요약으로 시작 + 타임스탬프 |
| 일반 질문 · 법률 카드 후속 | 한 줄 요약 없음 (Gemini 3.7 포함) |

## 7. 기대 효과와 위험

- 효과: 멀티턴 반복 제거, 경로 간 첫 화면 통일, Gemini 의 일반 질문 한 줄 요약이 **구조적으로** 사라짐, 템플릿 중복 제거.
- 위험: 요약 의도 정규식 누락 → 요약을 원했는데 직접 답. 완화 — "자료만 보냄"을 요약으로 보고, 애매하면 `template` 쪽으로 기운다(새 자료 첫 턴에 한해).
- 위험: 프롬프트 바이트 대폭 변경 → 골든 전면 갱신. 완화 — 단계 2 에서 의도별 포함/미포함을 직접 검사.
