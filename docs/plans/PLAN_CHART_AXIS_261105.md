## 1. 문제

차트가 **그려지지만 좌표가 틀린** 결함이다 — 모바일 UI 문제가 아니라 x축 해석이 틀리면 그래프 뜻이 달라진다.

- 11-05 수정에서 음수 눈금 빈칸·눈금 반올림을 고치려고 숫자 범주와 `{x,y}` 점을 **문자열 범주**로 바꿨다. 범주는 같은 폭으로 놓이므로 실제 간격이 사라진다: `x = 0,1,2,10` 에서 10 이 2 바로 옆, 출생아 1970·1980…2020·2021 이 같은 폭.
- 모바일 가로 스크롤이 데이터 개수(> 10)만 보고 걸린다 — y = x² 점 13 개가 스크롤돼 꼭짓점·대칭을 한눈에 못 본다.

## 2. 결정

**축의 의미가 우선, 기존 스키마에는 제한된 자동 추론.** 새 스키마 필드(`xAxis.scale`)는 P1 — 그 전까지 아래 규칙으로 추론한다.

| 입력 | 축 | 근거 |
|---|---|---|
| 선·영역·산점도의 `{x,y}` 점, x 가 숫자(또는 숫자 문자열) | **numeric** | 점이 좌표를 직접 말한다 |
| 선·영역의 숫자 범주(숫자 또는 `"1970"` 같은 숫자 문자열) — **간격 불균등** | **numeric** | 범주로 놓으면 간격 왜곡(1970·1980·2000·2020·2021) |
| 같은 숫자 범주 — **등간격** | category | 왜곡 없음(2020~2025, −0.4…0.4). 라벨이 받은 그대로 나온다 |
| `"2021년"`·`"1월"`·이름 등 숫자가 아닌 범주 | category | 기존 그대로 |
| 막대 | category | 막대는 범주 비교 — 숫자 x 막대는 P1 에서 판단 |

- 너비: numeric 축은 **항상 카드 폭**(가로 스크롤 없음). category 는 기존 규칙(> 10 개면 가로 확장) 유지.
- 눈금: 깔끔한 간격(1·2·5×10ⁿ)에 놓고 축 양끝을 그 배수로 맞춘다 — Apex 기본은 범위를 눈금 수로 나눠 1982.8·3.3 자리에 눈금을 놓고, 반올림해 보이면 **위치와 숫자가 어긋난다**. 후보 간격 중 축이 데이터보다 가장 덜 넓어지는 것(−3~3 → 그대로, 1970~2021 → 1970~2030).
- 보간: **numeric 축은 `straight`**, 범주 축은 `monotoneCubic` 유지. 구현 중 실측: Apex `monotoneCubic` 이 숫자 축에서 데이터 최솟값 아래로 꺼진다(0·1·4·100 이 x=1 직후 0 아래 2.4px, `straight`·`smooth` 는 0) — 오전 용수철 차트 끝 꺾임과 같은 결함. 보간은 정확한 함수 표현을 보장하지 않는다 — 실제 함수 샘플링은 P2.
- 하위 호환: `json:chart` 형식 변경 없음. 통계 차트(문자열 범주) 동작 그대로.
