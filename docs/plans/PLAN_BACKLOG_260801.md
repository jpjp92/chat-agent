## A. 사용자에게 깨져 보이는 것

### A1. LangChain 폴백 크래시 — `Cannot read properties of undefined (reading 'parts')`

SDK 경로가 빈 응답을 내면 LangChain 폴백으로 넘어가는데, **그 폴백이 죽는다.** 결과는 빈 화면이다.

```
Empty response - finishReason: UNEXPECTED_TOOL_CALL
SDK path failed for intent: data_viz — falling back to LangChain
LangChain path fatal error: Cannot read properties of undefined (reading 'parts')
```

- 오늘 `[TOOL AVAILABILITY]` 프롬프트로 **트리거 하나**를 줄였지만(§8-3), 폴백 경로 자체는 그대로 깨져 있다. 안전필터·응답 절단 등 다른 트리거로 언제든 재발한다.
- **해야 할 일**: 폴백 진입 시 응답 구조를 방어적으로 읽고, 실패하면 사용자에게 재시도 안내 문구라도 반환. 지금은 예외가 위로 전파돼 아무것도 안 보인다.
- 작업량 작고 체감 큼 — **A티어 1순위**.

### A2. 날씨 예보 아이콘이 전부 ☀️

현재 날씨가 `Cloudy`(구름 70%)이고 강수확률 20%인데 **5일 예보가 전부 맑음 아이콘**이다(한국어·영어 스크린샷 모두 동일). 하늘상태 코드 매핑이 의심된다.

- 카드는 우리 서비스의 대표 UI이고, **정보가 틀려 보인다**. 값(기온·강수확률)은 맞는데 아이콘만 어긋나면 오히려 신뢰를 깎는다.
- 확인 지점: `weatherTool`이 KMA 단기예보의 `SKY`/`PTY` 코드를 예보 항목에 넣는지, 넣는다면 렌더러 매핑이 맞는지. 현재 카드는 예보 아이콘을 어디서 얻는지부터 봐야 한다.
- 오늘 작업과 무관한 기존 동작이라 **별건**으로 잡되, A2로 둔다.

## B. 재발 방지 (테스트·절차)

오늘 결함 2건이 **스크립트를 통과했다.** 판정이 "형식이 유효한가"까지만이었기 때문이다.

## C. 커버리지 공백

### C1. 영화 후속 판정이 한국어 전용

`MOVIE_FOLLOWUP_QUESTION` · `MOVIE_STRONG_TERMS` · `MOVIE_WEAK_TERMS`가 전부 한국어 정규식이다. 비한국어 사용자는 3분기 중 강한 규칙이 항상 미스 → **LLM 판정 단독**이다.

- 날씨에서 같은 구조의 공백이 **실제 실패로 드러났다**(영어 8/11 → `activeCards`로 11/11). 영화는 아직 측정하지 않았다.
- **먼저 측정한다**: `Show me movie showtimes in Gangnam` → `What starts earliest?` 2턴. 2턴에 카드가 또 뜨면 공백이 확인된 것.
- 측정 전에 규칙을 4언어로 늘리지 않는다 — 날씨 때 "규칙이 없어서"라고 오진했다가 실제 원인이 창 크기였던 전례가 있다.

### C2. 4순위 잔여 검증

- 도구 카드 3종(약국·병원·법령) — 프롬프트에서 렌더러 스펙을 0으로 뺀 의도들
- 스페인어·프랑스어 1회 — `langName` 배선은 ko/en만 실측
- 긴 대화 카드 경계 — 카드 후 잡담 10턴 이상 뒤 재표시(20메시지 창 밖은 새 조회가 정상 동작)
- YouTube 요약 1건(60s 캡), PDF 첨부 3~4턴(413 대응)
- 차트를 **검색 켜진 경로**로 재확인 (§3-2 한계)

## D. 조건부 대기 (지금 하지 않음)

### D1. `activeCard` / `cardFollowup` 일반화

날씨·영화가 거의 같은 코드를 두 벌 갖고 있다(REF §5의 2순위).

- 오늘 `activeCards`가 들어가면서 **절반은 이미 일반화 가능한 모양**이 됐다(키만 늘리면 된다).
- 다만 약국·병원·법령에는 **후속 판정 자체가 없다.** 필요해지기 전에 추상화하면 쓰지 않는 구조만 늘어난다.
- **트리거**: 세 번째 카드에 후속 판정이 필요해지는 시점.

### D2. 히스토리 카드 복사 시 수치 노후화

재표시 요청에서 모델이 툴을 안 부르고 히스토리 카드 블록을 복사하면 수치가 낡을 수 있다(REF §7-3).

- 배포 검증에서 **재조회가 일어났다**(`Updated 15:00` vs `14:36`) → 발생 빈도가 낮아 보인다.
- **트리거**: 실사용에서 낡은 수치 신고가 나오면.

## E. 하지 않기로 한 것

### E1. 날씨 카드 지명 i18n

영어 UI에서도 `서울`·`부산광역시`로 표시된다. KMA가 주는 지명이라 **틀린 정보는 아니고**, 고치려면 지명 매핑 테이블(한→영/스/프)이 필요하다. 해외 도시는 OpenWeather라 이미 영문이다. 비용 대비 값어치가 낮다.

### E2. 극장 인접 지점 대체

`노원 → 중계(CGV)`처럼 가까운 다른 동네를 대신 보여주는 것. **오늘 고친 가산디지털 문제와 같은 성격**이라 의도적으로 넣지 않았다. 지역 인접성 데이터가 필요하고, "어디까지가 근처인가"라는 기준이 생긴다. 지금은 "지점이 없습니다 + 드롭다운으로 직접 선택"이 정직하다.

### E3. 검색 on/off에 따른 수치 편차

2021년 실질 GDP 성장률이 검색 턴에서 4.3%(확정치), 비검색 턴에서 4.1%(속보치)로 나왔다. **둘 다 출처가 있는 값**이라 오류가 아니다. 통일하려면 "항상 검색"이 필요한데 지연·쿼터 비용이 크다.
