## 1. 문제

차트는 그려지는데 **숫자가 어디서 왔는지 모른다.**
- 출생아 수 차트 출처가 `tistory.com`(블로그)과 `index.go.kr`(e-나라지표)인데 칩은 똑같이 보인다.
- 앱에서 서울 기온 차트 8월 ≈ 22°C, 본문 "8월 26.1°C" — 차트와 본문이 다른 수치(11-05 실화면).

통계 차트에서 근거 없는 숫자가 그럴듯하게 그려지는 것은 렌더링 결함보다 위험하다 — 사용자는 차트를 사실로 읽는다.

## 2. 구조 확인 (코드)

- 검색은 **Gemini 내장 googleSearch 한 번** — 모델이 스스로 검색하고 바로 답을 쓴다. 서버가 출처를 미리 걸러 넘길 단계가 없다.
- 서버가 받는 것(`groundingMetadata`): `groundingChunks[].web.title`(= **도메인**)·`uri`(redirect), `groundingSupports`(본문 바이트 구간 → chunk 인덱스). `server/agent/gemini-citations.ts` 가 이걸로 `[N](uri)` 마커를 심는다.

**③ 차트-본문 수치 일치** — 8 쿼리 × 2회(16 호출): 차트 16/16, 자동 비교 7쌍, 실제 불일치 **0**(자동 판정 1건은 "30조 달러" vs `30.76`(조 달러) 배수 미처리 오탐). 원문 수동 확인:

| 쿼리 | 차트 vs 본문 | 차트 vs 공식값 | 회차 간 |
|---|---|---|---|
| 서울 기온 | 일치(8월 26.1) | 기상청 1991~2020 평년값과 같음 | 동일 |

해석:
- 본문이 차트를 옮겨 쓰므로 **차트-본문 일치 ≠ 정확**. 환율은 두 회차 모두 자기 안에서는 일치했지만 서로 달랐다 — 적어도 한쪽은 출처에 없는 숫자. 출처 등급을 함께 봐야 한다.
- 자동 판정 범위가 좁다: 출처 붙은 문장 ≈ 50 중 비교 7 — 문장에 시점이 둘 이상이면("1월(-1.9℃) … 8월(26.1℃)") 건너뛰었다.
- 앱에서 본 기온 불일치는 **재현 안 됨**. 이번은 3.8 직접 호출, 앱에선 data_viz 턴이 2.5 로 강등된 로그가 있었다(`modelDowngraded: true`) — 앱 경로·강등 턴에서 생겼을 가능성. → 2차(앱 경로)에서 강등 0/16·불일치 0 — 원인 미확인으로 남김(§4-1).

- "공식 출처 없음" 한 문장 고지는 cand 12회 중 0회 — 모델이 지키지 않았다. 이 고지도 서버가 등급으로 판정해 붙여야 한다.

## 5. 확정안 (11-06, Claude·GPT 검토 합의)

### 5-1. 핵심 원칙 — 출처 분류는 수치 검증이 아니다

- grounding 은 본문에만 붙고 차트 블록은 0/6(§3). 지금 알 수 있는 것은 **"응답에 어떤 성격의 출처가 포함됐나"** 뿐이고, **"차트 수치가 그 출처와 일치하나"** 는 모른다.
- 그래서 문구·로그·UI 어디에도 **"검증"·"검증 완료"** 를 쓰지 않는다. 허용 문구: "공식 통계기관으로 표시된 출처 포함" · "공식 통계 출처 미확인".
- '정부·공식 통계' 라벨도 **출처 사이트의 성격 분류**다 — 정부 사이트가 다른 기관 자료를 재인용할 수 있으므로 1차 원자료 검증이 아니다.
- **표시 위치: 메시지 하단 출처 칩 영역.** 차트 카드 헤더에는 넣지 않는다 — 헤더에 두면 차트가 공식 통계로 검증됐다는 인상을 준다. 차트별 데이터 출처를 추적할 수 있게 된 뒤 카드 내부 표시를 다시 본다.

### 5-3. 세부 규칙

**출처 분류(P1-2A)**
- 입력은 `groundingChunks[].web.title`. 실측 74종 전부 호스트명 형태였지만 uri 는 Google redirect 라 **교차 확인은 불가** — redirect 를 따라가 확인하지 않는다(출처마다 HTTP 요청이 생겨 응답이 늦어진다).
- **호스트명 형식일 때만** 분류(`^[a-z0-9-]+(\.[a-z0-9-]+)+$`, 소문자화). 아니면 `기타 출처`.
- **점 경계 접미사 매칭** — `.go.kr` 은 `kma.go.kr` 에 맞고 `evilgo.kr` 에 안 맞는다. 목록은 데이터(정부·중앙은행·통계기관·거래소·국제기구 / 언론·위키·리서치)로 관리하고, 불확실하면 `기타 출처`.
- `sourceKinds` 는 `{ official: n, secondary: n, other: n }` **개수만** — URL·제목은 남기지 않는다. 뜻은 "응답에 포함된 출처의 성격별 개수".

**`origin`(P1-2B)** — `provided`(차트의 모든 수치가 사용자 입력) · `function`(식·함수에서 계산) · `external`(검색 등 외부 자료).
- 앞당긴 이유: 라우터가 사용자 숫자 질문("2024년 매출 100억, 2025년 120억 막대로 비교")에도 검색을 켰다(§4-3) — 검색 on/off 로는 사용자 숫자와 외부 통계를 못 가른다.
- `origin` 은 **모델이 쓰는 값**이다. 안내 문구를 고르는 **힌트**로만 쓰고, 근거 검사를 건너뛰는 강한 제어에 쓰지 않는다. 누락·모르는 값은 **중립**(안내 없음 — 기존 차트 호환).
- `provided` 를 믿을지 확인하는 방법(차트 수치가 사용자 문장에 모두 있는가)은 P1-2B 에서 따로 검토.

**출처 칩 영역 안내(P1-2B)** — **외부 통계 차트에만**(`origin=external`, 또는 data_viz·검색 on·출처 ≥ 1 이면서 `origin` 이 `provided`/`function` 이 아님). 공식 출처 ≥ 1 → "공식 통계기관으로 표시된 출처 포함", 0 → "공식 통계 출처 미확인". 함수 그래프·사용자 제공 데이터에는 붙이지 않는다. 문구 아래 한 줄: "출처 분류는 응답 전체 기준이며 차트 개별 수치의 검증을 뜻하지 않습니다."

**상대 날짜 시점 검사(P1-2B)** — 사용자 문장에 상대 시점("최근 N개월/년"·"최근"·"요즘"·"올해")이 있고 **과거 연도를 명시하지 않았을 때만**. 차트 마지막 시점이 오늘보다 월간 2개월·연간 1년 넘게 이르면 안내. §4-3 에서 프롬프트만으로 2 → 0 이 됐으므로 안전망.

**유지**: P0·P1-1 렌더링, 라우터·검색 정책. 단계마다 회귀 하니스·`npm run verify`·`next build`.
