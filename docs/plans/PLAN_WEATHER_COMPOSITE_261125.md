# PLAN_WEATHER_COMPOSITE_261125 — 날씨 + 미세먼지 복합 질문: 카드 유지, 빈 부분만 선택 모델 검색

> 2026-11-25 작성. 상태: **구현 완료(§7)** · 미커밋. 작업은 dev 기준.
> 관련: [DEV_261125 §11](../logs/2026/11/DEV_261125.md)(카드 뒤 짧은 답·역질문 `lookup`) · [PLAN_WEATHER_MID_FORECAST_261125](PLAN_WEATHER_MID_FORECAST_261125.md)

## 1. 문제

"오늘 서울 날씨 어때? 미세먼지는 어때?"처럼 날씨와 미세먼지를 한 번에 물으면 **카드 없이 검색으로만** 답한다. 그 답의 날씨 수치가 검색 결과에서 와 기상청과 어긋난다(11-25 로컬, GPT-6 luna).

| | 검색 답 | 기상청 카드(같은 날 20:22) |
|---|---|---|
| 현재 | 구름 조금, 약 5°C | 구름 많음, 5° |
| 오늘 최고 / 최저 | 8°C / **4°C** | 7° / **-4°** |

- 최저 기온이 8도 차이 난다. 영하인 날을 영상 4도로 안내한다.
- 출처 칩은 에어코리아 하나뿐이라 날씨 수치의 근거가 화면에 없다.
- "대기질을 한 번 더 확인해 주세요"처럼 사용자에게 확인을 넘긴다.

**원인**: 라우터의 "계절/현상 질의" 분기([router.ts:530](../../server/agent/nodes/router.ts#L530))가 날씨 의도라도 `미세먼지·초미세먼지·황사·자외선 지수·꽃가루·오존`이 있으면 통째로 `general` + 검색으로 보낸다. 원래는 장마 시작 시기·태풍 경로처럼 **카드가 아예 답할 수 없는 질문**을 위한 분기인데, "카드 + 추가 정보" 질문까지 같이 묶여 있다.

같은 날 GPT 실화면에서 나머지 흐름은 의도대로였다: "전주 날씨 알려줘"(카드 → 한 줄, 답 없음) · "이번주에 비소식 있어?"(카드 값으로 금·토 60%) · "미세먼지는?"(다음 턴 검색, 출처 칩).

## 2. 원칙

1. **날씨 수치는 기상청(해외는 OpenWeather) 카드가 정답이다.** 검색 결과의 기온·강수 수치는 쓰지 않는다.
2. **검색은 카드에 없는 부분만**(미세먼지·자외선·황사 등).
3. **검색해서 사용자에게 보여 줄 답은 생성기와 같은 모델이 쓴다(선택 모델 — 무료 키 Gemini 3.x 는 생성기처럼 역할 모델로 강등, §4-4).** 사용자가 GPT 를 골랐으면 GPT(web_search), Gemini 면 Gemini(grounding). 다음 턴에서 "미세먼지는?"이라고 따로 물을 때와 같은 모델이 찾아야 일관된다. 역할 모델(3.5 FL)은 라우터·파싱·판정 같은 내부 작업용이다.
4. 사용자가 이미 물었으니 역질문("찾아볼까요?") 없이 바로 찾는다. 역질문은 사용자가 묻지 않은 정보가 필요할 때만(DEV_261125 §11-5).

## 3. 검토한 안

| | A. 카드 뒤 답(역할 모델)이 검색까지 | B. 그래프에서 카드 + 생성 계속 | **C. 카드 뒤 단계에서 선택 모델로 검색(채택)** |
|---|---|---|---|
| 검색 답을 쓰는 모델 | 3.5 FL 고정 | 선택 모델 | 선택 모델 |
| 구현 | route 한 곳 | 그래프 두 경로(Gemini langchain fast-pass · GPT 함수 호출 fast-pass)에 "카드 내고 생성 계속" 경로 신설 | route 한 곳 + 선택 모델 검색 호출 재사용 |
| 날씨 수치 어긋날 위험 | 낮음 | 중간 — 선택 모델이 검색 결과 수치를 다시 쓸 수 있음 | 중간 → 지시문(카드 데이터 = 정답) + 하니스로 막는다 |
| 확장 | 날씨 한정 | 다른 카드 복합 의도에도 | 다른 카드에도 같은 자리에서 확장 가능 |

- A 는 원칙 3에 어긋난다(GPT 를 골랐는데 검색 답이 Gemini).
- B 는 필요한 검색 답이 한두 문장인데 그래프 두 경로를 바꿔야 한다.
- C 는 B 의 "선택 모델이 검색" 을 그래프 밖, 이미 있는 카드 뒤 단계(route)에서 한다.

## 4. 설계 (C)

### 4-1. 라우팅

- 현상 분기에서 **날씨 의도 + 카드가 답할 수 있는 날씨 요청이 같이 있을 때**는 `weather` 를 유지하고 "카드 밖 정보 요청" 표시만 남긴다(예: `weatherExtras: ['미세먼지']`).
  - 판단은 라우터 LLM 에 맡긴다(키워드로 "날씨 요청이 같이 있는가"를 가르지 않는다 — 의도는 문맥 기반 원칙). 라우터 출력에 필드 하나를 더하거나, 현상 분기가 LLM 의도(`weather`)를 덮어쓰지 않게 하는 쪽 중 실측으로 고른다.
- 현상만 묻는 질문("서울 미세먼지 어때?", "장마 언제 시작해?", "태풍 경로")은 지금처럼 `general` + 검색.

### 4-2. 카드 뒤 단계(route)

지금(§11): 본문이 카드 + 한 줄뿐이면 → 역할 모델이 판단 답(또는 `NONE`).

추가: 이번 턴에 카드 밖 정보 요청이 있으면 → **선택 모델을 검색 모드로 1회** 호출한다.
- 입력: 사용자 질문 · 카드 요약(관측/예보 분리, 요일 계산 포함 — `weather-answer-prompt.ts` 재사용) · 찾을 것(미세먼지 등)
- 지시: "날씨 수치는 이 데이터가 정답 — 검색 결과의 기온·강수는 쓰지 말 것. 검색은 {찾을 것}만. 1~3문장. 사용자에게 확인을 넘기지 말 것."
- 호출: GPT → `generateOpenAIChat`(`server/openai/chat.ts`, web_search) · Gemini → SDK grounding(생성기의 검색 경로와 같은 설정·키 규칙)
- 출처 칩: 검색 결과 출처를 지금 검색 답과 같은 `sources` 이벤트로
- 판단 답과의 관계: 카드 밖 정보 요청이 있는 턴은 이 한 번의 호출이 판단 질문까지 함께 답한다(호출 2회 금지)

판단 답만 있는 턴(검색 없음)은 **역할 모델 유지** — 짧은 한 줄이고 `NONE` 판정까지 32/32 로 맞춰 둔 상태. 선택 모델로 옮길지는 GPT 첫 토큰 지연을 잰 뒤 따로 정한다(§6).

### 4-3. 실패

- 검색 호출 실패·시간 초과 → 카드 + 한 줄은 이미 나갔다. 역할 모델 판단 답으로 내려가 "미세먼지도 찾아볼까요?" 역질문(다음 턴 `lookup` 으로 선택 모델이 찾는다).
- 제한 시간은 선택 모델 검색 첫 토큰 실측 뒤 정한다.

### 4-4. 코드 대조 검토 (2026-11-25)

| 항목 | 확인한 것 | 계획에 반영 |
|---|---|---|
| GPT 검색 호출 | `generateOpenAIChat({ model, messages, instructions, useWebSearch, maxOutputTokens, apiKey?, timeoutMs? })` 가 `{ text, sources }` 를 돌려준다 — 그래프 밖에서 그대로 부를 수 있다 | 재사용. `sources` 를 `st.allSources` 에 넣고 `sources` 이벤트 |
| Gemini 검색 호출 | 생성기 안에 인라인(`tools: [{ googleSearch: {} }]`, generator.ts 443·474·507…), 따로 부를 함수가 없다 | 인라인 복사 금지 — 작은 함수로 뽑아 생성기와 카드 뒤 단계가 같이 쓴다. grounding 출처·인용 처리(`gemini-citations.ts`)도 같은 경로로 |
| **Gemini 검색 강등** | 3.x 는 무료 키 검색이 429 라, 생성기는 `searchFallbackFor(apiKey)` 로 **검색이 필요하면 역할 모델(3.5 FL)로 바꿔** 답한다(generator.ts 189·395) | 카드 뒤 단계도 같은 규칙을 따라야 한다 — 게스트·무료 키는 결국 3.5 FL 이 검색한다. "선택 모델이 검색" 은 **생성기와 같은 모델이 검색** 으로 정확히 적는다 |
| 키 등급 | route 가 `runWithKeyTier(keyTier, …)` 로 스트림 전체를 감싼다(회원 유료 우선·게스트 무료) | 카드 뒤 단계는 그 안에서 돌아 등급을 물려받는다 — 별도 키 선택 없음 |
| 저장 순서 | route 는 스트림이 끝난 뒤 `st.fullAiResponse`·`st.allSources` 를 저장한다 | 카드 뒤 단계는 저장 **전**(지금 판단 답과 같은 자리). 출처도 저장 전에 `st.allSources` 에 |
| 라우팅 판정 | 현상 분기(router.ts:530)가 정규식으로 LLM 의 `weather` 를 `general` 로 덮어쓴다 | "날씨 요청이 같이 있는가" 를 정규식으로 더하지 않는다. 라우터 LLM 출력에 카드 밖 요청 필드(`weather_extra`)를 두고 분기는 그 값만 본다 — 실측에서 "서울 미세먼지 어때?"(현상만)가 `weather` 로 오지 않는지 꼭 본다 |
| 메모리 | 로컬 verify 가 한 번 OOM(137)으로 죽었다(3.7GB, 측정과 겹침) | 실측과 build 를 동시에 돌리지 않는다 |

## 5. 검증 계획

- 하니스(네트워크 없음): 라우팅 판정 · 카드 밖 요청 → 검색 단계 선택 · 프롬프트 계약(카드 수치 = 정답, 검색 수치 금지, 확인 떠넘기기 금지) · route 배선(호출 1회) · 실패 시 역질문 폴백.
- 실측(유료 키, Gemini·GPT 각각):
  - 복합: "오늘 서울 날씨 어때? 미세먼지는?" · "부산 날씨랑 자외선" · "내일 제주 날씨, 황사 있어?" · "날씨 어때? 미세먼지 심하면 마스크 써야 해?"
  - 현상만: "서울 미세먼지 어때?" · "장마 언제 시작해?" → 지금처럼 검색만
  - 기존: 판단 답 32문항 · 역질문 `lookup` 9경우 유지
  - 판정 기준: **답의 기온·강수 수치가 카드와 일치**(어긋나면 실패) · 미세먼지 등은 출처 칩 · 확인 떠넘기기 문구 없음
- 비용 추정: 복합 4 × 2모델 × 2회 + 현상만 2 × 2 × 2 ≈ 24회 선택 모델 검색 + 회귀 ~70회 역할 모델.

## 6. 나중

- 미세먼지·자외선을 검색 대신 공식 API 로(에어코리아 대기질·기상청 생활기상지수) — 날씨를 OWM 검색 대신 KMA API 로 옮긴 것과 같은 이유. 검색 출처가 매번 달라진다(에어코리아 ↔ Skymory).
  - 11-27 중간 조치: 검색 출처를 공식으로 고정(GPT `allowed_domains`, Gemini 는 프롬프트로 에어코리아 예보 페이지 지정)하고 답에 근거(등급·기준 시각·측정/예보)를 붙였다 → [DEV_261127 §11](../logs/2026/11/DEV_261127.md). API 로 옮기면 검색 지연(4~6초)과 무료 키 역질문이 함께 풀린다.

- 판단 답(검색 없음)도 선택 모델로 옮길지 — GPT 첫 토큰 지연·비용 측정 뒤.
- 다른 카드의 복합 의도("약국 찾아줘, 그리고 이 약 부작용은?")가 자주 보이면 같은 카드 뒤 단계로 일반화.

**라우팅 실측**(라우터 실호출, 11문항 × 2회)
- 1차(`weather_extra` 만): 15/22 — "서울 미세먼지 어때?"·"초미세먼지 농도"·"장마 언제"·"태풍 경로"에도 LLM 이 weather + extra(5건), "부산 날씨랑 자외선"은 정규식이 `자외선 지수`만 잡아 카드만(2건).
- 2차(날씨 요청 어휘 조건 + `자외선`): **21/22**. 남은 1건은 LLM 이 의도를 general 로 낸 경우 → 이전과 같은 검색 답(나빠지지 않음).
- 역질문 `lookup` 9경우 × 2회 다시: 18/18 유지.

**검색 답 실측**(실제 기상청 카드, 유료 키)

| 모델 | 지연 | 기온 수치 | 출처 |
|---|---|---|---|
| GPT-6 luna | 3.3~4.4s | 4/4 카드와 일치(대부분 수치를 안 씀) | 에어코리아·기상청 3, **Skymory(제3자) 1** |
| Gemini 3.8 Flash(기본 thinking) | **13~23s** | 4/4 | 에어코리아·기상청 |
| Gemini 3.8 Flash(가장 낮은 thinking) | **4.5~5.2s** | 4/4 | 에어코리아·기상청 |

- 예: GPT "서울 미세먼지는 오늘 예보 기준 보통이라 심한 편은 아니어서, 꼭 마스크를 쓸 필요는 없어 보여요." · Gemini "오늘 부산의 자외선 지수는 기상청 기준 '낮음' 단계로 … 맑은 날씨가 이어지므로 외출하시기에 무난합니다."
- 측정 중 KMA 가 다시 느려져 5s 시간 초과 → 부산·제주가 OpenWeather 로 폴백(23시대). 9s 였으면 4s 더 기다렸다.

**11-26 보정**: 답은 한 문장(판단 질문이 있을 때만 두 문장)·날씨 수치 말하지 않기. 무료 키(역할 모델 강등)는 검색 생략 → 역질문 — 3.5 FL 검색이 9.5s(GPT 3.7s · 3.8 Flash 5.8s). DEV_261125 §13.
