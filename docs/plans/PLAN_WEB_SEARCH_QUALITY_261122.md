## 3. 개선안

### W1 — 출처 표시 (코드, 유료 호출 없음)

1. **도메인 한 곳에서 구하기** — `sourceDomainOf({ uri, title })` 를 `lib/` 순수 함수로 옮긴다(현 `faviconDomain` 규칙: `vertexaisearch` 면 도메인 모양 제목, 아니면 URI 호스트). 화면 아이콘·분류·라벨이 모두 이걸 쓴다.
2. **분류 입력을 도메인으로** — `sourceKindOf` 에 제목 대신 도메인을 넘긴다. 서버 집계(`countSourceKinds` — `[turn]` 로그 `sourceKinds`, `app/api/chat/route.ts:269`)도 같은 입력으로 맞춘다. 호출부는 이 둘과 `SourceBar` 두 곳(`KindTag`·접힌 바 공식 개수)뿐이다(11-22 전수) — 화면과 로그 숫자가 어긋나지 않게.
3. **칩 라벨 = 도메인, 제목은 보조** — 칩은 `imf.org`, 목록 창(행)은 도메인 + 제목 한 줄. Gemini 는 제목=도메인이라 화면 변화 없음.
4. **제목 정리** — 서버에서 한 번: 마크다운 머리표·강조(`#`·`**`·`` ` ``)·연속 공백 제거, 길이 상한. 비면 도메인으로 폴백.

검증: `test-source-kind` 에 OpenAI 모양(페이지 제목 + 실제 URI) 케이스 추가 — 2·3·4 재현(전 RED → 후 GREEN). Gemini 모양은 바이트 동일 대조군. 호출부 배선 검사.

**원인이 검색어에 있다** — Flash 는 **기억 속 버전 번호로 검색어를 만든다**(`"iPhone 16 17"`, `"Pixel 9 10"`). 처음부터 옛 세대를 찾으니 옛 글이 걸리고, 답이 거기 끌려간다. Gemini 4 는 새 세대 이름으로 바로 찾는다. PLAN_RECENCY §4-3 의 가설이 운영 질문으로 확인됐다. 출처 수가 많아도(3.8 최대 11) 소용없다 — 찾는 대상이 틀렸다.

**모델 교체는 답이 아니다(지금은)** — Gemini 4 는 맞지만 지연 55~110s 로 채팅 턴에 못 쓴다. Flash 에 검색 순서를 가르친다.

**규칙(안) — 검색 턴, 최신·현재·라인업 질문**

1. 최신 제품·모델·버전을 물으면 **기억 속 버전 번호를 믿지 않는다** — 학습 시점이 오늘보다 오래됐다.
2. **먼저 현재 라인업을 찾는다** — 오늘 연·월과 함께, 버전 번호 없이("latest {브랜드} {제품군} lineup {YYYY}").
3. 그 검색으로 확인한 모델명으로 **두 번째 검색**에서 수치를 찾는다.
4. 비교 항목은 **같은 시점의 현행 모델**끼리 — 각 항목의 출시일을 확인한다. 글의 순위·게시일이 최신의 근거가 아니다.
5. 답(차트면 제목)에 **기준 시점**을 밝힌다.

사례 정답(모델명)은 넣지 않는다(§2). 날짜 블록 바로 뒤, 검색 턴에만. 공통으로 넣고 GPT 는 회귀만 본다.
