## 1. 배경

- 일반 발화(router · generator · vision · langchain-path · law · drug · summarize-title)는 전부 [`getNextApiKey()`](../../server/config.ts) 로 **무료 키 12개**(`API_KEY`..`API_KEY12`)를 돌린다.
- 무료 티어는 429·20~30s 지연이 반복된다(3.5 측정 기록). 응답 지연 변동의 상당 부분이 코드가 아니라 키 쪽이다.
- 유료 키 `API_KEY_TIER1` 은 지금 TTS 만 쓴다(`TTS_USE_TIER1=true`). 프로젝트는 Tier 2 로 올랐고 **이름은 `TIER1` 그대로 둔다**(2026-10-04 결정).
  `^API_KEY\d*$` 에 걸리지 않아 무료 풀에 섞이지 않는다.

## 2. 결정 (2026-10-04)

| 대상 | 키 순서 | 전부 실패하면 |
|---|---|---|
| **게스트** | 무료 키 로테이션 (현행) | 현행 안내. **유료로 넘기지 않는다** |
| **회원** | **유료 키 1회 → 실패 시 무료 로테이션** | 현행 안내 |

| TTS | 유료 (현행) | OpenAI 폴백 (현행) |

**근거**
- 유료 키는 **토큰을 검증한 회원에게만** 열린다 — TTS 와 같은 원칙. 무인증 경로에 유료 키를 열면 누구나 소진할 수 있다.
- 회원 트래픽이 빠지면 무료 12개를 게스트만 쓰므로 게스트 품질은 나빠지지 않는다.
- 회원도 유료 실패 시 무료로 내려가므로 유료 키 장애가 서비스 중단이 되지 않는다.

## 3. 설계

### 3-1. 요청 단위 tier — `AsyncLocalStorage`

호출처가 16곳(재시도 루프 포함)이라 인자로 tier 를 내리면 그래프 상태·노드 시그니처가 전부 바뀐다. 대신 요청 범위 컨텍스트를 쓴다.

```ts
// server/key-tier.ts (신규)
const store = new AsyncLocalStorage<{ tier: 'paid-first' | 'free'; paidTried: boolean }>();
export const runWithKeyTier = (tier, fn) => store.run({ tier, paidTried: false }, fn);
```

`getNextApiKey()` 는 시그니처를 바꾸지 않는다:
1. 컨텍스트가 `paid-first` · `GEMINI_PAID_FIRST=true` · 유료 키 존재 · 쿨다운 아님 · **이 요청에서 아직 안 씀** → 유료 키 반환, `paidTried=true`
2. 그 외 → 현행 무료 로테이션

**재시도 루프가 그대로 무료로 내려간다** — 기존 루프는 실패하면 `getNextApiKey()` 를 다시 부르므로 두 번째부터 무료 키를 받는다. 호출처 수정 0.

> ⚖️ "요청당 유료 1회" 는 너무 보수적일 수 있다 — 한 턴에 router + generator 두 번 부르면 generator 는 무료로 간다.
> **노드당 1회**(router · generator 각각 유료 먼저)가 의도에 맞다. 구현: `paidTried` 를 플래그 대신 "직전 호출이 실패해 재시도 중인가" 로 판정 —
> 실패 시 `markKeyRateLimited(paidKey)` 가 이미 쿨다운을 걸므로 **쿨다운 확인만으로 충분**할 가능성이 크다. 측정(4-2)에서 결정.

### 3-2. 진입점

- [`app/api/chat/route.ts`](../../app/api/chat/route.ts) 는 이미 `profiles.is_guest` 를 조회한다 → `is_guest === false` 면 `runWithKeyTier('paid-first', …)`.
- 🔴 **스트리밍 주의:** 그래프 실행이 `ReadableStream` 의 `start/pull` 안에서 돌면 ALS 컨텍스트가 이어지는지 확인해야 한다. 끊기면 조용히 무료로 돌아간다(안전한 쪽 실패) — 로그로 검증.
- 무인증 라우트·TTS 는 감싸지 않는다 → 기본 `free`. TTS 는 기존 `TTS_USE_TIER1` 경로 유지.

### 3-3. 쿨다운

유료 키도 기존 `markKeyRateLimited` / `markKeyDailyExhausted` / `markKeyInvalid` 맵을 그대로 쓴다(키 문자열 기준이라 별도 맵 불필요).
**TTS 와 공유된다** — 채팅이 유료 키를 429 로 쿨다운시키면 TTS 의 Gemini 도 쉰다. TTS 는 OpenAI 폴백이 있어 허용.

### 3-4. 안전장치

1. **`GEMINI_PAID_FIRST`** (기본 off) — 끄면 현행과 바이트 동일. 비용이 튀면 배포 없이 끈다.
2. **Google Cloud 예산 알림·상한** — TTS 와 같은 프로젝트. 🔴 켜기 전 필수.
3. **로그** — 호출마다 `key=paid|free#n` (키 값은 출력 금지).
4. **회원 일일 상한** — 지금은 두지 않는다. 비용 로그를 보고 필요하면 TTS 처럼 RPC 로.

**결론 → 설계 수정**
1. 유료 우선의 가치는 **검색 강등 해제**에 있다. 따라서 §3-1 의 "호출처 수정 0" 은 성립하지 않는다 — generator 의 강등 판단(`needsSearchFallback`)이 **이번 호출 키가 유료인가**를 알아야 한다.
   유료 실패 → 무료로 내려갈 때는 **모델도 2.5 로 같이 내린다**(무료 + 3.x 검색 = 즉시 429).
2. 플래그는 뒤집지 않는다 — 과금 축(`freeTierSearch`)만 유료 키일 때 무시, 품질 축(`groundingReliable`)은 그대로.
3. 다음 측정: 유료 키로 3.6·3.7 검색 **정답률**(어려운 문항, [3.8 계획 §8](PLAN_MODEL_3_8_MIGRATION_260906.md) 과 합침) → `groundingReliable` 재판정.

- **3.6 의 `groundingReliable=false`(과거 2/5) 는 09-22 에 이어 두 번째로 재현되지 않았다.** 이번엔 판별력이 있는 문항으로.
- 부수 확인: KBO 10/3 순위(KT·삼성·LG·KIA·두산)는 세 모델이 각자 검색해 같은 5팀을 냈다 — 사용자가 붙인 출처 링크의 날짜 파라미터(0804)가 의심스러웠던 점을 일부 보강한다(순서는 채점 안 함).

**판정 (사전 등록 기준 적용):** 3.6·3.7 모두 정답 ≥ 2.5 이고 `citedWrong` 0 ≤ 0 → **`groundingReliable=true` 근거 충족.**
한계: n=21(문항 7 × 3라운드), 한국어·수치형 위주. 판정은 **유료 키일 때 3.x 검색 허용**까지만 지지한다 — 무료 키는 여전히 429 라 2.5 강등이 유지된다.

**다음:** §6 결론대로 강등 판단에 키 종류를 연결한다 — `freeTierSearch` 는 유료 키일 때 무시, 3.6 `groundingReliable` 은 `true` 로(별도 커밋, 이 측정을 근거로 링크).
