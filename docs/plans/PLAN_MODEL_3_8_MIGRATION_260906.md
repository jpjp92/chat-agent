## 1. 목표와 현재 상태

목표는 일반 대화·도구 호출·긴 대화의 품질과 응답 속도를 개선하면서, 실제 요청 비용과 실패율을 통제하는 것이다.
새 버전이라는 이유만으로 기본 모델을 교체하지 않는다.

| 역할 | 현재 코드 | 이번 계획 |
|---|---|---|
| 기본 채팅 | 3.6 Flash — 서버·클라이언트 각각 기본값 존재 | 3.8을 선택 옵션으로 검증한 뒤 별도 승격 판단 |
| Gemini 선택 옵션 | 3.7·3.6·3.5·2.5 | 검증된 3.8 추가. 기존 저장된 선택값은 유지 |
| 의도 분류 router | 2.5 Flash (`ROUTER_MODEL`) | 초기 도입에서는 유지. 생성 모델과 별도 평가 |
| 제목 요약 | 2.5 Flash Lite → 2.5 Flash | 이번 모델 전환과 분리 |
| 음성 생성 | 별도 TTS 모델 | 이번 모델 전환과 분리 |
| 검색·업로드 등 fallback | 모델 능력·경로에 따라 2.5 | 3.8에서 통과한 경로만 점진적으로 해제 |

근거: [서버 모델](../../server/models.ts), [UI 모델](../../src/lib/models.ts),
[thinking 표](../../server/model-thinking.ts). 기존 멀티 공급자 계획의 목표 그림에는 router가
Flash Lite로 남아 있지만 현재 코드는 Flash다. GPT router 독립화는 [별도 계획](PLAN_MULTI_PROVIDER_ROUTING_260823.md)이다.

## 3. 하드닝과 함께 진행하는 순서

| 단계 | 작업 | 선행 조건·완료 기준 |
|---|---|---|
| A | 3.8 검증 설계·오프라인 하니스 준비 | 지금 가능. 공식 사양과 미검증 능력을 구분하고, 현재 프로덕션 함수·프롬프트를 사용하는 프로브를 준비한다 |
| B | 제한된 라이브 비교 | 사용할 프로젝트·무료/유료 키 구분, 호출 횟수·출력 토큰·총비용 상한을 실행 전에 고정한다. 실패 키 전부 순회로 측정량을 늘리지 않는다 |
| C | 3.8 선택 옵션 추가·dev 검증 | B의 필수 계약 통과 후 적용. 공개 적용은 [하드닝 §6](PLAN_HARDENING_260822.md#6-작업-순서)의 1·2 완료 후로 둔다. 기본은 3.6 유지 |
| D | 기본 모델 승격 판단 | 실제 생성 모델·fallback 비율·비용·긴 히스토리 결과를 비교해 3.8/3.7/3.6 중 결정. 서버와 클라이언트 기본값을 함께 변경 |
| E | router·검색·미디어 최적화 | C·D와 별도 변경으로 평가. 필요한 경로의 fallback만 해제하고 공급자 router 독립화와도 배포를 분리 |

하드닝 1은 두 무인증 LLM 라우트의 실제 토큰 검증과 기능별 제한, 2는 게스트 저장 실패 시 생성 중단이다.
이는 모델 도입 전에 우선 처리할 최소 비용 방어이며, 동시 요청·계정 생성 우회까지 해결됐다는 뜻은 아니다.
모델 검증 때문에 SSRF·남은 비용 라우트 보호·원자적 쿼터 작업을 미루지 않는다.
전체 하드닝 완료를 로컬 모델 조사·측정의 선행 조건으로 삼을 필요도 없다.
기존 main 환경 교정과 인증 컷오버 배포 조건은 그대로 적용한다.

## 4. 측정 설계와 통과 기준

같은 질문·히스토리·출력 상한·도구·티어 조건에서 3.6/3.7/3.8을 비교한다.
모델별 지원 하한 thinking을 명시하고, 3.8 medium은 low 대비 품질 개선이 필요한 표본에만 추가한다.
모델 실행 순서를 교차해 시간대 혼잡을 한 모델의 특성으로 오인하지 않는다.

| 검증 축 | 필수 표본·관찰 |
|---|---|
| 일반 대화 | 한국어 설명·코드·수식, 첫 토큰 시간·완료 시간·빈 응답 |
| 긴 입력 | 긴 URL 본문과 첨부 없는 10턴 이상 히스토리를 별도로 측정 |
| 렌더러 | 현재 등록된 렌더러 전체의 실제 프롬프트, JSON 파싱·필수 필드·실제 화면 표시 |
| 도구·카드 | 로컬 도구 호출 인자, 논문 주제 관련성·DOI/PMID·인용, 카드 후속 질문·무관한 새 질문 |
| 검색 | 검색 발동 여부와 답변의 사실 일치를 각각 채점. 출처 메타데이터만 있으면 통과시키지 않는다 |
| 미디어 | inline 이미지·PDF, Storage URL PDF/영상/오디오, YouTube. 큰 파일과 작은 파일을 모두 포함 |
| 오류 복구 | 429·503·timeout·빈 출력, 재시도 횟수와 전체 시간, 최소 thinking 재시도·모델 강등 |
| UI·상태 | 모바일/데스크톱 4개 언어 모델 선택, 저장된 기존 모델, 새 세션·기존 세션·재시도 |

1차는 각 필수 사례 3회로 명백한 호환성 결함을 찾고, 통과한 후보만 2차 반복 비교로 확대한다.
3회 성공을 낮은 실패율의 증명으로 쓰지 않는다. 성공 건수/전체 건수와 실패 원인을 함께 남긴다.
비용과 시간은 공급자 단독 호출 및 앱 종단 경로를 구분하고, 표본이 작으면 p95 대신 개별 값·중앙값·최댓값을 적는다.

- **C 진입:** 지원하지 않는 옵션 400, 빈 응답/JSON 파손, 잘못된 도구 인자 등 재현 가능한 필수 계약 위반이 없어야 한다.
  미통과 미디어/검색 경로는 검증된 fallback으로 성공하는지 확인한다.
- **D 진입:** 긴 히스토리 포함 반복 비교에서 현재 기본 대비 품질·실패율 악화가 관찰되지 않고,
  속도나 품질 개선이 확인되어야 한다. 허용 가능한 비용·지연 증가폭은 2차 측정 전에 정한다.
  기준이 미정이거나 표본이 부족하면 선택 옵션 단계에 머문다.
- 선택은 3.8인데 대부분 2.5가 응답한 결과를 3.8의 성능으로 기록하지 않는다.
  선택 모델·실제 모델·전환 이유·재시도 수·사용량을 기록하되 키·원문 민감정보는 로그에서 제외한다.

  기본값 승격은 별도 변경으로 하고 기존 모델의 저장값 해석은 유지한다.

  기존 모델의 계약을 보존하면서 3.8 사례를 추가한다. 전체 검증은 `npm run verify`.
- SDK 버전은 현재 설치본의 호환성을 먼저 확인하고 필요한 경우만 올린다.
  모델 도입을 Interactions API 등 호출 구조 전면 교체와 묶지 않는다.

## 6. 공개 적용과 롤백

선택 옵션 공개와 기본 승격은 분리한다. 3.8 기본 승격 시 3.6 기본값으로 되돌리는 변경을 준비한다.
서버·클라이언트 양쪽 기본값을 되돌려도 사용자가 저장한 3.8 선택은 남으므로,
3.8 자체 장애 때는 신규 선택 차단과 기존 저장값의 명시적 대체 정책까지 별도로 적용한다.
3.8 선택이 살아 있는 동안 capability/thinking 지원만 제거하지 않는다.
실제 모델과 fallback 이유를 확인해 장애가 router·생성·도구·공급자 중 어디서 발생했는지 구분한다.
