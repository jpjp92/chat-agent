## 2. 판단에 영향을 주는 점

1. **가격 차이는 기한이 있다.** 지금 Hydrogen 은 3.8 Flash 의 2배지만, 3.8·3.6 이 2027-01-01 에 같은 값으로 오른다. 그 뒤에는 "같은 가격의 상위 모델". 🔴 별건으로, **기본 모델(3.6)의 비용이 1월에 2배**가 된다 — Hydrogen 과 무관하게 비용 계획에 반영.
2. **기본 thinking 이 `high`.** 설정 없이 부르면 첫 토큰이 늦고 thinking 토큰이 과금된다. 넣는다면 [model-thinking.ts](../../server/model-thinking.ts) 표에 등록해 `low` 를 명시해야 한다(미등록 모델은 budget 경로로 가서 틀린 값이 조용히 적용된다).
3. **검색 테스트는 공용 월 한도를 깎는다** — 호출 수를 작게.
4. 화면의 한도는 처리량 보장이 아니다(공식 문서) — 실제 지연·오류율은 측정으로 본다.

## 6. 결과(11-15) — 0·1단계

실행: 유료 키, 합성 질문만. 스모크 9회 + A/B 30회, **실비 약 $0.09**(A/B $0.084). 스크립트 [probe-hydrogen-ab.mts](../../tests/manual/probe-hydrogen-ab.mts).

| `low`·`medium`·`high` | 정상. `low` 1.6s · 기본(`high`) 3.3s |

**1단계 A/B** — 한국어 질문 10개(논리·속력 계산·역사 함정·연결어미 뉘앙스·요약·코드·JSON 형식·물통 문제·맞춤법·배트와 공), temperature 0, 스트리밍.

| 구성 | 오류 | TTFT p50 / p90 | 전체 p50 / p90 | thinking 평균 | 10문항 비용(지금) | (1월~) |
|---|---|---|---|---|---|---|
| 3.8 Flash `low` | 0 | 2.5s / 3.8s | 3.2s / 5.8s | 0 | $0.0066 | $0.0133 |
| Hydrogen `low` | 0 | 3.2s / 4.4s | 4.1s / 13.7s | 260 | $0.0341 | $0.0341 |
| Hydrogen `medium` | 0 | 3.2s / 7.7s | 3.9s / 9.7s | 389 | $0.0434 | $0.0434 |

**품질(답 본문을 읽고 채점)**
- 정답이 있는 7문항(논리·속력·함정·물통·맞춤법·배트와 공·JSON 형식): **세 구성 모두 7/7**. 함정 질문(세종대왕·맥북)은 셋 다 허구라고 답했다.
- 요약·코드·뉘앙스: 셋 다 요구를 지켰다. Hydrogen 이 뉘앙스 설명에서 예문 풀이가 조금 더 자세한 정도.
- 3.8 의 잔실수 1건: 속력 문제에서 최종 값(66.32km/h)과 풀이는 맞는데 머리말에 틀린 분수(450/7)를 같이 적었다.

**판단**
1. **이 평가셋에서는 품질 차이가 없다** — 문항이 쉬워 세 구성 모두 천장에 닿았다. Hydrogen 이 더 낫다는 근거가 나오지 않았다.
2. **더 느리다** — 첫 글자까지 중앙값 +0.7s. `medium` 은 p90 이 7.7s 로 튄다. Hydrogen `low` 의 전체 p90 13.7s 는 한 건(코드 문항에서 스트림 꼬리가 멈춤)이라 표본이 더 있어야 판단 가능.
3. **더 비싸다** — 지금 약 5배. 1월 가격 인상 뒤에도 **약 2.6배**: 단가는 같아지지만 Hydrogen 은 끌 수 없는 thinking 토큰(문항당 평균 260~390)이 출력 단가로 붙는다. 짧은 답일수록 이 비중이 크다.
4. 3.8 `low` 는 thinking 토큰이 0 으로 보고됐다 — 쉬운 질문에선 생각을 건너뛴다. Hydrogen `low` 는 0~433 으로 들쭉날쭉.

**결정** — 계획의 조건("품질 차이가 보일 때만 확대")에 따라 **2단계(호환성)·`high`·장기 멀티턴으로 확대하지 않는다.** 선택 목록·기본 모델 변경 없음.

**다시 볼 조건**
- 어려운 평가셋(다단계 추론·긴 문맥·검색 근거 반영)에서 3.8 이 틀리는 문항이 모였을 때 — 그 문항으로 재비교. 지금 셋으로는 변별이 안 된다.
- 사용자가 "더 똑똑한 모델" 선택지를 원할 때 — 기본이 아니라 선택 옵션으로(비용은 회원 한도와 같이 본다, [PLAN_PRODUCTION_READINESS_261115](PLAN_PRODUCTION_READINESS_261115.md) A3).
- 표본 주의: 구성당 10건·1회 실행이다. 지연 수치는 경향만 본다.

## 7. thinking 을 끄는 방법 조사(11-15) — 안정적인 방법 없음

"끄는 방법이 따로 있는 것 아닌가" 를 문서와 실호출로 확인했다. 유료 30회(변형 16 + 10문항 재실행 10 + 진단 4), 약 $0.03. 스크립트 [probe-hydrogen-thinking-off.mts](../../tests/manual/probe-hydrogen-thinking-off.mts).

**문서** — thinking 가이드·모델 페이지에 Hydrogen 의 끄기 옵션이 없다. 최저 레벨은 `low`("Fewest tokens, lowest latency"), `minimal` 은 "Not supported on Gemini 4 models or `gemini-3.8-flash`". `thinkingBudget` 은 문서에 나오지 않는다. 기본이 Off 인 모델은 `gemini-2.5-flash-lite` 뿐.

**설정 변형**(질문 2개씩)

| 설정 | 결과 |
|---|---|
| `thinkingLevel: low`(기준) | thinking 227 · 97 |
| `low` + `thinkingBudget: 0` | 400 — 둘을 같이 못 준다 |
| `thinkingLevel: 'none'` · `'off'` | 400 — 없는 값 |
| `low` + `includeThoughts: false` | thinking 0 · 56 — 효과 없음(요약 표시 여부일 뿐) |
| `low` + `temperature: 0` | thinking 251 · 73 — 효과 없음 |
| `thinkingBudget: 0` 단독 | 수용하지만 thinking 186(§6) — 무시된다 |
| `low` + **지시문 "생각 과정 없이 곧바로 답한다"** | thinking 0 · 0 ← 유일하게 0 이 된 조합 |

**지시문 방식을 10문항으로 재확인** — thinking 은 10문항 모두 0. 그러나 **4문항(논리·함정·뉘앙스·물통)의 답이 비었다**(출력 0 토큰, 6~13초 대기).
- 진단: 빈 응답의 종료 사유가 `MALFORMED_RESPONSE`. 출력 상한(2048)을 빼도 같다 — 상한 문제가 아니다.
- 같은 질문이 실행마다 갈린다: 물통 문제는 한 번은 thinking 275 로 정상 답, 한 번은 `MALFORMED_RESPONSE`.
- 즉 지시문은 thinking 을 끄는 게 아니라 **모델이 생각이 필요한 질문에서 응답을 못 만들게** 한다. 답이 나온 6문항(계산·요약·코드·형식·맞춤법·배트와 공)은 생각 없이도 풀리는 것들이었다.

**결론**
- Hydrogen 의 thinking 을 안정적으로 끄는 방법은 **없다**. API 스위치가 없고, 지시문은 40% 가 빈 응답이라 쓸 수 없다.
- 쓸 수 있는 최저는 `low` 다 — 쉬운 질문에선 모델이 알아서 0 으로 건너뛰기도 한다(§6 뉘앙스 문항 0). 평균은 문항당 약 260 토큰.
- §6 의 판단(도입 보류)은 그대로다. 비용 격차(1월 뒤 약 2.6배)는 thinking 토큰 때문이고 이를 없앨 수단이 없다.
- 우리 코드에 넣게 되면: [model-thinking.ts](../../server/model-thinking.ts) 에 `levels: ['low','medium','high']`, `budget: false`(0 을 줘도 무시되고 level 과 같이 주면 400). 빈 응답은 generator 의 `empty` 재시도가 받는다.

## 8. 활용 방안(11-15 검토) — 전제: 어려운 질문에서 차이가 확인될 때

지금까지는 Hydrogen 이 3.8 보다 정확하다는 근거가 없다(§6). 아래는 그 근거가 생긴다는 전제의 후보다.

| 용도 | 판단 | 이유 |
|---|---|---|
| 라우터·대화 제목 | ❌ | 매 턴 맨 앞의 분류 작업 — 생각이 필요 없고 지연이 그대로 체감된다 |
| 기본 채팅 모델 | ❌ | 쉬운 질문은 품질 동률인데 느리고 비싸다 |
| 카드형 답변(날씨·약국·영화) | ❌ | 도구 결과를 보여 주는 턴이라 추론할 게 없다 |
| **회원용 "깊이 생각" 선택 옵션** | 후보 ① | 사용자가 느려도 되는 질문에 직접 고른다. 선행: 회원 호출 한도([PLAN_PRODUCTION_READINESS_261115](PLAN_PRODUCTION_READINESS_261115.md) A3) |
| 어려운 의도에만 자동 적용(법률 해석·의학·긴 문서·계산 섞인 차트) | 후보 ② | 근거 없음 + "고른 모델을 유지한다" 원칙과 충돌 |
| 오프라인 평가·채점(골든셋 판정, 답의 사실 오류 찾기) | 후보 ③ | 서비스 경로 밖이라 위험이 가장 낮다. `high`·`xhigh` 를 써도 된다. 판정자 정확도는 따로 검증 |

**다음 단계(급하지 않음 — 공개 전 필수 항목 뒤)**
1. 어려운 평가셋 20문항 — 다단계 추론·긴 문서 질의·검색 결과 종합·조건이 많은 법률/의학. 3.8 이 틀리는 문항이 섞여 있어야 변별된다. 이 셋은 1월 가격 인상 뒤 기본 모델 재선정에도 쓴다.
2. 3.8 `low` / Hydrogen `low`·`high` 비교(60회, `high` 의 thinking 때문에 $1 안팎 — 실행 전 재계산·승인).
3. 차이가 있으면 ① 로, 없으면 ③ 으로만 남긴다.
