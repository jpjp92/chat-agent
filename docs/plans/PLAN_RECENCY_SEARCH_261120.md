## 3. 개선안 — `[RECENCY]` 규칙

최신·최근·요즘·현재·라인업 질문(검색이 켜진 턴)에만:
1. 검색어에 현재 연·월을 넣는다(날짜 블록에서).
2. 출처별 게시일·발표일을 확인하고 가장 최근 출처로 답을 세운다 — 검색 순위는 최신의 근거가 아니다.
3. 검색 결과(날짜 있는)와 기억이 다르면 검색 결과가 이긴다.
4. 제품 라인업·출시는 공식 출처(벤더 블로그·문서) 우선 — 차트 1차 출처 원칙(11-06)과 같은 방향.
5. 답에 기준 날짜를 한 구절로 밝힌다("11월 18일 발표 기준").
6. (코드) 사용자 정정("오래된 거 아냐?", "틀렸는데") 턴은 `followup-guard` 예외로 재검색 — 원인 5 확인 뒤.

붙이는 자리(안): 검색 턴의 시스템 지시(날짜 블록 바로 뒤). 비검색 턴에는 넣지 않는다(토큰·지시 충돌).

**읽은 것**

2. **규칙의 효과는 "근거를 드러내는 쪽"** — Gemini 기준 날짜 명시 17 → 26, 검색어 연월 8 → 14(GPT 17 → 28). 정답률은 이미 천장이라 차이 없음. 지연 +0.5s 안팎.
3. **새 원인 — 검색어에 기억 속 버전 번호가 들어간다.** Gemini 라인업 질문 10회 중 다수가 `"Gemini 1.5 2.0 Flash Pro"`·`"2.5 3.0"` 같은 검색어를 만들었다(규칙 팔도 남음). 그 버전의 옛 글이 걸려 답이 끌려가는 경로로 보인다 → §3 에 "최신을 물을 때 기억 속 버전 번호를 검색어에 넣지 않는다" 추가 후보.

## 6. 정정 턴 재검색 — 확인·수정 (11-20)

> 🔴 **정정(같은 날)**: 처음 돌린 프로브는 `.env.local` 을 싣지 않아 **라우터 LLM 이 한 번도 호출되지 않았다**(`Loaded 0 Gemini API keys` → gray 판정이 default-on). 그 결과로 적었던 "오래된 모델인데? 는 원래 검색 on", "en·es·fr 가공 요청도 매번 재검색" 은 **둘 다 틀렸다**. 아래는 env 를 싣고 유료 키로 다시 잰 값이다. 프로브는 이제 env 를 싣고, 칸마다 `from=router`(LLM 판정) 를 찍고, 변형이 한 번도 안 걸리면 실패한다.

|---|---|---|

- **가드 수정은 유효** — "그거 옛날 정보 아니야?" 는 라우터가 on 을 내는데 `followup-guard` 가 덮던 것(규칙 하니스 수정 전 1/4 → 4/4, 실호출 3/3 on). [intent-rules.ts](../../server/agent/intent-rules.ts) `STALE_CORRECTION_PATTERN`.

- 변형은 3문장 중 2개를 고친다. "오래된 모델인데?" 는 예시를 더해도 그대로 — 그 문장을 예시로 넣는 건 과적합이라 하지 않았다.
