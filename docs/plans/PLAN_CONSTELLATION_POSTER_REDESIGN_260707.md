## 2. 렌더 파이프라인 (프로토 로직)

```
IAU RA/Dec
   ↓ project(): 중심 기준 정적 투영 + 바운딩박스 자동맞춤
   ↓ [관측지 모드일 때만] skyOrientation(): field rotation 적용
   ↓ view transform: scale · rot · pan (두 모드 공통, 마지막 단계)
   ↓ draw: 배경 → 성운 → 필드별 → 연결선 → 별(헤일로+스파이크+코어) → 라벨(충돌회피)
```

### 2-1. 정적 투영 `project(stars, W, H)`
- 중심 = 별들의 RA/Dec 평균(centroid).
- `x = -((ra - cRA) * 15) * cos(cDec)`, `y = -(dec - cDec)` → **하늘 방향(RA 왼쪽 증가·북쪽 위)**.
- **바운딩박스 자동맞춤**: `padX = W*0.15`, `padY = H*0.19` → 별자리가 프레임 **~70%** 차지, 중앙 정렬.
- 좌표는 **절대 수정 안 함** — 화면 scale·centering만.

### 2-2. 관측지 모드 `skyOrientation(cRAh, cDec, date)`
- 지방항성시(LST) → 시간각(HA) → **시야회전각(parallactic angle q)** + 중심 고도(alt).
- 프레임 유지한 채 정적 차트를 `q`만큼 회전 → "지금 서울 하늘에서 실제로 기운 각도"를 보여줌.
- 힌트에 고도 표시, `alt<0`이면 `지평선 아래`.
- **주의**: 프로토는 방향(회전)만 시연하고 화면에 유지. **실제 프로덕션은 여기에 horizon culling(지평선 아래 별 숨김) + 비중앙 구도**가 추가됨(= 기존 `ConstellationRenderer`의 alt/az 경로).

### 2-3. 뷰 변환 `view = {scale, rot, px, py}`
- 파이프라인 **맨 끝 화면공간 변환** → 정적·관측지 **두 모드 자동 동일 동작**.
- 별 크기·글로우는 magnitude 기반이라 줌해도 일정.

### 2-4. 별·라벨
- `starColor(mag)`: 등급별 색온도(웜 골드 우세, 밝을수록 흰빛).
- `sizeFor(mag)`: 밝을수록 큰 코어.
- **헤일로**: 어두운 별일수록 축소(`mag<2.5→4.4 / <3.4→3.4 / else 2.6`) — 밀집 asterism(물병 물병 γζηπ) 뭉침 방지.
- **십자 스파이크**: `mag<3.0`만.
- **라벨 충돌 회피**: 밝은 별 우선, 상/하/우/좌 4방향 중 안 겹치는 위치 자동 선택, 측면 배치 시 **leader line**. 무명 별은 라벨 없음.

## 3. 인터랙션 / 크롬

| 요소 | 동작 |
|---|---|
| 언어바(KO/EN/ES/FR) | `applyLang()`가 타이틀·드롭다운·툴팁·호버 라벨·모드힌트 현지화 |
| 커스텀 드롭다운 | 포스터 골드 스타일(네이티브 select 대체), 별자리 전환 |
| 슬라이더 | 별 밝기 / 연결선 투명도 |
| 관측지 버튼(아이콘) | 정적 ↔ 관측지 토글 |
| 뷰 컨트롤(우측) | 줌 `+`/`−`, **회전(단일 버튼: 탭 +15°·드래그 자유회전)**, 초기화 `⌂` |
| 캔버스 제스처 | 휠 줌 · 드래그 팬 · 터치 1손가락 팬 / 2손가락 핀치+트위스트 |
| 호버 | 최종 화면 좌표 hit-test → 이름·등급·RA·DEC 패널 (**두 모드·줌·회전 무관**) |
| 스냅샷(⤓) | 타이틀을 캔버스에 **합성(bake)** 후 PNG. 파일명 `별자리명_YYYYMMDD.png`. 언어·뷰 상태 반영 |

**i18n 정책**: 별 지도 라벨 = 라틴명(만국 공통). 크롬 = `STR{ko,en,es,fr}`. RA/DEC = 유지.

## 4. GPT 피드백 검증 로그 (receiving-code-review 적용)

실좌표 계산으로 대조 후 유효/반려 판정:

| 피드백 | 판정 | 처리 |
|---|---|---|
| 사자자리 낫이 직선적 | ✅ 유효(원인=데이터) | η Leonis 추가 + 낫 선 순서 ε/μ 교정. **좌표 왜곡 아님** |
| 데네볼라 위로 / 체르탄 오른쪽아래로 | ❌ 천문 오류 | 반려 — 실좌표상 데네볼라는 조스마보다 아래, 체르탄은 동일 RA(수직) |
| 오리온 두 발 연결선 | 비표준 | 제거 |
| 물병 항아리 Y 약함·상단 겹침 | ✅ 부분 | 어두운 별 헤일로 축소로 판별성↑ (단 물병은 35°내 ~2° asterism이라 본질적 소형) |
| 물줄기 짧음 | ✅ | τ Aqr 노드 추가(ζ→λ→τ→δ→88) |
| 알발리 왼쪽으로 이동 | ❌ | 반려 — 실제 ~20° 서쪽. 자동맞춤이 중심정렬로 해결 |
| 별자리별 스케일 표(1.0/1.25…) | ❌ 중복 | 반려 — `project()` 바운딩박스 자동맞춤이 이미 일반 대응(임의 88개 확장). 수동 표는 열등 |
| 라벨 충돌 회피 + 방향 자동 | ✅ | 추가(실제 컴포넌트도 이미 4방향 충돌회피 보유) |
| Leader line | ✅ | 측면 라벨에 추가 |
| 채움 70~90% vs 물병은 70~75% | 모순 | 균일 ~70% 절충(별자리별 적응형 여백은 유보) |
| IAU 연결선 별도 JSON 분리 | 검토 | **아키텍처 갈림길**(§6) — 현행은 LLM이 좌표+선 동반 생성 |

## 6. 미결(스펙에서 결정)

- **LLM 생성 vs 큐레이션 IAU JSON**: 현행은 Gemini가 별+연결선 동반 생성(임의 별자리 대응·유지비 0, 단 품질 모델 의존 — 이번 η 누락·선 순서처럼). 대안은 좌표+토폴로지 정적 카탈로그(정확 보장, 단 수작업·임의요청 미대응). → 결정 필요.
- **별자리별 적응형 여백**(dense는 꽉·sprawling은 여유) — 복잡도 대비 이득 작아 유보.
- ~~**관측지 모드 프로덕션 거동**~~ → **결정됨**: 기존 alt/az 경로 유지(horizon culling 그대로). 프로토의 field-rotation 데모는 미이식. (DEV_260708 §3)
