## 1. 목표와 원칙

- **오식별 0 우선** — 잘못된 약을 "유력"으로 내놓지 않는다. 정답률은 그다음.
- **지연을 늘리지 않는다**(11-28 사용자 지시) — 추가 단계는 필요한 경우에만(조건부). 판정 강화는 받은 결과를 서버에서 거르는 방식 우선. 모든 요청에 붙는 호출(상위 비전 재분석·이미지 대조)은 측정 후에만.
- **결정론 경로 우선** — 각인 색인 검색(DB·약학정보원)으로 찾을 수 있는 건 거기서 끝낸다. LLM 웹 검색은 마지막 수단.

## 2. 근본 원인 (실사진 사례 1에서 확인)

각인으로 찾는 **결정론 경로가 사실상 끊겨 있어**, 느리고 회차마다 결과가 다른 LLM 웹 검색 하나에 정확도가 걸려 있다. 오늘 테스트마다 다른 버그로 보였던 것은 모두 이 위의 증상이다.

1. **로컬 DB 공백** — `mfds_pills` 는 각인 텍스트가 ~9% 품목에만 있고, 사례 1 약(위더스세픽스캡슐)은 품목 자체가 없다.
2. **약학정보원 각인 검색이 꺼져 있다**
   - 호출 조건이 "MFDS 0건" 인데 MFDS 색상·모양 단계가 거의 항상 뭔가를 내서 **불리지 않는다**(G10).
   - 불려도 `CFX` 1·2·3페이지가 **같은 5건** — 페이지 넘김이 안 된다. GPT 가 찾은 서울세픽심캡슐(`pharm.or.kr idx=56632`)도 그 5건에 없다. 데이터는 약학정보원에 있는데 우리 조회가 못 가져온다.
3. 그래서 **LLM 웹 검색이 유일 경로** — GPT 웹 검색 8~10.5s(실측 2회), 회차마다 후보가 다르다(1회차 1개·정답 없음, 2회차 5개·정답 포함).
4. 비전 로고 오독(`WU`/`UU`)은 부차적 — `CFX` 만으로 찾을 수 있었다.

## 5. 단계

### P0 — 결정론 각인 검색 복구 (G10) · 지연 개선
1. 약학정보원 페이지 넘김: 실제 사이트 요청(파라미터·세션)을 확인해 전체 결과를 가져온다.
2. 호출 조건 변경: **각인을 읽었고 MFDS 각인 단계(1·2단계)가 0건**이면 약학정보원을 돈다 — MFDS 색·모양 후보가 있어도.
3. 질의 변형 × 페이지 **순차 루프 → 병렬**, 페이지 상한. 목표 1~2s.
4. 약학정보원이 각인 일치 후보를 내면 웹 검색은 생략. 웹은 약학정보원에도 없을 때만.
5. `fetchPage` 가 HTTP 오류·타임아웃·파싱 실패를 모두 `[]` 로 삼킨다 → 셋을 구분해 로그(사이트 구조 변경을 0건으로 오인하지 않게).

완료 기준: 사례 1(`CFX`)이 약학정보원 단계에서 위더스 제품을 후보로 낸다 · 웹 검색 없이 · 결과가 회차마다 같다.

### P1 — 판독 · 표시 (G12·G13·G2·G3·G4)
1. **G12** 비전 규칙: 그림 로고는 글자로 읽지 않고 `마크`. 검색은 `마크` 를 각인 조건에서 빼고 문자 각인으로.
2. **G13** 후보 표에 등록 사진 썸네일(MFDS `item_image`, 약학정보원 썸네일) — 사용자가 로고를 비교. 추가 모델 호출 없음. 같은 문자 각인 후보가 여럿이면 "로고를 사진과 비교하세요" 안내.
3. 면별 상태 스키마(기존 `imprint_front/back` 은 호환용 유지):
```
front/back: { imprint: string | null
              status: readable | logo | no_imprint | unreadable | not_photographed
              alternatives: string[] }   // 헷갈리는 글자 대안, 최대 3
image_quality: good | partial | poor
```
   - `not_photographed` → 그 면은 검색 조건에서 뺀다.
   - 재촬영은 `poor` 이거나 식별에 결정적인 면이 `unreadable` 일 때만. `partial` 이어도 각인이 읽히면 검색.
4. 카드 판정(DB `match_type` 과 분리):

| 상황 | 사용자 상태 | 카드 |
|---|---|---|
| 읽은 면의 각인이 DB 행과 각각 일치 · 1건 | 유력 | O |
| 앞면만 촬영 · DB 1건 | 단일 후보 · 뒷면 미검증 | O + "뒷면 확인 필요" |
| 한쪽 각인 상충 / DB 에 한쪽 미등록 / 같은 각인 여러 제품 | 후보 여럿·근거 부족 | X |
| 색상·모양만 일치 | 참고 후보 | X |

### P2 — 측정 (G1·G7)
1. 평가 세트 20~30장(정답 확인분, 저장소 밖 로컬): 선명한 앞면 / 앞·뒷면 / 흐린 각인 / 흰색 원형 유사약 / MFDS 미등록 / 같은 문자 각인·다른 로고 / 약 아닌 사진.
2. 하니스 지표: 각인 판독 정확도 · 맞힌 단계(MFDS·약학정보원·웹) · Top-1/Top-3 · **잘못된 유력 후보 수** · False exact · 웹 실행률·불필요 웹 · 단계별 지연 P50/P95.
3. LangSmith span `pill.vision/mfds/pharm/web` — `{attempted, status, reason, candidateCount, elapsedMs}` 정형 값만. 각인 원문·이미지 미기록.
4. 실측은 유료 키, 시작 전 호출 수·비용을 먼저 적는다. 20~30장에서 오식별 0 은 회귀 발견용일 뿐 운영 오식별률이 아니다.

> P0 를 측정보다 앞에 둔 이유: 사례 1 하나로 근본 원인(결정론 경로 단절)이 재현 가능하게 확인됐고, 고치는 데 정답 세트가 필요 없다.

### P3 — 앞·뒷면 누적 · 상태 문구 (G5·G6)
1. 보존: 세션(메시지 메타)에 추출 특징만 저장 — 이미지 재전송·저장 없음.
2. 병합: 새 사진이 같은 약의 다른 면인지는 비전만으로 모른다 → "뒷면 사진인가요?" 확인 후 면별 병합·재검색. 확인 없이 교체하지 않는다.
3. 상태 4종(유력 / 후보 여럿 / 근거 부족 / 재촬영)을 표 문구로. 새 렌더러는 만들지 않는다.

### 보류 (P2 측정 후 결정)
- MFDS 각인 데이터 재수집·`pg_trgm` · 공식 이미지 자동 대조·이미지 임베딩(pgvector) · 각인 가중치 점수 · 상위 비전 모델 재분석 · 이미지 전처리·복수 알약 분리
- 웹 검색 모델 비교(GPT 8~10s vs Gemini grounding) — P0 후 웹 호출 빈도가 줄면 우선순위 낮음

앱 최종 확인(11-28 마지막 테스트): 제형 필터는 동작, **웹 후보 표는 안 나옴** — 원인 미확정(모델 검색 15s 초과 추정, 로그 미확인). P0 로 웹 의존을 줄이는 것이 근본 해결.

## 8. 바꾸지 않는 것
- 카드는 `exact` 에서만 — 웹·유사 결과로 카드를 만들지 않는다.
- 비전 confidence·임의 일치율을 사용자에게 보이지 않는다.
- 라우터·일반 생성 경로는 건드리지 않는다(약 식별 경로 안에서만).

## 9. 리스크
- **약학정보원 스크래핑**: 이용약관·자동 접근 범위 미확인인 채로 이미 쓰는 중이고, P0 에서 의존이 커진다. 구조가 바뀌면 조용히 0건 → P0-5 로그 구분 + "연속 0건" 경고.
- **웹 검색 비결정성**: 같은 질의도 회차마다 후보가 다르다 — 웹은 후보 제시까지만, 확정에 쓰지 않는다.
- 평가 사진에 처방전·개인정보가 섞이지 않게(세트는 저장소 밖).
