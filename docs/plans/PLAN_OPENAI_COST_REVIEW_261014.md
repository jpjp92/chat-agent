## 4. 개선 항목

### 4-1. 대량 실측의 웹 검색 반복 (테스트 비용)

- 30일 웹 검색 $2.90 중 **$1.83 이 실측 세 날**(9/23·9/28·10/13).
- 모킹은 답이 아니다 — 이 실측들은 **실제 검색 동작**을 재려는 것이라 모킹하면 측정 목적이 사라진다.
- 대신:
  - 1차는 질의당 1회만 돌리고, 차이가 보이는 질의만 반복한다.
  - 재확인 때는 이미 받은 검색 결과를 다시 쓰는 캐시 옵션을 프로브에 둔다.
  - 실측 계획에 예상 검색 횟수(= 예상 비용)를 적는다.

### 4-2. 프롬프트 캐시 — 시각 블록 (실사용 비용 구조)

- **원인**: [generator.ts](../../server/agent/nodes/generator.ts) 가 `[CURRENT_SYSTEM_TIME …]` 를 **분 단위**로 만들고, [prompt-assembly.ts](../../server/agent/prompt-assembly.ts) 가 시스템 프롬프트 **맨 앞**에 둔다.
  OpenAI 프롬프트 캐시는 앞부분이 같아야 재사용되므로, 분이 바뀔 때마다 뒤의 프롬프트 전체가 새로 캐시에 쓰인다.
- **수치**: gpt-6-luna 입력 7.9M 토큰 중 캐시 쓰기 4.2M($0.525), 캐시 읽기 1.7M. 이 단가에서 캐시 쓰기($0.125/1M)는 일반 입력($0.1/1M)보다 비싸 **다시 읽히지 않는 쓰기는 손해**다.
  대량 실측이 없는 10/14 에도 캐시 쓰기 $0.02 > 일반 입력 <$0.01 — 테스트가 아니라 구조 문제다.
- **제약**: 맨 앞 배치는 의도된 결정이다. 9/28 A/B 에서 끝으로 옮기자 "오늘 날짜" 정답이 4/7 → 0/7 로 떨어졌다([DEV_260928](../logs/2026/09/DEV_260928.md)). 단순 이동은 안 된다.
- **후보**:
  - ① 맨 앞에는 **날짜만** 둔다(시·분 제거) → 같은 날·같은 의도 요청끼리 캐시 적중. 영업 중 여부는 서버가 계산하므로 분 단위가 필요한 곳이 있는지 먼저 확인.
  - ② 시스템 프롬프트는 고정하고 시각만 별도 메시지로 → 위치가 바뀌므로 날짜 정확도 재실측 필요.
- 금액은 6주 $0.5 수준으로 작지만 사용자 수에 비례하고 응답 속도(TTFT)에도 영향이 있다.
