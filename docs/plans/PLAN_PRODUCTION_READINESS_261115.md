## 1. A6 상세 — 재시도 간격

- 지금: OpenAI 0.6s → 1.8s 고정. Gemini 는 키를 바꿔 즉시(대기 없음).
- 바꿀 것(OpenAI): 대기에 ±30% 무작위 편차, 응답에 `Retry-After`(초)가 있으면 그 값(상한 5s)을 쓴다. 상한을 넘는 값이면 재시도하지 않고 바로 오류 — 사용자를 오래 붙잡지 않는다.
- Gemini 는 키 교체가 곧 분산이라 그대로 둔다.
- 검증: `test-retry-reasons` 에 `Retry-After` 주입 케이스.

## 2. B1 상세 — 알림 최소판

- 재료는 이미 있다: `[turn]` 의 `outcome`·`errCode`·`retryReasons`·`routerRetries`·`intentFrom`·`ms`·`routerMs`·`saveMs`, `[save]`, `[process]`.
- 필요한 것: 수집(Vercel 로그 드레인 → 로그 서비스) + 규칙 3개.
  1. 5분 오류율(`outcome=error` 비율) 5% 초과
  2. `intentFrom=rule` 비율 급증(라우터 LLM 장애 신호)
  3. p95 `ms` 20초 초과
- `[process]`·`[save]` 는 한 줄이라도 찍히면 알림(정상이면 0줄).
- 로그에는 사용자 내용·식별자가 없으므로 외부 수집에 그대로 내보낼 수 있다. 다만 `traceId` 는 DB 와 이어지는 값이라 수집처 접근 권한은 좁게.
- 드레인은 Vercel 요금제 조건을 먼저 확인한다(무료 플랜에서 안 될 수 있다) — 안 되면 대안은 route 가 `[turn]` 을 직접 내보내는 것.

## 3. C1 상세 — 턴 예산

- 지금 상한: 라우터 5s × 2, Gemini 일반 25s·무거운 미디어 90s(시도마다), OpenAI 120s(호출당) + 재시도, 함수 300s.
- 방향: POST 시작에 마감 시각을 정하고(`deadline`), 각 단계가 `남은 시간 < 그 단계 최소 필요 시간` 이면 재시도 대신 바로 오류로. 값은 공개 뒤 `ms` 분포로.
- 주의: 무거운 미디어(영상 30~48s 정상)는 예산이 달라야 한다 — 일률 적용 금지(호출 상한을 25s 로 일률 적용해 YouTube 분석이 끊긴 회귀가 있었다).
