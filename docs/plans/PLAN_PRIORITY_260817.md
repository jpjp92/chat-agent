### 0-3 이 왜 틀린 항목이었나 — 정책이 이미지 경로에 없다

원래 적은 것: *"8/17 이전 첨부 세션에서 이미지가 깨지면 SELECT 정책 롤백"*.
**이 테스트는 실패할 수 없다.** 이미지는 RLS 를 타지 않는다.

```
create-signed-url:35   getPublicUrl(filePath)        ← 공개 URL 을 만들어
chat/route.ts:137      attachment_url: storageUrl    ← DB 에 그대로 박고
useChatSessions.ts:89  data: attachmentUrl           ← <img src> 로 그대로 쓴다
```

`/storage/v1/object/**public**/chat-imgs/…` 는 공개 버킷의 익명 엔드포인트다.
인증 클라이언트의 `download()` 가 아니라 **평범한 HTTP GET** 이라 RLS 평가 자체가 없다.
레거시 이미지가 보이는 이유는 정책 예외가 아니라 **버킷이 공개라서**다 —
정책을 롤백하든 말든 결과가 같다. **판정 기준이 성립하지 않는다.**

RLS 가 실제로 걸리는 유일한 곳은 [`parse-document/route.ts:108`](../../app/api/parse-document/route.ts#L108)
의 user-scoped `download()` 인데, 그 위 `STORAGE_PATH_RE`(:29)가 **uid 세그먼트를 필수**로
요구해서 레거시 평면 경로는 RLS 에 닿기도 전에 400 이다. 게다가 이 라우트는 업로드 시점에만
불린다(세션 재진입 때 옛 문서를 다시 파싱하지 않는다). → **실사용 회귀 경로가 없다.**
정책의 `is null` 레거시 예외는 현재 **어느 경로도 태우지 않는 죽은 조항**이다.

> 🔴 **교훈: 롤백 기준을 적을 때 그 기준이 걸리는 경로를 먼저 읽는다.**
> 이 항목은 "SELECT 정책이 이미지 읽기에 관여한다"를 **가정**하고 최우선으로 올려뒀다.
> 확인은 5분이었는데 하지 않았다. **틀린 기준은 없는 기준보다 나쁘다** — 통과해도
> 아무것도 보장하지 않으면서 다른 항목을 밀어냈다.

> ⚠️ **Phase 2 때 되살아난다.** 버킷을 비공개로 돌리는 순간 이미지 읽기가 RLS 를 타기
> 시작하고, 그때는 레거시 예외가 **실제로** 필요해진다. `attachment_url` 에 박힌 공개 URL
> 백필도 함께 → [5순위 §5-1](#5순위--phase-2-비공개-버킷-이관).

> 부수 소득: 대응표는 **글피까지만** 주는데 모델이 8/26(다음 주 수요일)을 정확히 뽑았다.

### 5-4. 🔴 적재 스크립트 버그 — 약품 3,000건이 빠져 있었다 (2026-08-17)

1차 적재가 **22,359행**에서 멈춰 API 총계 25,362 와 3,003(11.8%) 차이가 났다.
`item_seq` 가 PK 라 "API 중복이겠지"로 넘길 뻔했는데 **버그였다.**

```
완료: 22,362건 저장, 3,000건 오류
  upsert 오류: ON CONFLICT DO UPDATE command cannot affect row a second time   × 6회
```

**3,000 = 500 × 6.** Postgres 는 한 `INSERT … ON CONFLICT` 안에 같은 키가 두 번 나오면
**그 문장 전체를 거부한다.** `flush()` 가 500건씩 보내는데 그 안에 중복이 **하나만 있어도
정상 499건이 같이 날아갔다.** 재실행마다 배치 경계가 달라져 **어느 약이 빠지는지가 매번 바뀌었다**
(22,359 ↔ 22,362) — 그래서 "대충 맞네"로 보였다.

**수정**(`docs/guide/db/sync-mfds-pills.mjs` `flush()`): 배치 **안**만 `Map` 으로 접는다.
배치 **간** 중복은 손대지 않는다 — upsert 가 정상 처리한다.

수정 후: **25,351건 저장 · 오류 0 · 배치내중복 11 → 최종 25,345행.**
25,362 = 25,345(고유) + 11(배치내) + 6(배치간) — **차이가 전부 설명된다.**
**약품 2,986건 복구.** 이 약들은 사진으로 물어도 1순위 DB 가 못 찾던 것들이다.

### 🔴 0-B 의 지시를 정정한다 — **삭제가 아니라 교체**

`url_cache` 는 **RLS 를 켜되 정책을 두지 않는다**(→ `service_role` 만 통과). 이유:

- 유저 데이터가 아니라 **공유 캐시**라 `auth.uid()` 로 나눌 수가 없다
- anon/authenticated 에 INSERT 를 열면 **캐시 오염**이 된다 — 임의 `url_key` 에 원하는 본문을
  심어두면 앱이 그걸 "페이지 원문"으로 믿고 모델에 주입한다. **간접 프롬프트 인젝션 경로**다
- RLS 를 아예 끄면 더 나쁘다. anon 키는 **브라우저 번들에 있는 공개 값**이다

따라서 이 라우트는 서비스 키가 **필요하다**. [PLAN_INDEX 0-B](PLAN_INDEX.md) 가 키 삭제를 지시하는
본래 이유는 *"스테이징 값이 main 에 들어갔다"* 이므로 **삭제가 아니라 프로덕션 값으로 교체**가 맞다.
