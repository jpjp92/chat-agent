### Google Search grounding 연동 방식

Google Search는 별도 서비스가 아니라 **Gemini API 내장 grounding 기능** (`{ googleSearch: {} }` 툴).

#### 사용 위치

1. **Generator Node (SDK path)** — 사용자 선택 모델에 직접 연동
   ```ts
   model: resolvedModel,  // Flash 또는 Flash Lite
   tools: useGoogleSearch ? [{ googleSearch: {} }] : undefined,
   ```

2. **drug-info-tool.ts** — `DEFAULT_CHAT_MODEL` (Flash) 하드코딩
   - MFDS DB에 없는 약품 검색 시 fallback용
   - 안정성 이유로 Flash 고정

3. **searchWebTool (tools.ts)** — Google Search 아님
   - DuckDuckGo HTML 스크래핑 방식, 완전히 별개

#### Google Search 활성/비활성 조건 (Generator)

| 조건 | 결과 |
|------|------|
| 멀티모달 없음 + 이미지 히스토리 없음 | ✅ 활성 |

## ✅ 구현 완료 — React Error Boundary (M4)

### 현황 분석

현재 7레이어 에러 처리 구조 중 훅/서비스 레이어는 모두 try/catch로 처리됨.
화이트스크린이 발생할 수 있는 미처리 경로 2종:

| 경로 | 원인 | 현재 처리 |
|------|------|-----------|
| **lazy 청크 로드 실패** | 네트워크 오류로 렌더러 js 번들 로드 불가 | `<Suspense>` loading fallback만 있음, error fallback 없음 |
| **렌더 단계 throw** | JSX 렌더링 중 unguarded 예외 | ErrorBoundary 없어 앱 전체 크래시 |

`ChatMessage.tsx`에 lazy 컴포넌트 11개:
```
ChartRenderer, ChemicalRenderer, BioRenderer, DiagramRenderer,
ConstellationRenderer, DrugRenderer, PharmacyRenderer,
HospitalRenderer, VetRenderer, LawRenderer, YoutubeEmbed
```
이 중 하나라도 청크 로드 실패 시 해당 메시지 전체 → 앱 전체 크래시.

---

### 구현 범위

#### 1. `components/ErrorBoundary.tsx` — 신규 생성

재사용 가능한 클래스 기반 ErrorBoundary.

```tsx
interface Props {
  children: React.ReactNode;
  fallback?: React.ReactNode;           // 커스텀 fallback UI
  onError?: (error: Error) => void;     // 에러 콜백 (로깅 등)
}

interface State { hasError: boolean; error: Error | null; }

class ErrorBoundary extends React.Component<Props, State> {
  static getDerivedStateFromError(error: Error): State
  componentDidCatch(error: Error, info: ErrorInfo): void  // console.error
  reset(): void  // 에러 상태 초기화
  render(): ReactNode
}
```

**fallback prop 없을 때 기본 UI**: 인라인 에러 카드
```
[!] 이 콘텐츠를 표시할 수 없습니다.
```

---

#### 2. `index.tsx` — 앱 루트 ErrorBoundary 래핑

앱 전체 예기치 않은 throw의 최후 방어선.

```tsx
// 현재
root.render(
  <React.StrictMode>
    <App />
  </React.StrictMode>
);

// 변경 후
root.render(
  <React.StrictMode>
    <ErrorBoundary fallback={<AppErrorFallback />}>
      <App />
    </ErrorBoundary>
  </React.StrictMode>
);
```

**루트 fallback UI** (`AppErrorFallback`): 전체 화면, "화면에 오류가 발생했습니다" + 새로고침 버튼.
언어를 알 수 없으므로 ko/en 2개 언어 병기.

#### 3. `ChatMessage.tsx` — 각 `<Suspense>` ErrorBoundary 래핑

렌더러 단위 오류 격리. 하나가 터져도 나머지 메시지/렌더러는 정상 표시.

메시지 카드 스타일과 동일한 테두리/배경으로 레이아웃 유지.

### 10. generator.ts thinkingConfig 모델 분기

**배경**: `thinkingConfig`가 `effectiveModel` 무관하게 동일하게 전달되어, 3.5-flash에서 deprecated `thinkingBudget`이 사용되고 있었고, thinking 기본값(`medium`)으로 인한 Vercel 60s 타임아웃 위험 존재.

**검증 선행** (`scripts/test-thinking-35flash.ts`, 3회 실행):

| 설정 | 1차 | 2차 | 3차 | 판정 |
|---|---|---|---|---|
| `thinkingBudget: 0` | ✅ N/A | ❌ 500 Error | ✅ N/A | deprecated, 간헐 500 |
| `thinkingLevel: minimal` | ✅ N/A | ✅ N/A | ✅ N/A | ✅ 안정 |
| `thinkingLevel: low` | 161 | 217 | 102 tokens | ✅ 안정 |
| 기본값 undefined | 108 | 267 | 261 tokens | medium 기본 |

**구현** (`api/_lib/agent/nodes/generator.ts`):

```ts
// effectiveModel 먼저 결정 후 thinkingConfig 분기
const effectiveModel = (useGoogleSearch && needsSearchFallback)
    ? SEARCH_FALLBACK_MODEL : resolvedModel;

const is3xModel = effectiveModel === SERVER_MODELS.FLASH_3_5;
const thinkingConfig = is3xModel
    ? (isYoutubeRequest && hasVideoData)
        ? { thinkingLevel: "minimal" as const }   // YouTube: thinking 비활성
        : { thinkingLevel: "low" as const }        // 그 외: low (60s 타임아웃 방지)
    : (isYoutubeRequest && hasVideoData)
        ? { thinkingBudget: 0 }                    // 2.5-flash YouTube
        : state.intent === 'medical_qa'
        ? { thinkingBudget: 3000 }                 // 2.5-flash medical_qa
        : undefined;                               // 2.5-flash 그 외: 모델 기본값
```

**적용 결과**:

| 경로 | 3.5-flash | 2.5-flash |
|---|---|---|
| YouTube 네이티브 영상 | `thinkingLevel: "minimal"` | `thinkingBudget: 0` |
| medical_qa | `thinkingLevel: "low"` | `thinkingBudget: 3000` |
| 그 외 모든 경로 | `thinkingLevel: "low"` | `undefined` |

- `effectiveModel` 기준이므로 Google Search 폴백(3.5→2.5)에서도 올바른 분기 적용

### 12. generator.ts 스트리밍 제거 → generateContent 단일 경로 전환

### 13. Two-track Google Search 경로 (3.5-flash + search)

**배경**: 3.5-flash는 무료 티어에서 Google Search grounding 직접 호출 불가 → 기존 단순 `SEARCH_FALLBACK_MODEL`(2.5-flash) 교체는 모델 선택 의도를 무시. Two-track으로 두 모델의 장점을 분리.

**아키텍처**: `useGoogleSearch && needsSearchFallback` 조건 시 활성

```
Stage1: 2.5-flash + Google Search
  → 그라운딩된 사실 텍스트 + groundingSources 수집
  → 8000자 초과 시 truncate (Stage2 타임아웃 방지)

Stage2: 3.5-flash (synthesis only, no search)
  → [GROUNDING_NOTES_FROM_STAGE1] + [SYNTHESIS_RULES] 형태의 합성 프롬프트
  → thinkingLevel: "minimal"
  → Stage2 quota 소진 시: 2.5-flash로 fallback → 실패 시 Stage1 텍스트 직접 사용
```

**폴백 체인**:
1. Stage2 3.5-flash 성공 → 사용
2. Stage2 quota 소진 → 2.5-flash 합성 재시도
3. 모든 키 소진 → Stage1 그라운딩 텍스트 직접 사용
4. Stage2 결과 empty → Stage1 텍스트 safe fallback (`stage1FallbackText`)

**단일 패스 경로** (Google Search 없거나 2.5-flash 선택 시): `generateContent` 단일 호출, 응답 없으면 `Error: SDK returned empty response text` throw.

if (isUnavailable) {
