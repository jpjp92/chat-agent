## 2. 버그 수정 3종 (구현 중 발견)

### B1 — LANGCHAIN_INTENTS 누락
- **파일**: `api/_lib/agent/nodes/generator.ts`
- **문제**: `LANGCHAIN_INTENTS` 배열에 `vet_search` 미포함 → SDK 경로(Google Search)로 분기 → vetTool 미호출, 웹 검색 텍스트 응답 반환
- **수정**: `LANGCHAIN_INTENTS = [..., "vet_search"]` 추가

### B2 — serviceKey URL 이중 인코딩
- **파일**: `api/_lib/agent/vet-tool.ts`
- **문제**: `new URLSearchParams({ serviceKey: VET_KEY })` 에 이미 URL 인코딩된 키(`%2F` 등)를 넣으면 이중 인코딩(`%252F`) 발생 → API `Unauthorized` 오류
- **수정**: `serviceKey`를 `URLSearchParams` 밖에서 URL 문자열에 직접 삽입 — `?serviceKey=${VET_KEY}&${qs}` 패턴으로 변경 (약국·병원 툴과 동일)

### B3 — chat.ts on_tool_end 핸들러 누락
- **파일**: `api/chat.ts`
- **문제**: `on_tool_end` 핸들러가 `pharmacyTool | hospitalTool`만 처리 → `vetTool` 결과가 SSE로 전송되지 않음 → fast-pass 후 빈 응답 → 프론트 `LLM returned empty response.` 에러 + 재시도 루프
- **수정**: 핸들러 조건에 `vetTool` 추가, `blockType` 삼항 연산자로 `"vet"` 분기 추가

## 3. Vet-Viz 추가 수정 필요 항목 (리뷰 결과)

> 아래 V1~V4는 구현 직후 리뷰에서 발견한 위험 항목이며, 실제 보완 내역은 4번 섹션(E1~E5)에 반영했다.

### V1 — 위치/병원명 없는 요청의 전국 첫 페이지 노출 방지
- **파일**: `api/_lib/agent/vet-tool.ts`
- **문제**: `sido`, `sigungu`, `dong_name`, `hospital_name`이 모두 비어도 API 호출이 가능함. 이 경우 사용자가 단순히 "동물병원 찾아줘"처럼 위치를 주지 않았을 때 전국 영업중 데이터 첫 100건 중 상위 10건이 카드로 노출될 수 있음.
- **수정 방향**: 주소 조건과 병원명 조건이 모두 없으면 API 호출 전 위치 정보 요청 또는 `search_web` fallback 지시문을 반환하도록 가드 추가.

### V2 — 병원명 단독 검색 시 전체 상태 재조회 누락
- **파일**: `api/_lib/agent/vet-tool.ts`
- **문제**: 영업중 필터 0건 시 전체 상태 재조회 조건이 `items.length === 0 && addrQuery`로 제한되어 있음. 병원명만 검색한 경우 휴업/폐업 데이터가 실제로 있어도 재조회하지 않고 "찾을 수 없음"으로 떨어질 수 있음.
- **수정 방향**: fallback 조건을 `items.length === 0 && (addrQuery || hospital_name)`으로 확장.

### V3 — 라우터 fallback의 `펫` 키워드 과매칭
- **파일**: `api/_lib/agent/nodes/router.ts`
- **문제**: 휴리스틱 fallback에서 `펫`만 포함해도 `vet_search`로 분류함. `펫보험`, `펫푸드`, `펫샵` 같은 비의료 요청이 동물병원 검색으로 오분류될 수 있음.
- **수정 방향**: `펫` 단독 키워드는 제거하고, `동물병원`, `동물 병원`, `수의사`, `동물의료`, `동물의원`, `수의과` 등 방문/진료 의도가 분명한 키워드로 축소.

### V4 — API 오류 응답과 0건 응답 구분
- **파일**: `api/_lib/agent/vet-tool.ts`
- **문제**: `fetchJson`이 `res.ok` 및 공공데이터 API 오류 코드/메시지를 확인하지 않고 바로 JSON 파싱 후 `extractItems`로 넘김. 키 만료, 인증 실패, 일시 장애가 "정보를 찾을 수 없습니다"로 오해될 수 있음.
- **수정 방향**: HTTP 비정상 응답과 `response.header.resultCode/resultMsg`류를 검사해 API 오류 메시지를 명시적으로 반환. JSON 파싱 실패도 별도 오류로 분리.

### V5 — 검증
- **빌드 확인**: `npm run build` 성공 (기존 chunk size warning만 발생)
- **추가 확인 필요**:
  - 위치 없는 요청: "동물병원 찾아줘"
  - 병원명 단독 요청: "OO동물병원 찾아줘"
  - 비의료 펫 요청: "펫보험 추천", "펫푸드 알려줘"
  - 정상 지역 요청: "전주시 덕진구 동물병원 찾아줘"

## 4. Vet-Viz 에러 보완 적용

### E1 — 검색 조건 없는 API 호출 차단
- **파일**: `api/_lib/agent/vet-tool.ts`
- **수정**: `addrQuery`와 `hospital_name`이 모두 비어 있으면 공공데이터 API를 호출하지 않고, 지역명 또는 병원명을 요청하는 안내 문구를 반환하도록 가드 추가.
- **효과**: "동물병원 찾아줘"처럼 위치가 없는 요청에서 전국 첫 페이지 데이터가 잘못 카드화되는 문제 방지.

### E2 — VET_KEY 누락 가드
- **파일**: `api/_lib/agent/vet-tool.ts`
- **수정**: `VET_KEY`가 비어 있으면 API 호출 전 환경변수 설정 안내를 반환.
- **효과**: 인증 실패가 0건 검색처럼 보이는 문제 방지.

### E3 — HTTP/JSON/API 오류 분리
- **파일**: `api/_lib/agent/vet-tool.ts`
- **수정**:
  - `fetchJson`에서 `res.ok` 확인
  - JSON 파싱 실패 시 응답 일부를 포함한 명시적 오류 반환
  - `response.header.resultCode/resultMsg` 검사 추가 (`00`, `0`, `NORMAL_CODE`, `INFO-000` 정상 처리)
- **효과**: 키 만료, 인증 실패, 일시 장애, 비JSON 응답이 "검색 결과 없음"으로 오인되지 않음.

### E4 — 병원명 단독 검색 fallback 확장
- **파일**: `api/_lib/agent/vet-tool.ts`
- **수정**: 영업중 0건 시 전체 상태 재조회 조건을 `addrQuery || hospital_name`으로 확장.
- **효과**: 병원명만 입력한 검색에서도 휴업/폐업 포함 데이터를 재조회.

### E5 — 라우터 휴리스틱 과매칭 축소
- **파일**: `api/_lib/agent/nodes/router.ts`
- **수정**: `펫` 단독 키워드 제거. `동물병원`, `동물 병원`, `동물의원`, `동물의료`, `동물 의료`, `수의사`, `수의과`만 `vet_search` fallback으로 분류.
- **효과**: `펫보험`, `펫푸드`, `펫샵` 등 비의료 요청의 동물병원 검색 오분류 감소.
