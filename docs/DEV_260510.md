# DEV_260510.md

## 1. C1 — `pill-logic.ts` Promise.allSettled 전환

- **파일**: `api/_lib/pill-logic.ts`
- **변경**: 1차 검색(L14)·2차 변형 검색(L24) 양쪽 모두 `Promise.all` → `Promise.allSettled` 전환
- **이유**: `fetchPage`가 try/catch로 개별 실패를 `[]`로 처리하지만, Promise가 예기치 않게 reject되면 `Promise.all`은 5페이지 전체를 즉시 reject함. 단일 타임아웃 하나가 전체 약 검색을 크래시시키는 문제 방지.
- **처리 방식**: `settled.forEach(r => { if (r.status === 'fulfilled') ... })` — 실패 항목을 조용히 건너뜀.
- **영향 분석**: `fetchPage`가 이미 예외를 `[]`로 흡수하므로 happy path는 동일. 방어 계층 추가만 됨. 기존 로직 변경 없음.

## 2. C2 — `geminiService.ts` response.ok 가드 전면 적용

- **파일**: `services/geminiService.ts`
- **변경**: 아래 7개 함수에 `response.ok` 체크 추가 (`streamChatResponse`·`uploadToStorage`는 기존 완료)

| 함수 | HTTP 에러 시 throw 메시지 | 호출부 에러 처리 |
|------|--------------------------|-----------------|
| `loginUser` | `Auth failed: {status}` | `useAuthSession` try/catch → `null` 반환 → 에러 화면 |
| `updateRemoteUserProfile` | `Profile update failed: {status}` | `App.tsx` try/catch → `profileUpdateFailed` toast |
| `fetchSessions` | `Failed to fetch sessions: {status}` | `useChatSessions` catch → `loadSessions` error toast |
| `createSession` | `Failed to create session: {status}` | `useChatSessions` catch → `createSession` error toast |
| `deleteSession` | `Failed to delete session: {status}` | `useChatSessions` catch → `deleteSession` error toast |
| `updateSessionTitle` | `Failed to update session title: {status}` | `useChatSessions` catch → `renameSession` error toast |
| `generateSpeech` | `Speech generation failed: {status}` | `ChatMessage.tsx` catch → `console.error`, TTS 버튼 리셋 |

- **이유**: `response.ok` 없이 `.json()` 파싱 시 401/403/500 등 비정상 응답이 정상 JSON이 아닌 경우 `SyntaxError`로 앱 크래시. 인증 실패·네트워크 오류 시 명확한 Error로 호출부 catch 블록에 도달 보장.
- **부수 효과 (버그 수정)**: 기존 `deleteSession`·`updateSessionTitle`은 API 실패 시 `response.ok` 가드가 없어 `.json()`이 throw 없이 진행 → 호출부가 성공으로 오인하여 UI를 업데이트(세션 삭제·이름 변경)하는 silent bug 존재. 이번 수정으로 API 실패 시 catch 블록으로 분기 → 에러 toast 표시, UI 롤백.
- **참고**: `summarizeConversation`은 이미 try/catch가 `"New Chat"` fallback 처리하므로 대상 제외.

## 4. B1 — `geminiService.ts` `streamChatResponse` 변수 스코프 버그 수정

- **파일**: `services/geminiService.ts`
- **변경**: `let receivedAnyText = false`·`let receivedDone = false`를 `try {}` 블록 내부 → 함수 스코프(try 바깥)로 이동
- **이유**: JavaScript `let`은 블록 스코프이므로 `try {}` 내부에서 선언된 변수는 `catch {}` 블록에서 접근 불가. 네트워크 드롭(`reader.read()` throw) 시 catch 블록의 `if (receivedAnyText && onCutOff)` 참조가 `ReferenceError`를 발생시켜 원래 에러(네트워크 드롭)가 가려지고 amber 배너 표시 경로도 동작하지 않았음.
- **영향 분석**: 초기값 동일(`false`), 변수 할당 위치 동일(while 루프 내부). happy path 동작 변경 없음. 네트워크 드롭 시 catch의 cutOff 배너 경로가 이제 정상 동작.
- **발견 경위**: GPT-5.5 Codex 코드 리뷰

## 3. H2 — `fetch-url.ts` 에러 응답 코드 502로 변경

- **파일**: `api/fetch-url.ts`
- **변경**: catch 블록 내 `res.status(200)` → `res.status(502)`
- **이유**: URL 페치 실패 시 200으로 반환하면 HTTP 레이어에서 성공/실패 구분 불가. 모니터링·로깅 도구가 에러를 탐지 못함.
- **호환성 검증**:
  - `fetchUrlData`(`geminiService.ts`)는 `response.json()`을 호출 — 502에도 JSON body가 존재하므로 파싱 성공.
  - `fetchUrlContent`의 `data.content.startsWith('[FETCH_ERROR')` 감지 로직 그대로 유지 → 빈 문자열 반환 경로 변경 없음.
  - `fetchUrlData`에 `response.ok` 가드 없지만 catch 블록이 `{ content: "" }` fallback 처리하므로 502 non-JSON 응답에도 안전.
