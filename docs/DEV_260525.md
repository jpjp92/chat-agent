## 1. Supabase 신규 프로젝트 이전

### 배경

기존 Supabase 프로젝트(구 계정)를 신규 계정의 프로젝트로 전면 이전. DB 테이블 3개 + Storage 버킷 3개 마이그레이션.

### DB 마이그레이션

**신규 프로젝트 테이블 DDL 생성 순서** (FK 의존 순서 준수):
1. `users` — `GENERATED BY DEFAULT AS IDENTITY` (원본 id 유지 목적으로 최종 변경)
2. `chat_sessions` — uuid PK, `user_id` FK
3. `chat_messages` — bigint PK, `session_id` FK

**초기 이전 시 발견된 문제**:
- `GENERATED ALWAYS AS IDENTITY` 컬럼에 명시적 id 삽입 불가
- users 재삽입 시 새 id가 부여되어 기존 로그인 기기의 localStorage `chat_user` 캐시와 불일치 → FK 오류
- 해결: `ALTER TABLE public.users ALTER COLUMN id SET GENERATED BY DEFAULT;` → `TRUNCATE public.users CASCADE;` → id 포함 재마이그레이션
- 마이그레이션 완료 후 시퀀스 리셋: `SELECT setval(pg_get_serial_sequence('public.users', 'id'), 1054);`

## 3. ** 볼드 렌더링 수정 (`components/ChatMessage.tsx`)

### 문제

모델 응답에서 `**"text"**의` 패턴처럼 closing `**` 바로 앞에 따옴표(`"`, `'`, `"`, `"`, `'`, `'`)가 오고 뒤에 한국어가 이어지는 경우 `**`가 렌더링되지 않고 raw 텍스트로 출력.

### 원인

CommonMark flanking 규칙상 closing `**`가 punctuation(따옴표) 뒤에 위치할 때 right-flanking 판정이 rule (b)를 따르는데, remark-gfm이 이 케이스를 정확히 처리하지 못하는 경우 발생.

기존 fix(closing `**` + 한국어 → 뒤에 공백 삽입)는 한국어 직접 인접 케이스는 처리했으나 `따옴표 + ** + 한국어` 조합은 불완전.

### 수정

`ChatMessage.tsx` 3곳(textPart, processedVisible, processedRemaining)에 ZWNJ(U+200C) 전처리 추가:

```ts
// 신규: 따옴표 뒤 ** + 한국어 → ZWNJ 삽입 (rule (a)로 right-flanking 강제)
textPart = textPart.replace(/(["""'''])\*\*(?=[가-힣A-Za-zÀ-ÿ])/g, '$1‌** ');
// 기존: ** + 한국어 → 뒤에 공백 (유지)
textPart = textPart.replace(/\*\*([^*\n]+?)\*\*(?=[가-힣A-Za-zÀ-ÿ])/g, '**$1** ');
```

**ZWNJ(U+200C)**: Unicode Cf 카테고리 — CommonMark 기준 whitespace도 punctuation도 아님 → closing `**`가 rule (a)로 right-flanking 처리되어 더 안정적으로 닫힘. 렌더 결과에서는 보이지 않음.

## 4. 사이드바 세션 로딩 성능 분석

### 현황

`api/sessions.ts`의 세션 목록 조회 쿼리에 `limit` 없음:

```ts
supabase.from('chat_sessions').select('*').eq('user_id', user_id).order('updated_at', { ascending: false })
// ← limit 없음 → 현재 1,267건 전체 반환
```

`user_id` 필터는 정상 적용되어 있음 (다른 유저 세션이 섞이는 문제는 아님).

### 원인별 분류

| 원인 | 발생 시점 | 심각도 |
|---|---|---|
| 세션 1,267건 전체 조회 | 앱 로드마다 | 🔴 High |
| localStorage 캐시 30개 → API 응답 1,267개 re-render | API 응답 후 리스트 확장 | 🟡 Medium |
| `isLoadingSessions` 초기값 `true` | 첫 로드 (캐시 없을 때) shimmer | 🟡 Medium |
| 세션 클릭 시 메시지 fetch + blur overlay | 첫 선택 시 | 🟢 Low |

### 개선 방향 (미적용 — 추후 진행)

**채택 방안: `limit(50)` + 서버사이드 검색**

- 초기 로드: 최신 50개만 조회 → payload 96% 감소
- 검색창 입력 시: `/api/sessions?user_id=X&search=키워드` → Supabase `.ilike()` 전체 대상 검색
- localStorage 캐시 크기도 30 → 50으로 통일
- 사이드바 기본 목록 50개 / 50개 밖 오래된 세션은 검색으로 접근

현재 클라이언트사이드 검색(`sessions.filter(...)`)은 서버사이드 검색으로 전환 필요.
