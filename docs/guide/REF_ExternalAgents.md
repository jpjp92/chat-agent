## 1. 채택 후보 (전부 무료티어 예산 친화 — 추가 LLM 호출 0)

우리 chat-agent 와 도메인이 거의 안 겹쳐 대부분 비채택. 실제로 남는 착수 후보는 **4개뿐**.

### 1-A. 렌더러 JSON 파서 견고성 (파트 A ①②) — 모델 무관

현재: `components/ChatMessage.tsx` 가 정규식 블록 추출 + trailing comma 치환 → `JSON.parse`, 실패 시 블록 폐기.

- **① `raw_decode` 방식** — 첫 완전한 JSON 값만 파싱(뒤 잡텍스트 내성). 현재 `JSON.parse` 는 JSON 뒤 군더더기에 "Extra data" 로 전체 실패 → 블록 소멸.
- **② 스트리밍 마커 부분-hold** — 마커(` ```json:chart `)가 청크 경계에 반쪽만 걸칠 때 접미사를 hold. 현재 `.split()` 은 깜빡임 가능.
- 순수 문자열/파싱 코드 → **Gemini/GPT 무관, 그대로 이식 가능.**

### 1-B. 프롬프트 경계규칙 = 주의사항 패턴 (파트 E ①) — 선별

레퍼런스 의도분류는 카테고리마다 **정의 → 주의사항(헷갈리는 이웃을 어디로) → 예시** 3단. 우리 `server/agent/nodes/router.ts` 는 같은 경계 혼동을 **코드 rescue 휴리스틱**(movie/weather rescue 등 100+줄 regex)으로 사후교정.

- 코드 rescue 는 결정론적이라 **더 안정적** → 기존 유지.
- **신규 오분류 발생 시 코드 패치 前 프롬프트 주의사항부터** 시도. router.ts 비대화를 줄이는 대안 도구.

### 1-C. 대조 예시 (파트 E ②) — 모델 무관

near-miss 쌍(`"A" → 차단 / "B" → 허용`)으로 경계를 못박는 기법. GPT/Gemini 양쪽 유효. generator 모호 규칙(검색 on/off 회색지대, source-preamble 금지 등)에 1~2쌍씩 저비용 이식.

### 1-D. 고정순서 JSON 계약 (파트 E ⑦, 부차) — 렌더러 견고성 상보

렌더러 JSON 프롬프트에 "필드 순서·개수 고정 + 없을 때 null 명시"를 추가하면 1-A 파서와 상보적으로 **깨진 JSON 발생 자체를 감소**. 단 현재 렌더러 15/15 유효라 우선순위 낮음.

## 2. 대기(상황적) — 필요 발생 시

### 2-A. 운영 오버라이드(핫픽스) 계층 (파트 B)

`{키워드, 메시지, start_at, expires_at}` 시간창 룰(JSON) → 키워드 즉시 매칭 시 **재배포 없이** canned 메시지 반환(LLM 호출 0). 용도: 렌더러 일시 장애 공지·이벤트 안내·알려진 오답 임시 교정.

- 소비자 취미 앱이라 상시 니즈는 아님. **운영 니즈 실제 발생 시 최소형**(작은 JSON + router 진입부 키워드 단락)으로.

## 4. GPT 5.2 → Gemini 이식 주의 (필독)

- **순수 코드(1-A)**: 모델 무관, 무영향.
- **structured output**(`with_structured_output(function_calling/json_schema, strict)`): GPT 규격 튜닝 → Gemini 이식 시 동작·성능·비용 상이. 우리는 `responseMimeType:"application/json"` + 파싱 방식이 다름. **재검증 필수.**
- **Checklist·reasoning_thoughts 필드**: 모델이 실제 사고를 거치는 전제 → 우리 **router 는 `thinkingBudget:0`(무사고)라 무효**. generator(사고 가능)엔 유효 여지.
- **290줄 규칙 벽**: GPT 5.2 는 소화하나 **flash-lite 는 규칙 과다 시 성능 저하** → router 는 린 유지, 선별만.
- **대조 예시·JSON 계약**: 모델 무관에 가까워 이식 안전.
