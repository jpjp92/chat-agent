## 2. Jina Reader URL 이중 프로토콜 버그 수정

### 증상

- 네이버 뉴스(`https://n.news.naver.com/...`) URL 요약 시 실제 기사와 전혀 다른 내용이 반환됨.
- 예: AI 에이전트 관련 기사 요청 → 의대 정원 관련 기사 내용으로 응답.

### 원인

`fetchJinaReaderContent`에서 Jina Reader URL을 생성할 때 프로토콜을 중복 삽입.

```ts
// 버그: targetUrl에 이미 https://가 포함되어 있는데 http://를 추가로 붙임
const readerUrl = `https://r.jina.ai/http://${targetUrl}`;
// → https://r.jina.ai/http://https://n.news.naver.com/...  (잘못된 URL)
```

Jina Reader가 잘못된 URL을 받아 캐시된 무관한 기사 내용을 반환하는 것이 원인.

### 수정

```ts
const readerUrl = `https://r.jina.ai/${targetUrl}`;
```

## 3. 지속적인 뉴스 기사 오요약 — 근본 원인 분석 및 최종 수정

### 증상

- URL 이중 프로토콜 버그 수정 후에도 배포 환경에서 계속 전혀 다른 기사를 요약.
- 로컬(`npx vercel dev`, 한국 IP)에서는 정상 동작.
- 배포 후 웹(Vercel 서버, 해외 IP)에서만 재현.

### 원인 분석

**원인 1 — generator.ts `hasUrlContent` 300자 조건**

```ts
// 기존: 내용 길이 300자 이상일 때만 Google Search 비활성화
const hasUrlContent = !!(urlContentMatch && urlContentMatch[1].trim().length >= 300);
```

- 로컬(한국 IP): Naver가 본문 포함 2199자 반환 → `hasUrlContent = true` → Google Search 비활성 → 정상
- Vercel(해외 IP): Naver가 짧은 HTML 반환 가능 → 추출 내용 < 300자 → `hasUrlContent = false` → **Google Search 활성화 → 전혀 다른 기사 요약**

**원인 2 — Jina fallback 트리거 조건 과도 설정**

초기 구현에서 `isBlockedOrChallenge` 함수가 `cf-chl`, `challenge-platform`, `cloudflare` 등 여러 패턴을 체크했음. 이 패턴들은 Cloudflare를 CDN으로 사용하는 정상 사이트 HTML에도 포함될 수 있어 오탐 발생. 오탐 시 Jina가 불필요하게 호출되고, Jina가 캐시된 엉뚱한 기사를 반환하는 경우가 생겼음.

**원인 3 — `content < 300` → Jina 호출 경로**

직접 fetch가 성공해도 추출 내용이 짧으면 Jina를 추가 호출하는 경로가 있었음. 이 경로에서 Jina가 캐시된 다른 기사를 반환하면 올바른 내용을 덮어씌움.

### 최종 수정

**`api/_lib/agent/nodes/generator.ts`**

```ts
// 수정: [URL_CONTENT:] 태그 존재 여부로만 판단 (길이 체크 제거)
// useChatStream.ts에서 fetch 완전 실패 시 태그를 추가하지 않으므로
// 태그 존재 자체가 "URL fetch 완료" 신호로 충분.
const hasUrlContent = state.webContent.includes('[URL_CONTENT:');
```

**`api/fetch-url.ts`**

Jina 트리거 조건을 Wikidocs처럼 실제로 Cloudflare가 차단한 케이스로만 최소화.

```ts
// Cloudflare challenge 감지: 비정상 status 또는 <title>Just a moment...</title>
// cf-chl, challenge-platform 등 다른 패턴은 정상 사이트에서 오탐 가능하여 제외.
if (!response.ok || html.match(/<title[^>]*>\s*just a moment/i)) {
    directFetchBlocked = true;
}

// 차단 감지 시에만 Jina Reader 호출
if (directFetchBlocked) {
    const jinaRes = await fetch(`https://r.jina.ai/${targetUrl}`, ...);
    // Jina 성공 시 반환 / 실패 시 [FETCH_ERROR]
}

// 직접 fetch 성공 시 → 내용 길이 무관하게 그대로 사용 (추가 Jina 호출 없음)
```

### 최종 동작 흐름

```
직접 fetch 성공 (200, 정상 HTML)     → 직접 추출 → URL_CONTENT 태그 → Google Search 비활성
직접 fetch 차단 (403 / Just a moment) → Jina fallback → URL_CONTENT 태그 → Google Search 비활성
Jina도 실패                           → [FETCH_ERROR] → URL_CONTENT 태그 없음 → Google Search 허용
fetch 타임아웃 / 연결 오류             → [FETCH_ERROR] → URL_CONTENT 태그 없음 → Google Search 허용
```

### 검증

- `npx tsc --noEmit` 성공.
- Naver 뉴스 URL 직접 fetch: 200 OK, 정상 추출, challenge 오탐 없음 확인.
- Jina Reader 올바른 URL(`https://r.jina.ai/https://...`) 응답 정상 확인.
- 비교 기준 커밋: `9d91933` (Jina 없던 정상 상태), `8f698c2` (정상 작동 확인된 커밋).
