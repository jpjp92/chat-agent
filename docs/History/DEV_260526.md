## ⚠️ 계획과 차이나는 항목

### 1. `vercel.json` 헤더 중복
**계획**: `next.config.ts`로 이전 후 `vercel.json`에서 제거  
**실제**: 양쪽 모두 동일한 6개 헤더가 존재 → 중복 상태

```
vercel.json          ← 제거 대상
next.config.ts       ← 유효한 위치
```

**해결방안**:  
`vercel.json`에서 `"headers"` 블록 전체 삭제.  
Next.js가 배포 시 `next.config.ts`의 헤더를 Vercel 플랫폼에 자동 등록하므로 기능 손실 없음.

---

### 2. `force-dynamic` 미적용 Route 11개
**계획**: 모든 동적 API Route에 `export const dynamic = 'force-dynamic'` 권장  
**실제**: `app/api/chat/route.ts`에만 적용, 나머지 11개 미적용

**영향 범위**: 정적 캐싱 없이 매 요청마다 실행되는 Route이므로 현재 기능상 문제는 없음.  
단, Next.js가 빌드 타임에 일부 Route를 정적으로 분석할 경우 예상치 못한 캐싱 발생 가능.

**해결방안**:  
요청마다 달라지는 데이터를 다루는 Route(auth, sessions, speech, upload 등)에 추가.  
`create-signed-url`, `sync-drug-image`처럼 외부 API 호출 포함 Route도 포함 권장.

```ts
// 각 route.ts 최상단에 추가
export const dynamic = 'force-dynamic';
```

---

### 3. `api/_lib/` → `server/` 리네임 미이행
**계획**: 서버 전용 모듈을 `server/` 디렉토리로 이동해 명시적 분리 권장  
**실제**: `api/_lib/` 경로 그대로 유지 (기능 동일)

**영향**: `server-only` 임포트가 정상 작동하므로 보안상 문제 없음.  
디렉토리 이름만 달라 계획서와 불일치.

**해결방안**: 낮은 우선순위. 리네임 시 12개 Route Handler의 import 경로 일괄 수정 필요.  
현 상태 유지도 무방.
