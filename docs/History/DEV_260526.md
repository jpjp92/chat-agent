## ⚠️ 계획과 차이나는 항목

### 1. `vercel.json` 헤더 중복
**계획**: `next.config.ts`로 이전 후 `vercel.json`에서 제거  
**실제**: 양쪽 모두 동일한 6개 헤더가 존재 → 중복 상태

```
vercel.json          ← 제거 대상
next.config.ts       ← 유효한 위치
```

**해결방안**:  
`vercel.json`에서 `"headers"` 블록 전체 삭제.  
Next.js가 배포 시 `next.config.ts`의 헤더를 Vercel 플랫폼에 자동 등록하므로 기능 손실 없음.

---

### 2. `force-dynamic` 미적용 Route ~~11개~~ → ✅ 완료
**계획**: 모든 동적 API Route에 `export const dynamic = 'force-dynamic'` 권장  
**실제**: `app/api/chat/route.ts`에만 적용, 나머지 미적용

**재검토 결과**:  
Next.js App Router에서 POST route는 빌드 타임에 정적 캐싱 대상이 되지 않으므로 `force-dynamic` 불필요.  
실제로 필요한 것은 **GET route 2개**뿐이었음.

| route | method | 조치 |
|-------|--------|------|
| `sessions` | GET | ✅ `force-dynamic` 추가 — 유저별 세션 데이터 |
| `proxy-image` | GET | ✅ `force-dynamic` 추가 — 외부 이미지 프록시 |
| 나머지 10개 | POST | 불필요 (POST는 항상 dynamic) |

`npm run build` 후 12개 route 전부 `ƒ (Dynamic)` 확인 완료.

---

### 3. `api/_lib/` → `server/` 리네임 ✅ 완료
**계획**: 서버 전용 모듈을 `server/` 디렉토리로 이동해 명시적 분리 권장

**작업 내역**:
- `api/_lib/` → `server/` 이동 (17개 파일)
- Route Handler 10개 파일 15줄 import 경로 일괄 수정 (`../../../api/_lib/` → `../../../server/`)
- 내부 상대경로 import는 변경 불필요 (상대경로이므로 자동 유지)
- 빈 `api/` 디렉토리 삭제 (Vite 시절 잔재 완전 제거)
- README 5곳 경로 업데이트
- `npm run build` 성공 확인
