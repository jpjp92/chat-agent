# DEV_260519 — Wikidocs URL 패칭 실패 원인 분석 및 대응

> 날짜: 2026-05-19

---

## 배경

URL 기반 요약 기능에서 `https://wikidocs.net/347355` 패칭 실패 확인.
Cloudflare Bot Management에 의한 차단으로 파악하고 전수 조사 진행.

---

## 현재 fetch-url.ts 파이프라인

```
direct fetch (UA 스푸핑)
  → isAccessChallengeContent 감지 시 Jina Reader fallback
    → 성공: 본문 반환
    → 실패: [FETCH_ERROR] 반환
  → direct 성공했지만 bodyText < 200자 → Jina fallback
```

---

## 테스트 결과 요약

### 1. Direct fetch
- **결과**: HTTP 403, CF-Ray: ICN(서울) 엣지에서 차단
- **응답**: `<title>Just a moment...</title>` (Cloudflare JS 챌린지)
- **헤더 조합 테스트**: UA만 / 풀 브라우저 핑거프린트 / Googlebot — 전부 동일하게 403
- **결론**: IP/ASN 레벨 차단, 헤더 조작으로 우회 불가

### 2. Jina Reader (`r.jina.ai`)
- **결과**: HTTP 200이지만 내용은 Cloudflare 챌린지 페이지 (431자)
- **API key 적용 후**: 동일하게 차단 (API key는 rate limit용, bot bypass 아님)
- **HTTP vs HTTPS**: 두 경우 모두 차단, 차이 없음
- **결론**: Jina 서버 IP도 Wikidocs Cloudflare 차단 목록에 포함됨

### 3. 클라이언트 사이드 fetch
- **결과**: 403 + `Access-Control-Allow-Origin` 헤더 없음
- **결론**: CORS 미허용, 브라우저에서도 접근 불가

### 4. Wikidocs Open API (`/napi/pages/{page_id}/`)
- **결과**: 인증 없이 401, 토큰 사용 시 404
- **원인**: API는 본인이 작성한 책/페이지만 접근 가능 (저자용 쓰기 API)
- **결론**: 타인의 공개 페이지 읽기 불가

## 커밋 히스토리 추적 — "며칠 전엔 됐던" 이유

| 커밋 | 변경 내용 | 영향 |
|------|---------|------|
| `5283489` | Jina fallback 최초 추가, `isBlockedOrChallenge`에 `cloudflare` 단순 포함 체크 | Wikidocs HTML에 `cdnjs.cloudflare.com` CDN 참조 → 오탐으로 항상 Jina 실행 |
| `7ab89c7` | `cloudflare` 단독 체크 제거 (오탐 수정) | 오탐 제거로 direct fetch 사용 시작 |
| 이후 | Wikidocs가 Cloudflare 룰 강화 → Vercel IP 차단 | direct fetch 403, Jina도 차단 |

**결론**: 구버전에서 오탐(`cdnjs.cloudflare.com` CDN 참조를 차단으로 잘못 감지)이 Jina를 항상 실행시켰고, 당시 Jina는 Wikidocs를 통과할 수 있었음. 오탐 수정 후 Wikidocs가 Cloudflare 룰을 강화하면서 현재 상태가 됨.

## 이번 세션에서 개선한 코드 (`api/fetch-url.ts`)

### 1. `isAccessChallengeContent` 함수 분리
- 인라인 `/<title[^>]*>\s*just a moment/i` 체크를 함수로 분리
- Jina 응답에서도 챌린지 감지에 동일 함수 재사용

### 2. `fetchViaJina` 헬퍼 함수 + JINA_API_KEY 지원
- 기존 코드 버그 수정: Jina가 챌린지 페이지(431자) 반환해도 100자 초과면 통과시키던 문제
- `JINA_API_KEY` env 있으면 `Authorization: Bearer ...` 헤더 자동 포함
- `.env`에 `JINA_API_KEY` 추가됨

### 3. `wikidocsPageMatch` 추출 패턴 추가
- `<div class="page-content">` 직접 타게팅 (Wikidocs 특화)
- 현재는 서버 IP 차단으로 실행되지 않는 dead code지만, 향후 차단 해제 시 동작

### 4. `bodyText < 200자` → Jina fallback
- direct fetch 성공해도 파싱 결과가 너무 짧으면 Jina 재시도

## Readability vs Regex 비교 테스트 결과

Wikidocs reference HTML (`view-source_https___wikidocs.net_347355.html`) 기준:

| 방식 | 추출 길이 | 추출 내용 |
|------|---------|---------|
| 현재 Regex (`page-content`) | 1,790자 | ✓ 실제 본문 |
| `@mozilla/readability` | 1,270자 | ✗ 목차/사이드바 |

Regex가 Wikidocs 구조에 더 적합함. Readability는 일반 블로그/미디엄용으로는 유용할 수 있으나 지금 당장 추가할 이유 없음.

## 결론 및 향후 방향

**무료로 할 수 있는 건 모두 시도, 전부 차단됨.**

향후 선택지:
- **유료 Scrapfly/Browserbase**: `SCRAPFLY_KEY` env 있을 때 3차 fallback으로 추가 가능 (월 1,000 req 무료 플랜 있음)
- **현 상태 유지**: Wikidocs는 "접근 불가" 케이스로 처리, 사용자에게 본문 복붙 안내
