# DEV_260512.md

## 1. 모델 레지스트리 중앙화 계획

### 목적

- 현재 모델 문자열이 프론트/백엔드 여러 파일에 하드코딩되어 있어 모델 교체·추가 시 누락 위험이 큼.
- 우선 Gemini 모델 문자열을 단일 레지스트리로 모아 관리하고, OpenAI 등 멀티 프로바이더 확장은 별도 단계로 분리한다.
- 이번 작업의 목표는 **동작 변경 없는 중앙화**다. Provider 추상화나 OpenAI SDK 도입은 포함하지 않는다.

### 현재 하드코딩 위치

- **프론트엔드**
  - `App.tsx` — `selectedModel` 타입, localStorage 기본값
  - `components/Header.tsx` — 모델 선택 메뉴, 표시명, 선택 체크
  - `src/hooks/useChatStream.ts` — `selectedModel` 타입
- **백엔드**
  - `api/chat.ts` — 기본 채팅 모델 fallback
  - `api/_lib/agent/state.ts` — GraphState `model` 기본값
  - `api/_lib/agent/nodes/generator.ts` — generator fallback 모델
  - `api/_lib/agent/nodes/router.ts` — router lite 모델
  - `api/_lib/agent/nodes/vision.ts` — vision 분석 모델
  - `api/_lib/agent/drug-info-tool.ts` — 약품 정보 보강 모델
  - `api/speech.ts` — TTS 모델
  - `api/summarize-title.ts` — 세션 제목 생성 fallback 모델 배열

## 2. 구현 범위

### Phase A — 서버 모델 상수화

**예상 소요**: 1시간 내외  
**위험도**: 낮음

- `api/_lib/models.ts` 생성
- 포함할 상수:
  - `SERVER_MODELS.FLASH = "gemini-2.5-flash"`
  - `SERVER_MODELS.FLASH_LITE = "gemini-2.5-flash-lite"`
  - `SERVER_MODELS.TTS = "gemini-2.5-flash-preview-tts"`
  - `DEFAULT_CHAT_MODEL = SERVER_MODELS.FLASH`
  - `ROUTER_MODEL = SERVER_MODELS.FLASH_LITE`
  - `SUMMARY_MODELS = [SERVER_MODELS.FLASH_LITE, SERVER_MODELS.FLASH]`
- 교체 대상:
  - `api/chat.ts`
  - `api/_lib/agent/state.ts`
  - `api/_lib/agent/nodes/generator.ts`
  - `api/_lib/agent/nodes/router.ts`
  - `api/_lib/agent/nodes/vision.ts`
  - `api/_lib/agent/drug-info-tool.ts`
  - `api/speech.ts`
  - `api/summarize-title.ts`

### Phase B — 프론트 모델 레지스트리

**예상 소요**: 30분~1시간  
**위험도**: 낮음~중간

- `src/lib/models.ts` 생성
- 포함할 값:
  - `CHAT_MODELS.FLASH`
  - `CHAT_MODELS.FLASH_LITE`
  - `type ChatModelId`
  - `DEFAULT_CHAT_MODEL`
  - `CHAT_MODEL_OPTIONS`
- 교체 대상:
  - `App.tsx`
  - `components/Header.tsx`
  - `src/hooks/useChatStream.ts`
- `Header.tsx`의 드롭다운을 `CHAT_MODEL_OPTIONS.map(...)` 기반으로 전환.
- i18n 텍스트(`t.model25Flash`, `t.model25FlashDesc` 등)는 우선 유지하고, 옵션 객체에서 translation key를 참조하는 방식으로 연결.

### Phase C — 검증

**예상 소요**: 20~30분

- TypeScript/build 확인:
  - `npm run build`
- 수동 확인 항목:
  - 기본 모델이 Gemini 2.5 Flash로 유지되는지
  - Header 모델 드롭다운에서 Flash / Flash-Lite 전환이 되는지
  - localStorage `preferred_model` 값이 기존 문자열과 호환되는지
  - 채팅 요청 payload의 `selectedModel` 값이 기존과 동일한지
  - 세션 제목 생성 순서가 `flash-lite → flash`로 유지되는지
  - TTS 모델이 `gemini-2.5-flash-preview-tts`로 유지되는지

## 3. 명시적으로 제외할 범위

### Provider 추상화 제외

OpenAI / Gemini 멀티 프로바이더 전환은 이번 범위에서 제외한다.

이유:
- `generator.ts`는 Gemini SDK의 `fileData`, `inlineData`, Google Search grounding, grounding metadata 처리에 강하게 결합되어 있음.
- OpenAI는 YouTube `fileData`와 Google Search native grounding을 그대로 지원하지 않으므로 공통 메시지 포맷·fallback 정책·tool binding 정책이 별도로 필요함.
- 단순 상수화와 함께 진행하면 변경 범위가 커지고 회귀 위험이 높음.

### 모델 추가 제외

- `gemini-3.x`, OpenAI 모델, Imagen 등 신규 모델은 이번 작업에 추가하지 않는다.
- 현재 운영 중인 모델 문자열만 중앙화한다.

## 4. 권장 구현 순서

1. `api/_lib/models.ts` 생성 후 서버 하드코딩 문자열 교체
2. `src/lib/models.ts` 생성 후 프론트 타입·기본값 교체
3. `Header.tsx` 드롭다운을 옵션 배열 기반으로 정리
4. `rg "gemini-2\\.|gemini-3\\.|selectedModel"`로 잔여 하드코딩 확인
5. `npm run build` 실행
6. `docs/TODO.md`의 모델명 상수화(Phase A) 항목 완료 처리
7. `docs/DEV_HISTORY.md`에 v4.79 계획/완료 내역 반영

## 5. 작업량 평가

- **Phase A+B만 수행**: 2시간 안팎. 회귀 가능성 낮음.
- **Phase A+B+C 및 문서 정리까지 수행**: 2~3시간.
- **Provider 추상화까지 포함**: 1~2일 이상. 별도 설계 필요.

## 6. 최종 판단

먼저 Phase A+B로 모델 문자열 중앙화를 끝내는 것이 적절하다.  
이 단계는 모델 추가를 쉽게 만드는 기반 작업이며, 현재 Gemini 전용 런타임 구조를 흔들지 않는다.  
OpenAI·Gemini 멀티 프로바이더 추상화는 모델 레지스트리 적용 후 별도 작업으로 분리한다.
