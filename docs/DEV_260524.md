# DEV_260524 — 타임아웃 에러 키 로테이션 보완 + ConstellationRenderer 모바일 UI 개선

> 작성일: 2026-05-24

---

## 문제 요약

Gemini 3.5 Flash에서 간헐적으로 타임아웃 또는 모델 응답 실패가 발생할 때, 기존 코드는 이를 키 로테이션 대상으로 분류하지 않아 폴백 없이 에러가 그대로 사용자에게 노출되는 구조였다.

---

## 누락된 에러 케이스

### 기존 처리 대상
| 에러 | 처리 |
|---|---|
| 429 RESOURCE_EXHAUSTED (RPM) | 키 로테이션 |
| 429 daily quota (RPD) | 24h 비활성화 |
| 503 UNAVAILABLE | 키 로테이션 |
| 401/403 | 키 무효화 + 로테이션 |
| 500 + 멀티모달 | 텍스트만으로 재시도 |

### 누락된 케이스 (이번 수정)
| 에러 | 원인 | 처리 방식 |
|---|---|---|
| `DEADLINE_EXCEEDED` | Gemini API 응답 타임아웃 | 키 로테이션 후 재시도 |
| `status 504` | 게이트웨이 타임아웃 | 키 로테이션 후 재시도 |
| `ERR_STREAM_DESTROYED` | 스트림 연결 끊김 | 키 로테이션 후 재시도 |
| `503 UNAVAILABLE` (LangChain 경로) | `isStreamError`의 문자열 검사에만 의존 | 상태 코드 직접 체크 추가 |

## 수정 내역

### 1. SDK 외부 catch (`api/_lib/agent/nodes/generator.ts`)

**위치**: SDK while 루프 catch 블록 (~line 573)

```ts
// 추가
const isTimeout = err?.status === 504
    || err?.message?.includes('DEADLINE_EXCEEDED')
    || err?.message?.includes('504')
    || err?.code === 'ERR_STREAM_DESTROYED';

// 변경 전
} else if (isRateLimit || isUnavailable) {
    // 키 로테이션
    console.log(`... reason:`, isRateLimit ? '429' : '503');

// 변경 후
} else if (isRateLimit || isUnavailable || isTimeout) {
    // 키 로테이션
    console.log(`... reason:`, isRateLimit ? '429' : isTimeout ? 'timeout/504' : '503');
```

2.5 Flash 단일 경로와 3.5 Flash 경로 모두 동일한 catch 블록을 공유하므로 양쪽에 동시 적용된다.

---

### 2. Stage2 inner catch (Two-track, ~line 452)

3.5 Flash + Google Search 선택 시 활성화되는 Two-track 경로의 Stage2(3.5 합성) 재시도 루프.

```ts
// 추가
const isStage2Timeout = status === 504
    || error?.message?.includes('DEADLINE_EXCEEDED')
    || error?.message?.includes('504')
    || error?.code === 'ERR_STREAM_DESTROYED';

// 변경 전
if (status === 429 || status === 503) {
    ...
    console.warn(`[LangGraph] Stage2 quota error (${status}) attempt ...`);

// 변경 후
if (status === 429 || status === 503 || isStage2Timeout) {
    ...
    const reason = isStage2Timeout ? 'timeout/504' : `quota(${status})`;
    console.warn(`[LangGraph] Stage2 error (${reason}) attempt ...`);
```

Stage2가 타임아웃되면 기존과 동일하게 키 로테이션 후 재시도하고, 모든 키 소진 시 2.5 Flash 합성 폴백으로 진입한다.

---

### 3. Stage2 fallback catch (~line 503)

Stage2가 모든 키를 소진했을 때 진입하는 2.5 Flash 합성 폴백 루프.

```ts
// 추가
const isFbTimeout = fbStatus === 504
    || fallbackError?.message?.includes('DEADLINE_EXCEEDED')
    || fallbackError?.code === 'ERR_STREAM_DESTROYED';

// 변경 전
if (fbStatus === 429 || fbStatus === 503) {
    console.warn(`... failed with ${fbStatus}`);

// 변경 후
if (fbStatus === 429 || fbStatus === 503 || fbStatus === 504 || isFbTimeout) {
    console.warn(`... failed with ${isFbTimeout ? 'timeout' : fbStatus}`);
```

---

### 4. LangChain catch (~line 754)

도구 인텐트(`drug_id`, `drug_info`, `pharmacy_search` 등) 및 SDK 경로 전체 실패 시 비스트리밍 폴백으로 동작하는 LangChain 경로.

**추가 발견**: 기존 LangChain catch는 503/UNAVAILABLE을 `isStreamError`의 문자열 포함 검사(`err.message.includes('503')`)에만 의존하고 있었음. 상태 코드 직접 체크가 빠져 있어 함께 보완.

```ts
// 추가
const isTimeout = err?.status === 504
    || err?.message?.includes('DEADLINE_EXCEEDED')
    || err?.message?.includes('504')
    || err?.code === 'ERR_STREAM_DESTROYED';
const isUnavailable = err?.status === 503 || err?.message?.includes('UNAVAILABLE');

// 변경 전
if (isRateLimit || isStreamError) {
    ...
    console.log(`... reason:`, isRateLimit ? '429' : 'stream-error', ...);

// 변경 후
if (isRateLimit || isStreamError || isTimeout || isUnavailable) {
    ...
    const reason = isRateLimit ? '429' : isTimeout ? 'timeout/504' : isUnavailable ? '503' : 'stream-error';
    console.log(`... reason:`, reason, ...);
```

### 5. 최종 에러 분류 (`api/chat.ts`)

그래프 전체가 실패했을 때 사용자에게 보여주는 메시지 분류.

```ts
// 변경 전
: status === 503 || msg.includes('503') || msg.includes('UNAVAILABLE') ? 'unavailable'

// 변경 후
: status === 503 || status === 504 || msg.includes('503') || msg.includes('UNAVAILABLE') || msg.includes('DEADLINE_EXCEEDED') ? 'unavailable'
```

504/DEADLINE_EXCEEDED 발생 시 "서버가 일시적으로 불안정합니다. 잠시 후 다시 시도해주세요." 메시지가 4개 언어로 표시된다.

## ConstellationRenderer 모바일 UI 개선 (`components/ConstellationRenderer.tsx`)

### 배경

모바일에서 카드가 세로로 긴 직사각형(500×420px 논리 크기 → 표시 390×420)으로 렌더링되는 문제. 전체적인 폰트·버튼 크기도 데스크톱 기준으로 고정되어 있어 모바일에서 과도하게 컸음.

### 수정 내역

#### 1. 캔버스 높이 축소

```ts
// 변경 전
const height = isMobile ? 420 : 500;

// 변경 후
const height = isMobile ? 340 : 500;
```

390px 폭 기준 390×340 — 정사각형에 가까운 비율로 개선.

#### 2. 별 이름 레이블 폰트 반응형 적용

캔버스 내부 `renderConstellation()`에서 `window.innerWidth`로 모바일 판단 후 분기.

```ts
const isMobileCanvas = window.innerWidth < 640;
const labelFontSize = isMobileCanvas ? 10 : 12;
const labelHeight = isMobileCanvas ? 15 : 18;
ctx.font = `${labelFontSize}px -apple-system, ...`;
```

기존 12px 고정 → 모바일 10px / 데스크톱 12px.

#### 3. 헤더 바 컴팩트화

| 항목 | 변경 전 | 변경 후 |
|---|---|---|
| 헤더 위치 | `top-3 left-3 right-3` | `top-2.5 left-2.5 right-2.5` |
| 헤더 패딩 | `py-2` | `py-1.5 sm:py-2` |
| 별자리명 폰트 | `text-xs sm:text-sm` | `text-[10px] sm:text-sm` |
| 시간 표시 폰트 | `text-[10px]` | `text-[9px] sm:text-[10px]` |
| 시간 버튼 폰트/패딩 | `text-xs px-1.5` | `text-[10px] sm:text-xs px-1 sm:px-1.5` |

#### 4. 카메라 버튼 높이 정렬

기존 카메라 버튼은 `p-1` + 배경 없음으로 시간 조절 버튼들과 높이·스타일이 불일치.
시간 버튼과 동일한 `py-0.5 px-1 bg-white/10 rounded` 패턴으로 통일.

```tsx
// 변경 전
className="p-1 sm:p-1.5 hover:text-white text-slate-300 ..."

// 변경 후
className="px-1 sm:px-1.5 py-0.5 text-[10px] sm:text-xs text-slate-300 bg-white/10 hover:bg-white/20 hover:text-white ... rounded"
```

#### 5. 줌/리셋 버튼 크기 축소

```tsx
// 변경 전
className="w-10 h-10 ..."

// 변경 후
className="w-8 h-8 sm:w-10 sm:h-10 ..."
```

컨트롤 위치도 `bottom-3 right-3` → `bottom-2.5 right-2.5 sm:bottom-3 sm:right-3` 조정.

#### 6. 별 인포패널 컴팩트화

| 항목 | 변경 전 | 변경 후 |
|---|---|---|
| 패딩 | `px-4 py-3` | `px-3 py-2 sm:px-4 sm:py-3` |
| 별 이름 폰트 | `text-[13px]` | `text-[11px] sm:text-[13px]` |
| 라벨/값 폰트 | `text-[10px]` / `text-[11px]` | `text-[9px]` / `text-[9px] sm:text-[11px]` |
| min-width | `min-w-[185px]` | `min-w-[150px] sm:min-w-[185px]` |
| border-radius | `rounded-2xl` | `rounded-xl sm:rounded-2xl` |

#### 7. 줌 퍼센트 인디케이터 위치 조정

버튼이 `w-8`(32px)로 줄었으므로 우측 오프셋 조정.

```tsx
// 변경 전
className="absolute bottom-3 right-14 ... h-6"

// 변경 후
className="absolute bottom-2.5 sm:bottom-3 right-11 sm:right-14 ... h-5 sm:h-6"
```

### 설계 검토 중

- **별자리명 위치 변경 검토**: 헤더 좌측 고정 텍스트 → 캔버스 상단 워터마크 방식으로 이동 시 헤더 공간 확보 가능. `docs/constellation-card-sample.html`에 Option A/B 비교 샘플 작성. 모바일 hover 미지원 문제로 "탭 시 표시" 방식은 discoverability 저하 우려 — 워터마크 방식 채택 검토 중.
